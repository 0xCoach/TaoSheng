# 任务卡 030：推送测试优先发日报 + 通道里的日报用完整版（后端，小卡）

## 背景（负责人要求）

1. 推送通道的“测试一下 / 保存并测试”：**有日报就直接发最近一份日报**，没有日报时才发现在的测试消息。
2. 推到微信等通道的日报要能直接读：发**完整版**（一句话 + 各栏目），手机本地通知仍只发一句话简洁版。

## 要做的

1. **日报正文生成**（放 `push/` 或 `review/` 下一个小函数）：输入 `DailyReview`，按通道格式输出：
   - Markdown：
     ```
     **10月23日 星期五 · 回顾**

     一句话那行

     ### 要紧的
     - …
     ### 发生了什么
     - …
     ```
     （栏目按回顾里的顺序，空栏目不写，“一句话”栏目作为导语不重复列）
   - 纯文本：同样结构，用“【要紧的】”代替 `###`，去掉加粗。
   - JSON（通用网址）：沿用现有 JSON 外壳，`body` 放纯文本版，另加 `review` 字段放 `{date, brief, sections:[{title, lines}]}`。
   - 标题：`回响 · 10月23日回顾`。
2. **每日回顾推送**：`RoomReviewRepository` 推送时，本地通知照旧用 `brief`；转发到通道的用上面的完整版。`Notifier` 签名不改：给 `ChannelNotifier` 加一个只在内部用的重载或参数（例如额外的 `remoteBody`），本地通知走 `body`，通道走 `remoteBody ?: body`。
3. **`test(id)`**：取最近一份日回顾（`ReviewRepository.recent()` 的第一条，或直接查表）。有 → 用第 1 步的完整版发出，标题前加“测试 · ”，成功返回“已发送 10月23日的回顾”；没有 → 发现在的测试消息，返回原来的文案。日志标题照实写。
4. 测试用的日报发送不受“每日回顾推送”开关影响（测试是用户主动点的）。

## 测试（适度，共不超过 4 个）

Markdown / 纯文本正文格式；有日报时测试发日报、没有时发测试消息；每日回顾推送时本地用简洁版、通道用完整版。`./gradlew assembleDebug` 通过。**不要跑全量测试，不要反复重跑。不做真实发送。**
