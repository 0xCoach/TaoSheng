# 卡 056 · 停录时段 / 睡眠模式（后端）

App 名叫“涛声”。给用户看的文字一律写“涛声”，只说结果、不讲机制。
约定文件（签名不要改；确需改，在交付说明里提）：
- `capture/QuietScheduleContract.kt`（新文件，负责人已写）：`QuietRule`、`QuietWindow`、`QuietSchedule`。
- `capture/CaptureContract.kt`：`CaptureStatus` 新增 `quietName`（负责人已加）。

界面（“录音与后台”里的停录时段卡片、首页录音卡上的“睡眠中 · 7:00 自动恢复”）由 Claude 做，**本卡不改 `ui/` 和 `MainActivity.kt`**。界面只用 `AppGraph.quietSchedule` 和 `CaptureController`。

## 一、已定方案（负责人已确认）

- 只有一种规则，叫“停录时段”，可以加多条。每条规则有：开始时间、结束时间（可以跨午夜，`endMinute <= startMinute` 即跨天）、重复的星期（按开始那天算）、开关。
- 首次安装（以及老用户升级后第一次启动）预置一条 `id = "sleep"`、名字“睡眠”、23:00–7:00、每天、**默认关闭**。用户删掉后不再自动补回。
- 到了停录时段：**沿用现有“暂停”的做法**。服务和前台通知都不退出，只放下麦克风，到点再拿起来。这是硬性要求：安卓 14 起不允许从后台重新启动麦克风类的前台服务，彻底停掉的话第二天早上很可能起不来。
- 处在时段内时，`CaptureStatus` 为 `state = Paused`、`pausedUntil = 本段结束时间`、`quietName = 规则名字`。
- 时段内用户点“恢复”（`CaptureController.resume()`、通知栏按钮）：**只对本段生效**，立即恢复录音，此后 `QuietSchedule.active` 为 null；下一段照常停。
- 时段内用户手动暂停 N 分钟，或手动暂停期间进入停录时段：恢复时间取**结束得晚的那个**。显示上，停录时段结束得晚就带 `quietName`，否则不带。
- 多条时段重叠或首尾相接：合并成一段，`endsAt` 取合并后的结束时间，名字用最先开始的那条。
- 用户主动关掉录音（`Stopped`）时，停录时段什么都不做。在时段内打开录音：直接进入时段暂停状态。
- 改、删、开关规则后立刻重新判断：比如当前这段被关掉了，而且没有手动暂停，就马上恢复录音。

## 二、实现要点

1. **存储**：规则用 JSON 存进 `capture.xml`（备份白名单里已有，规则会跟着备份）。键名 `quietRules`；“本段已提前恢复”存 `quietSkipUntil = 被跳过那段的 endsAt`。
2. **纯计算（便于测试）**：`QuietRules.windowAt(rules, now, zone): QuietWindow?` 和 `QuietRules.nextChange(rules, now, zone): Long?`（下一次进入或离开时段的时间）。夏令时不用特殊处理，按 `ZonedDateTime` 正常算。
3. **定时**：在每个边界（进入、离开）用 AlarmManager 定精确闹钟（参考现有 `CaptureWatchdog` 的暂停闹钟），没有精确闹钟权限就退回 `setAndAllowWhileIdle`；另外服务每次心跳时也对一遍，防止闹钟被系统延后造成漏判。开机、App 更新、改时区、改系统时间之后要重新定闹钟（`BOOT_COMPLETED`、`MY_PACKAGE_REPLACED`、`TIMEZONE_CHANGED`、`TIME_SET`）。
4. **服务**：`CaptureService` 进入停录时复用 `pauseUntil` 的放麦克风流程，并且要区分这是停录时段、不是手动暂停（`resume` 时据此写 `quietSkipUntil`）。看门狗、被杀检测、漏录统计都**不能把停录时段算成故障或漏录**（同手动暂停的处理）。守护记录写 `Paused`，detail 写“停录时段：睡眠，至 07:00”；恢复时写 `Resumed`。
5. **通知**：处在停录时段时，前台通知标题写“涛声 · {名字}中”（如“涛声 · 睡眠中”），正文“7:00 自动恢复，点此立即恢复”，按钮写“现在恢复”。手动暂停的通知文案不变。
6. **装配**：`AppGraph` 增加 `quietSchedule` 和 `isQuietScheduleReady`，由 `ResoundApp` 装配。

## 三、必测（适度，一共 6～10 个）

- `windowAt`：跨午夜 23:00–7:00 在凌晨 2 点命中、`endsAt` 是当天 7:00；星期按开始那天算（周五 23:00 起、规则只选周五，周六凌晨 2 点命中，周六 23:00 不命中）。
- 两段首尾相接合并。
- 时段内 `resume()` 后 `active == null`，下一段照常生效。
- 手动暂停与时段重叠时取较晚的结束时间。
- 关掉当前这段后立即恢复录音（用假的控制器或服务层测试，1 个即可）。
- 老用户升级后预置“睡眠”且为关闭，删掉后不再补回。

测试规矩见 `AGENTS.md`：只跑本卡测试，跑通一次就停，总耗时不超过 10 分钟。
