## 验证

编译前均设置 `export JAVA_HOME=/opt/homebrew/opt/openjdk@21`，使用本机缓存离线执行：

```sh
./gradlew --offline :app:testDebugUnitTest \
  --tests app.resound.devices.DeviceCards129Test \
  --tests app.resound.devices.core.CardCodec118Test \
  --tests app.resound.devices.Device119Test --console=plain
```

首次结果：27个用例，26通过、1失败；Gradle总耗时37秒。`CardCodec118Test` 15/15通过，`Device119Test` 10/10通过，新增匹配回归通过。唯一失败是既有占位卡：

```text
folotoy.json：match：至少填写一种识别规则
```

任务卡同时要求“不动 folotoy.json”“全部 JSON 可解析”“只做调研和数据”。既有空 `match` 与解析器严格规则不兼容，无法只改新增卡使该测试通过；不跳过该文件、不伪造通过结果。已向负责人提出最小修正方案：仅允许 trial、无音频/离线/控制配置的纯占位卡使用空匹配，实际设备卡仍要求识别规则。解析修正待确认。

打包命令 `./gradlew --offline :app:assembleDebug --console=plain` 成功，耗时20秒。实际输出 `app/build/outputs/apk/debug/app-debug.apk`，114,754,320字节；检查ZIP中4张说明卡，均与源码逐字节一致。未安装到手机、未发布。SHA-256：`376bdd2b0fc90239d70d16745c66ed2412d761253c794f7675e4f52281f811ab`。

`git diff --check` 通过；受限路径及两张要求保留的卡与基线一致。测试仅运行上述三组，没有运行全量回归。

## 每张卡真机最应验证的地方

| 卡 | 重点 |
| --- | --- |
| ADeus ESP32-C3（新增） | 只在确认刷入引用版本时开启；服务 UUID 也被其他示例/设备使用，不是品牌鉴权。确认音频特征与 CCCD 存在、通知开启成功、实际协商 MTU 足够182B载荷；监听速度/音高正确、无持续缺样。源码未显式添加 BLE2902，且发送有两次4ms延迟；是否可持续录音本次没有证明。 |
| Omi（修改） | DevKit 编码号20/10ms与CV1编码号21/20ms都读对；小MTU下分片重组、断连尾帧处理、电量读取。CV1须先解除持久静音；卡不负责解除静音，也不补传离线录音。检查旧 Friend 通过服务 UUID仍能发现、独立 Friend 不误匹配。 |
| 声云（保持） | 请持CB08真机者确认实时帧长/采样参数/单包是否多Opus帧，检查AE22半帧与多帧、AE21无响应整帧写、启停与文件名消息过滤；补传依赖既有插件，不能仅凭卡解析通过判断。 |
| FoloToy（保持占位） | 原版实时声音走Wi-Fi/IP，不能作为BLE实时输入；占位即使能解析也不应匹配任何设备或产生音频来源。 |

- Omi 名称/服务也被部分 DIY 示例复用；现有 OR 匹配不提供强型号认证。遇不明固件不应仅凭“同UUID”认定协议相同。
