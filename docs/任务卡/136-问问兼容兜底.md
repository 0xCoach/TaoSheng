## 背景

问问完全依赖模型“自己调用工具查记录”。只要某家兼容接口在工具调用上有一点不同，问问就整个不能用：
- Gemini（OpenAI 兼容地址）：检测页“工具调用格式不对”。流式 `tool_calls` 很可能不带 `index`（`LlmStream.kt` 里 `getInt("index")` 直接判格式错）；Gemini 3 还会在工具调用里带 `extra_content.google.thought_signature`，下一轮必须原样带回，否则 400。
- OpenRouter 免费思考模型：检测全绿，实战“格式不对”——推测思考占满 `max_tokens 1800`，`finish_reason=length` 被当成格式错。
- 任何模型：说“你好”也报红字“模型没查记录就作答”。

## 要做

### 1. Gemini 兼容（`LlmSseParser`）

- 工具调用分片没有 `index` 时：有 `id` 按 id 归并；都没有时按出现顺序（同一轮内一个 delta 内第 j 个 → j）。有 `index` 的照旧。
- 保留每个工具调用上的 `extra_content`（整段 JSON 对象，原样合并），`LlmToolCall.json()` 发回时原样带上；没有就不加这个字段（其他服务商请求体不变）。
- 用 Gemini 形状的 SSE 样例写测试（无 index、带 thought_signature、两轮往返）；DeepSeek/OpenAI 形状的旧测试必须照过。

### 2. “程序先查、模型只答”兜底

- 新增问法 `Prefetch`：程序先用 `AskTools` 的同一套查询（关键词 + 语义）按用户问题查记录；问题里的时间词（今天/昨天/前天/上午/下午/晚上/本周/上周/这个月）用本地规则解析成时间范围，能解析就带上；查到的结果按 `AskContext` 的格式（带 ref）放进本轮上下文，再**不带工具**请求模型作答。出处校验沿用现有 `AskCitations`。
- 什么时候用：
  - 该模型（按“服务商配置 id + 模型名”记）被标记为“不会自己查”：模型检测的“工具调用”不过，或实际问答中出现下列情况之一——带工具的请求返回格式错/400、模型没调用工具就回答（且不是 3 里的闲聊）、第二轮带工具结果的请求 400。
  - 实际问答中途触发时，**本次问答立刻改用 Prefetch 重答一次**，不报红字；并记住标记。
  - 配置改动或该项检测重新通过时清除标记。
- 能自己查的模型继续用原来的工具方式（多轮查找效果更好），不受影响。
- 每条回答记下这次用的是哪种（`AskMessage` 加字段，如 `mode = Tools | Prefetch`，走数据库迁移的话和卡 135 错开：**不要改数据库版本**，用已有可扩展字段或偏好；实在需要改表就在交付说明里写明，由 Claude 合并时统一编号）。

### 3. 闲聊不报错

- 系统提示允许“不需要查记录的寒暄/通用问题”直接答，并在回答开头输出固定标记（如 `[无需记录]`，展示前去掉）。带此标记且没有引用出处时，不报“没查记录”“缺少出处”。
- 两种问法都适用。

### 4. 具体提示（替换笼统的“格式不对”“可能不支持工具调用”）

| 情况 | 文案 |
|---|---|
| 不会自己查，已兜底 | 不报错；回答数据里标 `Prefetch` |
| `finish_reason=length` | 回答没写完就被截断了：模型思考太久，可在设置里关掉深度思考或换个模型 |
| 401/403、402、429、断网 | 沿用现有文案 |
| 其他服务端错误 | 沿用“大模型服务暂时不可用，等待重试” |

- 问问的流式 `max_tokens` 从 1800 提到 4096（思考类模型思考也算在内）。
- **模型检测**：工具调用不过时，这一项显示为“不会自己查记录，问问将改用程序先查（可用）”，不算失败（给 `ModelCheckItem` 加一个“可用但降级”的状态，交付说明写清界面怎么显示）；“标注出处”一项在 Prefetch 方式下照样检测。另记“上次实际问答失败原因”（固定文案 + 时间），检测页结果里带出来。
- 问题记录（卡 133 的“整理与大模型诊断”）里加：当前模型是否被标记为“程序先查”、标记原因、时间。
