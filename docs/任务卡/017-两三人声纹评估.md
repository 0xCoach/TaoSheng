# 两三人对话：声纹与耗电初步评估（未实现多人分离）

用户范围：两人为主，最多三人轮流讲话；暂不以多人重叠、嘈杂场景为验收目标。

现有任务卡 006 明确了 CAM++ 声纹录入、markMe / markNotMe / enrollPcm，只服务于认出“我”。任务卡 008 增加自动样本和缓存重打分。现有接口尚非任意多个人物的声纹库。多人分段、聚类、命名和转写对齐需要独立补充。

实测依据：此前本机独立 CAM++ CPU 单线程测试，16 个窗口，合计 47.098 秒音频，模型推理 1.943 秒，首次加载 0.745 秒，192 维特征。此为 sherpa 实验实现，不是完整 App 管线，不包含解码、完整多人分段、对齐和能耗。

仅按这次小样本线性外推，每 4 小时**有效人声**，不重叠提特征约 9.9 分钟计算；若使用 50% 重叠短窗，约 19.8 分钟。不是持续运行 4 小时，也不是新增耗时：现有“认我”已经做一部分声纹计算，可复用缓存与特征。

耗电百分比尚无实测。不能把 CPU 的 ASR 功耗套到 CAM++，也不能将速度直接换成电量。若仅作公式示例：增量平均功率 P 瓦 × 新增计算秒数 / 3600 = 增量瓦时；P 和新增时间都需同音频 A/B 测量。

建议实现路线：按现有批处理运行；先用短窗声纹变化找候选换人边界，聚成最多三个匿名说话人；可靠片段与录入声纹比对命名；边界、短句、重叠低置信度保留未知，不强行归“我”。若精度不够再评估专门的说话人分段模型，不能为了省算力把人分错。

建议验证：真实双人交替音频与人工说话人时间标注；比较当前 SenseVoice+认我 与 增强多人方案的等量任务、同一运行条件，测新增计算时间、错认率、整机扣基线能耗。重复并交换顺序，避免上轮空闲功耗漂移。新增三人只增加少量向量比较，主要计算成本取决于音频时长和切分频率，不是人数线性相乘。
