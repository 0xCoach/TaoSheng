# 卡 047 交付说明

## 已完成

- 正式生成接入 `SkillGenerationWork`：按“技能 id + 日期”使用 WorkManager 唯一任务和 `KEEP`，要求联网，加急配额不足时退回普通任务；Android 10/11 提供加急兼容前台通知。
- `generate` 返回前同步设置 `generating`、清掉对应旧 `generated`。观察任务终态后先写结果再退出生成中；Application 作用域独立于页面。进程重新创建时从 WorkManager 未完成任务恢复生成状态，入队遇到已有任务时观察实际保留的任务。
- Worker 复用 `run(..., MANUAL)`，保留运行记录和用量。网络/服务器错误最多重试 2 次，采用 30 秒起的指数退避；密钥和最终格式错误直接结束。系统停止的协程继续抛取消异常，交由 WorkManager 重新调度，记录显示“系统暂停，等待后台重试”。耗尽重试后，记录、界面结果和通知都显示最终失败原因。
- 完成时直接调用 `LocalNotifier` 的“技能生成”通知类别：单卡摘要并直达卡片，多卡显示“出了 N 张”并带日期；没出卡/失败分别写明原因。不受技能的推送开关影响，不经过外部推送通道；原有 `auto && skill.push` 保持自动运行专用。
- DAO 在事务内区分手动/自动合并。手动恢复同实体或重叠时段的删除卡，保留合并别名并清掉删除标记；之后自动运行能更新该卡。自动仍尊重删除记录。恢复也受每天有效卡数量限制。
- 删除跳过与数量上限分开返回并写入运行记录：`这天的卡你删过，自动运行跳过了` / `今天已经有 N 张，达到每天上限`。

没有修改 `ui/`、`MainActivity.kt`、任何约定文件签名、数据库结构或依赖版本。

## 验证

新增 `SkillGeneration047Test`，共 8 项定向用例：

1. 一天一张的删除卡：自动跳过原因、手动恢复、随后自动更新。
2. 会议删除时段的重叠与旧实体别名恢复。
3. 满额时报告实际数量（内置会议技能为 8 张）。
4. 返回前状态、重复生成去重、完成结果、重新生成清旧结果、加急/网络配置。
5. 重建仓库后恢复排队状态，沿用已有任务并完成。
6. 成功/没出卡/失败通知的标题、正文、类别与跳转，以及多卡日期入口；关闭技能推送仍有本地通知且不调用推送通道。
7. 网络和服务器错误最多重试两次，中间不发完成通知，最终运行记录与失败结果一致。
8. 模拟系统停止时取消执行，保留等待重试记录；再次执行能保存卡并发完成通知。

已全部通过。首轮实际执行 8 项时通过 7 项；上限用例原先错误地用覆盖设置修改官方限额，修正为填满实际 8 张。随后仅重跑该用例和修改了最终失败记录的重试用例，2 项通过。另一次早期测试初始化因 JUnit 方法返回类型失败，已修正。没有跑全量测试，相关测试及构建总用时不足 1 分钟。

## 真机需要注意

本卡未连接、安装或操作手机。Robolectric/WorkManager 测试覆盖了后台逻辑和恢复模拟，不代表已验证澎湃 OS 的实际调度。

负责人在小米 14 Pro 验收：删除当天收工卡后手动生成，立即切页/锁屏，再确认卡片、完成通知和单卡直达；断网恢复、系统回收进程后重新打开时，确认生成状态恢复及最终结果。通知需要系统允许“技能生成”类别，关闭通知不影响卡片保存。

## 遗留问题与界面配合

- 多卡、没出卡和失败通知复用现有 `resound://review?open=review&date=…` 日期入口，能切到指定日记忆；现有界面在当天回顾存在时还会打开回顾弹层。若希望只定位当天卡片而不弹回顾，需 Claude 后续增加纯日期入口，本卡没有修改界面。
- 用户在系统设置中“强行停止”应用，以及澎湃 OS 自身的后台限制，仍由系统决定何时恢复执行；本卡未做真机验证。
