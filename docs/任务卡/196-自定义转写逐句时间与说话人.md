# 卡 196：自定义转写支持逐句时间戳与说话人（议题 #48）

基线：main（数据库 38）。执行：Codex（Astra）。工作目录 `~/Developer/TaoSheng-196`，分支 `codex/196-custom-segments`。目标版本 0.5.0。**不改数据库**，不改 `ui/`、`MainActivity.kt`（界面如需配合写进交付说明）。

先读议题 #48（`gh issue view 48`）：提议人给出了现状分析、代码位置和真实返回样例。本卡按 #48 的方向做，并按下面“与 #48 的差异”补齐。

## 现状

- `shared/.../net/NetCustomAsr.kt`：请求固定 `response_format=json`；响应经 `NetQueries.customTranscriptionText()` 只取 `text`，压成一条 `AsrSentence(0, duration, text, null)`。
- 结果：自定义转写的整段录音只有一行、没有逐句时间、不能点句跳转、没有说话人；声纹阶段只能给这一整行贴一个身份。
- 豆包（`DoubaoProtocol` 读 `utterances` 的 start/end/speaker_id）和本地转写都能逐句 + 说话人，界面、导出、声纹阶段已支持多句多说话人。

## 目标

### 1. 请求：默认要带时间戳的格式，不支持就退回并记住
- 默认请求 `response_format=verbose_json`（OpenAI 官方及多数兼容服务只有这样才返回 `segments`）。
- 服务返回 4xx 且判定为“不认这个格式”（400 / 415 / 422，或错误信息含 response_format）时，**同一段录音立刻改用 `json` 再请求一次**，并**按接口地址记住“只支持 json”**，之后这个地址直接用 `json`，不再每段多传一次（慢速链路的用户见 #46）。网络错误、超时、5xx、401/403 不触发退回。
- 记住的结果是本机运行状态：键用地址指纹（不存明文地址以外的密钥信息），按卡 190 归为“不备份”，守卫测试要过；用户改了转写地址或模型时清掉，重新试探；另每 30 天重新试探一次 `verbose_json`（服务可能升级）。
- 热词 prompt、请求头、超时（#46 的上传与总时限）等现有行为不变。

### 2. 解析：有 segments 就逐句，没有就照旧
- 解析放 `:shared`（如 `CustomTranscription` 规则），平台无关。
- `segments[]`：`start`/`end` 为秒（可为小数）→ 毫秒；`text` 去首尾空白；按 `start` 排序。
- 坏数据处理：`end <= start`、负数、`text` 为空的段丢弃；超出录音时长的截到时长；有效段为 0 时退回 `text`。不能因一段坏数据让整段失败。
- **不要重复文字**：用 `segments` 时只取各段自己的 `text`，不拼顶层 `text`（#48 的服务在顶层 `text` 里带了“[00:17] 说话人2：”前缀）。段内文字若也以 `[mm:ss] 说话人N：` 或 `说话人N：` 开头，去掉这个前缀。
- **说话人**：`speaker`（整数或字符串均可，也兼容 `speaker_id`）按**首次出现顺序**重新编成 `"0"`、`"1"`…（界面显示时 +1 成“说话人 1/2”）；没有说话人字段的段 `speakerTag = null`；整份返回都没有说话人时全部为 null，与现在一致。
- 用户在设置里关掉了“区分说话人”时，忽略服务端说话人（全部 null），逐句时间照常保留。
- 只有 `text`（含 `json` 退回）时：与现在完全一致（一条、0 到时长、无说话人）。错误响应（`base_resp.status_code` 等）映射保持不变。

### 3. 后续流程兼容
- 确认转写落库（`TranscribeRunner` 逐条写 `TranscriptLineEntity`）、声纹阶段、原话页分组气泡、导出 SRT/文本、整理输入对“服务端给的说话人标签”与豆包路径一致处理：声纹阶段应能把这些标签对应到“我”/熟人（与豆包 `speaker_id` 同一套逻辑）。若声纹阶段对来源有区分，补齐并说明。
- 不改豆包、本地转写的任何行为。

## 不要做

- 不在手机上做说话人分段（本地分段模型只用于本地转写，本卡不接）。
- 不改数据库、不改界面文件、不加用户可见的新开关（退回与记住全自动）。
