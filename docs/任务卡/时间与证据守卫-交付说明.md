# 时间与证据守卫（TemporalGuard / EvidenceGuard）交付说明

## 做了什么

### TemporalGuard（shared，纯函数）

`shared/.../data/TemporalGuard.kt`：提取出的"提及时间"（dueAt）与"说话时间"（recordedAt）互相校验。

- dueAt 早于说话时刻超过 36 小时、或晚于说话时刻超过约 750 天 → 判为模型写错日期字面量，**作废 dueAt**。
- `dueText`（模型摘的原文，如"下周三"）始终保留——人还能看到原文，只是不再发出错误提醒。
- recordedAt 为 null（手打条目、无原话行）时不做判断，原样放行。
- 作废时记 `FailureNotes`，可追查是哪条内容、偏差多大。

接入点（全部真实入库路径）：
- `DigestRunner`：recordedAt 取原话行 startAt → 事件起点 → 整理时刻，dueAt 过守卫后**再算** `valueScore`——无效期限不再给条目加权。
- `TopicGeneration`、`RedoFactory` 两条路径同样接线。

### EvidenceGuard（shared，纯函数）

`shared/.../qa/EvidenceGuard.kt`：问答证据质量守卫。

- `clean()`：清掉回答里越界的 `[#n]` 出处编号（如只有 3 条证据却引用 `[#9]`），计数交给界面提示——模型编造的引用不再伪装成有出处。
- `hasCitation()`：回答是否还留有有效引用。
- `strength()`：证据强度 0-3（0 无 / 1 单薄 / 2 尚可 / 3 强），事件级来源与价值加成来源加权更高。

接入点：
- `GroundedQA.ask()`：模型回答先过 `clean`，`QaAnswer` 新增 `invalidCitations`、`evidenceLevel` 两字段。
- `QaScreen`：新增两条如实徽章——"已剔除 N 处无效出处编号"、"证据单薄，仅供参考"。（界面改动仅限此两行徽章，AGENTS「不写界面」约束下最小必要，用于守卫结果的用户可见性。）

## 真机需要注意什么

- 守卫是被动逻辑：只在提取/问答输出越界时生效，正常运行无感知。
- 若后续看到 FailureNotes 里有 `dueAt` 记录，说明模型确实写错过日期——那是守卫在工作，不是新问题。
- 问答界面新增徽章只在模型编引用/证据单薄时出现。
