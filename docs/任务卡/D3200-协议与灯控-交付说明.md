# D3200 专有协议与灯控适配

## 做了什么

在 0.2.22 的专用录音设备框架内增加试用设备卡 `d3200`，支持安克 / 飞书录音豆。设备通过私有 BLE 协议提供音频，不依赖 Android 通话音频路由。实现 P-256 ECDH、HKDF、文件密钥解封、AES-CTR 音频解密，以及 Opus 解码为 16 kHz 单声道 PCM。

灯控与录音由同一个连接会话管理：BLE 完成固定的 SPP 准备命令，SPP 发送 RGB 命令并持续处理回执。提供“停止控灯 / 常灭 / 暖橙常亮”，默认停止控灯；停止控灯只停止发送灯光命令，保留共用的音频通道。未验证的固件不会发送灯控命令。设备选项页是最小实现，供维护者审核界面接入方式。

离线文件通过 `FileSourcePlugin` 接入现有 `DeviceSync`，复用下载缓存、进度持久化、重试、导入完成确认和时间线入库。D3200 只能在停止录音时读取保存文件，因此先等待设备保存、补传，再按用户设置决定是否开始录音；不会主动停止用户当前录音。新文件优先，实时采集覆盖范围用于避免重复导入。保留设备原文件，`delete=false`。

框架只增加可选能力：按设备卡注册连接器、逐帧时间元数据、串行补传标记和可选的新文件优先顺序。其他设备保持原默认行为；未修改 `AudioSource.kt` 或 `*Contract.kt` 的接口签名。增加 connectedDevice 前台服务类型，并在有蓝牙连接权限时使用。

不包含个人包名、签名、更新限制、设备地址、录音、密钥或私有验证版迁移逻辑，不改变官方版本号和数据库版本。

## 接入与复测

1. 在设置的专用录音设备入口启用试用 D3200 卡，扫描并配对；其他管理 App 应先断开设备。
2. 在录音输入选择该设备。默认自动补传已保存文件，默认不自动启动设备录音。
3. 设备选项中可设置灯光、自动补传和补传后自动录音，也可手动检查离线录音。
4. 设备离开手机后独立录音，回来先按键停止并保存；保持停止，连接涛声后等待补传和导入确认。
5. 切换为手机音源或停止涛声收音可暂停补传，已持久化进度保留；不得根据灯控回执推断声音已经落库，应在时间线试听确认。

## 验证与限制

- 适配基线：上游 `d82cc5545403fd34d83375a295634d5fec61f1ee`（0.2.22）。
- 新增三个测试类，覆盖分帧和校验、密钥派生、音频序号、Ogg、历史分页与范围、断点边界包、串行补传启动顺序、排队帧时间戳和官方任务标识。本分支 `:app:assembleRelease` 通过（8 分 13 秒）；22 项相关 JVM 检查通过（JUnit 4.13.2，3.219 秒），直接针对本次编译类运行，未运行全量或 Android/Robolectric 测试。
- 相同协议和框架接入实现已在 realme 手机上配合 D3200 主固件 `04.92` 验证：常灭时实时短句清晰；设备独立录音后补传到时间线、完成本地转写，手机回放由用户确认内容清楚完整；重新检查不重复排队。暂停补传、恢复实时输入以及停止控灯后保持音频连接均已验证。
- 上述真机验收使用独立验证包；本 PR 去掉其包名、签名和历史迁移逻辑后，不覆盖安装到用户正在录音的手机。维护者仍需用官方构建进行真机验收。
- 暖橙模式有协议回执，尚未完成本轮肉眼观察；不能当作已验证的物理灯效。
- 常灭是连接期间反复发送的偏好，不是永久修改。离线新录音、设备上电、断线及重连前可能亮灯。保留 Android 前台通知和系统麦克风指示。
- 未完成长时间录音、全量历史文件、冷启动和无线电重启的稳定性验收。设备缺包、无进展或命令超时会重连或保留任务重试，不将不完整音频标为导入完成。
- 固件兼容性、电量显示和设备时钟偏差还需更多设备验证；当前按设备文件时间入库，不做时钟写入。未增加删除、重置、绑定、OTA 等命令。

## 协议来源

协议实现参考 [AllDayRec](https://github.com/suyiiyii/AllDayRec) 的 MIT Bean 实现，保留许可证于 `vendor/d3200/LICENSE-AllDayRec`。另参考 [tacshi/Soundcore](https://github.com/tacshi/Soundcore) 的协议研究，参考版本 `f01a19c227aac0cee9a7c851b3f6b69cf5540a24`；未引入其 SDK 或二进制。灯控帧与该设备的回执已在用户授权的真机测试中验证。
