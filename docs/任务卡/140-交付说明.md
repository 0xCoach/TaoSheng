# 卡 140 交付说明

## 范围与兼容

本卡新增设备中枢与 Android 插口，仍由 ManagedDevices 驱动现有设备；不接入新中枢，不改界面、录音服务、数据库结构或既有约定签名。

实施前确认的必要范围例外：备份代码位于设备目录外，且采用白名单。按任务卡要求，最小修改 `BackupSettings.prefs` 与 `BackupArchive.safePrefs`，纳入独立的 `device-drivers` 配置文件；不改变备份格式或其他配置规则。

新增仓储、连接工厂与状态类型放在 hub 包，作为卡 140 明确要求的新平台无关插口，不修改 `*Contract.kt`。卡 141 可通过这些插口接线；旧设备身份使用 `android:` + `ManagedDevices.deviceKey(address)`，不更改存量配对键和补传表。

装配例外（实施前记录）：`AppGraph.kt` 增加一个设备平台容器属性，由现有 `createDevices` 装配。旧 `AndroidDeviceRadio` 的扫描委托同一个蓝牙中心，确保新旧入口共用扫描限流；不更换 ManagedDevices 或接入新中枢。这里只增加依赖容器属性，不调整其他功能。

## 完成内容

- `:devices/commonMain/app.resound.devices.hub` 新增 `DeviceHub`、状态/仓储/连接插口、会话和驱动调用边界。只用 Kotlin、协程及现有驱动约定；无平台 import、文件或数据库操作。
- 广播支持唯一确定匹配、冲突诊断、候选返回、人工选定和已选驱动缓存。保存句柄、设备身份与驱动编号的对应关系；冲突不会建连接。
- 同设备租约用 `Mutex` 排队，`wait=false` 返回 `BusyRetry`。租约块及其子任务结束才释放；物理断开取消持有者，取消/失败都走释放路径。
- 每个会话最多 4 个定时任务，重复名称或超额返回 `BusyRetry`；间隔至少 30 秒。会话取消时取消全部任务，释放经工具箱创建的解码器，再关闭驱动与 GATT。
- 诊断按设备句柄保存最近 500 条，单条最多 2048 字符。匹配冲突、故障次数和驱动日志进入诊断；状态错误只暴露 `ErrorCode`，停用原因用枚举。
- Android 新增唯一蓝牙中心、GATT 适配器、JCA 加密、Opus 包装、时钟和 SharedPreferences 仓储。经典串口明确返回 null。
- 蓝牙中心将厂商原始数据、服务 UUID、名字和信号强度转成 `Advertisement`；多个收集器共享扫描，可传服务 UUID 集合。扩大过滤范围才重启，30 秒窗口最多启动 5 次，第 6 次延后；旧设备扫描也委托此中心。
- GATT 沿用旧连接的串行操作队列和单通道 CCCD 复用。两种写入模式均报告协商 MTU−3，未知时为 20；超长直接 `WriteTooLong`，不拆包。底层断开事件重放给中枢，保留说明卡 MTU 请求偏好。
- 原 `AndroidOpusDecoder` 文件未改。新包装读取它报告的真实 PCM 采样率，按请求速率做连续箱形平均降采样，保留交错声道；不支持的格式返回 `Unsupported`。解码输出可为空，不能按回调次数计算音频时长。

## 状态机与卡 141 接线

| 触发 | 状态与动作 |
|---|---|
| `match` 唯一确定或 `select` 人工选定 | 保存选择；尚未连接 |
| `connect(handle)` | `Connecting`，打开平台连接并调用驱动 `open` |
| `open` 成功 | `Connected`，保存身份并持续汇总驱动 `status` |
| `withConnection(..., Backfill)` | 租约期间 `Backfilling`，结束恢复 `Connected` |
| 驱动 `closed` 发出/结束、底层断开或连接失败 | 关闭会话和通道，进入 `WaitingReconnect` |
| 等待到期 | 再次 `Connecting`；等待依次为 3/6/12/24/48/60 秒，随后保持 60 秒 |
| 稳定连接至少 60 秒后再断开 | 退避从 3 秒重新开始 |
| 10 分钟内第 5 次意外故障，或显式 `disable` | `Disabled`，持久化原因，停止连接与重试 |
| 用户显式 `enable` | 清除停用及故障计数，等待旧会话释放后重连；仅匹配失败、尚无选择的设备只恢复匹配资格 |
| `forget` | 取消连接/重试，删除选择与该设备存储，移出列表 |

驱动调用通常最多 15 秒；文件读取按等待下一块计时，最多 30 秒，消费者落盘时间不算驱动超时。预期 `DeviceException` 和外部取消不累计意外故障；其他异常统一映射 `ProtocolError`，超时映射 `Timeout`。故障按驱动及设备分组，用单调时钟计算 10 分钟窗口；持久化停用不会因重启 App 自动解除。

`AppGraph.devicePlatform` 已装配。卡 141 可把它的 `repository`、`connector`、`toolbox`、`clock`、`extras` 和应用作用域传入 `DeviceHub`；收集 `bluetooth.scan(services)` 后调用 `hub.match(ad)`。自动或人工选定后显式 `connect`；实时声音、补传、临时控制在 `withConnection` 块内使用连接，不把连接或流带出租约。`wait=true` 只排队等待租约；当前未连上仍返回 `Disconnected`，调用方观察设备状态再请求。

会话先使用 `驱动 + handle:<句柄>` 临时空间；得到身份后迁入 `驱动 + id:<身份>`，保留未覆盖的历史字段，合并本次 open 写入并清理临时空间。后续拿着同一个 `session.store` 引用也会访问正式空间。仓储的组件使用长度前缀编码，避免冒号、斜杠引起命名空间碰撞。

旧设备身份辅助函数：`AndroidDevicePlatform.legacyIdentity(address)`，值为 `android:CardDevice:<原地址>`，作用域为 `PlatformLocal`。没有重写配对记录或补传表。

## 备份

新配置文件是独立的 `device-drivers.xml`，含选择、身份、停用原因和驱动命名空间存储。已加入两处白名单：

- `BackupSettings.prefs`：现有 settings.json 导出/校验/恢复路径。
- `BackupArchive.safePrefs`：旧整包归档的 SharedPreferences 文件范围。

设备目录的 Robolectric 测试执行了“保存选择、文本和字节进度、停用原因 → 备份 → 清空 → 恢复”，并验证归档路径获准、命名空间不冲突、忘记设备后清理存储。没有改变备份格式。

## 加密向量

- HKDF-SHA256：[RFC 5869 A.1 测试用例 1](https://www.rfc-editor.org/rfc/rfc5869.html#appendix-A.1)，校验完整 42 字节输出。
- AES-CTR：[NIST SP 800-38A F.5.1](https://nvlpubs.nist.gov/nistpubs/Legacy/SP/nistspecialpublication800-38a.pdf)，校验全部四块及逆变换。
- AES-GCM：[NIST GCM-AES128 Example 2](https://csrc.nist.gov/CSRC/media/Projects/Cryptographic-Standards-and-Guidelines/documents/examples/AES_GCM.pdf)，校验完整密文与 16 字节标签；篡改标签必须得到 `CryptoFailed`。
- P-256：本机 Python `cryptography 50.0.0` 生成固定 ECDH 与 ECDSA 向量，放在 `app/src/test/resources/devices/hub-p256-python.json`；同目录 `generate_hub_p256.py` 可复现。测试用公开固定私钥，无实际设备密钥。验证 65 字节未压缩点、32 字节共享 X 坐标、SPKI 公钥、DER 签名、篡改消息和非法曲线点；另验证生成密钥的双方 ECDH 一致。

## 真机注意与遗留

- 本卡未安装手机、未做 BLE 或 MediaCodec 真机验收，也没有 iOS 编译结果。
- 小米 14 Pro 需要确认：旧说明卡设备仍能扫描/配对/实时收音；快速开关搜索不触发系统扫描频率错误；MTU 协商、超长写入拒绝、同通道多收集器和断连关闭无异常；Opus 的真实采样率/声道与连续输出正确。
- 新中枢仅由假驱动/假通道验证，运行路径仍是 `ManagedDevices`。卡 141 负责新驱动接线、调用租约、能力/补传策略；界面由 Claude 消费 `HubDevice`、`MatchResult` 及停用原因，并提供人工重新启用入口。
- 协程超时是协作式取消：挂起调用可超时取消；同步阻塞的 match/JCA/MediaCodec 不能由纯 Kotlin 协程强制抢占，迟到返回会被判为超时。驱动不得永久阻塞调用线程。
- 经典蓝牙串口、PR #30 迁移、TaoEcho 驱动和诊断导出界面仍按后续任务卡处理；没有引入数据库迁移或请求约定签名变更。
