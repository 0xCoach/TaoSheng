# 027 每日回顾定时修复交付说明

分支：`codex/027-review-fix`。

## 做了什么

- 统一按设置的 `dailyAtMinutes` 和本地时区计算截止时刻。日期 D 覆盖 `(D-1 截止时刻, D 截止时刻]`；手动、定时生成共用该窗口。
- 事件按 `startAt` 归属，关联提取项随事件进入同一回顾。默认 22:00 时，21:59 和恰好 22:00 属于当天，22:01 属于次日；上一日恰好 22:00 不重复纳入当天。
- `ReviewWork` 使用最近已到的截止时刻确定日期，22:00 后运行归当天，次日凌晨或截止时刻前运行归前一天。
- 定时仅复用 `generatedAt >= 当日截止时刻` 的回顾；更早生成的旧回顾重新调用模型并覆盖。手动始终重生成且不推送，保留空事件不调用、不推送的保护。
- 模型输入增加带时区的明确窗口及“昨晚 22:00 到今晚 22:00”说明；系统提示词同步以窗口判断“今天新增”，避免继续按自然日筛选待办。
- 沿用已合入的推送接口，传入 `PushTopic.DailyReview`。两处旧测试替身补齐 topic 参数，仅修正编译兼容，不运行其测试。
- 未修改 `ui/`、`MainActivity.kt`、`*Contract.kt`、`AudioSource.kt` 或数据库结构。

## 怎么验证的

仅新增并运行 `ReviewTimingTest` 的 5 个测试，一次通过：

1. 相邻时间窗边界、事件及关联提取项归属、模型窗口说明。
2. 23:00、次日 00:30 / 21:59 / 22:00 的目标日期，以及自定义 20:30 截止时刻。
3. 19:35 的旧回顾被重新生成，包含后续事件、覆盖旧记录并推送新内容。
4. 截止时刻及其后生成的回顾直接复用，无模型调用和新增用量。
5. 手动使用自定义窗口，已有截止时刻后的回顾仍重生成、不推送。
