# 101 交付说明

## 改动

- 取消 chatJson 和 DigestRunner 的统一 64,000 字符限制，改用当前服务商、模型的容量预算。容量来自 assets/llm-providers.json，新字段独立解析，不改 Contract。保存的服务商转为 LlmPreset 时绑定容量快照，因此 UUID 服务商、技能指定模型也能取到对应容量。
- 未知模型、没有容量字段的旧格式、完全自定义服务商（即便模型名称与内置相同）默认 128,000 token。
- 字符预算为 `contextTokens - 8192 - max(ceil(contextTokens × 5%), 4000)`，一个 UTF-16 字符按一个 token 估算，system 和 user 合计检查。平台另有更小的最大输入限制时再取较小值。DeepSeek 为 941,808 字符，默认值为 113,408 字符。
- 回顾先使用原有 ReviewPrompt 完整生成输入。只有超限才按原顺序删除普通事件 points，再按原顺序缩短普通事件 summary（至少保留开头 80 字符和省略号，不切断代理对）；足够后立即停止。重要、星标、有未完成待办/约定的事件全部保留；所有提取项、独立事项、starred_stale 原样保留。只修改请求副本，不改数据库材料，不生成或替换 id。
- 保险方案加入 compressed 说明；仍超限时不发请求，提示“内容超出所选模型的容量，请换用容量更大的模型”。回顾未知错误统一为“生成失败，请稍后重试”，任务取消提示中文；读取历史保存的异常类名提示时也替换为中文。
- 整理质量分批的超长单句使用独立 DigestBatchLimitException，提示拆分后整理；LlmInputLimitException 仅表示模型预算超限。
- MAX_BATCH_CHARS = 12,000、MAX_LINES、MAX_JSON_OUTPUT_TOKENS = 8192、数据库版本、界面、Contract、输出结构、各栏目条数上限均未改。

## 超时评估

保留默认 readTimeout 180 秒、callTimeout 200 秒以及调用方自定义超时。15 万中文字符正文约 450 KB，加上 JSON 元数据仍远小于常见多模态上传，上传大小本身不能证明必须调大超时。非流式接口仍要等待模型预填充、排队、思考和输出，180 秒无数据或 200 秒总耗时仍可能触发超时；这与上下文能否容纳是不同限制。

本次只使用本地合成数据和拦截器验证长请求，不发送用户资料或调用付费模型，因此不宣称云端长输入已在时限内完成。没有稳定复现长请求超时的证据，依任务卡“只有确实需要才调大”保留原值。真机验收记录同一长回顾的等待时长；若反复触及 180/200 秒，再依据具体模型和接口耗时单独调整，避免拉长所有短请求的失败等待。
