# 开源录音硬件说明卡调研（卡 129）

调研日期：2026-11-10。目标是判断 **0.2.21 当前核心能否仅靠 JSON 接收实时声音**，不是购买推荐或真机兼容认证。按审批联网读取 GitHub API、固定版本源码及官方文档；未获取二进制固件、SDK 包，未执行第三方程序，未连接设备。

## 结论与统计口径

共核对 **18 个设备／固件变体：能 4、部分 12、不能 2**。同一硬件刷不同固件也分行统计，不能将此数当成 18 个品牌或销量排名。

- **能**：选定固件的实时音频参数已明确，现有说明卡结构可表达；不包含离线同步、静音管理、升级等扩展。Omi DevKit 1、DevKit 2、CV1 共用已有 `omi.json`，不复制三张相同匹配规则的卡；新增 `adeus-esp32c3.json`。
- **部分**：有公开源码或部分协议，但编码、分片、动态会话、型号识别或必要字段尚不适合静态卡；本次不新增卡。商业设备的社区连接器不等于厂家正式开放协议。
- **不能**：没有可据以填写的 BLE 音频协议或根本不是 BLE 音频路径。不猜 UUID、音频参数或命令。
- 所有交付卡保持 `trial`、`minApp=0.2.21`。这只表示待用户手动试用，**解析通过不表示硬件可用**。

| `bond/keepAliveSec/keepAlive` | 不填，默认 false/0/空 | 该固定 BLE 源码无绑定要求、心跳控制或超时门控；不新增不存在的命令。 |

**识别和真机边界：** A 服务 UUID 是常见示例值，[Omi 常量][O-ids]里的 Fieldy 也用了它。因此只有用户确认自己刷的是上述 ADeus 固件时才打开此卡；此值不能认证品牌。现有卡匹配是 OR，不支持“服务+名称+特征存在”联合校验。本卡不额外填写泛化名称以扩大匹配；误选其他设备会因没有指定音频特征而连接失败。源码还没有显式添加 BLE2902 描述符，是否由所用 Arduino BLE 栈提供 CCCD，必须真机核对；本次不下载/编译/修复第三方固件。每批182B后两次4ms延迟也不能视作稳定吞吐证明。

## 示例帧与验证原则

- 新增 ADeus 卡没有包外壳；未找到该固定固件真实音频抓包，不编造测试向量。
- Omi 源码有包头构造逻辑，但本次未找到可直接作为完整真实音频帧引用的固定向量；不把自造字节称为抓包。
- 声云 [S-proto] §7.3 的真实 **TX 文件下载请求**已经被 `CardCodec118Test.realCaptureLocksEndianAndExtractsData` 使用；本卡按要求运行该测试，复用真实外壳验证，不重复添加同一向量，也不宣称验证了 Opus 解码。
- 增加遍历所有 `assets/devices/*.json` 的解析及 ID 唯一性检查，不跳过 trial 和 FoloToy 占位。
- 新增匹配回归：独立 Friend 不再因名称落到 Omi；旧 Friend 广播 Omi 服务仍可匹配。
- 执行记录、占位解析冲突的处理以及真机清单见[129交付说明](../任务卡/129-交付说明.md)。

## 检索范围与后续缺口

除原清单外，实际查询了 GitHub 仓库搜索 `pendant ble audio`、`esp32 ble microphone`、`nrf52840 audio ble`、`friend wearable firmware`、`esp32 ble audio opus`，并检查 FoloToy 官方组织目录。新增深入核对了 aapatni、ShivaanshRaturi、ai-passport-mic、Voice Link、ebowwa 等来源，未把只列二进制或只有宣传的项目算作可写卡。
