`UsageRepository` 本身即共用读取/保存边界，`RoomUsageRepository` 继续实现它。实际按天/用途聚合在原 DAO SQL 中，按卡不改 SQL；UI 中费用和展示汇总保留，避免超出“仅机械日期转换”的授权。日期公开类型需要对调用方可见，datetime 0.7.1 从 implementation 改为 api，版本未升级。

## 留在安卓的部分及原因

- 推送发送、HTTP/SMTP、闹钟/通知、Worker、SAF、文件持久化、指纹密码学、PushTrace/诊断及失败落盘仍在安卓。`SubscriptionRuntime` 继续协调上述边界，没有搬整个运行器。
- `DailyMemory` 内层事件/技能卡/语音上下文映射，`MemoryFolder` 事件/技能卡/环境声音渲染、`PushSnapshot` 实体读取与坏记录诊断仍依赖未迁的 review、skills、envsound、transcribe 模型和全局展示器。已拆独立规则；为搬完整生成器而复制这些包的协议或改卡 151 文件会扩大范围，保留后续迁移。
- `PushFields` URL 与云存储校验继续使用 OkHttp/CloudAddress；`PushErrors` 异常链识别、URL 凭证解析和脱敏继续使用原平台实现，避免更换 URL 解析器改变安全边界。
- `DigestThingExtraction` 的事务协调、refreshLines、Room 诊断写入，`RoomThingRepository` 的编辑/保存事务仍在安卓。`FindThingsTool` 同步查询、时间展示和 AskSource 引用编号仍在安卓，筛选排序已共用。
- 旧模型回复允许单引号、未加引号的键等宽容 JSON 语法；安卓入口用原 JSONObject 规范化后交给共用规则。shared 使用 SharedJson/JsonElement，没有 org.json。iOS 接入前需提供同等输入规范化边界；不把严格解析替换冒充行为完全一致。
- 隐私删除保留原事务、音频互斥、队列和文件执行顺序。该文件没有独立“保留多少天”的规则；本卡没有创造新的保留策略。
- `LlmBalance.kt`、`digest/LlmClient.kt`、`digest/ServiceHeaders.kt`、`transcribe/*`、数据库、MainActivity、devices 源码无差异；没有访问或操作 TaoSheng-151。

## JSON 逐字一致证据

`JsonParity154Test` 在 Robolectric/安卓 JSON 实现下对照搬迁前 HEAD 中固定保存的 `LegacySubscriptions154`、`LegacyThingPrompt154`：

1. 默认、定时/去重星期、Manual/空值订阅，直接断言旧字符串等于新字符串，不先解析成对象再比较。
2. 寻物输入含上下文、空值、斜杠、换行、双引号、Tab、emoji 和 `</script>`，直接比较全文；另比较空手动输入。
3. front matter 对照原 `JSONObject.quote`，保留斜杠转义及换行。
4. 模型回复的宽容语法、数值 lineId、大小写布尔字符串和 aliases 对照原解析结果。

shared 的 `Rules154Test` 另固定断言回顾正文/JSON、daily_memory 空值与省略 lines、增量字段顺序及 upsert/delete 文本。`legacyText()` 专门保留原安卓 `\/` 转义。

测试曾发现真实迁移回归：对记录先转 JSON 再算指纹，会把原 canonical 中日期对象的表示改成带引号字符串，导致第二次发送未变内容。已改为从原对象计算指纹，传入共用增量比较；`Subscription042Test.webhookDeltaSignsUpsertsDeletesAndTracksFailureStatus` 复跑通过，不修改旧断言。
