## 文件与状态位置

- 导出结果：MediaStore `Download/Resound/录音包/涛声录音 YYYY-MM-DD.zip`；跨天为 `涛声录音 YYYY-MM-DD 至 YYYY-MM-DD.zip`，重名加 `（2）` 等。
- ZIP：`YYYY-MM-DD/HH-mm-ss 3分12秒.ogg`，同名加序号；全部条目使用 STORED，不转码。开启原话时附同名 `.txt` 和根目录 `原话.txt`。音频分块写入；总表通过临时文件写入并在 finally 删除。
- 打包任务：`shared_prefs/recording-pack.xml`，保存最近任务请求、状态及 MediaStore URI。失败/取消删除半成品；系统中断重跑时先删除上次半成品。最近已完成任务可用 `shareUri(id)` 获取 content URI；文件被外部删除时返回 null。
- 上传账本：`files/recording-uploads/<channelId>.json`，原子替换保存首次补传起点、段号与目标文件名、OGG 成功标记、原话 SHA-256、逐日成功上传字节、最后时间和固定错误。不含凭据、原话内容；不修改文字同步账本。
- 订阅仍在 `shared_prefs/push.xml` 的既有通道 JSON 中。该文件另有 `audio-diagnostic-<id>` 计数摘要。

## 云端规则与调度

- `<通道文件夹>/录音/YYYY-MM-DD/HH-mm-ss <时长>.ogg`；原话为同名 `.txt`。路径在账本中预留，冲突编号持久化，原声删除不会改变其他段的路径。
- Speech 仅传已完成、非空、非媒体/环境跳过的人声；All 在落盘后即可传。`excludeMedia` 同时作用于 All。原话在转写完成后传，内容或说话人改变后覆盖同名 txt；已上传的原声本机过期后，仍可更新数据库保留的原话。
- 首次启用按 `backfillDays` 固定起点（0 为今天，null 不限），每轮再与 `rangeDays` 取交集。
- `audioWifiOnly` 使用 WorkManager `UNMETERED` 约束，与本项目现有“仅 Wi-Fi”采用非计费网络的语义一致；关闭后为 `CONNECTED`。
- 录音使用独立唯一任务，不阻塞文字推送。每批最多 20 段；成功且仍有待传立即接续，失败使用 30 秒起步的指数退避。数据库/配置变更触发，运行期间每分钟校对，另有 WorkManager 15 分钟补扫。
- 已确认成功的 OGG 不再探测或重传；本机删除原声不删云端。原有 `FolderSync.owned` 白名单不包含 `录音/` 或 `my-notes/`，因此 rebuild 不触碰两者。
- `uploaded` 为确认成功的 OGG 段数；`pending` 为需要传 OGG 或更新 txt 的段数。本月字节包含成功 OGG 和每次成功 txt 写入；月预估为最近 7 个自然日成功字节 / 7 × 30。

## 错误映射

| 返回/情况 | 用户可见原因 |
| --- | --- |
| 401 | 坚果云账号或应用密码不对 |
| 507，或错误响应包含“流量”/quota/traffic | 坚果云本月上传流量用完了 |
| 403（非流量原因） | 坚果云拒绝访问，请检查文件夹权限 |
| 429、503 | 坚果云暂时限流，稍后自动重试 |
| 413 | 录音文件太大，超过坚果云单文件限制 |
| 3xx | 坚果云地址要求跳转，请检查通道地址（不跟随跳转） |
| 其他 HTTP 错误 | 录音上传失败（HTTP 状态码），稍后自动重试 |
| 网络/本地读写异常 | 录音上传失败，请检查网络后重试 |
| 关联备份账号缺失或通道冲突 | 坚果云账号未连接或通道配置冲突，请检查推送设置 |

只检查有限大小错误响应来分类，不保存或展示响应原文。507 按任务卡约定映射为流量提示。
