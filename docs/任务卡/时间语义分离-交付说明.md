# 时间语义分离 — 交付说明

## 背景

积压转写暴露了时间语义混用：`memory_items.createdAt`（整理处理时刻）被回顾等查询当作"说话时间"。积压场景下整理比说话晚几小时，条目被归属到错误的日期。

## 改动

四类时间字段现在明确分开：

| 字段 | 语义 | 来源 |
|---|---|---|
| `memory_events.startAt/endAt` | 事件时间 | 语音区间 |
| `memory_items.recordedAt`（新增） | 录音时间：这句话被说出来的时刻 | `transcript_lines.startAt` |
| `memory_items.createdAt` | 处理时间：行写入库的时刻 | `now()` |
| `memory_items.dueAt/dueText` | 提及时间：话里说的期限 | LLM 提取 |

- `MemoryItemEntity` 末尾新增 `recordedAt: Long?`（默认 null，位置参数兼容）。
- 迁移 38→39：加列 + `UPDATE memory_items SET recordedAt=(SELECT startAt FROM transcript_lines WHERE id=lineId) WHERE lineId IS NOT NULL` 回填存量。
- `DigestRunner`：提取项 `recordedAt` 依次取 原话行 startAt → 所属事件 startAt → 整理时刻（兜底的 createdAt 语义，仅当无任何语音来源时）。
- `RoomManualTodos`：手动待办挂到事件时取首句原话行时间；纯手打（无线索行）保持 null。
- `IdeaRepository.convertToTodo`：灵感转待办带 `sourceLineId` 时同步回填。
- `MemoryDao.lineStartAt(lineId)`：新查询，按行 id 取原话时间。
- `ReviewDao.items` 日期归属：`COALESCE(e.startAt, i.recordedAt, i.createdAt)`——事件时间优先，其次录音时间，处理时间只作兜底（此前无事件条目直接按 createdAt，积压条目会错日）。

## 顺带修复

- `ReviewRepository177Test` 金样本在 Windows 检出行尾被 autocrlf 转 CRLF 导致恒挂，读取时归一化（与本功能无关的存量问题）。

## 遗留 / 未测

- `transcript_lines`/`segments` 自身行时间未动；`memory_events.createdAt` 仍是处理时刻（事件时间已由 startAt/endAt 表达，无歧义）。
- 纯手打条目 `recordedAt=null`：回顾按 createdAt 归属当日，语义正确（没有更早的"说话时间"）。
- `NOT_TESTED`：iOS 侧（无 Xcode 环境）；跨天边界条目归属在真机只抽查了样本行，未做全量对照。
- 建议后续立规约：任何按"什么时候说的"取数的查询走 `recordedAt`/`transcript_lines.startAt`，禁止直接拿 `createdAt` 当说话时间。
