# 103：主模型失败时自动切换备用模型

## 背景（用户已拍板）

用户可以配置多个模型服务商（`LlmProviders.saved`）。主模型宕机、不稳定、余额不足时，App 应自动换用其他已配置的模型，不影响使用。**默认打开**，设置里可以关。

## 已定方案

### 1. 候选顺序
- 主模型是当前服务商 `activeId`。技能单独指定了 `presetId` 的，以技能指定的为主。
- 备用模型取 `saved` 列表中的其他服务商，**按列表顺序**排列；只算已填密钥的，或者 `allowsEmptyKey()` 为真的。
- 每次请求**最多试 3 个**（主模型 + 2 个备用）。
- 在 `LlmProviders` 里新增 `fun move(id: String, toIndex: Int)`，用来调整顺序并持久保存（界面由 Claude 做拖动排序）。

### 2. 哪些失败会切换
| 情况 | 是否切换 |
|---|---|
| 网络不通、超时（`LlmError.Network`） | 切 |
| 5xx、408、429 请求过多 | 切 |
| 402 / 余额不足、额度用完 | 切 |
| 401 / 403 密钥无效 | 切 |
| 其他 4xx（例如模型不支持某参数） | 切 |
| `LlmInputLimitException` 超出该模型容量 | 只切到**容量更大**的备用模型（用 101 的 `LlmInputBudget`） |
| `LlmError.Format` 格式不对 | **不切**，维持现有重试和放弃逻辑 |
| 取消（`CancellationException`） | 不切，直接抛出 |

- 新增“余额不足或额度用完”这一类错误：402 对应它，429 对应“请求太频繁”。中文文案自定，要说结果，不讲机制。
- 所有候选都失败时，报**主模型**的错误，并附一句“备用模型也没成功”。

### 3. 短时间内跳过失败的主模型
同一个模型失败后进入冷却期，期间排到候选最后，避免自动整理的每一批都先撞一次失败的主模型：
- 网络或服务出错：冷却 5 分钟
- 密钥无效、余额不足：冷却 30 分钟

冷却只在内存里记，不持久保存。用户修改了该服务商的密钥或配置，或者手动“测试”成功，就立即解除冷却。

### 4. 统一入口
在 `digest` 包里做一个统一的切换层（例如 `LlmFailover`），所有调用点都经过它，不要每个调用点各写一份。调用点包括：自动整理 `DigestRunner`、回顾 `RoomReviewRepository`、技能 `LocalSkillRepository`、重新整理 `RedoFactory`、问答 `AndroidAskRepository`、导入纪要 `AndroidImportKinds`、寻物 `AndroidThings`、手动待办 `RoomManualTodos`。
- **问答的流式回复**：只有在**还没收到第一个字**之前失败才切换；已经开始输出后失败，按现在的方式报错，不要中途换模型。
- **试连、查余额、拉模型列表**不走切换。

### 5. 记录实际用了哪个模型
- 事件的 `model`、回顾的 `model`、技能结果等原本记录模型的字段，一律记**实际生成**它的模型。
- **（Claude 决定，取代原先的“用量按模型记账”）不做数据库迁移。** 用量表维持现在的口径（按日期 + 用途），不新增模型维度。现在本来就不区分模型，切换功能不需要它。每次实际调用的用量照常累加，失败请求有返回用量的也照记，重放时不重复记。
- `PendingDigest` 不加模型字段。从缓存恢复事件时，如果拿不到实际模型，就用主模型名。只在崩溃恢复这种少见情况下会不准，可以接受，在交付说明里写明。
- 新增一个可观察的“最近一次切换”状态，供界面显示“本次由 X 生成”：包含时间、功能（整理/回顾/技能/问答……）、原模型名、实际模型名、原因类别（中文）。只放内存，不含原话或请求内容。

### 6. 整理链路的注意事项（关键，务必小心）
- `DigestRunner` 的 `identity(lines, preset)`、`PendingDigest` 缓存、`inflight` 恢复逻辑都依赖 preset。切换后，**同一批内容不能因为换了模型而重复请求、重复入库或重复扣用量**。缓存键要和“这一批内容”绑定，而不是和“碰巧成功的那个模型”绑定，但旧版本的缓存仍要能读。写清楚你的处理方式。
- 寻物的 `thingBatch.revision` 与回复的对应关系不能被破坏。

### 7. 设置开关
- 新增设置项 `failoverEnabled`，默认 `true`，持久保存。关闭后行为和现在完全一样。
- 只提供状态和接口，不改设置界面（Claude 来做）。
- 备份和恢复要包含这个开关和排序（参考现有设置的备份方式）。

## 测试（适度）

新增 `LlmFailover103Test`，8～12 个用例：
- 主模型 503 → 第一个备用成功，结果和用量记在备用模型名下
- 402、401 → 切换；`Format` 不切换
- 最多试 3 个；全部失败时报主模型的错误，并附“备用也没成功”
- 冷却期内主模型排到最后；修改密钥后立即解除冷却
- 超出容量时只切到容量更大的模型
- 关闭开关后不切换
- 问答流式：开始输出前失败 → 切换；输出中途失败 → 不切换
- `DigestRunner`：主模型失败、备用成功后，同一批不重复请求，`inflight` 中断后恢复也不重复
- `move()` 调整顺序后持久保存

只跑本卡新增测试，以及 `digest`、`review`、`skills`、`ask` 包里直接相关的现有测试，各跑一次。不跑全量，总耗时不超过 10 分钟。
