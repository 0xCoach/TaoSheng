# 任务卡 007：回响自身耗电估算

## 背景

安卓不开放“每个 App 用了多少电”给普通应用，统计页现在只能显示整机耗电，容易误解。改成由回响自己估算自身耗电。

## 约定（Claude 已改）

`capture/CaptureContract.kt` 的 `DayStats` 新增 `appPowerPerHour: Float?`：回响自身每小时耗电占电池容量的百分点。界面由 Claude 改，**不要改 `ui/` 和 `MainActivity.kt`**。

## 要做的

1. **采样**：录音服务运行时每 10 分钟（可复用现有电量采样的节奏）记一行：时间、本进程累计 CPU 时间（`Process.getElapsedCpuTime()` 或读 `/proc/self/stat`）、本 App 累计上传/下载字节（`TrafficStats.getUidTxBytes/RxBytes`）、这段时间麦克风处于开启（Listening/Recording/MicBusy 中真正打开 AudioRecord）的毫秒数、是否在充电。进程重启后计数器会归零，计算时按区间差值处理、遇到负数的那段丢弃。存进新表（数据库升 v5，写迁移 4→5；注意卡 006 正在把库升到 v4，以 main 上最新的为基础，若 006 尚未合并，先基于 v3→v4 占位并在交付说明提示合并时重排版本号）。
2. **估算模型**：`耗电 mAh = CPU 秒 × a + 麦克风开启小时 × b + 流量 MB × c`，除以电池容量（`BatteryManager.BATTERY_PROPERTY_CHARGE_COUNTER` / 容量，拿不到就用 4880 mAh）得到百分比。系数 a、b、c 集中放在常量里。
3. **校准（不要往手机装包）**：另一个任务也在用这台手机，本卡**禁止 `adb install`**。校准只用手机上现有版本的系统统计：
   - 读 `adb shell dumpsys batterystats`（必要时加 `--checkin` 便于解析），找 `app.resound` 的 uid，取它的 CPU 时间、各分项估算耗电（mAh）、移动/WiFi 流量；手机自上次充满后的数据就够用，不要 `--reset`；
   - 用这些数据解出 a（每 CPU 秒多少 mAh）和 c；麦克风的 b 若系统未单独归到本 App，先按 15 mA 取并在说明里标注为待真机复核；
   - 在交付说明写出读到的原始数据、系数和推算依据。
   - **不要点手机屏幕，不要操作其他 App，不要卸载、清数据或改系统设置。**
4. **输出**：`RoomCaptureStatsRepository.dayStats` 填上 `appPowerPerHour`（只用不充电时段；不足 30 分钟数据为 null）。诊断导出加上这几项原始计数。
5. **测试**：区间差值与进程重启归零、充电时段剔除、估算公式的单元测试；迁移测试覆盖到最新版本。只跑本卡相关测试；`./gradlew assembleDebug` 通过（`JAVA_HOME=/opt/homebrew/opt/openjdk@21`）。
