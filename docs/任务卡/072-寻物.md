# 卡 072 · 寻物：从原话里记下东西放哪了，确认后入库，问问能查（后端，关键）

App 名叫“涛声”。在 **`find-things` 分支**上开发（从 `env-sound` 分支拉出，含卡 070/071）。**本卡不改 `ui/` 和 `MainActivity.kt`**，界面由 Claude 按约定另做。
约定文件：`app/src/main/java/app/resound/things/ThingContract.kt`（已写好，签名不要自行改；确需改在交付说明提出）。`AppGraph.things` 已预留，由 `ResoundApp` 装配。

## 一、负责人已定的原则

1. **当场**：每转写完一轮就判断新原话，不等整理。延迟约等于转写间隔即可。
2. **判断偏松**：随口一句也要抓（“钥匙我搁鞋柜了”“你充电器我放餐桌上了”“伞在门后”）。错的靠确认卡划掉。
3. **确认后才入库**：和待办“待确认”一个逻辑。待确认的不自动入库、不自动删。
4. **效果优先于费用**：不用关键词预过滤；新原话连同前文一起发给大模型，求准。
5. **不打扰**：不弹通知、不响。**只有用户主动说“记一下 / 帮我记住 / 记住”之类**，才发一条轻通知（无声）。
6. 归属只打标签（我的 / 家人的 / 别人的），不按人分开。
7. 第一版只做：当场找 + 确认、借出与还、带走、问问能查（含反着查和找不到时回忆）、手动添加。**不做**：位置词表、重要物品清单、“记一下”几秒加急转写、借出超时提醒。

## 二、自动找（ThingWatcher）

- **触发**：转写一轮结束、且这一轮产出了新原话时触发；防抖 30 秒、同一时间只跑一个。也在 App 启动时补跑一次。
- **进度**：存一个“处理到哪句”的水位（按原话 id），只处理新句子；断网、失败不前进水位，下次重试（最多连续失败 3 次后跳过这一批，记问题记录）。
- **不处理**：导入的音频（`sourceId == "import"`）、卡 070 判为疑似影视 / 标记为媒体的片段、`autoDetect` 关着时（关着期间水位照常前进，打开后不补旧的）。
- **每次请求**：新句子最多 80 句一批（多了分批）；附上前面 20 句作上文（标明“已处理过，只作参考”）；附已知东西清单（名字、别名、当前状态与位置，最多 200 样，按最近用过排序）；附日历（复用 `DigestPrompt.calendar`）和说话人（我 / 认出的人 / 未知）。
- **模型**：用整理的同一服务（`LlmClient.chatJson`），用量计入现有 `llm_usage`，功能名“寻物”。
- **提示词**：新增 `assets/prompts/things.md`，按 `PromptTemplates` 现有方式登记（id `things`，标题“找东西放哪了”），可改可恢复默认。要点：
  - 要抓：已经放好 / 别人告诉我在哪 / 回答“在哪”的问话 / 借给谁 / 还回来了 / 带走了 / 主动“记一下”。随口话、口语、方言说法都算。
  - 不抓：将来的打算（“待会放车里”）、假设、电视或视频里的内容、不是实物的东西（文件在服务器、钱在卡里）、泛泛而谈（“东西总是乱放”）、上文里已处理过的句子。
  - 每条输出：名字（统一叫法）、别名、动作（`ThingAction`）、位置、借给谁、归属、依据的句子 id、是否主动“记一下”、是不是已知清单里的某样（给 id）以及有没有把握。
  - 只说了“放好了”没说哪 → 结合上文能推出位置就填；推不出不输出。
- **入库为待确认**：
  - 模型有把握是已知某样 → `thingId` 直接填；没把握但像某样 → `sameAs` 填那样，`thingId` 空；新东西 → 都空。
  - **去重**：和这样东西当前已确认的位置一样（名字与位置都相同）→ 不生成；2 小时内已有同名、同动作的待确认 → 用新内容更新那一条，不再加一张卡。
  - `explicit = true` 时发轻通知：新建通知渠道“寻物”（`IMPORTANCE_LOW`，无声无震动），标题“已记：钥匙 → 鞋柜第二个抽屉”，点开打开 App 并带 extra `open = "things_pending"`（界面那头由 Claude 接）。
- **原话变动**：重新转写（卡 071）或删除原话、删除事件、按时段删除数据时：待确认记录若依据的原话没了就删掉；已确认记录保留（`sourceText` 已存），`sourceLineId` 置空。

## 三、存储与接口（实现 `ThingRepository`）

- 数据库 **24 → 25**，按 `CaptureDatabase.MIGRATIONS` 规矩只加一条：
  - `things`：id、名字、别名 JSON、归属、建立时间、最近更新时间、已删。
  - `thing_records`：id、thingId（可空）、名字、动作、位置、借给谁、归属、说话时间 `at`、原话 id、原话文字、状态、来源、主动、sameAs 的 thingId、建立时间、确认时间。
  - 水位存在 `SharedPreferences` 或一张小表均可，你定。
- 语义按约定注释实现。补充：
  - `Thing.latest` 只看已确认记录；只有待确认记录的东西不出现在 `things()` 里。
  - 确认时名字改了，按新名字找已有同名（含别名）东西归并；找不到就新建。归并时把新名字加进别名。
  - `search`：名字、别名、当前位置、最后位置、借给谁都参与模糊匹配（`LIKE`）。
  - `draft`：手动打字 / 按住说话的文字交给模型拆成 `ThingDraft`（复用同一提示词或单独一段，你定）；按住说话复用现有 `TodoVoiceInput`，不新做录音。
- **备份**：`things` 加进 `DayVolumeRows.global`，`thing_records` 加进 `dated`（按 `at`）；增量备份、恢复都要覆盖。

## 四、问问能查

- `assets/prompts/ask-tools.json` 加工具 `find_things(query?, place?)`：
  - `query` 按东西找，`place` 按位置反着找（“书柜里有什么”）。
  - 返回每样东西的当前状态、最后位置、最近 5 条记录（时间、动作、位置、借给谁、原话 id、原话文字）；**待确认的也返回，标“未确认”**。
- `assets/prompts/ask.md` 补规则：
  - 问东西在哪时先 `find_things`；
  - 查不到或只有很旧的记录，再用 `search_lines` 搜这样东西的名字和“放 / 搁 / 塞 / 收 / 借 / 拿走 / 带走”等，从原话里回答，并说明“这是从原话里找到的，没有记录过”；
  - 回答要给时间；未确认的要说明“未确认”；
  - 引用用记录的原话 id（`[^n]` 指向 line），不改 `AskSource`。
