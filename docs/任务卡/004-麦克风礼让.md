# 任务卡 004：麦克风被占用时礼让，不抢别人的麦克风

## 背景（10-23 真机实测，`adb shell dumpsys audio` 的录音事件）

- 回响被静音（`isClientSilenced`）时，`MicAudioSource` 抛 Busy → 释放 AudioRecord → `MIC_RETRY_MS`（3 秒）后新建一个 → 新建的成了“最近开始录音”的那个，**把别的 App 挤成静音**。
- 实测 14:35:42：小米系统语音输入 `com.iflytek.inputmethod.miui` 被标成 silenced，回响 not silenced —— 回响打断了负责人的语音输入。半小时内回响开关录音 24 次。
- 同时 omi-local（`com.friend.ios.dev`）的麦克风前台服务一直在跑，两边轮流抢，回响 2 小时只录到 2 段。

**原则：回响是后台记录者，必须让着前台的人。绝不能打断语音输入、通话、录音、视频通话等任何其他 App 的收音。**

## 要做的（只改录音底层，不改界面和约定签名）

1. **被静音时不关麦克风**：保持 AudioRecord 打开，进入 MicBusy；静音期间读出的数据丢弃，不喂人声检测；正在录的片段按正常结束处理（不足 1 秒的照旧丢弃）。系统取消静音（录音回调里 `isClientSilenced` 变 false）后直接回到 Listening。整个过程不新建录音对象。
2. **必须重开时先看有没有人在用**：只有录音对象出错或失效（如 `ERROR_DEAD_OBJECT`、启动失败）才重开；重开前查 `AudioManager.activeRecordingConfigurations`，只要有不属于回响的录音在进行，就等录音回调通知对方结束后再开，不要每 3 秒轮询抢一次。
3. **通话期间**（`MODE_IN_CALL` / `MODE_IN_COMMUNICATION` / 响铃）：同样不新开录音，等通话结束。
4. 把“要不要读 / 等待 / 能否重开”的判断写成不依赖安卓的纯 Kotlin 小类，写单元测试覆盖：被静音、取消静音、别人在录、通话、录音对象失效几种情况。
5. 守护记录的 MicBusy 说明里写清楚原因（被静音 / 通话 / 录音对象失效），不需要也拿不到对方包名。

## 真机验证（手机已用 USB 连接，可用 adb）

- 安装：`adb install -r app/build/outputs/apk/debug/app-debug.apk`，然后 `adb shell am start -n app.resound/.MainActivity`（打开后会自动恢复聆听）。
- 用 `adb shell dumpsys audio` 的录音事件验证：回响在跑时，任何其他 App 开始录音后，不应再出现“对方 silenced、回响 not silenced”；对方结束后回响能自动恢复。可以用 `adb shell` 启动一个系统录音类操作做对照；做不到的写进交付说明，交给负责人用语音输入实测。
- **禁止**：卸载或停止任何其他 App（包括 omi-local）、清除数据、改系统设置、点开负责人的聊天等 App。
