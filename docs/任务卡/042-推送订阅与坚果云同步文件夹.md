**分支 / 工作树**：`codex/042-push-subscription`，`~/Developer/resound-codex-042`。

## 一、订阅的保存与兼容

1. 订阅随通道存（现有存储方式，JSON），读回 `PushChannel.subscription`。老通道迁移：
   - 有 `DailyMemory` 主题的 → `records = 全部五类`、`lines = memoryWithLines ? All : Off`、`trigger = Schedule([22:00])`、`incremental = false`；
   - 只有消息主题的 → `summaries = DailyReview/SkillCard 任一在`、`reminders = TodoReminder 在`、`records = 空`。
   - 迁移后旧字段 `topics` / `memoryWithLines` 继续按新订阅填，界面不再用它们。
2. `saveWithSubscription`：按 `capabilities(kind)` 收紧（聊天类强制 records 空、lines Off、incremental false）；校验时刻 0..1439、minGap ≥ 5 分钟；坚果云同步文件夹：
   - `useLinkedNutstore = true`：账号、应用密码、地址都取数据备份里已连接的坚果云（`AndroidBackupRepository` 的账号 + 安全区密码，不复制密钥，每次推送时现取）；备份没连坚果云时保存失败“先在数据备份里连接坚果云，或改为单独配置”。
   - `false`：用通道自己填的账号、应用密码、地址（地址默认 `https://dav.jianguoyun.com/dav/`）。
   - **一个文件夹只给一个通道**：同一账号 + 同一文件夹已被别的通道用，返回失败“这个文件夹已经给“XX”通道用了，换个名字”。
3. `linkedNutstoreAccount`：数据备份里的坚果云账号（邮箱），变化时更新。

## 二、触发

| 内容 | 触发 |
| --- | --- |
| 摘要类（每日回顾、每周回顾、技能卡片） | 生成后推（沿用现有回顾、技能推送入口，按 `subscription.summaries` 过滤；资料类通道把它写进对应文件，见第三节） |
| 提醒类（待办到期、标星 3 天没进展） | 到点推（现有提醒入口按 `reminders` 过滤） |
| 整理结果、原话 | `OnChange`：每轮整理完成 / 条目状态变化 / 标星变化后，距上次推送 ≥ minGap 才推（不到就排一个延迟任务到间隔满时再推）；`Schedule`：到点推（多个时刻、可限星期几）；`Manual`：只 `pushNow` |
| 全量校对 | `fullCheckAt` 到点：按全量重新生成一遍（只上传内容有变化的文件） |

调度用 WorkManager，每通道一个唯一任务名；要网络；失败指数退避；单通道失败不影响别的通道。

## 三、内容生成

### 1. 统一数据
按 `records`、`lines`、`rangeDays`、`excludeMedia`（排除场景“媒体”“旁人”的事件及其原话）从库里取：时间线事件（含 starred、要紧、条目）、待办与约定（进行中 / 约定 / 最近 30 天完成）、灵感（合并后的独立条，带 repeats）、决定与关键信息与知识、我的重点（starredEvents + 进展：相关条目状态、标星后有没有完成）、技能卡片、每日 / 每周回顾、原话（`MeOnly` 只取 speakerName = “我”）。

### 2. 坚果云同步文件夹 `Resound-Memory`（布局 `ByCategory`，默认）
```
README.md
recent-days-index.md
starred-highlights.md
todos-and-appointments.md
ideas.md
decisions-and-facts.md
daily/YYYY-MM/YYYY-MM-DD-Ddd_daily-record.md
weekly/YYYY-Www_MMDD-MMDD_weekly-review.md
transcripts/YYYY-MM/YYYY-MM-DD-Ddd_transcript.md   （lines ≠ Off 才有）
archive/YYYY/ideas.md、archive/YYYY/decisions-and-facts.md
inbox/   （只建空文件夹 + 说明，不读）
my-notes/   （永不读写、不删）
```
- **命名**：日期 `年-月-日`；星期英文三字母（Mon…Sun）；周用 ISO 周号 + 周一到周日 `MMDD-MMDD`；按月分子文件夹。全部英文。
- **每个文件开头说明卡**（YAML front matter，中文值）：`类型`、`日期`（或范围）、`内容`、`更新`（时间）、`来源: 回响自动生成，请勿手动修改（改了会被覆盖）`、`条数`。下一行 `# 中文标题`：每日“2026年10月24日 星期六 · <最主要的一件事>等 N 件事”；每周“2026年第43周（10月19日—10月25日）”。
- **每日记录**：当天回顾 → 时间线（按时间，★ 重点、“要紧”标注，每件事带编号 `E<id>`、场景、参与人、摘要、要点、条目）→ 当天待办（新提 / 到期 / 完成）→ 灵感等 → 技能卡片（字段按类型渲染）。原话不在这里，链接到 `[[transcripts/…]]`。
- **汇总文件**：只放最近一年（按条目时间），更早的移到 `archive/<年>/`。条目带编号 `I<id>` 和来源 `[[daily/…#E<id>]]`。
- **recent-days-index.md**：最近 30 天每天一行：日期 · 星期 · 几件事 · 一句话（回顾的一句话，没有就第一件事标题）· 重点数 · 链接。
- **README.md**：一张表说明每个文件 / 文件夹是什么、多久更新；“给智能体的用法”：先读 recent-days-index → 某天细节读 daily → 核对原话读 transcripts → 重点和待办直接读汇总文件；写明 my-notes/ 归用户、其余勿改、inbox/ 预留。
- `ByDay` 布局：只有 README + daily/（每日文件里把当天汇总也写全）+ weekly/ + transcripts/。

### 3. 增量上传（文件夹类）
- 每个通道记下每个文件上次上传内容的 SHA-256（存本地，不进库也可以；放 `files/push-state/<通道id>.json`）。生成后只上传指纹变了的文件，删掉不再需要的文件（只删回响写过的、指纹表里有的，`my-notes/` 和未知文件不碰）。
- 上传：PUT 到 `<名>.part-<随机>` 再 MOVE（坚果云不允许 MOVE 覆盖：目标存在先 DELETE 再 MOVE，见 `WebDavClient` 现有做法）；目录不存在逐级 MKCOL。
- 请求要少：一轮最多上传 20 个文件，多了分批（下一轮接着传）；遇 503 / 429 退避，别连续重试。
- **删除同步**：手机上删除事件 / “这段别记” / 取消重点 / 删除卡片后，对应文件在下一轮更新或删除（每日文件重新生成即可）。
- **首次开启 / 全部重新生成**：按 `backfillDays` 生成，分批上传；`rebuild` 先删除指纹表里的所有文件再全量生成。

### 4. 其他通道
- **Webhook 增量**：`{"type":"records_delta","version":1,"changes":[{"op":"upsert|delete","kind":"event|item|card|review|line","id":…,"data":{…}}]}`；全量用现有 `daily_memory`。签名、局域网规则沿用卡 032。
- **Notion 增量**：一天一页，只更新内容有变化的那天（沿用卡 032 的归档重建做法）。
- **Telegram / 邮件**：整理结果按 `Schedule` / 手动时以 Markdown 附件全量发；`OnChange` 对它们按最短间隔合并。
- **聊天类**：只发摘要和提醒（现状）。

## 四、状态与记录
`status(id)`：lastPushAt、lastResult（如“更新 3 个文件”“推了 12 条变化”）、lastError、running。推送记录 `logs` 照常写，标题如“同步文件夹 · 更新 3 个文件”。
