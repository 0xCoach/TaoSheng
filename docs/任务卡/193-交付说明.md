# 193 交付说明

## 做了什么

蓝牙通话输入和 LE 蓝牙输入在播放开始时自动让出，默认改用手机麦克风继续录；也支持让出期间暂停录音。自动让出可关闭。USB、有线、手机和专用设备输入沿用原行为。

共用规则在 `shared/.../audio/BluetoothPlaybackYield.kt`。安卓适配监听既有 `AppGraph.playback.state.playing`，不改播放检测器、外放片段标记和外放跳过转写。数据库、界面目录、MainActivity、已有 Contract 和 AudioSource 签名均未修改。

输入设置仍存 `inputs`：`bluetoothPlaybackYield`、`bluetoothPlaybackContinueOnPhone` 均默认 true，沿用卡 190 的设置备份分类。输入选择保存从清空整个文件改为只移除旧设备 key/name，避免选择设备时误删新开关。监听偏好变更，备份恢复和设置修改在采集期间生效。

## 让出与接回时序

1. 选中的蓝牙输入 + 自动让出开启 + 采集会话运行时，新增播放订阅；播放开始立即产生让出指令。
2. InputSwitchLoop 先 cancelAndJoin 原录音。沿用 RoutedRecording 的 finally：停录并 release、清通信设备或停 SCO、释放本进程 MODE_IN_COMMUNICATION 请求；旧片段正常收尾。然后才开手机麦，或进入不打开任何 AudioSource 的暂停等待。
3. 连续停播 3 秒后才撤销让出；中途重新播放取消确认窗口。切换输入或关闭开关退出本卡订阅；会话结束注销设置监听与播放订阅。让出期间保留播放监听，才能知道何时接回。
4. 接回仍经过现有输入冷却与故障回退。若其他应用还在录音，蓝牙录音器继续使用原来的等待逻辑，不重新抢占通话模式；手机录音仍接受系统静音礼让。
5. 问题记录写入 MicBusy / MicReleased（让出及等待结束），收到新输入首帧后写 InputSwitched（实际接回）。不把“等待结束”当成“已成功接回”，不记录播放器应用或标题。

耗电说明：#47 原有的服务级播放订阅负责所有输入的外放检测，本卡保持它不变；本卡额外订阅只在启用的蓝牙采集会话及其让出等待期间存在。PlaybackMonitor 本身及其无订阅者注销规则未修改。

## 给 Claude 的界面配合

建议在“录音输入”页蓝牙设置处放两个开关：

- “用蓝牙麦时，放视频音乐自动让出”：`BluetoothYieldSettings(context).read().enabled` / `setEnabled(Boolean)`。
- “让出期间用手机麦克风继续录音”：`read().continueOnPhone` / `setContinueOnPhone(Boolean)`；关闭表示暂停录音。主开关关闭时可禁用这个选项。

`changes` 可收集最新 Options。首页读取既有 `AppGraph.inputs.status.note`，显示“正在播放视频或音乐，蓝牙麦已暂时让出；先用手机麦克风”或“……；暂停录音”。手机续录时仍保持 Listening/Recording，不假装整机停止；暂停模式通过 CaptureState.MicBusy / busyDetail 显示原因。通知栏已接入相同 note；普通暂停仍显示原暂停内容。

未改首页和设置界面，需 Claude 接入上述开关及首页提示。版本号保留基线值，0.5.0 的版本发布统一处理；本卡不发布、不推送、不安装手机。

## 真机验收与限制

未操作手机；电脑测试不能证明小米/大疆实际路由和媒体声已经恢复。负责人需用大疆 Mic 或任意蓝牙耳机验证：

- 蓝牙录音中打开视频/音乐，媒体恢复出声，手机续录片段正常保存且外放标记/转写跳过不变。
- 暂停视频后不到 3 秒不接回，超过 3 秒恢复蓝牙；切歌和广告短间隙不反复切换。
- 关闭自动让出保持原行为；关闭手机续录后确认让出期间没有新增音频。
- 播放期间其他应用申请麦克风，停播后该应用仍录音时不抢占，结束后恢复；同时验证蓝牙断连、切换 USB、手动暂停/停止。
- 首页（Claude 接入后）、通知栏和问题记录的原因、时间与真实录音输入一致；停止采集不遗留本卡监听或通信模式。
