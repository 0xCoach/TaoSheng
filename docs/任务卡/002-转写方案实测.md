# 任务卡 002：豆包转写方案实测（技术探路）

## 目标

用最少的花费实测，选出回响的转写方案。只写探测脚本和实测报告，**不改 App 代码**。

背景：回响把手机录下的人声片段（OGG Opus，16kHz 单声道，单段 1 秒到 5 分钟）每 30～60 分钟批量转成文字，并要分出说话人。手机上的录音没有公网网址。

候选：

| 方案 | 资源 ID（以实测为准） | 价格 | 待确认 |
| --- | --- | --- | --- |
| A 录音文件识别 2.0 | `volc.seedasr.auc` | 0.8 元/小时 | 能否不用网址、直接传音频数据；是否支持说话人分离；账号是否已开通 |
| B 流式识别 2.0 | `volc.seedasr.sauc.duration` | 约 1.0 元/小时，账号有 20 小时免费额度 | 能否把录好的文件快速发送（不按实时速度）；`bigmodel_async` 与 `bigmodel_nostream` 两种模式的差异；是否支持说话人分离 |
| C 录音文件识别极速版 | `volc.bigasr.auc_turbo` | 4.5 元/小时 | 已知支持 base64 直传；是否支持说话人分离；账号是否已开通 |

## 凭证（重要）

- 豆包语音 API Key（新版控制台，`X-Api-Key` 头）在 `/Users/coach/Developer/anti-scam-granny/API Key.md`。
- 脚本运行时从该文件读取。**不得在终端输出、日志、报告、提交里出现密钥的任何部分**；不要复制该文件；需要确认读取成功时只输出"已读取，长度 N"。
- 可参考 `/Users/coach/Developer/anti-scam-granny/app/voice/cascade.py` 中流式识别 2.0 的调用方式（只读，不要改那个项目）。

## 要做的

1. 在本仓库 `tools/asr-probe/` 下写探测脚本（Python，用 uv 或系统 python 均可）。
2. 生成测试音频：用 macOS `say` 的两个不同中文音色（如 Eddy 和 Flo，`zh_CN`）合成一段约 40 秒的两人对话，再加一段约 20 秒单人独白；用 ffmpeg 转成 16kHz 单声道的 WAV 和 OGG Opus 两种格式。音频放在 `tools/asr-probe/samples/`。
3. 对每个方案实测：
    - 能否直传（data/base64 或流式发送），失败时记录原始错误码和信息（例如未开通、参数不支持）；
    - 能否分出说话人：查清参数名（如 `enable_speaker_info`、`with_speaker_info` 等），实际返回里是否有说话人编号，两个音色是否被正确分开；
    - B 方案：分别测"按实时速度发送"和"尽快发送"，记录总耗时，确认快速发送是否被接受、结果是否一致；
    - OGG Opus 能否直接识别，还是必须 WAV/PCM；
    - 识别文字准确度（与原文对比，大致即可）。
4. 只读查询：如果能查到当前 Key 开通了哪些资源，记录下来。

## 限制

- **总共发送的音频不超过 5 分钟**，预计费用不到 1 毛钱。
- **不得在火山控制台做任何开通、购买、创建、修改操作**；遇到"未开通"就记录下来，交给负责人决定。
- 不改 `app/` 目录。
