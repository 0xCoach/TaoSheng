# 097：问问追问出处衔接与有限纠正

## 排查

- “回答出处不完整，请重新提问”由 AskEngine 检测到越界引用时产生，问答界面优先展示此错误。
- 旧流程仅传历史正文并移除引用标记，上一轮出处未重新装载；事件入口的上下文只存在于第一轮。模型使用不存在的 ref 或把数据库 id 当成 ref 时直接报错。
- 缺少用户当次原始模型响应，不能断言那次具体用了哪个错误编号；本次修复并验证可复现的流程缺口。

## 修复

- 追问按最近回答的来源 ID 从本机重新查询当前记录，重新编号；最多 8 个候选、约 6,000 字符，普通回答不新增模型请求。
- 事件入口的定位信息保存在现有用户消息来源字段，重开会话后仍能重新查询；不保存整份请求上下文，不改 Contract 或数据库 schema。
- 只发送当前有效记录；过滤已删除事件/条目及其原话、已合并条目。旧来源快照不会直接作为新证据发送。旧回答的来源未重新核验、原话已变化或回答本身失败时，不再转发该旧回答正文。
- 无效引用、已有依据却遗漏引用时最多自动纠正一次，显示“正在核对回答出处…”。纠正请求禁用工具和数据修改，仍记真实用量；再次失败则停止，不猜测编号绑定，不无限重试。
- 原有每轮最多 6 次工具调用保持不变；最坏 6 轮工具 + 最终回答 + 1 次纠正。没有依据时明确没找到，不能靠随意添加引用通过检查。
- 默认提示词同步说明局部上下文和重新核验的来源可引用；运行时核心规则兼容现有自定义指令，不覆盖用户保存的模板。

## 验证

- 12 项针对性测试通过：追问与重新打开会话、3 类来源刷新和删除、上下文大小限制、错误 ID/缺失引用纠正、重试上限/禁用修改、六次工具预算、用量统计及既有持久化行为。
- 0.2.15-preview.12（51）Release 与测试 APK 构建成功，修复版已保留数据安装到手机。
- 实机当前模型验证通过（2.819 秒）：独立内存数据库合成会议，两轮均输出有效引用，第二轮为“最后结论是啥”。首轮 3 次请求、追问 1 次，共 4 次、13,028 Token，已记入问问统计；不读取或发送用户原话。
- 测试组件已卸载，恢复打开主应用。APK 构建及实机测试均通过后，继续执行已授权的正式发布。
- 用户首次取消测试组件安装；明确回复“继续”后才重新申请安装。

## 边界

- 有效引用编号只能证明来源可定位，不能证明所有模型结论都忠实于原话；实际语义质量仍受模型影响。自动纠正失败保留明确提示。
- 本轮真实模型验证只覆盖合成会议的连续追问，不能替代所有服务商、长会话和模糊问题的质量评估。
- 对外正式发布需等待本卡验证结束；三个发布渠道沿用用户既有授权。
