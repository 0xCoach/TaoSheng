# 寻物共用整理请求及报告展示优化

## 行为

- 自动寻物不再启动 ThingWatcher，也不再在转写完成后单独调用 LLM。DigestRunner 在原有请求中增加 things 字段；新原话只发送一次，最多附带最近十分钟的旧上下文和相关物品参考。
- 相关已知物品加最近八件兜底，总计最多四十件；未匹配的事实仍可作为新物品待确认，不按关键词丢弃新原话。压缩默认寻物指令，日期只保留当天，不再重复附带二十二天日历；用户自定义模板保持不变。
- 自动入库随时间线整理，沿用现有间隔/时间点设置；手动添加仍即时处理。寻物页面说明更新时机。
- 同一次整理与寻物入库使用同一个 Room 事务；原话删除/修改、自动开关变更、导入和媒体内容均受保护。忽略过的同源事实不会因重新整理再次冒出。
- 寻物字段缺失或单条格式错误会记 ThingsShared 诊断并忽略问题项，不为寻物单独重发付费请求；有效兄弟项仍保存。该策略优先避免重复费用，模型格式不遵循时可能漏记，需要真机观察。
- 自动共用请求的全部用量计入“整理”，不虚构寻物占比；手动添加和历史自动用量仍在“寻物”。ThingsShared 日志记录条数/异常数量，手动 ThingsUsage 记录调用 Token，无原话和密钥。
- 日报橙色、周报浅紫色用于列表及详情导语，支持深色模式。
- 周报环境概览本地去重、不新增模型调用，逐事件环境默认折叠；详情有“这周一句话”时不再重复显示顶部摘要。旧报告无需重新生成。

## 分支与边界

基于手机当前版本 0.2.15-preview.3（f87a026），独立工作区 TaoSheng-token-saving、分支 codex/things-token-saving。原 TaoSheng-079 工作区未提交的 SkillVisuals.kt 修改保持原样；本分支未将其一并提交。未修改 Contract 签名或数据库 schema。
用户已明确授权调整报告展示，因此本次同时实现所需 UI 改动。

旧 ThingWatcher 保留供旧行为回归测试使用，生产装配中已无调用。thing_watch_state.watermark 在共用路径中仅作为旧历史/开关切换的排除边界，不按整理批次推进，以免按时间整理时跳过 ID 顺序不同的原话。

## 验证

25 项针对性测试通过：ThingsSharedTest 6 项、Things079Test 16 项、DigestForce053Test 1 项、环境概览与显示开关 1 项、ReportPresentationTest 1 项。共享请求测试验证一次调用保存两类结果、问问本地工具查询真实原话、用量只计一次；关闭开关、删除依据、导入/媒体排除、错误物品字段、事务回滚和忽略后重处理均覆盖。

Debug APK 已成功生成（app/build/outputs/apk/debug/app-debug.apk）。浅深色 Compose 预览已导出并检查；发现深色紫色文字偏暗后提高对比度，单独复查界面与重新打包均通过（1m12s）；最终 APK ZIP 完整性校验通过。预览位于 app/build/report-previews/Light.png 与 Dark.png。

测试使用合成返回值，不代表已验证线上模型的提取准确率或手机实际节省比例。默认寻物模板从 2293 字符缩至 1380 字符，仅为字符数，不等同 Token 降幅。主要节省来自取消独立自动请求和避免重复发送新原话。

首次构建因两条本任务 Gradle 命令同时编译发生 Kotlin 缓存冲突，已终止本任务对应进程，改为单进程顺序验证并成功；未停止其他项目或用户应用。

## 真机验收

1. 说“钥匙放鞋柜第二层了”，待整理或点“现在整理”，确认时间线和寻物均出现；在问问中问钥匙在哪，检查原话依据。
2. 工作闲聊、未来计划、演示引用不得变成已发生物品位置；检查跨句“它在抽屉里”的指代。
3. 对比相同使用时长下总 Token（整理＋寻物），不能只看寻物归零就判定节省；自动请求应不再产生 ThingsUsage，ThingsShared 应随整理出现。
4. 检查旧周报环境明细折叠与展开、日报/周报浅深色显示。

本次不发布、不自动安装到手机。需后续预览实测确认模型遵循 things 输出结构与实际节省效果。
