# R5 核心场景增强：源码级差距核对

> 结论：四个卖点的**底层都比预期厚**，没有一块要推倒重来；缺的是「把已有产物结构化、串成交付面」的最后一公里。三个共性瓶颈：`digest_done` 钩子声明未发射、`projectId` 链路断、卡片产物是 JSON 字符串而非可流转的结构化行。

## 共性发现

| 共性断点 | 影响面 |
|---|---|
| `RuleEvent.digest_done` 已声明、零发射器 | 决定同步（`DecisionRepository.syncFromDigest`）、灵感同步（`syncFromDigest`）、会议后处理都只能靠启动/手动触发，新鲜产物滞留到下次开 App |
| `DecisionRepository.kt:62` 导入时硬写 `projectId=null` | 决策永远上不了项目；项目分析缺最重要的输入 |
| 卡片产物（`skill_cards.valuesJson` 的 decisions/actions）是平铺字符串 | 不能勾选、不能流转进 memory_items/decisions 表、不能统计 |
| 跟进/提醒通知复用 `daily-review` 渠道且深链未接 | `open=followups/rules/todos` 点了只开 App 不落地；跟进提醒不会推到外部通道（无 `PushTopic.Followup`） |
| 灵感两套层未打通（`memory_items 灵感` vs `ideas` 收件箱） | 追加/自动合并/轨迹都缺 |

## ① 会议智能助手（P0）—— 底子最厚，缺「跟进闭环」

**已有**：`topics(kind=Meeting)` 显式专题（含每周周期重复）+ `meeting` 自动技能双通道；纪要卡字段齐（topic/conclusion/points/decisions/actions/people/quotes+原话行号）；`memory_items` 已带 who/dueAt/kind方向（我要做/我答应别人/别人答应我）/doneHint；`decisions` 有全生命周期+topicKey 冲突检测+证据门；`followups` 扫停滞项。

**缺口**：
1. 卡片 `decisions`/`actions` 是字符串——不进入 decisions/memory_items 表，不可勾选流转（`SkillVisuals` 纯展示）
2. 无会议系列实体：`repeatRule` 自动建的下一场只是同名新行，无 `seriesKey/prevTopicId`
3. 无「上次承诺」注入：纪要 prompt 收到的是全局未完成待办，不知道来自上次同系列会议
4. `decisions` 会后不自动同步；纪要卡 decisions 永远进不了表
5. `who` 自由文本，未挂 `voiceprint_people.personId`
6. 无会议索引页/详情聚合页（卡+决策+行动项+跟进分散在专题历史/技能卡/事件三处）
7. 无 `RuleEvent.TopicDone`

**建议任务卡**：
- R5.1 会议系列与承诺闭环：`topics.seriesKey`（规范化名称）+ 回链；纪要上下文注入「上次同系列纪要要点+该系列未闭行动项」；卡片 actions→`memory_items`（解析负责人/时间）、decisions→`decisions` 表（过证据门）；`syncFromDigest` 挂到整理完成钩子；新增 `RuleEvent.TopicDone`。
- R5.2 会议详情聚合页：纪要卡+本场决策+本场行动项（可勾选，写回 item status）+关联跟进；会议索引视图（kind=Meeting 的 topics + meeting 卡）。

## ② 办公工作助手（P0）—— 单件都齐，缺「聚合面板+承诺建链」

**已有**：随口说→待办双路径（主动语音直达 Accepted / 录音管线 Pending 确认）；dueAt/who/doneHint/证据链全；强提醒三连响；`reviews` 日报全链路（生成/推送/深链/UI）；`workflow_rules` 自动化可用。

**缺口**：
1. `FollowupKind.Commitment` 是死代码：kind=「我答应别人/别人答应我」的 item 永不建承诺型跟进；首发现最差 ~30h（Accept+24h+6h tick）
2. 跟进通知复用日报渠道（关掉日报=关掉跟进）、深链不落地、无外部推送
3. 周报是 `skill_cards` 里的 weekly 技能卡，非 `reviews.type='weekly'`，无一等入口
4. 无统一面板：待办/跟进/日报/周报散在四处
5. `dayStart()` 按 UTC 取模算日界，非本地时区

**建议任务卡**：
- R5.3 承诺闭环+提醒通路：scan 对 kind=「…答应…」的 Accepted item 直接建 Commitment 跟进（不等 24h）；`followup-reminder` 专用渠道+`PushTopic.Followup`+MainActivity 深链 `open=followups/rules/todos`；dayStart 改本地时区。
- R5.4 工作面板+周报一等化：「今日」或「待办」页聚合今日待办/待跟进/今日日报入口/本周周报；`reviews` 支持 type='weekly'（或回顾页直接露出 weekly 卡）。

## ③ 随手灵感助手（P0）—— 双轨未并轨，缺「追加与轨迹」

**已有**：`ideas` 收件箱（状态机/来源证据/手工合并/挂项目/转待办/派任务/AI分析）；item 层 `IdeaMerger` 自动合并（cosine≥0.88）+「还说过 N 次」展开；`memory_revisions` 已声明支持 `targetKind='idea'`（未用）；FollowupEngine 已催 48h 停滞灵感。

**缺口**：
1. 无追加：所有入口（分享/原话标灵感/记灵感/转灵感）只建新卡；`update()` 死代码无编辑面
2. `ideas` 不进 embeddings（`EmbeddingStore.documents` 只有 event/item），收件箱层无自动合并
3. 无发展轨迹：ideas 无 revision 行、无 fragments 表
4. `convertToProject` 未实现（`markConverted`/`projectId` 字段在，无调用方）；`convertedKind` 单槽
5. `syncFromDigest` 不接 digest_done，同步靠启动/手动

**建议任务卡**：
- R5.5 灵感追加+自动归类：`idea_fragments` 表（shared）；各入口增加「追加到已有灵感」选择；`EmbeddingStore` 增加 idea 文档类+复用 IdeaMerger 阈值做候选合并（先人工确认）；`syncFromDigest` 挂 digest_done；idea 全量变更写 `memory_revisions`。
- R5.6 灵感轨迹+转项目：灵感详情页加时间线（fragments+revisions+合并项+分析记录）；实现 `convertToProject`（create+link+markConverted+种子 project_marks）；分析结果回写 `project_marks`。

## ④ 高级项目分析（P1）—— 需要先把「归属」修好

**已有**：`projects/project_links/project_marks` 结构完整（mark 5 类+timeline/summary）；`analysis_runs` 全生命周期+提示词快照+sourcesJson+离线导出粘回；`decisions` 生命周期+证据；`projectId` 字段在三张表里都已就位。

**缺口**：
1. `decisions.projectId` 永远 null（导入硬编码 + 无 UI 路径）
2. `project_marks.Decision` 与 `decisions` 表双轨不并
3. 无项目×时间窗的装配查询（`projectMaterial` 只拉 marks+links，无日期窗）
4. 关联 100% 手动（仅灵感卡/收集卡两处入口可挂）
5. `ProjectMarkKind` 无 Blocker；followups 无 projectId
6. 无阶段报告模板；AskEngine 工具集无 projects/decisions（GroundedQA 决策/灵感臂是整句 LIKE 几乎打不中）
7. `runsForProject`/`observeForProject` 均未被 UI 消费；timeline 不合并 decisions

**建议任务卡**：
- R5.7 项目归属修复：decisions 导入时按内容/来源事件挂 projectId（或提供归属 UI）；`project_marks` 增加 Blocker kind；followups 加 projectId 字段。
- R5.8 项目阶段报告：`AnalysisType.PhaseReport`+内置模板；`projectMaterial` 改为「窗口内 marks+decisions+关联事件/条目+跟进」装配；ProjectScreen 消费 runsForProject+decision timeline+阻塞区；AskEngine 加 project/decision 工具。
