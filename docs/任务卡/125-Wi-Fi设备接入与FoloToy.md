# 卡 125 · Wi-Fi 设备接入（局域网）与 FoloToy

- 工作目录 `~/Developer/TaoSheng-125`，分支 `codex/125-wifi-devices`（从 `plan/0221` 拉出）。**不改 `ui/`、`MainActivity.kt`、版本号**。
- 版本：0.2.21（不急，做稳）。与卡 119（蓝牙接入）、122（收拢）并行：不要改蓝牙连接代码；共用的录音输入接入点等 119 合并后由 Claude 收拢，你在交付说明里写清楚。

## 背景

负责人手上有一张 FoloToy 开发卡。卡 121 查明：FoloToy 实时声音走 Wi-Fi（UDP，默认端口 8085），设备与服务器用 MQTT 通信，蓝牙只用于配网（见 `docs/任务卡/121-交付说明.md` 的 FoloToy 一节）。负责人决定：**做 Wi-Fi 兼容方案**，第一版说明卡里预留的 `transport` 字段这次用上。

## 第一步：查清楚再动手（结论写进交付说明）

1. FoloToy 官方开源的自建服务器（如 `folotoy-server-self-hosting` 等仓库）和固件资料：设备怎么找到服务器（配置里写服务器地址？），MQTT 主题和消息格式、UDP 声音包格式（编码、采样率、帧长、包头、有没有加密/鉴权）。
2. 能否让设备把声音直接发到**同一局域网里的手机**（手机当“服务器”）。需要手机上跑哪些东西：只收 UDP 就够，还是必须有 MQTT 服务端。
3. 有没有不改设备固件就能做到的办法；如果必须改固件或用官方配置工具，写清步骤。

**停下来的条件**：如果必须在手机上内置一个 MQTT 服务端，而现成的库超过 1 MB 或依赖很多，或者声音是加密的、拿不到密钥，就不要实现，写清楚交付说明里的结论和可选方案，交给 Claude 和负责人决定。

## 第二步：实现（满足条件才做）

1. **约定**：本卡允许在 `devices/DeviceContract.kt` 里**只新增**：`Transport.Wifi`，以及 `DeviceCard` 的可选字段 `wifi: CardWifi? = null`（`CardWifi` 里放端口、发现方式、需要的控制消息等，你按查到的协议设计，注释写清每个字段）。不改已有字段。`docs/方案/外设接入字段表.md` 同步补一节。
2. **局域网声音接收**：作为 `AudioSource` 输出标准帧（16 kHz 单声道，480 采样一帧），声音解码复用卡 118 的 `AudioDecoder`。只接受局域网地址（10/172.16–31/192.168/169.254 和 IPv6 本地地址）发来的包，**不连外网**。
3. **找到设备**：优先用设备自己上报（比如它连上手机这个“服务器”）；需要时在设置里显示“请在设备配置里把服务器地址填成 手机IP:端口”，手机 IP 由 App 提供给界面。
4. **保活和断开**：录音前台服务在跑时才收；一段时间收不到包按断开处理，换回手机麦克风（复用卡 112 的逻辑），设备回来自动切回。小米上要加多播锁/Wi-Fi 锁的话只在收音时持有。
5. **安卓 16 的“局域网访问”权限**：查清是否需要、怎么申请，没有权限时给出明确的 `lastError`。
6. **FoloToy 说明卡**：`assets/devices/folotoy.json` 改为 `transport: wifi`，按查到的协议填好，`status: trial`（负责人真机验证后再改 verified）。

## 必测（5～10 个即可）

- 假 UDP 发送方按 FoloToy 包格式发包 → 产出标准帧；外网地址发来的包被丢弃。
- 超时断开 → 换回手机；恢复 → 切回。
- 说明卡解析：wifi 字段校验。

## 真机由负责人测

FoloToy 开发卡和手机连同一个 Wi-Fi，按交付说明配置设备，指定为录音输入，录一段、关掉设备再打开。
