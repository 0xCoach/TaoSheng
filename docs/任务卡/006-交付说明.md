# 006 声纹——交付说明

## 完成内容

采用方案 **A：现有 onnxruntime-android 1.23.2 + Kotlin Kaldi fbank**。先完成 `tools/voiceprint-probe/` 的独立离线实验和 Kotlin 逐值对齐，再把模型与实现接入 App。未增加 Android 依赖或原生库；现有 Silero VAD、界面、MainActivity 和全部 Contract/AudioSource 签名未改。

- `AppGraph` 只增加 `voiceprint`、`isVoiceprintReady`；`ResoundApp` 手工装配。
- Room 升 v4：句子 `speakerScore`、录音段 `voiceprintProcessedAt`、样本表、排除组表，提供 Migration 3→4 和导出 schema。
- 转写完成后按 `(segmentId, speakerTag)` 处理。句子绝对时间换算为 PCM 范围、裁剪边界、合并重叠，排除句间其他声音，再用 20ms RMS ≥ 0.002 去静音。该门限匹配小米当前低增益采集；没有修改采集服务的 VAD。
- 没有 speakerTag 的句子各自独立，避免把云端未分清的多人拼成一个人。有效音频不足 1.5 秒不算向量，分数留空，但记录该段已处理。
- 样本仅持久化 192 维向量、来源、时长和时间；不保存注册原音。每条向量归一化后取平均，再归一化，计算余弦；负余弦按 Contract 的 0..1 范围记为 0。
- 至少 3 条、有效人声合计 ≥30 秒才自动比对。分数 ≥0.50 写“我”；低于只写分数。`RoomTranscriptRepository` 会正确返回名字与分数。
- `markMe` 从同组全部句子建样本并重算；同组重复点击不会累加条数/时长。样本不足时不自动标“我”。`markNotMe` 撤回该组误加样本、清除认人结果、持久化排除；自动重算不会恢复，明确再次 `markMe` 才撤回排除。
- `reset` 删除样本、排除及已有句子的名字/分数，回到未录入状态。已整理事件不自动重新生成。
- `TranscribeWork` 顺序为转写 → 声纹 → 整理 → 过期录音清理，周期/立即任务共用一把流水线锁。声纹计算、人工纠正、清理互斥；整理期间也固定声纹结果。
- DigestRunner 从数据库判断 readiness，避免冷启动 StateFlow 初值误放行；ready 时整组会话等待涉及的录音段处理完，“立即整理”也不能绕过。未 ready 照原流程整理。
- 分数与处理时间同一事务提交。解码/模型异常保留录音和待处理标记，交 WorkManager 重试；已经过期缺失的旧录音记录错误并标为处理完成、放行整理，避免永远卡住。声纹临时解码 PCM 在 finally 删除。

## 离线结果

脚本、固定依赖、合成夹具和完整统计见 `tools/voiceprint-probe/README.md` 与 `results/`。全部声音推理在 Mac 本地执行，没有上传声纹音频；App 声纹实现也不调用网络。

有效音色：Tingting、Meijia、Sinji，各 5 段。Tingting 前 3 段（去静音后 40.8 秒）注册，后 2 段留出验证。最初第四个音色 Eddy 在本机实际输出和 Tingting 相同，剔除后没有把它当作“不同人”。

| 比较 | 数量 | 最低 | 中位 | 最高 |
| --- | ---: | ---: | ---: | ---: |
| “我”的留出语音 vs 三样本平均 | 2 | 0.976852 | 0.978007 | 0.979163 |
| 其他音色 vs 三样本平均 | 10 | 0.271291 | 0.495530 | 0.707297 |
| 所有音色内部同人配对 | 30 | 0.955582 | 0.970312 | 0.978100 |
| 所有不同音色配对 | 75 | 0.240187 | 0.357411 | 0.719744 |

选择平均向量：最大样本匹配的留出同人分数约 0.972707，异人最高 0.719744，较平均向量分离更差，因此没有叠加最高分兜底。

**阈值建议仅提交 Claude 决策：候选 MAYBE=0.75、SURE=0.85。未修改约定中的 0.50/0.62。** 现有阈值在这组实验中会把 Meijia 的五段误认为“我”，不能把当前阈值称为校准完成。建议阈值可以分开本次合成音色，但不代表真实场景误识率；需要本人和非本人的人工标注录音校准，较高门限也可能漏掉短句/远讲。

只用 `adb devices`、`adb exec-out run-as app.resound ls/cat files/segments/...` 读取三段手机原有 OGG：

| 匿名录音 | 去静音秒数 | 前/后半段余弦 | 与合成“我”的余弦 |
| --- | ---: | ---: | ---: |
| 0 | 18.26 | 0.207989 | 0.314788 |
| 1 | 3.7778 | 0.737159 | 0.134342 |

这三段没有身份标签，也没有确认是单人；前后半段不当作同人真值。结果证明实际 OGG 能解码并产生非退化分数，不能证明已经认出负责人。个人音频只在被 Git 忽略的 `tools/voiceprint-probe/private/`，提交中只有匿名统计。

## fbank 对齐与运行方式选择

实现参数按 sherpa-onnx **v1.13.8 实际 C++ 配置**：16k、25ms 窗、10ms 移、80 维、20～7600Hz、Povey、去 DC、预加重 0.97、dither=0、首尾反射补边、全段减均值。上游 Python 示例的默认 snip_edges/high_freq 不同，本卡已纠正后再验证。

静音、固定噪声和 say 语音共 **21,440 个特征值**逐值比较：

| 输入 | 原始 fbank 最大绝对误差 | Kotlin 减均值后最大误差 | 两套特征经同一 Python ORT 推理的余弦 |
| --- | ---: | ---: | ---: |
| 静音 | 0 | 0 | 约 1.0 |
| 噪声 | 0.00005246 | 0.00005460 | 1.0 |
| 语音 | 0.00036621 | 0.00036669 | 1.0 |

Python KNF 与 sherpa `get_frames` 原始 fbank 最大差为 **0**。另做了 sherpa 完整 embedding 对照，余弦 **0.997134**，并非位级相同；差异出现在 fbank 之后，原因未继续归因。方案 A 以“Python KNF + 明确的均值归一化 + ONNX Runtime”为验证基准，Kotlin 特征与该基准对齐。Mac Python ORT 1.31.0 与 Android ORT 1.23.2 的原生端到端一致性尚需手机验证。

因此选 A：误差有逐值证据，包体增量符合限制，且无需替换现有人声检测或处理两套 onnxruntime .so。

4. 本人与他人轮流说话，完成转写后检查同组各句名字/分数一致；不足 1.5 秒的组不标。检查整理原话中负责人显示“我”，待办归属是否正确。
5. 重复确认同组“是我”不增加样本数；确认“不是我”后新增样本、重跑、重启均不能自动恢复该组“我”。reset 清空样本与认人结果。
6. 模型/解码失败应保留原录音并等待重试；成功处理的录音满一天后可清理。核对录音中断恢复、五分钟长段耗时/内存、发热、后台工作与耗电。

## 遗留边界

- 真实身份校准、Android 原生推理/解码及长时间后台表现由负责人真机验收；当前仅确认离线结果、编译与本卡 JVM/Room 用例通过。
- Contract 阈值明显偏松，待 Claude 根据上述建议及真实带标签录音调整；本卡没有擅自修改常量。
- 句子内 RMS 裁剪能去低能量静音，不能分离重叠讲话或消除背景音乐；云端把多人标为同一 tag 时也无法凭这一组平均声纹纠正。
- 样本未 ready 时不阻塞整理，也不延长既有一天录音保留期；之后录入样本无法补算已经删除的旧声音。已完成的事件/提取项不会因重新标记自动重跑，以免重复生成或计费。
