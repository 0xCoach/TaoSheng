## 1. 功能全景（一句话版）

**官方 AI = 服务端托管的大模型服务**：App 只下发状态/额度元数据，密钥/地址/模型永不出服务端；用户登录授权→同意→即选即用，按点数计费（Free 100 点/月、Pro 1000 点/周期）；BYOK 自填密钥方式永远并存保留。

涉及的完整生命周期：

```
游客试用 → 注册/登录（Free）→ 状态下发 → 同意 → 自动选中官方 → 整理/问问/回顾/技能按点扣费
        → Pro 授予 → 额度 1000 + auto_digest 放行
        → 登出/会话失效 → 官方条目标"未就绪"，重新登录（登回原账号即归属自动解除）
        → Pro 到期 → 回 Free 行为（auto_digest 本地拦截）
```

## 2. 服务端契约（`server/src/`，worker.js / ai.js）

### 2.1 公开端点（需登录会话）

| 端点 | 行为 | 错误码 |
|---|---|---|
| `GET /ai/official/status` | 下发 `{enabled, configured, consented, plan, remaining, period_end…}` | 401 会话失效 |
| `POST /ai/official/consent` | 记录同意 `{version}` → `ai_consents` | 401 |
| `GET /ai/official/quota` | 当前周期额度明细 | 401 |
| `GET /ai/official/usage` | 用量/扣点历史 | 401 |
| `POST /ai/official/estimate` | 按 task_type+文本估点（返回区间，不扣） | 401 |
| `POST /ai/official/generate` | 生成并扣点；`request_id` 幂等（见下"凭据生命周期"）；`task_type` ∈ digest/auto_digest/ask/analysis/manual_todo/generic | 401 / 402 `QUOTA_EXHAUSTED` / 403 `CONSENT_REQUIRED` / 429 `DAILY_TASK_LIMIT`·`RATE_LIMITED` / `REQUEST_TOO_LARGE` `TASK_FAILED` `PROVIDER_UNAVAILABLE` `UNKNOWN_PROVIDER_OUTCOME` |

**要点**：`auto_digest` 仅 Pro 放行（Free 一律 402）；点数 = 原子"预留→结算"，服务端是唯一扣点裁决者；所有非 401 业务错误都不是会话问题。

**429 两类限流必须区分**（`source` 字段标识，1.0.11 起）：
- `DAILY_TASK_LIMIT`（`source:"daily_task_limit"`）：**本网关**的每日成功次数上限，返回 `{limit, used, reset_at}`（北京时间 08:00 重置）。`free_daily_tasks`/`pro_daily_tasks` **默认 0 = 不限次数、只扣点**；管理员可另设正整数；PATCH 负数返回 400。
- `RATE_LIMITED`（`source:"upstream"`）：**上游服务商** 429，请求未扣点、已释放预留，审计 `ai.provider_rate_limited`。

**request_id 凭据生命周期**（1.0.11 起，按 `request_key` 唯一）：
- `settled` → 重放返回 `duplicated` + 原内容，不重复扣点、不访问上游。
- `reserved`（在途）→ 409 in-flight。
- `failed`/`rejected` → **可凭同一 request_id 重试**：CAS `UPDATE … WHERE status IN ('failed','rejected')` 只有一个重试能夺回 `reserved`，其余 409；重试复用原行，结算后凭据仍幂等。
- `error_code` 以 `UNKNOWN_PROVIDER_OUTCOME` 开头 → **永久禁止再次访问上游**（超时时上游可能已执行），重放一律 504。
- 结算后余额查询/审计失败不回滚：`settled`/`released` 一次性守卫保证"成功结果不可撤销、失败释放只执行一次"。

### 2.2 管理端（ADMIN_TOKEN Bearer / 控制台 csrf）

- `POST /admin/release` — 发布 `{channel, manifest:{versionCode,versionName,notes,apk:{file,sha256,size},patches}, files:{文件名:下载URL}}` → `app_release` 表
- `GET /release/update.json|preview.json` — 公开，读 manifest
- `GET /release/<file>` — 按 files 映射 302 到真实包
- `GET/POST/PATCH/DELETE /console/api/ai/providers|rules|users|usage` — 官方 AI 六块管理：运营开关/暂停、服务商 CRUD（含加密密钥、连通测试、默认切换、真删除）、点数规则（含 SSRF `allowed_hosts` 白名单）、用量成本、用户点数调整、权益
- `POST /console/api/users/<id>/reset_password` — 服务端哈希重置
- 用户 CRUD、会员授予/撤销、兑换码批次、审计

### 2.3 错误语义红线

- **HTTP 401** = 会话问题（App 才做 refresh-token 轮换重试）；**其余状态码一律是业务错误**，不得当会话失效处理。
- 管理台 `api()`：**只有 401 跳"会话失效"**；403（如 SSRF 拒绝、CSRF）就地显示真实错误。

## 3. Android 侧行为全集

### 3.1 条目三态（`ProvidersCard.kt`，订阅 `auth.status` + `officialAi.status` 两个 StateFlow）

| 状态 | 副标题 | 点按行为 |
|---|---|---|
| 游客（`AuthStatus.Guest`） | `official · 登录授权后可用` | **先 `activate(official)` 持久化选择**，再弹登录面板（原因栏"官方 AI 需要登录授权后使用"） |
| 已登录未同意 | `official · 同意后即可用` | **先 `activate(official)`**，再弹同意说明页（「同意并启用」） |
| 就绪（登录+enabled+configured+consented） | `official · 点数制·剩 N 点` | 正常切换/检测；剩点随扣费实时变 |

**重组机制**：文案**直接订阅两个 Flow**，不依赖 `_saved` 列表重发（列表内容不变时 StateFlow equals 去重不 emit → 曾致注册后永远显示"登录授权后可用"）。

**显式选择持久化**（1.0.10 起）：点按未就绪官方条目时**先调 `activate()` 写入 activeId** 再弹登录/同意——不依赖就绪沿自动替换（就绪沿不会覆盖已用密钥的 BYOK 条目，会导致"点了官方但登完还是旧服务商"）。`activeId=official` 重启后仍然生效。

### 3.2 登录/同意/自动选中链路（1.0.10 起改为**账号维度**）

- `AuthGate.onAuthSuccess` → `officialAi.refreshStatus()`（登录即拉，不用等重启）。
- `OfficialAi.consent()`：服务端记账 + 本地 `official-ai.xml` `consentVersion=1` **+ `consentAccountId=<当前账号>`**；status==null **或 status 属于别的账号**时补拉 refreshStatus 自愈。
- **`statusAccountId` 账号隔离**：`refreshStatus` 记取状态时的账号；`ready()` 额外要求 `statusAccountId == sessionAccountId`——**换号后旧账号的就绪快照不会误用**；请求/同意进行中账号被切换 → 结果作废返回 `NeedLogin`。
- **服务端为同意权威**：`parseStatus` 不再拿本地 `consentVersion` 覆盖服务端 `consented=false`（管理员撤销同意/换号时本地缓存不得放行）。
- `localConsented()` = 当前会话账号 == `consentAccountId` 且版本达标——仅用于"服务端漏记账时补登记重试一次"。
- `officialAi.onStatusChanged` → `providers.refreshOfficial()` → 重发 saved 行（官方行 `hasKey=officialReady()`）；**false→true 就绪沿**且当前服务商不可用（无密钥/非免密/无 headerAuth）→ 自动 `activate(official)`；已填密钥的当前服务商不被抢占；只沿触发一次，用户手动切回不覆盖。
- **登出/会话失效** → `officialAi.clearStatus()`（清 `_status`+`statusAccountId` 并广播）→ 官方条目回"登录授权后可用"。
- 官方条目**不可编辑**（无密钥框/编辑钮），服务端下发的唯一标识 `OFFICIAL_PROVIDER_ID="official"`。

### 3.3 免密钥语义（1.0.9 核心修复）

`LlmPreset.allowsEmptyKey()` 现含 `id == OFFICIAL_PROVIDER_ID` —— 语义 = "该预设免本地密钥"。
效果：**所有共享密钥门**（ReviewStoreRepository / LocalSkillRepository.model.ready / SkillDrafting / AskSuggestions.hasKey / GroundedQA / ManualTodos hasBackup / digestSettings.usable → settings.hasKey）一律放行官方；
之后**由官方桥报真因**（`ResoundApp` 映射，1.0.11 更新）：`NeedLogin`/HTTP 401→"请登录后使用声声不息官方 AI"，`CONSENT_REQUIRED`→"请先在设置里同意使用声声不息官方 AI"，`QUOTA_EXHAUSTED`→"官方 AI 点数已用完，请等下周期或升级 Pro"，`DAILY_TASK_LIMIT`→"今日官方 AI 次数已达上限，每日北京时间 08:00 重置"，`RATE_LIMITED`→"官方 AI 上游服务繁忙，请稍后重试（未扣点）"——替代原先的"还没填写大模型密钥"/"请求过于频繁"误报。

### 3.5 归属与登录（1.0.9 死锁修复 + 1.0.10 状态加固）

- `ownershipIssue()` 两分支：**①未绑定+已登录+有本地数据 → true（绑定未完成前，验过机主也不算数）**；②已绑定且 `bound != session`（含已验机主）→ true。登出态（session==null）两分支都不成立 → 登录面板可弹。登回原绑定账号 = `AlreadyBound` 自动解除；登异号 = `BoundToOther` 拒绝接管（数据隔离是设计）。
- **`AuthLoginHost` 按 `auth.status` 分流**：仅非 Guest 才考虑归属弹层——防止已登出但状态流未更新的瞬间把归属层当登录页弹。
- **`require()` 待归属分支放行 `ExportBackup`**：未绑定/未验机主时唯一允许的能力是导出备份——保证绑定前置条件"先有一份真实备份"永远可达。
- `bindLocalData` 门槛：会话 + 先有一份真实可用备份（本机文件夹或云端），90s 等落盘，失败不绑定；**备份等待结束后复核 `sessionAccountId` 未变才写绑定**（等待期间换号不得错绑）。
- **`ownerVerified` 是会话级**：`saveLogin`/`logout`/`invalidate` 都清零——登录本身不授予机主身份，新会话必须重新验证。
- `afterAuthSuccess()` **复核决策**：登录成功后若被拦能力仍不允许（典型：归属待绑定），保留 `loginRequested`（原因更新为真实阻断）并只触发 `onAuthSuccess`，**不执行 `pendingAction`**——防止"登录成功但归属未完成"时动作被错误放行。
- 会话失效：`expireSession` 清会话 + 主动 `_loginRequested` + `onSessionExpired` 通知回调；`bindDeclinedAt` 冷却只对"已登录归属确认暂不"生效，登出取消不冷却。
- `authed()` 401 处理（1.0.10）：Mutex 串行 refresh → **重试**：重试仍 401 → `expireSession("登录授权已失效")`；refresh 失败/离线 → 返回 `Network("会话续期暂未完成")`（不算业务拒绝）；`NoSession/SessionGone` → 原样返回。非 401 业务错误不刷新不登出。
- `checkStatus()`：status 请求遇 401 同样先 refresh 再重试，只有 refresh 后仍 401 才 `expireSession("会话已被撤销")`——误伤面收窄。
- 服务端 refresh 轮换**带 prev 宽限窗**（`prev_refresh_hash`/`prev_valid_until`，migration 0005）：旧 refresh token 在宽限内可恢复"响应已轮换但客户端没收到"的场景，宽限过后真失效。

## 5. 设计红线（复核时按此判对错，不是按"方便"）

1. 官方上游地址/模型/密钥**永不出服务端**；App 拿到的只有 status/quota 元数据。
2. 官方条目 App 内**不可编辑、不可当 BYOK 备用、失败不静默切 BYOK**——计费方式选择必须显式。
3. **免密钥 ≠ 免费**：`allowsEmptyKey` 只决定"要不要本地密钥"，可不可用永远以就绪态+服务端裁决为准。
4. 请求幂等凭据（request_id、进行中凭据、预留结算）**不可删改弱化**——同一请求只扣一次点；**已结算结果不可撤销**，失败重试只能复用凭据不能重复扣。
5. `request_id` 稳定派生（账号/任务/内容）；用户主动重生成用 nonce 换号。
6. 401 才刷会话；402/403/429 等业务码进各自错误类型；**429 两类必须区分**——本网关每日上限 `DAILY_TASK_LIMIT`（配额语义）vs 上游繁忙 `RATE_LIMITED`（瞬时限流，未扣点），不得混报。
7. 归属：数据跟账号走；绑定前必须有一份真实可用备份；**登录≠机主**，ownerVerified 随会话清零。
8. 本地优先：原始音频不出手机；官方请求只送所需文本。
9. **状态记到账号不记到设备**：官方状态/同意快照必须绑定 sessionAccountId——换号后不得沿用旧账号的就绪、同意、余额（防串号泄密/错扣）。
