- 用独立偏好 `ask-compatibility` 按“服务商配置 id + 模型名”保存标记、固定原因、时间，以及上次实际问答失败。配置、密钥、请求头等保存后清除旧状态；工具检测通过清除降级标记。配置版本与请求快照一起取得，旧在途请求不能重新标记已修改的配置。检测失败不冒充实际问答失败；读取已知标记不增加 HTTP 用量。
- 两种模式均允许以 `[无需记录]` 开头、没有引用的寒暄/通用回答；展示前去掉完整标记，并隐藏尚未收齐的前缀。用户经历类结论仍需出处。
- 流式 `max_tokens` 提至 4096。`finish_reason=length` 单独识别，不触发兼容降级，提示“回答没写完就被截断了：模型思考太久，可在设置里关掉深度思考或换个模型”。保留认证、余额、限流和网络提示；其他问答服务错误使用固定服务不可用提示。
- 模型检测工具不兼容时为“降级可用”，继续用预查资料检测出处。卡 133 的“整理与大模型诊断”增加当前模型降级标记、原因、时间及上次实际问答失败。新增持久记录只存枚举和时间，不存原话、提示词、密钥、服务端正文或思考签名。

## 给界面的字段

| 字段 | 含义与接法 |
|---|---|
| `AskMessage.mode: AskMode` | 默认 `Tools`；本次程序预查为 `Prefetch`，可在回答旁标“程序先查”。切换过程中和历史恢复后均提供。任务单明确要求的默认字段追加；未改 AskRepository 方法签名。 |
| `AskEngine.Update.mode` | 引擎内部向仓库传递模式，界面继续读取 AskMessage。 |
| `ModelCheckItem.status` | `Passed / Degraded / Failed / Skipped`；Degraded 建议显示可用提示色，不显示失败红色。 |
| `ModelCheckItem.degraded`、`ok` | 降级项为 `degraded=true, ok=true`，旧界面仍会显示可用及明确文案；可按 status 区分正常与降级。 |
| `ModelCheckItem.lastAskFailure` | 可空的 `AskFailureRecord(reason, at)`；`reason.human` 为固定中文文案，`at` 为毫秒时间戳。各检测项携带同一快照，检测页只展示一次“上次实际问答失败”。成功检测清除降级标记，但保留这一失败历史；配置改动清除旧配置状态。 |

回答 mode 保存在已有 `ask_messages.sourcesJson` 的 `{sources:[...],mode:"Prefetch"}` 包装中。旧数组仍能读取，旧消息默认为 Tools；`AskCitations.encode/decode` 的来源读写兼容保留。**未改数据库表、版本、迁移或 schema，无需 Claude 为本卡分配迁移编号。**
