# 009 问问后端交付说明

已在 `codex/009-ask` 完成后端并装配到 `ResoundApp`。界面可从 `AppGraph.ask` 取得仓库，通过 `AppGraph.isAskReady` 检查装配。未改 `ui/`、`MainActivity.kt`、任何约定文件签名；未推送远端。

## 做了什么

- 复用整理服务、密钥及 `LlmClient`，增加可取消的 SSE 流式和工具调用，保留 `chatJson`。一轮最多执行六次工具；额度耗尽后保留工具定义、禁用调用并要求给最终回答，避免 DeepSeek 把 DSML 工具语法当成正文。
- 四种工具共用 `assets/prompts/ask-sql.json`：原话关键词 OR、事件、提取项、日概览。使用绑定参数及 LIKE 字面量转义，过滤已删除事件，每次最多 40 条 / 约 6000 字。from 包含起点，to 包含该日/该分钟；提取项按原事件发生时间筛选，计划日期保留在 dueText。
- 事件与提取项带同事件原话上下文，每个字段最多 900 字；正文 `[^n]` 解析、去重并重编号，始终对应 `sources[n-1]`。越界引用或无出处回答给固定中文错误。
- 数据库升级 v6，新增 `ask_conversations`、`ask_messages`、会话外键和索引，提供 Migration 5→6，提交导出的 `6.json`。只在结束/取消时原子保存用户问题和最终回答，流式中间态仅在内存。
- 仓库提供进度、停止保存部分回答、重启恢复最后会话、新会话隔离。超时、断网、鉴权及格式问题只显示固定中文文案，不带服务端原文。
- 推荐问题基于今天和此前三天的事件，最多 4 个、每个不超过 12 字；本地缓存，间隔至少六小时且每天最多尝试两次，失败也占次数。没有密钥或没有可用结果时给两个固定示例。
- 问答和推荐请求接入 `llm_usage`。取消/失败仍计一次调用；服务未回传 usage 时 token 记 0，不猜测，因而中断请求可能少计实际 token。

## 离线实测

按负责人 2026-10-23 的明确授权，脚本只将与问题相关的有限检索片段发送到 `https://api.deepseek.com`。密钥仅由脚本读取，不输出；完整数据库从未上传。实测完成后才接入 App。

使用之前只读取得的稳定 v5 快照（74 句原话、27 个事件、24 条提取项），六问及真实工具调用、回答和摘录见 `tools/ask-probe/results.md`。

- 36 处引用逐项核对数据库 id 和原文，全部真实存在。
- 会议主题回答为原话中的“讨论测试结果”。日志问题明确没找到后续完成记录，未编造已导出或已修复；火星燃料问题明确没找到，未编造数量。
- 初测的摘录上下文不足、DSML 和相对日期口误已针对性修正复核；报告保留真实最终回答，未人工润色模型答案。
- “线上桥梁”是疑似转写错误，回答保留不确定性；“不耗电”应理解为原话里的省电诉求。不能用这份报告保证未来所有模型回答完全正确。

原始快照和完整响应在 `tools/ask-probe/private/`，Git 忽略；报告只提交任务要求的问答和被引用摘录。离线调用的用量留在报告原始轨迹，没有写回手机数据库。

## 已知边界

- SQL 检索依赖模型拆关键词，结果有条数/字数截断；没有向量语义检索，宽泛问法可能遗漏，日概览只列已整理事件。不能把“没找到”当作事情绝对没发生。
- 真实语义准确性需要结合转写原文判断；当前自动检查保证引用编号、数据库来源和协议边界，不能逐句证明所有模型措辞。
- 进程被系统杀死时，正在流式输出的内存内容尚未保存；用户主动 stop 会保存。流式临时消息 id 为负数，最终入库后替换为 Room 的真实 id。
- 旧会话保存在库内；当前合约只暴露最后一个/新开的会话，没有历史会话选择接口。
