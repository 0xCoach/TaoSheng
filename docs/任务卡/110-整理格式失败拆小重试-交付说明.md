# 卡 110 交付说明

## 改了什么

- 新增纯函数 `splitForRetry`：少于 40 句不拆；在 25%～75% 的切分位置中，用后一句开始时间减去此前最大结束时间，选择最长停顿，并列选最靠近中点的位置。
- 重新整理仅在 `LlmException` 的类型为 `Format` 时递归拆分，先前半、再后半，保留事件顺序及条目与事件 ID 的对应关系。不能再拆时原样抛出异常；原始分批、批数和进度文案保持不变。
- 自动整理的格式错误先尝试拆分，大批不增加格式失败次数；不能再拆的小批沿用连续失败 3 次后放弃的处理。

## 自动整理的选择及原因

选择**同一轮按顺序继续整理两半**。拆出的每一批重新进入现有 `digest` 流程，按自身原话生成 identity，沿用 `pendingDigest`、`unsavedReply` 和 `inflight` 的保存、重放与清理机制，不增加持久化拆分状态。

前一半成功或按原规则放弃后，才处理后一半；若前一半返回仍需重试的错误，本轮停止，未完成原话留给后续轮次。已成功的半批已标记整理完成，不会被后续自动整理再次选中。这样改动集中在格式错误分支，不改变现有缓存逻辑。

## 验证

新增 5 个用例：

1. 少于 40 句不拆。
2. 选中间区间的最长停顿，覆盖重叠语音的最大结束时间及并列靠近中点规则。
3. 重新整理整批格式失败后，两半成功，事件、条目及原话关联正确，进度文案不增加小批计数。
4. 自动整理收到截断 JSON 后，同一轮按顺序整理两半；各批 identity 独立，大批不累计失败，缓存及在途标记正常清理。
5. 自动整理仅对不能再拆的半批累计失败，达到 3 次才放弃，然后继续处理后一半。
