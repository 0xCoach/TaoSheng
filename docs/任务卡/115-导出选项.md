# 卡 115 · 导出可选内容与格式（后台部分）

- 工作目录 `~/Developer/TaoSheng-115`，分支 `codex/115-export-options`（从 `plan/0220` 拉出）。**不改 `ui/`**，导出面板由 Claude 做。
- 版本：进 0.2.20。

## 背景

用户反馈：导出只能是 m4a 加原话 txt，不能只导文字、不能导摘要和待办、没有 md；主页多选批量导出也一样。负责人已定：
- 音频可以不要；
- 文字内容可选：摘要、待办、原话（可多选）；
- 格式：txt 或 Markdown；
- 多段（含主页多选的多件事）**合并成一个文件**；
- 不要音频时直接给单个文字文件（打包与分享由界面处理，底层只要产出文件）。

## 约定（已由 Claude 写好，签名不要改）

`transcribe/AudioExportContract.kt`：`ExportRequest.includeAudio / textParts / textFormat`，`ExportTextPart`，`ExportTextFormat`。`includeText` 是过渡用的只读属性，本卡做完后底层不要再用它（保留属性，界面改完后由 Claude 删）。

## 要做

1. `LocalAudioExporter`：
   - `includeAudio = false`：不解码、不合成音频，也不出 srt；文字里不写“在合成录音里的位置”，只写当时时刻。预估 `ExportEstimate` 的 `durationMillis/bytes/etaMillis` 为 0，`audioSegments` 仍报有录音的段数（界面用来说明）。
   - `textParts` 为空且 `includeAudio=false`：返回失败“没有选要导出的内容”。
   - 文字内容顺序固定：**摘要 → 待办 → 原话**，只出选中的部分。
     - 摘要：选中段落所涉及的事件（按时间），每个事件写时间、标题、摘要。
     - 待办：这些事件里的待办与约定，写状态（未完成/已完成）、到期时间。
     - 原话：现在的写法不变（时刻、说话人、句子；有音频时加位置）。
   - 开头仍写标题、日期、总时长（有音频时）、涉及的人名。
   - Txt：UTF-8 **带 BOM**（Mac/Windows 直接打开不乱码），扩展名 `.txt`。
   - Markdown：扩展名 `.md`，`#` 标题、`##` 分节、事件用 `###`，待办用 `- [ ]` / `- [x]`，原话每句一行（行尾硬换行或列表，保证在常见 md 阅读器里一句一行）。不带 BOM。
2. `AndroidExportJobs`：任务持久化 JSON 存上新字段；读取旧记录（只有 text/srt/media）时按旧含义还原（text=true → 原话）。
3. 主页多选导出走的是同一个 `ExportRequest`，确认多件事合成一个文件、按时间排，不重复同一个事件。

## 必测（5～10 个用例即可）

- 只要文字（无音频）：只出一个 .txt，带 BOM，无 m4a、无 srt。
- 三部分全选 + Markdown：顺序为摘要、待办、原话，待办有勾选框。
- 什么都没选：失败并给说明。
- 旧任务 JSON 能读。
- 原有导出用例保持通过（只跑导出相关的测试）。
