## 连接复用

- `AndroidNetwork` 使用进程级配置缓存与协程 Mutex；同一配置借用同一个 Ktor `HttpClient`，不再按请求创建引擎或连接池。默认安卓客户端从共同模板派生，模型列表、自定义转写、LLM、豆包的重复调用不会产生新的传输模板。
- 分组包含 connect/read/write/call 超时、HTTP/HTTPS 重定向、retry、ping，以及代理、DNS、TLS、证书校验、协议、拦截器、cookie、cache、事件监听器等平台配置。显式注入的不同连接池/dispatcher 也是隔离边界，避免覆盖调用者传输设置。
- 地址、密钥和自定义请求头不入分组键；每次从当前请求读取。配置变化创建新组，旧组保留到进程结束，避免关闭仍在执行的请求；恢复原配置可取回原组。
- LLM JSON/SSE、余额、模型列表、自定义转写都去掉单次完成时的 client.close / dispatcher.shutdown / pool.evictAll。响应仍由 `execute` 作用域释放，取消只结束本次请求。
- 豆包也共用同组 Ktor 客户端与底层 OkHttpClient；每次会话有自己的 `AndroidSocketControl`，保留原背压、错误分类和即时取消。使用本地路由标识找到会话控制器，在交给真实 OkHttp 前移除；如用户原本有同名头则恢复原值。服务商看到的连接 ID、鉴权和自定义头保持原语义，两个会话即使自定义相同连接 ID 也互不干扰。finally 注销会话并 cancel 自己的 socket。
- 旧 OkHttp 实现没有改动；回退时仍使用原来的独立默认构建器，避免旧路径的关闭逻辑关闭新链路共享资源。开关仍按 151 约定重启生效。

## 每个循环的处理与行为

| 位置 | 处理 | 行为保证 |
|---|---|---|
| AndroidAsrChooser，1 秒 | options 或 lastChoice 有订阅者才刷新；首个订阅立即刷新 | 打开选择器立即更新，显示时仍每秒校对下载状态；重做估算、入队、真正执行前另行即时刷新，后台任务不依赖旧的界面快照 |
| AndroidRecordingPacker，30 秒 | availableDays 有订阅者才查元数据 | 打开列表立即扫描，显示时仍每 30 秒刷新；打包估算/执行仍独立读取最新源数据 |
| AndroidHealthCheck，60 秒 | report 有订阅者才保留分钟兜底 | 设置页打开立即刷新；原状态 Flow、权限、系统广播、Activity 恢复等事件监听保留，无人看时仍响应真实变化 |
| AndroidExportJobs，60 秒 | jobs 非空才 prune/publish | 运行中任务及最近完成结果都算任务，保证一天保留期不变；清空/过期到空列表后立即停，无任务不再反复写偏好 |
| TopicFeature，60 秒 | current 为 Running/Paused 才 tick | 启动仍校对一次并安排整理；预约由已有 TopicAlarm 触发，进行中/暂停的提醒和截止时间兜底保留；结束仍由 onEnded/Room 变化安排 Worker，Worker 继续负责重试 |
| RecordingAudioPush，60 秒 | 只有 enabled 的 MarkdownFolder 通道且 audio 非 Off 才保留分钟校对 | 分钟校对用于补偿文件过期、用量月份变化等非 Room 变化；通道与 Room 事件及原 1 秒 debounce 保留，启用后立即触发校对 |
| RoomTranscriptRepository，60 秒 | 原来 clock.shareIn(Eagerly) 且 queue/onboarding 常驻收集，实际并非按需；现 clock 仅在原话/引导订阅时运行，最后订阅离开即停止并清除 replay | 文件存在状态在页面上仍每分钟更新；queue 继续常驻响应 Room/WorkManager，跨日、改时区/时间改由系统广播更新，不依赖页面订阅 |
| RoomTranscriptRepository，失败过期 | 从分钟心跳中拆出：失败行发生变化先校对，只等最早的三天过期点；无失败行不安排计时 | 保留不可恢复音频归档、firstFailedAt 初始化、三天失败静默规则；时间广播重新计算截止点。失败行去重避免写库回通知形成循环 |
| AndroidVoiceInputCapture，60 秒 | todayCount 改 WhileSubscribed(0) | 原来冷 clock 被 Eagerly stateIn 常驻收集；现在首个计数订阅立即取当前日期，显示时仍每分钟刷新；保存语音输入的事件通道未动 |
| LocalOnboarding（共用 transcript clock） | tips 有订阅者才订阅 heartbeat | 不再暗中维持仓库时钟；展示时立即校对两天/三天提示期限，偏好/新原话/说话人变化仍即时更新 |
| AndroidRedoService，1 秒（额外发现） | LLM 选项仅有订阅时每秒更新；快照/历史清理拆为任务变化和实际 24 小时截止点驱动 | 不再每秒查快照/写列表；在截止点清理并更新撤销可用性；日期/时间/时区广播会重排，执行仍使用当前模型配置 |
| ExternalAudioSource，1 秒 | 保持 | 只在采集 Flow 被收集、当前使用蓝牙输入且别人占麦时等待；不是全局空闲轮询。500ms 录音看门狗及读音频循环属于核心，不动 |

新调度共用逻辑：需求从 false 变 true 立即刷新，保持 true 不重启周期；变 false 取消等待及正在执行的刷新。普通完成记录的保留清理不依赖 UI。

### 全局扫描的其他结果

扫描了 ResoundApp、AppGraph、各安卓装配与 app 非 UI Kotlin 中的 while/delay/Timer/postDelayed/scheduleAtFixedRate：

- ResoundApp / AppGraph 本身无额外固定周期循环。
- QuickActionsAndroid 的 60 秒是系统拒绝发布快捷菜单后的重试，成功即退出，新状态取消旧重试；不是正常空闲心跳，保留，避免菜单长期停在旧状态。
- LocalEnvSoundRepository 的 5 秒 tick 仅由 flagged/stats 冷 Flow 消费，未发现后台常驻订阅；保留。
- LocalOriginalAudio 的 5 秒轮询只在有待完成的本地原声请求时等待，结束即退出；录音租约超时是单次计时。LocalAsrConnection 的空闲断连、AndroidAsrSpeedSettings 的临时模式到期也都是单次计时，保留。
- 设备配对/扫描预算/串口连接超时、DeviceImport、上传背压、输入切换重试、语音采样均在相应任务中运行，未添加空闲常驻轮询；保留。
- CaptureService 心跳/暂停恢复/失败重试及 ExternalAudioSource 采集看门狗属于本卡明确排除的收音核心，保留。
- 数据队列的 Channel 消费和串口阻塞读取不属于固定周期唤醒；已有 WorkManager/闹钟调度未扩大或重设频率。没有改 UI 内的显示时钟。

## 每小时后台唤醒次数静态估算

这里统计的是固定 `delay` 到期后的协程执行机会，不能直接等同于硬件 CPU 从睡眠唤醒次数或电量百分比；系统可能合并、延后执行，普通协程 delay 也不会自行申请唤醒锁。

主情景：进程录音中、未打开 App/无相关 UI 订阅、无专题、导出列表为空、没有启用原声上传通道、无到期失败记录或重做快照、快捷菜单发布正常。忽略启动一次和真实数据变更，收音核心及系统 Worker 不计入这组小计。

|---|---:|---:|
| 转写方式选择 | 3,600 | 0 |
| 录音日期列表 | 120 | 0 |
| 健康兜底 | 60 | 0 |
| 导出 prune/publish | 60 | 0 |
| 专题 tick | 60 | 0 |
| 原声上传分钟校对 | 60 | 0 |

其他条件：

- 若启用原声上传，则这一项仍为 60 次/小时，以上合计变为 60；Room/通道真实变化的事件刷新另计。
- 导出已完成但尚未超过一天/未 dismiss，仍为 60 次/小时，到空列表后归零；这是有保留任务的情景。
- 有重做快照/终态历史或三天失败期限时，只在实际截止点额外执行一次；数据变化会重新规划，不按秒/分钟巡检。
- 未改的 recording-audio-sweep 原本就由 WorkManager 每 15 分钟兜底，名义约 4 次/小时，仍保留；其他原有 Worker、录音心跳/看门狗、系统广播和实际处理录音的事件另计。不能把上述 0 写成整个 App 零唤醒。
- 是否退后台就没有订阅取决于界面生命周期。没有改 UI；若 Compose 页面退后台仍持有订阅，这些展示轮询仍会运行，需 Claude/负责人按真实页面生命周期确认。

失败与修正均记录如下：

1. 首轮 app 82 项中 Redo071Test.queuedJobsAreSerialAndRestartUsesPersistedRequests 的 undo 断言失败。该测试的 engine 用固定 now=100，而 service 用真实系统时间；新的即时清理立即把合成快照视作过期。两处 service 构造改为同一 now=100，保留全部产品断言，定向复测通过。没有放宽产品保留期限。
2. 扩充同组 WebSocket 并发验证时，新增测试误用 http:// URL，请求收到 101 但 Ktor 没有按 WebSocket 转换，报 NoTransformationFoundException。测试修正为 ws:// 后通过；151 原有真实握手/协议对照始终通过。
3. 新增系统时间广播后，重做过期虚拟时间测试暴露 Robolectric 测试 Application 缺少 `DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION`。最初怀疑 Room 异步调度，统一查询调度器和等待初始化仍失败；直接检查广播首发才定位到注册异常。最终对这些受保护系统广播使用原生版本兼容注册（API 33+ 显式 NOT_EXPORTED、旧版原生注册），在 API 32 下通过。测试子协程挂到父 Job，使初始化异常直接报告；保留准确截止点断言。临时 API 33 试跑停在 MavenArtifactFetcher 下载 SDK，确认本工作区 PID 后仅终止该 Test Executor，未停止任何 Gradle daemon，回到已缓存 API 32 验证。
4. Onboarding132Test 的 fixture 增加 tips 订阅，明确模拟正在展示提示；否则测试只读 value 不再启动按需时钟。原提示内容/期限断言未改。
