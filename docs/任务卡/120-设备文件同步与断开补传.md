## 要做

1. **入口**：`DeviceSync`（内部类，名字可自定），方法 `onLinked(card: DeviceCard, link: DeviceLink, gapStart: Long?, gapEnd: Long?, clockOffsetMillis: Long?)`：设备连上时由卡 119 调用。`gapStart/gapEnd` 是手机时间（毫秒）；首次连接没有断开过时为 null。
2. **插件注册**：按 `card.filePlugin` 找 `FileSourcePlugin`；找不到就记一条问题记录，不崩溃。插件统一放 `devices/plugins/<名字>/`，核心代码里不出现品牌名。
3. **同步什么**：
   - 有断开时间段：`list()` 后只取与断开时间段重叠的文件（文件开始时间按 `clockOffsetMillis` 换算成手机时间；没有对时能力时按“文件结束时间 ≈ 修改时间”对齐），**只截重叠的那一段，前后各多留 2 秒**，转成标准音频后交给导入流程。已经实时收到的部分不重复。
   - 首次配对：不自动导入设备里的旧文件（与文件夹导入的默认一致）；提供方法“导入设备里的全部录音”给界面用。
4. **传输**：
   - 排队，一次只传一个文件；断点续传：`caps.resume=true` 时记住已收字节，断开重连后从断点接着传；否则整个文件重下。
   - 校验：`caps.checksum=true` 时比对设备给的校验值，否则比大小；不通过就重下，最多 3 次。
   - **存好才删**：文件完整存进涛声、校验通过、导入成功之后，才在 `caps.delete=true` 时调用 `delete`。任何一步失败都不删。
   - 去重：与卡 117 的指纹去重共用（同一个文件分享过、从文件夹导入过，就不再导入）。
   - 进度给 `Devices.devices` 的 `backfill`（卡 119 装配时接上；本卡提供 Flow）。
5. **记录**：传输进度和“已导入”的记录存数据库（数据库升到 31：只在 `CaptureDatabase.MIGRATIONS` 里加一条，迁移测试照 AGENTS.md 规矩写）。
6. **格式**：`FileFormat` 里的 wav / opus / ogg / mp3 / m4a / aac / pcm16 都能转成导入流程能吃的格式（看 `ImportMedia.kt` 现有能力，缺的补上）。

## 第一个插件：声云（`devices/plugins/sonicloud/`）

照公开协议写（https://github.com/SonicloudTech/sonicloud_opensdk 的 `pnote-web-win&Mac-demo/docs/协议.md` 第 6、7 节，以及同目录 Python 实现，MIT），**不用厂家的 AAR 开发包**：
- `list()`：命令 2-1，文件名被截断要补回扩展名（文档 7.1）。
- `download()`：命令 2-2，**36 字节整条一次写入**（文档 7.2），优先请求 `.wav`。文档没写能否从中间续传，按 `caps.resume=false` 处理；如果你在 Python 实现里找到了偏移参数，写进交付说明，由 Claude 决定。
- `delete()`：照文档；找不到删除命令就 `caps.delete=false`。
- 字节顺序、CRC 复用卡 118 的 `FrameCodec`（卡 118 还没合并时，先按文档自己实现一份放插件里，交付说明写明，合并时由 Claude 收拢）。

## 必测（10～15 个即可，用假插件和假 DeviceLink）

- 断开时间段内的文件只截重叠部分（含前后 2 秒），时间换算正确。
- 断点续传：传一半断开，重连后从断点继续；不支持续传时整个重下。
- 校验失败重下、3 次后放弃且**不删设备文件**。
- 导入成功才删；去重生效。
- 声云插件：用协议文档里的真实帧做列表和下载请求的组包测试。
