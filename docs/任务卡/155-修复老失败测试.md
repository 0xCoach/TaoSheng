## 要做的

对每一个失败，**先判断是谁错了**：
1. **测试过时**：产品行为后来按负责人要求改过（看 git log、对应任务卡/交付说明、CHANGELOG），测试没跟上 → 改测试，使其断言现在的正确行为。
2. **产品真有 bug**：测试描述的行为仍是正确要求，代码退化了 → 修代码，改动尽量小，并说明影响到哪些用户场景。
3. **测试环境问题**（如 AskToolsTest 少注册回调、依赖时区/当前日期/资源文件变化）→ 修测试搭建，让它稳定（固定时区、注入时间等）。

不确定属于哪种时，**不要猜着改代码**，在交付说明里写清证据，标“待负责人定”，该测试可先 `@Ignore("待定：原因")` 并注明。
