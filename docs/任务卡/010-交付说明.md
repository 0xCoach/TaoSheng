# 010 坚果云备份交付说明

## 做了什么

- 实现 `AndroidBackupRepository`，在 `ResoundApp` 装配；`AppGraph` 仅新增 `backup`、`isBackupReady`。未改界面、`MainActivity.kt`、接口签名、数据库版本及依赖版本。
- OkHttp WebDAV：Basic 认证、PROPFIND、MKCOL、PUT、MOVE、DELETE、GET。默认地址集中在 `BackupConfig`，远端目录使用 `context.appName + "备份"`；禁止自动重定向。连接测试实际写入并删除临时探测文件。
- 应用密码使用现有 `SecretStore`，由 Android Keystore AES-GCM 密钥保护；错误只返回固定中文，不回显服务端正文或密码。
- ZIP 包含数据库一致快照、声纹特征缓存、无密钥设置及 manifest（时间、App 版本、数据库版本、逐文件大小与 SHA-256）。现代 SQLite 使用 `VACUUM INTO`；Android 10 的旧 SQLite 使用独立连接事务内的逻辑快照，不复制正在写入的数据库文件。
- 设置文件采用白名单：`capture.xml`、`digest.xml`。**现有 `transcribe.xml` 同时存放加密 API 密钥，因此整文件排除**；所有其他未知设置、密钥容器、录音音频均不备份。数据库与 ZIP 不额外加密。
- WorkManager 每 24 小时一次，首次尽量安排当地时间 03:10，要求充电、不计流量网络、设备空闲；手动备份只要求联网。唯一任务防重复排队，进程级 Mutex 串行执行备份、连接测试和恢复。
- 手动任务显式配置指数退避；周期任务使用 WorkManager 默认指数退避，避免 `requiresDeviceIdle` 与显式 backoff 配置冲突。账号错误、空间不足等需人工处理的错误保留中文状态；网络和临时服务错误重试。
- 先上传唯一 `.part`，MOVE 成功发布后才清理旧备份，仅保留本应用目录下最近 7 份正式 ZIP。失败不清理旧正式文件。名称为 `回响-yyyy-MM-dd-HHmm-ssSSS-随机8位.zip`，补充秒、毫秒与随机后缀，避免一分钟内重复备份覆盖且保持时间排序；兼容识别任务卡中的分钟格式。
- 内部 `restoreLatest()`：下载最新正式 ZIP，验证路径白名单、文件集合、大小、SHA-256、数据库版本和 SQLite 完整性；校验失败不关库、不替换。校验通过后保存待恢复目录、关库并请求进程重启；新进程在业务仓库初始化前替换文件。逐文件 AtomicFile 写入，完整提交前保留恢复标记，启动中断可重放；提交标记原子移走后才清理。保留本机密钥。

## 手动触发内部恢复

本卡没有恢复 UI，也没有导出的广播或调试后门。负责人后续用调试构建，在同一 `app` 模块临时调用以下代码（先通过 `saveCredentials()` 配置账号和第三方应用密码）：

```kotlin
app.scope.launch(kotlinx.coroutines.Dispatchers.IO) {
    (AppGraph.backup as app.resound.backup.AndroidBackupRepository)
        .restoreLatest()
}
```

其中 `app` 为当前 `ResoundApp` 实例。`restoreLatest` 是 `internal suspend`，成功后会结束当前进程；失败返回 `Result.failure`，状态里有中文错误。首次恢复到新安装必须重新填写转写、大模型及备份密钥。测试只用回调验证重启顺序，不执行真实进程终止。

## 真机需要注意什么

以下留给负责人后续验证，本次未执行：

- 小米 14 Pro 上的 Keystore 保存/清除、重启后账号状态与真实坚果云第三方应用密码认证。
- 中文目录、真实服务的 MOVE 支持、断网重试、空间不足、连续上传超过 7 份后的保留结果。
- 澎湃 OS 后台限制下充电、网络、空闲约束与调度；WorkManager 不保证精确在凌晨 03:10 执行。
- 在可丢弃测试数据上验证恢复和进程重启。AlarmManager 请求的启动可能被系统后台限制延迟；若未自动打开，手动启动 App 会提交已校验的待恢复数据。
- 不备份音频，恢复后旧录音文件不可播放，尚未完成转写的历史录音也无法补转写。声纹缓存可重建，但不能恢复原音频。

## 遗留与边界

- 未接真实账号、未做真机或大体量性能验收；本卡恢复只接受与当前数据库相同版本，跨版本恢复需另做迁移设计。
- 转写间隔及 Wi-Fi 设置因与密钥共文件，本卡不备份/恢复；若需保留，应后续将密钥拆至独立安全容器。
- 声纹缓存、设置与数据库不构成跨文件事务；数据库本身保证一致快照，缓存作为可重建数据处理。旧 SQLite 的兼容快照期间会暂时阻塞写库。
- 进程突然被杀可能留下远端 `.part`；它们不计入 7 份正式备份，也不会被当作恢复候选。本卡不删除不属于本次上传的临时文件。
- 解压总量上限为 2 GiB，manifest 上限为 4 MiB；更大的备份需要另行扩展。SHA-256 用于完整性校验，不是带密钥的真实性认证。
- 界面由 Claude 后续通过既有 `BackupRepository` 契约接入；无本卡待修改的接口签名。
