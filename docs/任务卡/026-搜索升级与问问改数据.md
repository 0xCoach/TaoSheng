# 任务卡 026：问问搜索升级（全文索引 + 本地语义向量）与改数据确认卡片（后端）

## 背景与已定方案（负责人已拍板）

说明书 4.5：搜索 = 关键词（全文索引 + 中文分词）+ 语义（向量）；增、改操作先出确认卡片；断网时关键词搜索照常可用。现在问问的查询工具只用 `LIKE`，意思相近但字面不同的找不到。界面由 Claude 做，**本卡不改 `ui/` 下的文件**。

**向量用手机本地模型**（不花钱、断网可用）：`bge-small-zh-v1.5` 的 ONNX int8 版（约 25MB），用项目里已有的 onnxruntime 运行。下载方式复用 `transcribe/local/LocalModels` 的那套（SHA 校验、断点续传、一次校验后记标记）；**不要求 WiFi**（负责人已定）。模型没下好时，语义搜索静默跳过，只用关键词。向量环节做成接口 `Embedder`，以后能换云端。

## 约定（Claude 已写，签名不要改）

- `ask/AskContract.kt`：`AskMessage.action: AskAction?`、`AskAction`、`AskActionState`；`AskRepository.confirmAction(messageId)`、`cancelAction(messageId)`、`askAbout(source, question)`（接口里有默认实现，请在真实仓库覆盖）。

## 要做的

1. **数据库 10 → 11**
   - 全文索引：建 FTS4 虚拟表（`transcript_lines` 的 text；`memory_events` 的 title、summary、points；`memory_items` 的 content），中文用**二字切分**（写入时把中文按相邻两字切成词、空格分隔，英文数字按词）；查询词同样切分后用 MATCH。用触发器或在写入点同步维护；迁移时把已有数据全部灌进去。
   - 向量表：`embeddings(kind TEXT, refId INTEGER, model TEXT, dim INTEGER, vector BLOB, updatedAt INTEGER, PRIMARY KEY(kind, refId))`，只给**事件和条目**算向量（原话太多，靠全文索引）。
   - 写 Migration 10→11，跑一次 1→11 整链测试，导出 schemas/11.json。
2. **向量计算**：WorkManager 后台任务，在整理完成后、充电或电量 > 30% 时，把还没算的事件 / 条目分批算掉（每批 ≤ 64 条）；第一次装好模型后补算全部历史。事件文本 = 标题 + 摘要 + 要点；条目 = 类别 + 内容。向量归一化后存 float32。
3. **问问检索改为混合**：`search_lines` 用全文索引（保留时间、说话人过滤）；`search_events` / `list_items` 有关键词时，全文索引结果与向量相似度结果合并（各取前 20，按排名倒数加权合并，取前 10）。新增工具 `semantic_search(query, from?, to?)` 只走向量，在 `assets/prompts/ask-tools.json` 里登记并改 `ask.md` 说明何时用。比对在内存里暴力算余弦即可（几千条以内）。
4. **改数据确认卡片**：新增工具 `propose_change`，支持四种：条目改状态（完成 / 接受 / 忽略）、新建待办或备忘（内容、截止时间可选）、改条目截止时间、事件标重要/取消。模型调用后**不直接改**，在该条回答消息上挂 `AskAction(summary, detail, Pending)`，持久化到消息表（加字段或放进 sourcesJson 旁的新列，随 10→11 迁移）。`confirmAction` 执行改动并置 Done（失败置 Failed，文案给人看）；`cancelAction` 置 Cancelled。一条回答最多挂 1 个改动。
5. **`askAbout`**：新开会话，把这件事 / 条目的标题、摘要、原话（≤ 40 句）作为上下文附在第一轮，再问 question。
6. 只把相关的几条内容发到云端（沿用现有做法），不上传整库。

## 测试（适度，共不超过 10 个）

二字切分；Migration 10→11 与 1→11；全文检索能命中中文词；混合合并排序；模型未就绪时退回关键词；`propose_change` 不直接改库、`confirmAction` 生效、`cancelAction` 不生效；`askAbout` 带上下文。`./gradlew assembleDebug` 通过。**不要跑全量测试，不要反复重跑。**

允许用 DeepSeek 做**最多 3 次**真实问答验证（密钥在 `~/.config/resound/deepseek.key`，只能由脚本读取，不得输出），只发相关几条测试数据。
