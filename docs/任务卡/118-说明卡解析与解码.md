## 要做（全部放在 `devices/core/` 下，名字可自定，下面是建议）

1. **`CardParser`**：JSON → `DeviceCard`，实现 `DeviceCards.parse` 的解析部分。
   - JSON 写法按字段表（小驼峰、枚举小写，如 `"status":"trial"`、`"codec":"opus20"`、`"endian":"le"`）。
   - 字节写法：`"hex:AA55"`；`CardCommand` 可写 `"hex:…"` 或 `{"type":1,"cmd":0,"payload":"hex:…"}`。
   - **严格校验**：未知字段、未知枚举值、UUID 不合法、`role=crc` 缺 `crc`、`LengthFrom` 指向不存在的字段、`minApp` 格式不对、`keepAliveSec>0` 却没有命令、`offline=files` 却没有 `filePlugin` 等，一律失败，并写明哪一项、为什么（中文）。
   - `minApp` 高于当前 App 版本时失败，说明“需要涛声 X 以上”。
2. **`FrameCodec`**：按 `FrameSpec` 拆收到的包、装要发的命令。
   - 拆：按字段顺序读；`const` 对不上丢弃；`crc` 按 `over` 列出的字段原始字节算，对不上丢弃；`LengthFrom` 取声音长度；返回 `(字段值表, 声音字节)`。
   - `Endian.Probe`：提供“用一个应答包试两种顺序、哪种校验对就锁定哪种”的方法；锁定前收到的包先丢弃。
   - 分片：`FragmentSpec` 按分片序号拼回整帧；序号跳号（丢包）时丢弃这一帧，不拼错。
   - 序号：记录 `Seq` 字段，丢包时给出“丢了几个包”的计数（卡 119 用来写诊断）。
   - 装：`CardCommand.Raw` 原样；`Framed` 按同一套字段补上开头标记、自增序号、长度、校验。
   - CRC：crc16-xmodem、crc16-modbus、crc32 三种，各用公开的标准测试值核对（如 "123456789"）。
3. **`AudioDecoder`**：声音字节 → 标准帧。
   - `pcm16`（小端）、`pcm8`（无符号）、`mulaw` 自己解；`opus10/opus20` 用安卓 `MediaCodec` 的 Opus 解码器（这一个允许碰安卓接口，单独一个类，电脑单测里用假实现替换）。
   - `OpusPacking.LengthPrefixed`：一包多帧、每帧前 1 字节长度。
   - 采样率不是 16 kHz、或是双声道时，转成 16 kHz 单声道（可复用 `audio/PcmInputConverter` 的做法），输出切成 480 采样一帧。
4. **校验工具**：`CardParser` 之外，给 Claude 审卡用的一个函数：把一张卡的要点（认设备的规则、通道、命令字节、包外壳）整理成一段中文说明。
