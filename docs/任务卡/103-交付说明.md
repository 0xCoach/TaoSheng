# 103：模型自动切换备用——交付说明

## 实现范围

按更新后的任务卡实现，不做数据库迁移。用量继续按日期＋用途累计，不增加模型维度；PendingDigest 表和数据库版本保持原样。八类业务请求共用 `digest/LlmFailover.kt`，试连、查余额、拉模型列表仍直接调用原客户端。

## 给 Claude 的接口

- `AndroidDigestSettings.failoverEnabled: StateFlow<Boolean>`：默认 true；`setFailoverEnabled(Boolean)` 同步持久保存。
- `AppGraph.llmFailover` 提供界面直接访问切换状态的入口，无需修改原 DigestSettings Contract。
- `AndroidDigestSettings.failover.latestSwitch: StateFlow<LlmSwitch?>`：最近一次成功切换；字段为 `at`（毫秒）、`feature`、`originalModel`、`actualModel`（服务商名＋模型名）、`reason`（安全中文类别）。只放内存，不含原话、提示词、密钥或服务端错误正文。
- `LlmProviders.move(id, toIndex)`：任务卡明确授权增加的 Contract 方法；目标下标限制在有效范围，保存后更新 saved，不改变 activeId。
- `LlmFailover.chat(...)` 返回 `LlmReply`，新增可空 `actualModel`，不改现有构造调用。`request(feature, dao, purpose, call)` 为原有注入式仓库生成统一请求函数。
- 流式问答使用 `StreamSession`；一轮内各工具请求和出处修复共用“是否已经输出正文”标志。已输出后任何后续失败均不换模型。
- 界面仍需 Claude 增加设置开关、拖动排序和最近切换提示；本次未改 ui/ 或 MainActivity。

## 候选与错误处理

主模型使用调用入口固定的 preset（技能优先指定 presetId），其他候选取 saved 顺序，只选有密钥或允许空密钥的服务商。每次最多尝试三个模型。冷却候选后置，配置或密钥修改、手动试连成功立即解除对应冷却；旧在途请求不能把修改后的配置重新放进冷却。

| 错误 | 行为 | 冷却 |
| --- | --- | --- |
| Network、5xx、408、其他 4xx | 切换 | 5 分钟 |
| 429 / RateLimit | “请求太频繁，请稍后再试”，切换 | 5 分钟 |
| 401 / 403 / Auth | 切换 | 30 分钟 |
| 402 / Quota | “大模型余额不足或额度已用完”，切换 | 30 分钟 |
| LlmInputLimitException | 只试输入容量更大的候选 | 不冷却 |
| Format | 不切，保留调用方格式重试和放弃逻辑 | 不冷却 |
| CancellationException | 原样抛出 | 不冷却 |

全部失败保留主模型错误类别、HTTP 状态和安全文案，附“备用模型也没成功”。关闭开关后只请求原模型，不使用冷却排序。

## 缓存键、inflight 与用量

新键为 `batch-v2:` 加原话批次序列化后的 SHA-256，不包含 preset。主模型失败和备用成功共用一个 batch ID 和 inflight 标记。收到成功响应仍先调用 `rememberDigest()`：pending 插入和成功用量同一事务，重放只做本地提交，不再请求或累计用量。

旧键兼容：以当前主模型及已保存服务商的 preset 验证旧散列，匹配后直接重放旧记录，沿用旧 ID，不通过重新插入“迁移”记录，避免重复计费。来源已删除或新键内容不符时失效；若旧模型配置已消失、无法验证旧键，则保留缓存并暂停，提示恢复原配置，不静默删缓存后重发。

有 pending 的 inflight 只恢复本地提交；没有 pending 的 inflight 保留原保守行为，自动任务暂停，用户手动整理才能重试。`thingRevision` 仍随原 pending 响应保存、恢复，未改变寻物开关代次校验。

实际模型仅在本进程内按 batch ID 暂存，正常完成及同一 Runner 的本地保存重试使用实际模型。**进程退出或 Runner 重建后恢复缓存时，模型快照不可得，事件使用当前主模型名**，这是更新后任务卡接受的限制，不影响内容、去重和用量。

失败 HTTP 响应中的 usage 由切换层在不可取消上下文累计，格式错误响应有 usage 也记录；成功用量仍由各调用方原逻辑记录。流式回复每个实际尝试单独结算已收到的 usage，取消也保留。用量表仍是日期＋用途，没有服务商或模型字段。

开关位于 `digest` 偏好，排序保存在 `llm-providers.saved` 数组；现有 BackupSettings 已捕获和恢复这两组设置，不需新增备份格式。
