## 负责人已定（10-30）
- 四类：会议、培训、通话 / 访谈、普通。导入时每次都问，**预选**：有线索按线索（小米通话录音文件夹 `MIUI/sound_recorder/call_rec` 或文件名含“通话”/电话号码 → 通话；左右声道内容明显不同的双声道 → 通话），否则用上一次选的，都没有默认会议。
- 一个文件只按一种类型处理，不在文件内再分段判断类型；纪要可写“讨论集中在前 40 分钟”。
- 事后能改类型，改后重新生成纪要。

## 各类型处理
| 类型 | 区分说话人 | 纪要 |
|---|---|---|
| 会议 | 照常（不限人数） | 会议纪要：议题、结论先行、分点要点、决定、行动项（谁做什么）、参与的人、关键原话 |
| 培训 | 不区分（这些段 `separateSpeakers=false`，同 073 课堂模式路径） | 培训笔记：主题、要点、知识点、练习/作业、讲师强调的话 |
| 通话 / 访谈 | 限定 2 人：本地分人聚类人数固定为 2；豆包查官方文档是否支持指定人数，支持就传，不支持照常并在客户端把多于 2 个的编号按声纹相似度合并到 2 个（做不到就照常，写明）。**双声道**：两声道分别转写（各自不分人），左/右各为一人，按时间合并；声纹认出“我”的那一侧标“我”，另一侧“对方” | 通话记录：谈了什么、对方说的要点、约定的事、我要做的、对方要做的 |
| 普通 | 照常 | 不生成纪要，照常拆事件 |

- 会议/培训/通话：**照常**也拆成事件和待办（待办仍进待确认），另外**一定生成一份纪要**（不走技能自己判断“是不是会议”）。纪要存为技能卡（新建三个内置隐藏技能模板 `import_meeting`/`import_training`/`import_call`，复用 `assets/skills/meeting` 的字段格式；不出现在技能列表、不定时触发）。
- 行动项里属于“我”的照常进待确认待办，不重复：与整理出的同一待办合并（沿用现有合并逻辑）。
- **长录音**：按约 25 分钟分块各出小结，最后合成一份总纪要；块边界不丢结论和行动项。上下文与费用写进交付说明（每小时录音大约多少 token）。
- 纪要生成时机：该文件所有段转写（及分人/认人）完成后自动生成；失败可 `regenerate`。状态变化反映在 `ImportRecord.status`。

## 追加（负责人 10-30）：同一批导入的合成一条，连续播放
- 一个文件切出的多个段本来就属于同一条 `ImportRecord`；时间线不再按段零散显示（界面只显示一张导入卡，Claude 做）。
- **一次选了多个文件**（如录音机把一场会自动拆成几个文件）：前后首尾相接（后一个开始时间 − 前一个结束时间 ≤ 5 分钟，按文件录制时间排序）的合成**同一条记录**，类型一个、纪要一份；不相接的各自一条。确认面板会显示“这 3 个文件将合成一条”，用户可关掉（`start` 增加批次参数前请先在交付说明提出约定修改方案；建议：`ImportKinds.startBatch(pendingIds: List<String>, startAts: List<Long>, asr, kind, merge: Boolean)`，可直接加到约定里，Claude 已同意这个签名）。
- 合成一条后，段的时间轴按文件顺序首尾接上（用各文件录制时间；读不到时按选择顺序紧接前一个结束）。
