# 任务卡 028：导入录音文件 + 热词（后端）

## 背景与已定方案（负责人已拍板）

说明书 4.1：导入录音文件（m4a / mp3 / wav 等），可改开始时间，排进当天时间线。4.2：热词——我的称呼、常见人名与专有名词。界面由 Claude 做，**本卡不改 `ui/` 下的文件**。

## 约定（Claude 已写，签名不要改）

- `importer/ImportContract.kt`：`ImportInfo`、`PendingImport`、`ImportProgress`、`AudioImporter`（`receive`、`pending`、`start`、`discard`、`progress`）。
- `transcribe/HotwordContract.kt`：`HotwordSettings`（`words`、`setWords`、`automatic`）。
- `AppGraph`：已加 `importer` / `isImporterReady`、`hotwords` / `isHotwordsReady`，在 `ResoundApp` 里赋值。

## 要做的

### 一、导入录音（**负责人补充：最常见的是在录音机 App 里“分享 → 回响”，回响本身不保存录音**）

1. **接收分享**：Manifest 给 `MainActivity` 加 intent-filter：`ACTION_SEND` 与 `ACTION_SEND_MULTIPLE`，`audio/*`；另加 `ACTION_VIEW` `audio/*`（“用其他应用打开”）。MainActivity 收到后在 `lifecycleScope` 里调 `AppGraph.importer.receive(uris)`，并处理 `onNewIntent`。**不要做界面**：界面由 Claude 根据 `importer.pending` 弹确认面板；receive 失败的，用一个 Toast 给出原因即可。
2. **`receive`**：立刻把每个文件**流式复制**到 `cacheDir/import/<id>`（分享来的读权限是临时的，不能等到后台任务再读）；复制后读信息：时长（`MediaExtractor`），`suggestedStartAt` 依次取文件元数据录制时间（`MediaMetadataRetriever.METADATA_KEY_DATE`）→ 来源给的最后修改时间 − 时长 → null；显示名取 `OpenableColumns.DISPLAY_NAME`。读不出音轨的删掉副本并返回失败（“这个文件里没找到声音” / “暂不支持这种格式”）。`pending` 持久化到 SharedPreferences（App 被杀后再打开仍能看到待确认的）。
3. **`start(id, startAt)`**：进 WorkManager 串行队列（前台任务通知“正在导入 xxx”，通知里可取消）；多个文件依次处理，`progress.queued` 给出排队数。
   - 解码：`MediaExtractor` + `MediaCodec` 流式解成 PCM，重采样到 16k 单声道（多声道取平均，线性插值即可），不要整段读进内存。
   - 切段：**复用现有 `SpeechSegmenter` 与 VAD**（同一套参数、5 分钟硬切与 1 秒重叠），片段 `startAt = startAt参数 + 文件内偏移`。
   - 入库：每段按现有方式编码保存，`sourceId = "import"`，状态 Pending，进入正常转写队列（外放检测不适用，`playbackMillis = 0`）。导入完成后**立即删除缓存副本**。
   - 导入完成后立刻触发一次转写（`runNow`），不等定时。
   - 进度：按已解码时长 / 总时长更新 `percent`；失败给人看的原因，不含路径。
4. **不保存录音**：`sourceId = "import"` 的片段**转写成功（或确认没有文字）后立即删除音频文件**，不走“保留 1 天”的规则；转写失败的保留到重试成功，最长 3 天后也删除。外放过滤、声纹补样本照常可用（在删除前完成；声纹只存特征值）。
5. `discard(id)`：删缓存副本、移出 pending。
6. 时间与已有录音重叠时照样入库（时间线会并排），不去重。

### 二、热词

1. **存储**：SharedPreferences `transcribe` 的 `hotwords`（JSON 数组，最多 200 个，每个 1–20 字，去重）；加进备份白名单（这个文件已在白名单里则无需改）。
2. **`automatic`**：声纹人物的名字（排除“我”）+ 设置里的称呼（如果没有称呼字段就只用人物名）。人物改名、增删后自动更新。
3. **送进转写**：
   - 豆包流式 2.0：按豆包语音文档在请求里带上热词（`request.corpus` 的热词 / context 字段，以官方文档为准，写进交付说明并附链接）。手动词 + 自动词合并，超出接口上限时手动词优先。
   - 自定义（OpenAI 兼容）：把热词拼进 `prompt` 参数（“可能出现的词：A、B、C”），总长不超过 200 字。
   - 本地 SenseVoice 不支持热词：**不做**，交付说明写明。
4. **送进整理**：`digest.md` 的输入里加一段“常见人名与专有名词：…”，让大模型在整理时纠正同音错字（只纠正这些词，不改别的原话）。

## 测试（适度，共不超过 9 个）

`receive` 复制并推算开始时间、坏文件返回失败；重采样（48k 立体声 → 16k 单声道长度正确）；导入切段的时间偏移正确；多文件排队；导入片段转写成功后音频立即删除；热词去重与上限；豆包请求里带上热词；自定义服务 prompt 拼接与截断；整理输入带上热词。可用代码生成一小段带人声的 wav 做测试，不要放大文件进仓库。`./gradlew assembleDebug` 通过。**不要跑全量测试，不要反复重跑。**
