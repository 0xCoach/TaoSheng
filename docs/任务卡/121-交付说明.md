# 卡 121 交付说明

## 实现

- `RemoteDeviceCards` 实现 `DeviceCards`，由 `AppGraph.deviceCards` 暴露，主进程启动装配。按包内、已验签缓存、新远程表合并，同 id 只接受更大的卡版本。
- Ed25519 验原始文件字节，`.sig` 是 64 字节二进制，不是 Base64。使用 Bouncy Castle 1.81 的轻量验签 API，兼容 minSdk 29，不依赖手机系统是否提供 Ed25519 Provider。构建增加该依赖和一个重复 OSGi 元数据排除项，未改版本号。
- 验签、整表解析、重复 id、表版本检查通过后才原子写缓存并发布状态。表版本倒退拒绝；相同版本只接受相同内容。仍提供最高卡版本的历史签名表继续保存，防止新表遗漏卡、单卡降级后重启丢失旧卡。
- 表上限 256 KiB、200 张卡；保留表总量上限 4 MiB，超过则拒绝新表并保留旧状态。缓存重启重新验签，放 `noBackupFilesDir`，不被备份恢复覆盖。
- verified 默认开、trial 默认关；用户明确设置的开关持久保存，更新或重启后保留（含用户明确关闭 verified）。不兼容 `minApp` 的卡不加载。
- WorkManager 在启动和每天调度，约束联网；持久化最近尝试时间，24 小时内最多一次，失败也计入。失败不弹提示、不立即重试，问题类别通过现有 `UpdateDiagnostics` 进入导出问题记录，不写响应内容或密钥。
- `UpdateRemote.deviceCards` 复用更新检查客户端、超时、限长方式；GitHub 失败或表验证失败后尝试魔搭，表与签名必须取自同一来源。

## 签名初始化和发布

首次执行（本机已安装 `cryptography`；其他机器先在 Python 虚拟环境安装）：

```sh
python3 scripts/sign_device_cards.py device-cards.json \
  --public-key-out app/src/main/assets/device-cards-public-key.hex
```

- 默认私钥 `~/.config/taosheng/cards-signing.key`，不存在则排他生成 PEM/PKCS8 Ed25519 私钥，权限 600。拒绝符号链接、非 600 权限和非 Ed25519 私钥，不覆盖已有私钥。
- **生成后立即离线备份私钥**。私钥不进仓库、不上传镜像。公钥可以提交；旧公钥不同则脚本拒绝自动覆盖，换钥需通过 App 更新协调。
- 后续编辑 JSON，递增整表 `version`；修改某张卡时也递增该卡 `version`。新增卡默认写 `status: trial`，仅官方确认后改 verified。然后运行 `python3 scripts/sign_device_cards.py device-cards.json`。
- 签名后不可再格式化 JSON、改换行或加 BOM。同步发布 JSON 和 `.sig` 两个文件，短暂不同步时 App 会拒绝并保留旧表。仓库初始表为空，不伪造卡 118 的默认卡。
- 发布位置（本次未推送、未上传）：
  - GitHub：`0xCoach/TaoSheng` 仓库 `main` 根目录，读取 `https://raw.githubusercontent.com/0xCoach/TaoSheng/main/device-cards.json` 及其 `.sig`。
  - 魔搭：沿用 `UpdateSources.MODELSCOPE` 对应的 `OpenRecode/TaoSheng-releases` 模型仓库 `master` 根目录，读取 `https://modelscope.cn/models/OpenRecode/TaoSheng-releases/resolve/master/device-cards.json` 及其 `.sig`。
- 首次公钥必须随 APK 打包后远程表才能生效；公钥缺失或无效时记录 `official_key_missing`，拒绝所有远程表，仍可用包内卡。

## FoloToy 依据与限制

2026-11-09 核查：

- [官方 FAQ](https://docs.folotoy.com/docs/faq/) 写明实时录音通过 UDP 上传，默认端口 8085；MQTT 负责设备与服务器通信。此处不能推导 BLE 传音格式。
- [官方固件 25.6.4.49 发布说明](https://github.com/FoloToy/folotoy-bin/releases/tag/25.6.4.49) 明确部分中国版产品使用蓝牙配网；Octopus 开发板另有固件型号。蓝牙配网不等于开放 BLE 实时声音通道。
- [MagicBox 官方开源 BSP](https://github.com/FoloToy/MagicBox/blob/main/README.md) 提供硬件驱动和示例，说明网络、服务协议由应用负责。
- [AI Passport 官方开源仓库](https://github.com/FoloToy/ai-passport) 是另一类硬件和固件基线，不能直接套到负责人手上的未知型号开发卡。

未找到能确证适用于该开发卡的 BLE 音频服务/notify/write UUID、开始停止命令、编码与采样率、包头和分片协议。因此 `assets/devices/folotoy.json` 标 trial，`audio` 留空，`match` 为空；这是待补全的说明卡，不会匹配任意设备，手动打开也不提供实时收音。不捏造广播名、UUID 或借用 Wi-Fi 协议。

负责人需确认：PCB 型号和固件版本；用 nRF Connect 等查看实际广播名、广播服务及完整 GATT 服务/特征 UUID、read/write/notify 属性；向厂商取得音频协议或对应固件源码。未明确命令含义前不盲写特征。补全后在小米 14 Pro 检查开始/停止、编码、丢包/分片、持续收音和重连，再决定改 verified。
