# 126 足迹（全天定位）交付说明

## 做了什么

- **全天定位记录**（`location/Location.kt`）：跟着收音前台服务走。足迹打开且有定位权限时，前台服务类型为“麦克风＋定位”；否则只用麦克风，收音不受影响。用系统 `LocationManager`（优先 fused，否则网络＋GPS），不依赖谷歌服务；约每 5 分钟一个点，精度差于 200 米丢弃，双来源重复点去重。数据只存手机本地。
- **立刻定位**：给完权限、打开开关、从系统设置回来或收音服务启动时，马上要一次位置（先用 2 分钟内缓存，再向系统要最新的，30 秒内不重复）。系统“位置信息”总开关关着时页面提示并可跳转。
- **地名**（`location/Places.kt`）：停留和“最后位置”显示地名＋地址。填了高德 Web 服务 Key 用高德（先转高德坐标），没填用系统地理编码；按约 100 米格子缓存在 `location_places`。Key 加密保存不回显；可关“显示地名”，关后完全不查。
- **一天时间轴**（`location/DayTimeline.kt`）：默认 0–24 点横条，按地点分段上色，路上斜纹，没记录灰色；点一段看时间、地点、时长；下面列各地点累计时长。夜里（0–6、22–24 点）待得最久且满 1 小时处认作“家”。原连线图保留在“路线”标签。
- **手动改地点**：点“最后位置”或任一停留，可改名称、地址、标“这里是家”或恢复自动；方圆 150 米内生效，换 Key、清缓存都保留。
- **推送每日足迹**（`push/FootprintPushWork.kt`、`location/FootprintReport.kt`）：推送通道订阅加“每日足迹”（默认关，默认 22:00），所有通道可选。内容含在家/外出时长、移动距离、各停留时间与地名、长时间没记录的时段；Webhook JSON 另附 `footprint`（停留、时间轴分段、全部定位点）。每个通道每天一次，失败走原重试队列；“现在推一次”顺带推今天；当天无定位点不推。
- **界面**：设置 → 足迹（`ui/location/LocationPage.kt`）；推送通道页加每日足迹订阅。
- **数据库 29→30**（`MIGRATION_29_30`）：新建 `location_points`、`location_places`（含手动名坐标与“家”），schema 已导出 `30.json`。

## 怎么验证的

- `./gradlew assembleDebug` 通过。
- 单测 12 例全部通过：`LocationTrackTest` 4 例（停留切分、飘点过滤、双来源去重、29→30 升级后读写）、`PlaceResolverTest` 4 例（高德解析、坐标换算、缓存、手动名与家）、`DayTimelineTest` 1 例、`FootprintPushTest` 3 例（订阅存取、正文与 JSON、到点只推一次）。
- 功能已在小米真机上实际使用（开发分支版本），系统地理服务不填高德 Key 也能给出地名。

## 真机需要注意

- 系统先问“使用时允许”；要在重启或后台拉起收音后继续记录，需改成“始终允许”（页面有“去授权”）。只给“使用时允许”时后台拉起会退回只录音，不崩，但不记位置。
- 澎湃 OS 省电策略可能拉长定位间隔，正常约 280 点/天。收音停掉时足迹也停。
- 查地名会把停留坐标发给高德或系统地理服务；位置记录本身只在本机。国行手机系统地理编码可能不可用，页面会提示填高德 Key（选“Web 服务”类型）。
