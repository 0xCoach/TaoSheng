# 卡 052 · 预览版通道 + 问题记录（后端）

App 名叫“涛声”（包名仍是 `app.resound`）。给用户看的文字一律写“涛声”。
约定文件（签名不要改；确需改，在交付说明里提）：
- `app/src/main/java/app/resound/update/UpdateContract.kt`（本卡新增 `previewChannel` / `setPreviewChannel` / `isPreviewBuild`、`UpdateInfo.preview`）
- `app/src/main/java/app/resound/diagnostics/ProblemReportContract.kt`（新文件）

界面（关于页连点版本号 7 下露出开关、“预览版”小字、导出按钮、今天页闪退提示）由 Claude 做，**本卡不改 `ui/` 和 `MainActivity.kt`**。

## 一、已定方案（负责人已确认，不要改）

- 同一个 App、同一个包名、同一套签名，多一条“预览版通道”。不做第二个 App。
- 预览版的版本名：`<下一个正式版号>-preview.<序号>`，如 `0.2.12-preview.1`。和正式版**共用一条递增的 versionCode**（0.2.12 的几个预览包占 27、28、29，正式版 0.2.12 用 30）。
- 预览通道开着时：**正式版、预览版都查，取 versionCode 大的**。关着时：只查正式版（和现在一样）。
- 关掉开关不降级：等下一个 versionCode 更大的正式版自然覆盖。
- 预览通道开着时：**每次打开 App 查一次（不做 1 小时节流）+ 后台每 1 小时查一次**；关着时保持每 6 小时 + 启动时 1 小时节流。“自动检查更新”关掉时两种都不自动查（和现在一样）。
- 预览版两处都放：魔搭 + GitHub 预发布。GitHub 的 `releases/latest` 本来就跳过预发布，正式用户不受影响。
- 问题记录：只本机生成文件，交给系统分享；App 自己不往外传。**不含原话、待办内容、人名、地点、任何密钥**。

## 二、发布到哪

正式版保持不变（`update.json`）。预览版的版本说明文件名固定 `update-preview.json`，格式和 `update.json` 完全一样：

- 魔搭：放在同一个仓库 `OpenRecode/TaoSheng-releases` 的 `preview/` 目录下：`.../resolve/master/preview/update-preview.json`，安装包、差异包也放 `preview/`。
- GitHub：每个预览版建一个预发布，标签 `v0.2.12-preview.1`，安装包、差异包放在它下面；另有一个固定的预发布，标签 `preview-channel`，只放 `update-preview.json`（每次发布覆盖）。手机读 `https://github.com/0xCoach/TaoSheng/releases/download/preview-channel/update-preview.json`。
- 地址全部写在 `UpdateSources` 里，和正式版的放一起。

解析放宽：`versionName` 允许 `数字(.数字)+` 后面接 `-preview.数字`；`UpdateInfo.preview` 由版本名是否带 `-preview.` 决定。正式通道读到带 `-preview.` 的版本名一律当作这个来源失败（防止发错文件）。

## 三、实现要点

1. **通道开关**：`previewChannel` 存本地偏好，默认关。`isPreviewBuild` 看当前 `versionName`。切换后立刻重排后台检查周期（1 小时 / 6 小时），并在开着时马上查一次。
2. **查新版本**：预览通道开着时，两个文件（`update.json`、`update-preview.json`）各按“先魔搭后 GitHub”去查，各自超时 15 秒；两个里取 versionCode 大且比当前大的。一个文件查不到不影响另一个。“跳过这个版本”“稍后”“同版本只通知一次”逻辑照旧按 versionCode。
3. **下载地址**：哪个文件查到的版本，就去它对应的目录下载（预览版去 `preview/` 和 `v<版本名>` 预发布）。差异包、拼包、签名核对、装前备份全部沿用卡 051。
4. **通知**：预览版的通知标题写“涛声 0.2.12 预览版 1 可以更新”，正文用更新说明第一行。
5. **装前备份留 3 份**：`PreUpdateBackup` 现在只留最近 1 份，改成保留最近 3 份（按时间命名的子目录，最旧的先删）。强制快照失败照旧拦安装。
6. **闪退记录**：在 `ResoundApp` 装一个未捕获异常处理器（先记再交给原来的处理器，**不要吞掉异常**）。写入 `filesDir/crash/` 下一个文件：时间、版本、线程名、异常类名和调用栈（只要类名和行号，**不要异常的 message**，message 里可能有原话或接口返回）。最多保留最近 10 条。下次启动发现有没看过的闪退，`lastCrashAt` 给出时间。
7. **问题记录 `ProblemReports.export()`**：生成一个 txt，内容依次是：
   - 版本名、versionCode、是否预览版、预览通道开关、手机型号、安卓版本、生成时间；
   - 最近 10 条闪退记录；
   - 现有“导出诊断记录”（`CaptureStatsRepository.exportDiagnostics()`）的全部内容——它本来就只有步骤和数字；
   - 更新诊断最近 50 行（卡 051 已有）。
   导出前对全文做一次兜底清洗：去掉形如 API Key 的长串（`sk-` 开头、32 位以上十六进制/Base64 串）。文件放 `cacheDir`，能用现有 FileProvider 分享（没有就在 Manifest 加一个，只开放这个目录）。
8. **装配**：`AppGraph` 增加 `problemReports` 和 `isProblemReportsReady`，由 `ResoundApp` 装配。
9. **构建预览包**：`app/build.gradle.kts` 支持 `-PpreviewNumber=1`：有这个参数时 `versionName = "<versionName>-preview.<N>"`，没有时保持原样。versionCode 仍由负责人手动在 build.gradle.kts 里改，不要自动算。
10. **发布脚本** `scripts/publish_update.py` 加 `--preview`：
    - 读安装包的版本名，必须带 `-preview.`；不带 `--preview` 时版本名**不能**带 `-preview.`。对不上直接报错退出（防止发错通道）。
    - 预览版的差异包：从“最近 5 个版本”做，范围包括正式版和预览版（`gh release list` 不排除预发布，但排除 `preview-channel`）。
    - 上传：魔搭写 `preview/` 目录、GitHub 建预发布 `v<版本名>`（`--prerelease`），最后才传 `update-preview.json`（魔搭 `preview/` + GitHub `preview-channel`）。**任何情况下预览发布都不碰正式的 `update.json`**，代码里加断言。
    - 正式版发布做差异包时，要把预览版也算进“最近 5 个版本”（负责人手机上装的通常是预览版）。
    - 只做 `--dry-run` 本地验证，**不要真上传**。

## 四、必测（适度，一共 6～10 个）

- 解析：`0.2.12-preview.1` 能解析且 `preview=true`；正式通道读到预览版本名判失败。
- 双文件取大：预览 28、正式 27 → 选 28；预览 28、正式 30 → 选 30；预览文件查不到 → 只用正式。
- 通道关掉后，不会再选预览版。
- 装前备份连做 4 次只留 3 份，最旧的被删。
- 闪退记录不含异常 message；超过 10 条删最旧的。
- 问题记录清洗掉 `sk-` 开头的长串。
- 发布脚本：`--preview` 配正式版本名报错；不带 `--preview` 配预览版本名报错（用假 apk 名或把 badging 抽成函数测）。

测试规矩见 `AGENTS.md`：只跑本卡测试，跑通一次就停，总耗时不超过 10 分钟。
