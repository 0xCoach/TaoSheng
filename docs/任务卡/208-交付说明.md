# 卡 208 睡眠时段与午睡

## 后台行为

- 旧设置在反序列化时转为两条时段。原夜里为 21:00–12:00 时启用自动，改过任一端则使用原时间；午睡默认关闭，预设 12:00–15:00。原总开关继续生效。
- 自动时段取本地今天及前 13 个醒来日期内已整理、可信度为“好”或“一般”的夜里记录，按记录当时的时区取钟点。满 7 晚后，用入睡中位数减 2 小时、起床中位数加 4 小时，取最近半点，从开始算起将长度限制为 8～18 小时。样本不足时用 20:00–次日 12:00。
- 最多 3 条自定义。保存时校验开启的时段，允许首尾相接。若日后自动计算结果移入已保存的手动时段，交叠部分优先执行手动时段。自定义按夜里规则记录，日期取时段结束当天。
- 午睡自暂定进入起算。熄屏、静止、无人声达 10 分钟后进入，再持续 10 分钟确认。确认后解锁、明确拿起或累计亮屏超过 30 秒即结束，使用证据发生时间，最晚记到时段末尾。确认前用手机会丢弃暂定记录，片段走现有隐私清理。进程重启后，暂定午睡丢弃，已确认午睡保留至最后一次成功检查点。
- 夜里和午睡共用声音识别、推理门控和写库降频。时段外关闭音频分窗。同日可各有一条夜里和午睡，已完成的同种记录挡住再次进入。多条夜里或自定义时段归属同一醒来日期时，共用该日的夜里名额。
- Room 升至 42。41→42 在原表增加 kind、windowId，旧行两列均为 night。原日期索引换为日期与种类的复合唯一索引，保留原记录 ID 及其子表引用。迁移在 CaptureDatabase.MIGRATIONS 登记一次，已导出 42.json。同步更新 index183 的版本差异白名单，历史快照、旧 schema 和既有测试断言保留。

## 给 Claude 的接口

以下均在 app.resound.night。SleepWindow 的分钟取当地钟点 0..1439，结束小于等于开始表示跨午夜。编辑时保留已有时段的 id，自定义新时段分配独立稳定的 id。

```kotlin
enum class SleepWindowKind { Night, Nap, Custom }
data class SleepWindow(
    val id: String, val kind: SleepWindowKind, val name: String,
    val enabled: Boolean, val auto: Boolean, val startMinute: Int, val endMinute: Int,
)

// NightSettings 新增的末尾参数
val windows: List<SleepWindow> = SleepWindows.legacy(windowStartMinute, windowEndMinute)

// NightRepository
val settings: StateFlow<NightSettings>
fun saveWindows(windows: List<SleepWindow>): String?
val automaticWindow: StateFlow<SleepWindow>
fun naps(date: LocalDate): Flow<List<NightSummary>>
fun nightById(id: Long): Flow<NightDetail?>
suspend fun deleteNight(nightId: Long)

// NightLive 增加末尾可选参数
data class NightLive(val state: NightState, val mode: NightMode?, val since: Long?,
    val awakeAt: Long? = null, val window: SleepWindow? = null)
```

- 设置页从 settings 读取列表，用 saveWindows 保存。返回 null 表示成功，有文字时保留编辑内容并展示原因。仅 Night 可选 auto。自动模式展示 automaticWindow 的起止，末端标为“最晚记到”；半点选择器写入整数分钟。既有 update(settings: NightSettings) 和旧字段继续兼容旧设置页。
- 首页从 live.window 取名字和种类，窗口为空表示当前没有录制会话。Nap 对应午睡，Custom 按夜里处理。午睡列表用 naps(date)，点击后按摘要 id 订阅 nightById，点“不是午睡”调用 deleteNight。
- night(date) 和 nights(from, to) 只返回夜里种类；“昨晚”、趋势、周报、医生页和推送沿用这些入口或同种类的查询。

## 本机验证

- 新增 5 个共享规则用例和 1 个 Android Room 集成用例。覆盖旧设置、夜里自动与回退、午睡确认和取消、累计亮屏、拿起、窗口收尾、白天自定义、保存冲突，以及 41 库带旧夜升级后同日午睡的读写和删除。
- 13:00 熄屏静止的样例在 13:10 进入、13:20 确认、13:42 解锁，得到 32 分钟。13:15 解锁返回取消；持续到 15:00 则由时段末尾结束。
- 定向运行卡 202 的 12 项、卡 204 的 8 项和 NightWakeTest 的 3 项；同时运行卡 200 的 18 项及数据库差异、迁移回归 8 项。
- 共 55 个不同用例通过。共享边界脚本、限定用例的 `:shared:check`、Android debug 编译均通过；最后用指定 Gradle 登记目录运行 `tools/check_ios.sh`，shared 与 devices 的 iOS 真机和模拟器目标编译通过。
