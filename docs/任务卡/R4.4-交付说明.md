# R4.4 交付说明：专题暂停=停录音停转写 + 账号入口上移

## 背景

真机反馈：专题卡片点「暂停」后波形仍在动、转写仍在跑——原语义是「只暂停归属，不停采集」，与用户（负责人）预期冲突。负责人明确：暂停应同时暂停录音与转写。同时反馈找不到账号登录入口（原 `MyAccountSection` 埋在「模型与整理」页中）。

## 改动

### 1. 专题暂停 = 录音与转写一起冻结

- `shared/capture/SceneEngine.kt`：`SceneSignals` 新增 `topicPaused`；`decide` 在隐私暂停之后判 `topicPaused → Pause(Long.MAX_VALUE, "专题暂停", Manual)`，场景记为 `Paused`，原因「专题暂停中」。
- `app/capture/AndroidScene.kt`：`signals()` 从 `AppGraph.topics.current` 采集 `topicPaused`（Running/Paused 之外的专题不产生信号）。
- `app/ResoundApp.kt`：观察 `topics.current.map{status}`，变化即 `CaptureService.recheck()`——暂停/继续/结束/到期/自动截止都会触发重新核对，无需逐调用点接线。进程重启后信号由 DB 专题状态派生，保持一致。
- 转写门：`ready`/`sourceReady` 在既有会员额度门之上加 `!topicPaused()`，专题暂停期间整轮转写冻结，恢复后继续。
- `CaptureService.pauseUntil`：看门狗日志区分「专题暂停（恢复专题后继续）」与「隐私暂停」。
- `shared/capture/KnockActionRules.kt`：`decide` 增加**带默认值参数** `topicPaused`（向后兼容，算约定签名扩展，按约定在此声明）；专题暂停时敲敲返回 `Blocked`（长振），防止再叠一层手动暂停或单独解冻录音。`KnockGestureController` 传入实际专题状态。
- 交互矩阵：隐私暂停＞专题暂停＞手动定时暂停＞停录时段；各暂停源只由自己的恢复路径解除（专题暂停只能「继续专题/结束专题」解除）。

### 2. 账号入口上移（设置首页）

- `SettingsPage` 新增 `Account("账号与会员")`；`MyAccountSection` 从「模型与整理」页挪到独立账号页。
- `SettingsHome` 顶部新增「账号」组：一行「账号与会员」，副标题显示用户名/授权状态，过期或停用亮黄点。

## 真机要测

- 专题进行中点「暂停」：波形停、分钟数冻结、转写队列不再前进、「录音与后台」行显示「专题暂停中」；点「继续专题」全部恢复；点「结束」同样解冻。
- 专题暂停中敲两下：只长振，不叠加暂停、不恢复录音。

## 遗留

- 敲敲在专题暂停时被拦是保守策略；若希望「敲敲=继续专题」，在 controller 里对 Blocked 分支加 `topics.resume()` 即可，暂未做。
