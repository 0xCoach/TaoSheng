## 已发现的查询退化，必须在实施时处理

- A 诱导近期 Done 录音放弃原 startAt 范围索引；0.094 → 3.541 ms。需保持原范围路径。
- A 诱导未整理/日记/推送/技能/专题原话从大量 Done 段开始联查；需限制连接顺序或维持原扫描路径。
- B 诱导未整理列表、语音输入全历史、按人物过滤的原话，为排序读取全部时间索引并回表；需保留先筛选后排序的表扫描。
- `digestedUntil` 只有开始时间上界，B 会扫描大部分索引再回表；不能擅自加开始时间下界而漏掉跨边界原话，应保留旧扫描。
- 大批状态更新的索引维护成本归入写入开销；不以查询收益掩盖。

上述是实测发现，尚未宣称“无查询退化”。所有候选在现有审计样本中返回行摘要一致；修改后还要经过真实 DAO、旧夹具及针对性反例。
