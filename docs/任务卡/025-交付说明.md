# 025 推送通道交付说明

分支：`codex/025-push`。日期：2026-10-24。

## 完成内容

- 实现 `AndroidPushChannels`：通道增删改、启停、配置 Flow、测试发送和最近 100 条日志。配置与日志写入 SharedPreferences `push`，无数据库变更。
- 密钥复用现有 `SecretStore` 的 Android Keystore / AES-GCM，密文单独存于 `push-secrets`，配置中仅存随机引用。编辑时密钥留空保留旧值；更换类型或删除通道清理旧密钥。摘要只显示“已设置 / 未填写”。
- 实现 PushPlus、企业微信机器人、Server酱 Turbo、HTTPS Webhook。请求不跟随跳转、不自动重发，整个调用超时 10 秒；平台响应最多消费 64 KiB，达到上限拒绝；Webhook 只判断 HTTP 2xx，不读取响应正文。按任务卡的业务返回码判断其他三种通道是否成功，不保存服务端错误原文、完整地址或底层异常。
- `ChannelNotifier` 先发本地通知，再并行转发给启用且 topic 匹配的通道。某一路失败不影响其他通道；本地权限失败仍尝试远端，并保留原本的本地通知错误反馈。topic 为 null 时只发本地。
- 首次失败后入 WorkManager，要求联网，初始延迟 30 秒、指数退避，最多额外重试 3 次（合计最多 4 次发送），每次发送结果写日志。WorkManager Data 只含任务 ID；消息放在独立的 `push-retries` 中，发送时按通道 ID 读取当前配置和密钥。正常推送重试时重新检查启用状态和 topic；测试消息允许测试未启用通道。成功、达到上限或通道删除后清理消息。
- `ResoundApp` 装配 `AppGraph.push`，每日回顾接入 `DailyReview`。继续遵守原有每日回顾推送开关。
- `push.xml` 加入备份设置白名单；`push-secrets`、`push-retries` 不进备份。同机恢复也清空旧推送凭据与待重试消息，避免复用旧凭据或重发恢复前的消息。

## 给界面对接的信息

不改 `ui/`、`MainActivity.kt`、约定文件或 `AudioSource.kt` 签名。直接使用已有 `AppGraph.push` / `PushChannels`。

| 通道 | `values` 字段 | 密钥字段 |
| --- | --- | --- |
| PushPlus | `token`、可选 `topic` | `token` |
| 企业微信机器人 | `webhook` | 整个 `webhook` |
| Server酱 | `sendKey` | `sendKey` |
| 通用网址 | `url`、可选 `authorization` | `authorization` |

`fields(kind)` 返回上述字段描述。新建默认启用；编辑保留启停状态。密钥留空按约定表示不改，不能用空字符串清除已有 Authorization；需要清除时重建该通道。恢复后摘要显示缺少密钥，需重填再测试。通用网址属于普通配置，会随备份保存。

格式：PushPlus 对应 txt / markdown / json；企业微信 JSON 选择按 text 发；Server酱使用表单 title / desp；Webhook 始终发送含 title、body、topic、deepLink、at 的 JSON 对象。Text 去除常见 Markdown 标题、加粗、链接和代码标记，Markdown 保留正文；Webhook `at` 为原消息时间的毫秒时间戳，topic 为枚举名。
