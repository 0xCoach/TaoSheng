# 卡 115 · 导出选项交付说明

## 做了什么

- `LocalAudioExporter` 支持 `includeAudio / textParts / textFormat`。关闭音频时不调用解码器、编码器，不生成 M4A 或 SRT；只返回一个文字文件。预估的时长、字节数、耗时均为 0，保留有录音的段数。
- 没选音频且文字部分为空时，返回“没有选要导出的内容”。
- 文字固定按“摘要 → 待办 → 原话”输出，只出现选中的节。摘要包含事件时间、标题和摘要；待办包含关联事件的待办与约定、完成状态和到期时间。
- TXT 为 UTF-8 带 BOM；Markdown 无 BOM，采用标题分级、待办复选框和原话逐句硬换行，并转义内容中的 Markdown 标记。
- 多个段落合并为一个文字文件；段号、事件和待办按 ID 去重，事件按开始时间排序，原话按每句话的时间排序。
- 新增待办只读查询，排除删除、合并、忽略的旧项及其他类别。到期日期优先用 `dueAt`，无结构化日期时保留 `dueText`，都没有则写“未设置”。
- 后台任务 JSON 保存新选项；旧 `text/srt/media` 记录还原为音频开启、TXT、`text=true` 时附原话，继续保留旧字幕和媒体过滤开关。
- 未改 `ui/`、`MainActivity.kt`、约定文件或数据库版本。本卡供 0.2.20 合入，发布版本号由集成发布统一调整。

以下为格式示例；TXT 文件开头有不可见的 BOM。纯文字不写总时长或合成位置。

```text

人名：小王

摘要

2026-11-09 09:30:00 讨论排期

确认下周交付方案。

待办

已完成 · 约定：确认会议 · 到期：未设置

原话
```

Markdown（原话行尾保留两个空格）：

```markdown
# 项目讨论

日期：2026\-11\-09  
人名：小王  

## 摘要

### 2026\-11\-09 09:30:00 讨论排期

确认下周交付方案。  

## 待办

### 2026\-11\-09 09:30:00 讨论排期

- [x] 已完成 · 约定：确认会议 · 到期：未设置  

## 原话

09:30:05 说话人 1：我明天整理方案。  
```

## 界面需要知道的变化

- 使用新选项构造同一个 `ExportRequest`；底层已不再读取过渡属性 `includeText`。
- 关闭音频时，即便 `includeSrt=true` 也不会输出字幕；预估的 `audioSegments` 仍是源录音数，不能用它判断会输出音频。
- `Done.files` 中音频仍在前，文字扩展名根据格式为 `.txt` 或 `.md`。纯文字结果只有一个文件，界面直接分享/保存该文件。
- 主页多选应一次传全部段号，底层会合并排序去重；不要逐事件分别发起导出。
- 有音频时原话保留合成位置和当时时刻；无音频时只保留当时时刻、说话人与句子。
