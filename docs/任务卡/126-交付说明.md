# 卡 126 交付说明

## 做了什么

- 版本进入 `0.2.21`，`versionCode=61`。
- 新增纯函数 `EarlyTranscribe.shouldBatch(interactive, charging)`：仅锁屏且未充电时攒批。
- 实时转写首次入队等待 10 分钟、不加急，使用 `KEEP` 保留首次计时；执行中新增片段继续用 `APPEND_OR_REPLACE` 追加，追加轮也遵守当时的攒批规则。已有等待批次时新段合入该轮，不连续追加多个延迟批次。
- 复用录音服务接收器，监听亮屏和接电；在后台线程把等待中的批次改成立即加急任务。使用 `updateWork` 原位替换等待请求，去掉延迟并保留依赖关系，避免“查询后任务刚开始运行”时被 `REPLACE` 取消。正在执行的父轮不受影响，后续轮在父轮结束后接续。
- 关闭实时转写时不新排、不提升批次，已有实时任务启动后直接退出。低电量、发热的入队限制及原 30 分钟周期兜底、到点整理、间隔整理保持不变。
- 卡 124 的 `BIND_IMPORTANT`、单次推理 `PARTIAL_WAKE_LOCK` 和最长 660 秒自动释放保持不变。只在原有推理范围持锁，取消/异常/finally 均释放；排队、等待批次和模型空闲驻留不增加持锁。
- 未修改 `ui/`、`MainActivity.kt`、`*Contract.kt` 或 `AudioSource.kt`；无需界面配合。

## 参数与诊断

- `CaptureTuning.BATCH_DELAY_MS = 600000`（10 分钟）；保留线性重试退避 30 秒。
- 亮屏/充电时延迟为 0，申请加急；额度不足仍降为普通任务。
- 新增按天累计诊断，保留最近 30 个有记录的日期，经 `PipelineTimes.dump` → 运行诊断 → 问题记录导出：
  - `localAsrHeldMillis`：本地推理持锁毫秒，按单调时钟计时，跨午夜拆分，最多计至本次系统超时上限；取消后和重复释放不重复累计。
  - `realtimeExecutions`：实际进入实时 Worker 的次数，包含重试和流水线忙导致的重试；排队、KEEP 忽略的请求不计数。
  - `expedited` / `batched`：上述执行次数按请求类型分类。加急额度不足降级仍归入 `expedited`，不代表系统实际授予了加急额度，也不是硬件唤醒事件数。
- 主进程及 `:local_asr` 共享小型诊断文件，以文件锁串行读写、原子替换保存，不使用跨进程 SharedPreferences 缓存。仅保存日期、时长、次数，不新增音频、文本、路径记录，不进入备份。
