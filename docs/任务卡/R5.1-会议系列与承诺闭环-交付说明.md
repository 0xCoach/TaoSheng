# R5.1 会议系列与承诺闭环——交付说明

## 做了什么

按《R5-核心场景增强-差距核对》首卡实施：不重做系统，把已有的专题纪要、决定、灵感、待办、跟进串联成"会议闭环"。

1. **会议系列实体**：`topics` 表新增 `seriesKey` 列（DB 41→42），值为 `TopicPolicy.seriesKey()` 对专题名归一化（去全部空白后小写，匿名专题为 NULL 不参与系列）。四处专题写入点（周期计划、手动新建、补建、迁移回填）统一赋值。
2. **跨场跟进注入**：`MeetingSeriesRules.previousContext()`（:shared）取上一次同系列纪要的结论/决定/行动项 + 该场事件仍未闭环的 待办/约定 条目，拼成资料区注入本场纪要生成（Normal/Script 以外的专题，含 Meeting）。模型由此能看见"上次安排的事这次解决了吗"。
3. **整理落地即同步，不再等启动**：
   - `DigestDone`（digest_done）在 `afterDigest`（有新事件产出时）发射；
   - 新增 `RuleEvent.TopicDone`（topic_done），专题纪要落地时发射；
   - 两处钩子同步调用 `decisionRepo.syncFromDigest()`、`ideas.syncFromDigest`、`followupEngine.scan()`。
4. **承诺闭环**：`FollowupEngine.scan()` 把"约定"从落后待办里拆出——已接受的约定立即登记为 `FollowupKind.Commitment` 跟进（此前该枚举只有手动 add 使用，属死代码）；待办/备忘仍按事件落后一天发现，去重逻辑（openByRef）不变。
5. **决定上得了项目**：`DecisionRepository.importFromItem` 不再把 `projectId` 硬重置为 null，改按 `project_links` 解析（Item 链接优先、Event 链接兜底）；`projects` DAO 可选注入，测试与无项目场景不受影响。

## 真机需要注意什么

- 已有专题在升级后由迁移回填 `seriesKey`；名差异大的专题不会误并（归一化只去常见场次修饰）。
- "上次承诺"依赖上次纪要卡 + 事件条目存在；首次使用或上一场无纪要时资料区为空、不注入。
- 承诺跟进去重沿用 `openByRef("item", id)`：同一约定不会重复登记。

## 给界面（Claude）的说明

- 会议详情页"上次承诺"区块数据源：上一同系列专题 = `dao.previousDone(kind, seriesKey, excludeId)`；未闭项 = 该专题 `eventItems` 中 `category in (待办,约定)` 且 `status in (Pending,Accepted)`；上次纪要要点 = 该专题 `card.valuesJson` 的 conclusion/decisions/actions（结构同 `MeetingSeriesRules`）。
- 专题完成时已有 `topic_done` 规则事件可挂自动化。
