# 卡 117 · 文件夹自动导入

- 工作目录 `~/Developer/TaoSheng-117`，分支 `codex/117-folder-import`（从 `plan/0220` 拉出）。**不改 `ui/` 和 `MainActivity.kt`**，设置界面由 Claude 做。
- 版本：进 0.2.20。

## 背景

很多录音设备要靠厂家 App 把录音拉到手机。负责人已定：用户选一个文件夹，涛声**自动**把里面的新录音导入，不用每次手动分享。分享导入（`importer/ShareAudio.kt`）已经有了，本卡只做文件夹自动导入，复用同一条导入→转写→整理流程。

## 约定（已由 Claude 写好，签名不要改）

`importer/FolderImportContract.kt`（`WatchedFolder`、`FolderImportState`、`FolderImports`），注释即需求。在 `AppGraph` 里装配，并加 `isFolderImportReady`（照现有 `isXxxReady` 写法），界面据此决定显示真数据还是假数据。

## 要做

1. **权限**：`add()` 时对目录地址 `takePersistableUriPermission`（只要读权限）。每次扫描前确认权限还在，丢了就 `accessible=false` 并写 `lastError`，不再扫描，等用户重新选。
2. **什么时候看**：
   - App 打开时、`scanNow()` 时各看一次；
   - 后台用 WorkManager 周期任务（15 分钟，不要求联网、不要求充电），录音前台服务在跑时不额外加唤醒。
3. **哪些文件算录音**：用现有导入支持的格式（看 `ImportMedia.kt`），只看该文件夹本层和下一层子文件夹（不要无限递归），跳过隐藏文件和 0 字节文件。
4. **文件还在写怎么办**：大小和修改时间**两次扫描之间都没变**、且修改时间早于 2 分钟前，才导入。
5. **只导入一次**：按“文件大小 + 开头和结尾各 64 KB 的哈希”识别，改名、挪到子文件夹也不重复导入；与分享导入的记录也去重（同一个文件先分享过，就不再从文件夹导入）。记录存数据库（需新版本号：只在 `CaptureDatabase.MIGRATIONS` 里加一条，迁移测试照 AGENTS.md 的规矩写）。
6. **importExisting=false**：加入时把当前已有的文件全部记为“已见过、不导入”。
7. **导入方式**：开始时间用文件里读到的录制时间（`suggestedStartAt`），读不到用修改时间；类型用该文件夹的 `kind`；转写服务用默认的。不弹确认，直接进队列。连续多个文件依次排队，不并发解码。
8. **源文件永远不动**：不删、不改名、不写入。
9. **提示**：自动导入了新文件时发一条普通通知“从〈文件夹名〉导入了 N 个录音”，点开进今天页（通知渠道沿用导入相关的）；同时更新 `lastImported/lastImportedAt`。
10. 文件夹设置随备份一起备份；恢复到新手机后授权会失效，`accessible=false` 让用户重新选即可。

## 必测（5～10 个用例即可）

- 新文件稳定后导入一次，再扫不重复；改名后不重复。
- 正在写的文件（大小在变）不导入。
- importExisting=false 时旧文件不导入。
- 授权丢失 → accessible=false。
- 数据库迁移测试（照规矩）。

## 真机由负责人测

小米 14 Pro 上选“录音机”或某个下载目录，放进新录音，等后台自动导入；锁屏一段时间后能否照常导入。
