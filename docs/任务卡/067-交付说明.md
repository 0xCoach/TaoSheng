## 源头排查

搜索了上述字段的读写位置：

- `SkillOutput` 的 fields/values/evidence 使用 `SkillJson` / `JSONArray` 编码；`SkillDao` 合并 evidence 后也编码为数组。
- `DigestRunner` 的 points/people 使用 `JSONArray`；`AskChanges` 新建事件写 `[]`。
- `RoomReviewRepository` 的 sections 使用 `ReviewPrompt.encode`。
- `RoomMemoryRepository` 编辑的 points 使用 `JSONArray`。
- 未发现这些正常生成路径直接写入模型原文、空字符串或字面量 `null` 的证据，不能据此确定用户设备中坏技能卡的最初来源。
- 找到的传播风险：卡 062 的编辑备份直接将旧 points 复制到 originalPoints，恢复时再复制回来，可能传播已有坏值。本卡在 DAO 事务内将解析失败的值规范成 `[]`，也防御编辑入口传入坏 points；无原始备份的 SQL NULL 仍保留。
- 未做全库清洗，也不删除坏记录；推送跳过后，原数据仍留在库内供修复。

## 结果文案

- 部分损坏：`已推送；有 N 条记录格式异常，已跳过`（成功）。
- 全部损坏：`本地有 N 条记录格式异常，无法生成推送内容`（失败）。
- 服务回复无法解析：`服务返回了无法识别的内容：地址可能指向了网页而不是接口`。
- 状态重置诊断：`订阅状态损坏，已重置该通道，下次全量重推` / `同步状态损坏，已重置该通道，下次全量重推`。

## 真机注意和遗留

- 由负责人验证原问题通道“立即推送”和问题记录导出；本次没有碰手机。
- 状态重置会丢失该通道的本地指纹/触发游标，继续执行时按订阅范围重新推送（增量通道重新 upsert 全部所选记录），接收端可能看到重复内容；提醒状态损坏也可能让已有提醒再次发送。不会主动删除其他通道状态。
- 坏记录未修复前会在每次推送继续提示；恢复合法后可重新进入推送。
- 有坏记录时暂缓远端文档清理，避免坏数据被当成删除。记录修复后，后续正常同步恢复清理。
- 原始坏技能卡的产生来源仍待设备数据证据确认；本卡修复容错、误报和可诊断性。
