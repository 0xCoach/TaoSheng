# 卡 047 · 技能后台生成 + 手动生成不被“删过”拦住（后端）

负责人反馈（10-24）：收工打卡点生成一直提示“卡片已删除或今天卡片已达上限”；而且一切页面生成就中断。
**真机数据已核实**：今天 18:00 自动出的收工打卡（skill_cards id=1）被删过，之后手动生成全被 `SkillDao.merge` 第一行的删除记录拦住；另有两次“运行已中断”是离开页面导致的。

**约定**：`skills/SkillContract.kt` 新增 `generate(skillId, date)`、`generating`、`generated`。签名不要改。界面三个入口（技能页“试一下 → 生成”、记忆“给这天生成卡片”、卡片“重新生成”）Claude 已改为调用 `generate` 并观察这两个状态。“试跑”保持原样在页面里跑。
**分支 / 工作树**：`codex/047-skill-background`，`~/Developer/resound-codex-047`。

## 一、后台生成

1. `generate`：用 WorkManager 加急任务（`setExpedited`，配额不够时退回普通任务），唯一任务名按“技能 id + 日期”，`KEEP`：同一技能同一天正在跑时不重复排。要网络。
2. **`generate` 返回前**就把 (id, date) 放进 `generating`，并把 `generated` 里这一项的旧结果清掉（界面靠这个判断“正在跑 / 刚跑完”，不能有空档）。任务结束后移出 `generating`、写入 `generated`。进程被杀后重启，`generating` 要能从 WorkManager 的状态恢复。
3. 任务里调用现有 `run(…, MANUAL)`（复用全部逻辑与记录），中途被系统停掉按 WorkManager 规则重试，不要让用户看到“运行已中断”后就没了。网络 / 服务器错误最多重试 2 次。
4. **完成通知**（走现有 `LocalNotifier`，新开一个通知类别“技能生成”，即使技能本身的“推送”关着也发，因为是用户主动点的）：
   - 出了卡：“回响 · 收工打卡已生成”，正文是卡片摘要，点开 `resound://card?open=card&id=…` 直达。多张时写“出了 N 张”，点开到那一天。
   - 没出卡：“回响 · 收工打卡没有出卡”，正文写原因。
   - 失败：“回响 · 收工打卡生成失败”，正文写原因。
   - 不要再通过推送通道重复发（`run` 里 `auto && skill.push` 的推送逻辑保持只对自动运行）。

## 二、手动生成不被删除记录拦住

1. `SkillDao.merge` 加一个参数区分手动 / 自动：**手动**时忽略同一实体的删除记录，并把那条删除记录清掉（或换成新卡），让之后的自动运行也照常更新这张新卡；**自动**仍跳过删过的。时段型（会议）卡的“与删过的时段重叠”同理。
2. 把“删过”和“满了”分开报：
   - 自动跳过删过的：运行记录写“这天的卡你删过，自动运行跳过了”。
   - 满了：“今天已经有 N 张，达到每天上限”。
   - 不要再出现合在一起的“卡片已删除或今天卡片已达上限”。

## 三、必测（5～8 个）

1. 删过的一天一张卡：手动生成能出卡，之后自动运行更新这张新卡；自动运行遇到删过的仍跳过并记对原因。
2. 满了时报“已达上限 N 张”。
3. `generate`：返回前 `generating` 已包含、旧结果已清；结束后写 `generated`；同一键重复调用只跑一次。
4. 通知：出卡 / 没出卡 / 失败三种的标题、正文、跳转；技能推送关着也发；不走推送通道。
5. 被停后重试不丢结果。

- 不改 `ui/` 包和 `MainActivity.kt`；不改约定签名。不操作手机。测试适度，只跑本卡相关的，跑通即停。
