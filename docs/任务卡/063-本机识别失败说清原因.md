# 卡 063 · 本机识别：录音读不出来时别报“识别失败”，也别卡住整轮（后端）

App 名叫“涛声”。给用户看的文字只说结果和该怎么做。在 `preview-0.2.13` 分支上开发。**本卡不改 `ui/` 和 `MainActivity.kt`。**

## 一、问题（已查明）

用户反馈“本机识别失败，可改用 CPU 识别或重新下载模型”。问题记录（0.2.13-preview.2，Xiaomi 25067PYE3C，安卓 16）显示：同一时段 20 多段本机转写都成功，**只有一段（segment 589，比其他段早得多）反复失败**，耗时 1.6 秒，`errorType=LocalEngine`。模型和引擎本身没问题。

代码原因：`transcribe/local/LocalAsrService.process()` 里 `phase` 一开始就是 `"asr"`，**检查路径、`AsrAudioReader.readPcm()` 读文件/解码也在这个阶段**。所以录音文件缺失、被截断、解码失败，都会被报成 `LocalEngine`（“本机识别失败，可改用 CPU 识别或重新下载模型”），误导用户去换 CPU 或重下模型。而且 `LocalEngine` 在 `TranscribePolicy.ROUND_STOPPERS` 里，**一段坏录音会让整轮转写停下**。另外失败时只回传阶段，不回传原因，诊断记录里看不出是什么异常。

## 二、已定方案

1. 服务里把阶段分清：路径检查 + 读文件 + 解码 = `"audio"` 阶段；分人 = `"speakers"`；识别 = `"asr"`。`"audio"` 阶段失败回传后，`LocalAsrConnection` 映射成 `AsrError.Audio`（文案已有：“录音文件不可读取或解码失败”）。
2. 文件不存在时单独区分：映射成 `AsrError.Audio`，并在该段记录里写明“录音文件已不存在”（如有现成字段就用；没有就只写进 `PipelineTimes`/诊断）。
3. `AsrError.Audio`：**不中断整轮**（不在 `ROUND_STOPPERS` 里，确认现状），这一段按现有规则重试有限次后标成不再重试的失败，不要无限重试。
4. 回传失败时多带一个**异常类名**（不带 message，避免泄露内容），写进 `AsrAttempt` 的诊断（`errorType` 旁边有可用字段就用；没有就进 `PipelineTimes` 一行），**问题记录导出能看到**，以后能直接判断是哪种失败。
5. 同一段若在 NPU 上 `asr` 阶段失败，现有逻辑如有“自动改用 CPU 再试一次”就保持；没有的话**本卡不加**，只在交付说明里说明现状。
6. 顺带检查：segment 被判失败后，原声清理规则（卡 062 会改保留时长）不要删掉还在重试中的失败段的文件；只删已确定不再重试的。若与 062 的改动冲突，以 062 为准并在交付说明里写明。

## 三、必测（适度，3～5 个）

- 文件不存在 → `AsrError.Audio`，整轮其余片段照常转写。
- 文件被截断/内容不是音频 → `AsrError.Audio`。
- 识别阶段异常 → 仍是 `LocalEngine`。
- 失败诊断里带异常类名、不带 message。

测试规矩见 `AGENTS.md`：只跑本卡测试，跑通一次就停。编译需 `JAVA_HOME=/opt/homebrew/opt/openjdk@21`。
