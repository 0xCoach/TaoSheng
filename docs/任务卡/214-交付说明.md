基线为 `15c4acc7`，工作分支 `codex/214-keep-recordings`。本卡只做非界面；没有修改 `ui/`、`MainActivity.kt`、数据库、版本号或依赖。Claude 已添加的 kindColor 兜底足够，本次未使用额外界面兜底授权。

## 实现

1. **到期保留闸门**：`:shared` 的 `RecordingKeepRules` 统一判断通道范围、媒体、人声、通话/导入、任一通道成功凭据；旧 `audio=true` 且无 verified 的记录兼容为成功，新记录必须 `verified=1`。自动清理扣住应推未成功的录音，原有重点、转写/声纹、读取保护保留。手动清空/范围清空可直接清，预览返回 unpushed；releaseHeld 只清当前到期扣留且符合原规则的文件。
2. **手机文件夹**：新增 LocalFolder，非密钥配置只存 treeUri/displayName。同树 URI 冲突拦截；复用整理记录、原话和录音布局；本地任务不依赖网络。SAF 写固定临时名、完整读回 SHA-256 核对后重命名；失效或缺失统一报“文件夹不可用，请重新选择”。
3. **远端核对**：WebDAV 依次 PUT 临时名、Depth:0 PROPFIND 成功属性中的 getcontentlength、MOVE；S3 直接 PUT 正式键后 HEAD Content-Length。缺长度/不等都不记成功；不 GET 下载录音。取消会取消 DAV/S3 请求或停止 SAF 复制，凭据可续做。
4. **整天逐字稿**：新增 Daily/PerSegment/Both/None；新默认 Daily，旧 JSON 缺 audioText 按 audioWithText 映射。当地日结束后输出带 UTF-8 BOM 的日文件，引用登记的实际文件名、逐句时间和说话人。按内容哈希重推，改字、重转、认人及变空均可刷新；本机音频删除不妨碍已有文字重写；滚动范围过期不会清空过去已推日文件。
5. **隐私同步**：RoomPrivacyActions 各删段入口（含 forgetEvent）在原事务前、上传互斥锁内落盘精确待删清单。只删登记的音频、同名文本及确实登记过的未完成临时文件，不扫目录；受影响的日逐字稿重写，通道关闭也会处理。断网/权限失败重试；已删通道或目的地已变更则保留供人工处理。原声清理不走远端删除。删除标记防止部分事件删除后剩余段再次上传。
6. **充电、来源、提醒和模板**：充电为录音 Worker 约束，并拒绝旧任务使用放宽的约束；提供 textOnly/keepRecordings。扣留摘要按原定到期时间计算满 7 天；空间小于十进制 1 GB 且有扣留时通过“录音保留”渠道每天最多发一条通知。坚果云 ≥800 MB 时每月记录一次 quotaHint，S3/自建 DAV/手机文件夹不提示。

## 最终界面接口

- `OriginalAudio.heldSummary: StateFlow<app.resound.recordings.HeldSummary>`，字段 `segments: Int, days: Int, bytes: Long, oldestDay: String?, remind: Boolean`。只统计已到期、原规则可删而被扣留的文件。
- `OriginalAudio.keepStatus: StateFlow<app.resound.recordings.KeepStatus>`，字段 `channels: List<String>, protecting: Boolean`。
- `OriginalAudio.releaseHeld(): AudioTrim` 为 suspend；`AudioTrim` 末尾新增 `unpushed: Int = 0`，原四个字段不变。previewTrim 反映闸门后的自动清理；previewClear/previewClearRange 包含可手动清除的未推数量。
- `PushChannels.audioOffPreview(id: Long): Int` 为 suspend，返回当前已到期且关闭该通道后失去保护的段数；同一预览可用于删除通道。
- `PushChannels.pendingRemoteDeletes: Flow<List<PendingRemoteDelete>>`；数据字段 `channelName: String, path: String, channelId: Long = 0`；`suspend dismissRemoteDelete(channelId: Long, path: String)` 清除相应人工确认项。相同通道改过目的地且出现同路径时，该操作确认这些同名待删项，需用户核实旧目的地。
- `PushSubscription` 新增 `audioText: AudioText = Daily`、`audioChargingOnly: Boolean = false`、`audioCalls: Boolean = true`、`audioImports: Boolean = false`。audioWithText 仅保留旧数据兼容；新界面应编辑 audioText。
- `AudioPushStatus` 新增 `quotaHint: String? = null`、`held: Int = 0`。quotaHint 为当月一次生成的静态提醒，界面展示即可，不应在每次 Flow 更新时反复弹窗。
- `PushKind.LocalFolder` 能力与 MarkdownFolder 相同，values 为 `treeUri`、`displayName`；`useLinkedNutstore=false`。系统选择器复用 `LocalBackupFolderContract`；界面拿到结果后调用 ContentResolver.takePersistableUriPermission，传 READ|WRITE，再保存 values。权限失效不记成功。
- `PushTemplates.textOnly()` 与 `PushTemplates.keepRecordings()` 返回默认订阅，可随后修改。

## 来源核实

`ImportWork` 实际把卡 199 通话和普通导入切段写到 `files/import-segments/`，原 RecordingSources 只收 `files/segments/` 下 OGG，因此原先两类都没有纳入。现在推录音专用来源同时读取这两个受控目录，通过 importRecordId 查询现有 import_records.kind；Call 默认推，其余 import 默认不推。普通打包来源保持原范围。

SegmentEncoder 在 OGG 不可用时会回退 M4A；推录音保存原始 M4A 和真实扩展名，同名文本、核对、保留、隐私删除同样适用，不重编码或伪装成 OGG。麦克风回退 M4A 也纳入推录音。

## 持久化与恢复

沿用 `files/recording-uploads/<id>.json`，添加 verified/dailyHash/dirtyDays/temporary/history 等字段。目的地变更会移走当前成功凭据，并保留旧路径历史以供隐私清理；不把旧成功算到新目的地。`pending-deletes.json` 保存待删目标身份和删除标记，不保存账号密码或原话。未知/丢失目的地不猜测删除，留人工清单。新业务范围、摘要、日文档选择和精确删除计划在 `:shared`；Android 侧负责 JSON 文件、Room、SAF、HTTP 和 WorkManager 适配。
