# R6.2 官方 AI 服务与点数体系 — 交付说明

## 做了什么

### 服务端（Cloudflare Worker + D1，已部署）

- `server/migrations/0004_official_ai.sql`：新增 7 张表
  `ai_settings / ai_provider_configs / ai_quota_periods / ai_usage_requests / ai_usage_ledger / ai_consents / ai_point_adjustments`（远程 D1 已应用，现共 21 表）。
- `server/src/ai.js`：
  - 点数引擎：Free 每自然月 100 点；Pro 每 30 天周期 1000 点；年付 365 天 = 11×30 天 + 第 12 期 35 天（残尾并入末期，不碎发）。兑换码 Pro 同权。重复激活/同步不重复发点（周期行唯一键）。
  - 计费：`points = max(1, ceil(input/1000 + output/250))`，按服务商回执 token 计量；缺回执按估算并记 ESTIMATED。
  - 网关 `POST /ai/official/generate`：登录校验 → 同意校验 → 服务开关 → 任务白名单 → 原子预留 → 调服务商（最长 55s）→ 契约校验 → 原子结算释放余量 → 存幂等结果。`request_id` 重复提交：已结算回放不重复扣点；进行中返回冲突。失败/取消释放预留不扣点。
  - 预留与账本写入全部由 D1 UPDATE 条件语句保证原子性，不依赖单实例内存锁，余额不为负。
  - 限额：单任务 ≤100 点；Free 每日 ≤10 任务、Pro ≤60；auto_digest 仅 Pro，周期 ≤300 点/日 ≤40 点（计入主池）。
  - 服务商密钥 AES-GCM 加密存 D1，主密钥为 Worker Secret `AI_KEY_SECRET`；任何读取接口只回 `has_key`，永不回明文。Base URL 白名单 + 私网/回环地址拒绝，防 SSRF。
- `server/src/worker.js`：AI 路由在 membership 路由之前派发。
- `server/src/membership.js` 管理台新增「官方 AI」页签：服务商增删改/测试连接/设默认/启停、点数规则、用量成本、用户周期余额、人工调点（带原因审计）、一键暂停。
- 端点：`status / quota / usage / estimate / consent / generate`，全部走既有 access token + 401 串行刷新。

### Android（不动 ui/ 与 MainActivity）

- `shared/.../OfficialAiContract.kt`：`OFFICIAL_PROVIDER_ID="official"`、`LlmTaskKind` 协程上下文（计费任务类别）、`officialTaskKind(feature)` 中文功能名→类别映射。
- `auth/AuthApi.kt`：官方 6 端点；`call` 加可选 `http` 参数，`generate` 用长读超时 client（读 90s/全程 100s > 服务端 55s）。
- `auth/AuthGate.kt`：官方方法统一走 `authed{}`，复用串行刷新，不另建刷新机制。
- `auth/OfficialAi.kt`（新）：状态/额度/同意封装；`generate` 以 `SHA-256(账号|任务|system|user|nonce)` 为幂等 request_id（同内容重发不重复扣点，主动重生成传 nonce 视为新任务）；本地已同意但服务端未记录时自动补登重试一次；`ready()`=登录+开启+已同意。
- `digest/LlmClient.kt`：`preset.id=="official"` 时分流到 `OfficialBridge`；`LlmException.terminal` 标记——官方错误（点数尽/需同意/服务异常/需登录）一律 terminal，failover 不切换 BYOK；streamChat 官方路径把多轮消息按序拼进 user 保上下文，工具调用报 Format 终态走问问预取降级。
- `digest/LlmFailover.kt`：备用候选排除官方条目（双向不静默互切）；classify 尊重 terminal。
- `digest/AndroidLlmProviders.kt`：官方条目自动注入列表（"声声不息官方 AI"），hasKey=ready()；禁删、禁改、禁填密钥；`refreshOfficial()` 供状态刷新重发。
- `digest/DigestRunner.kt`：官方选中时跳过本地密钥门、按条目 hasKey 判就绪并给官方专属提示；安静自动整理标 `auto_digest` 类别（服务端仅 Pro + 独立上限）。
- `AndroidDigestSettings.test()/check()`、`RoomManualTodos`、`GroundedQA`、`AnalysisRepository.llmReady()/execute`、`TopicAndroid` 的密钥门统一放行官方条目。
- `ResoundApp`：`AppGraph.officialAi` 装配 + `officialBridge`（GenOutcome→LlmReply/LlmException 映射，全 terminal）+ 启动即刷新状态联动 providers。

## 给界面（Claude）的交接清单

`ui/` 与 `MainActivity` 未动，需补：

1. **服务商列表**：官方条目已自动出现在 providers 列表（名称"声声不息官方 AI"，不可删不可改）。建议把它置顶/推荐，隐藏其 Base URL/模型/密钥输入框（字段值为占位 "official"，不应展示）。
2. **同意流程**：首次选官方或首次发起官方任务前弹告知：`officialAi.consent()` 落账；`officialAi.localConsented()`/`status.consented` 可查。
3. **点数显示**：`officialAi.quota()` 返回 plan/周期/已发/已用/预留/剩余/刷新时间；`usage()` 返回最近使用记录（含每次点数）。只显示点数，不显示 token/模型/价格。
4. **估算**：`officialAi.estimate(taskType, chars)` 生成前给区间提示。
5. **错误态**：官方错误经 LlmException 上抛，`detail` 已是中文用户文案（点数尽/需登录/需同意/服务暂不可用/内容超限），直接展示即可；不需要"换服务商"按钮（terminal 保证不自动切）。
6. **游客**：`ready()` 为 false 时官方条目 hasKey=false，可显示"注册后可用官方 AI"入口。

## 真机/上线注意（负责人实测）

- **不要在真机上用 debug 包覆盖 release 1.0.7**（证书不同会被拒）。真机验证请等正式签名包或走内部渠道。
- 管理台配一个真实服务商 → 测试连接 → 设为默认并开启服务，官方 AI 才真正可用；未配置时 `status.configured=false`，App 端就ready()=false（不会假装可用）。
- 内部灰度顺序：管理员账号登录 → 同意 → 手动整理一条（看点数扣减与余额）→ 同内容重试（应命中幂等不重复扣）→ 把余额调到 0 验证"点数尽"终态且不自动切 BYOK → 账号切换验证不串额度。
- 录音、SenseVoice、BYOK 路径未改语义，回归点：本地转写、自己密钥整理、安静自动整理。
- iOS 编译检查未跑（无 Xcode）；shared 改动仅新增纯 Kotlin 文件，风险低但需在下一次有 Xcode 的环境补跑 `tools/check_ios.sh`。

## 遗留问题

1. **真实服务商未配置**：生产官方 AI 尚未对任何用户开放；未验证真实 token 计费与供应商成本。上线前必须内部账号灰度+成本核对，再逐步开放。
2. **UI 未接入**：同意弹窗、点数卡片、官方条目展示样式待 Claude 实现；现阶段底层就绪但用户看不到入口。
3. **官方"测试连接"**：providers.test() 走真实 generate（约耗 1 点），是有意的实连通性验证；UI 若给官方条目显示测试按钮需知会用户会消耗点数。
4. **auto_digest 开关**：服务端已强制"仅 Pro + 上限"，App 端安静整理的"官方自动整理开关（默认关）" UI 待做；未做前 Pro 官方用户安静整理会按 auto_digest 计费（有服务端上限兜底）。
5. 年付 Pro 的 12 期发放依赖 `ensurePeriods` 惰性补齐，跨设备一致性靠服务端周期行唯一键；极端并发已按条件更新防重，未做真机并发实测。

## 2026-11-20 增补：官方 AI 选择行为（游客提示 + 登录后默认选中）

**需求**：试用/游客进服务商列表，官方 AI 不可用且要明确提示（可自行填密钥）；授权登录后，若用户之前没填过可用服务商，默认选中官方 AI。

### 改动

- `AndroidLlmProviders.refreshOfficial()`：官方就绪态 false→true 沿时，若当前服务商不可用（无密钥、非免密自定义、无自定义请求头），自动 `activate(OFFICIAL_PROVIDER_ID)`。仅就绪沿触发一次——用户此后手动选回其他服务商不被覆盖；当前服务商已填密钥可用时也不抢。
- `ui/settings/ProvidersCard.kt`：点官方条目未就绪（`!hasKey`）时不再静默选中一个用不了的项，而是 `AppGraph.auth.requestLogin(AiAnalysis, "官方 AI 需要登录授权后使用")` 直接弹登录面板；登录成功 → `officialReady` 翻转 → `refreshOfficial` 自动把它设为当前，形成"点官方 → 登录 → 自动启用"闭环。
- 游客态条目文案维持「official · 登录授权后可用」，DeepSeek 行内密钥框不变（可以自己填）。

### 验证

- `LlmProviders076Test` 16/16：新增两个用例——①未填密钥 + officialReady 翻转 → 自动选中官方、就绪前不切换；②已有密钥服务商被选中时不被官方抢走、就绪回落不重复切换。
- 顺手修 3 个过时断言（官方条目注入列表尾部后，迁移测试的列表相等/单元素断言需排除官方行）。
- `assembleDebug` + `-PlocalAsrValidation` 验证包编译通过。

### 真机验收点（本轮未跑：手机无线调试已关闭，adb 连接被拒）

- 游客：设置→模型与整理时间 → 点「声声不息官方 AI」→ 应直接弹登录面板（不是选中空圈）。
- 登录后：当前是无密钥 DeepSeek 占位 → 官方 AI 自动变为当前（实心点）；DeepSeek 行仍显示行内密钥框可自己填。
- 已填密钥的用户登录：选中不被切换到官方。
- 登出：官方条目回到「登录授权后可用」。
