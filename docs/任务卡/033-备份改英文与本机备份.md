## 三、本机备份（新功能）

负责人要求：不用坚果云的人也能备份；可以导出到手机、从手机导入恢复；支持自动备份；删历史备份只保留最新的。

1. **文件夹**：界面用 `ACTION_OPEN_DOCUMENT_TREE` 让用户选一个文件夹，把返回的地址交给 `setLocalFolder`。后端 `takePersistableUriPermission`（读+写），用 `DocumentFile` 读写；文件夹名给人看（如“Download/Resound”）。权限丢了（用户删了文件夹等）→ `lastError = "本机文件夹无法访问，请重新选择"`。
2. **备份内容和格式**：与云端完全相同（同一个 zip、同样的加密口令、同样的文件名规则 `resound-….zip(.enc)`），这样云端和本机的文件可以互相恢复。把“生成备份文件”从 `AndroidBackupRepository` 里抽成一个共用函数，云端和本机都调用，不要复制两份。
3. **自动**：`auto=true` 时每晚和云端备份同一时机运行（云端没开也要跑本机）。云端和本机互不影响：一边失败另一边照常。现有调度条件（充电、空闲等）沿用；只开本机时不需要网络。
4. **只保留最新几份**：`keep` 取 1 / 3 / 7，**默认 3**（只留 1 份的话，万一最新那份坏了就没有退路；用户可以改成 1）。每次成功写入后删除多余的旧文件，只删匹配 `resound-…zip(.enc)` 规则的文件，文件夹里别的东西绝不碰。
5. **导出一份**：`exportTo(uri)` 生成一份写到用户用 `ACTION_CREATE_DOCUMENT` 选的位置（界面默认文件名 `resound-日期.zip`）。
6. **从文件恢复**：`restoreFrom(uri, passphrase)` 和 `restoreLocal(name, passphrase)` 走和云端恢复**完全相同**的流程（先校验、本地快照、替换、密钥清空需重填、自动重启）；只是来源不同。把“从一个本地 zip 恢复”的核心抽出来共用。加密的备份没给口令 → 返回“这份备份加了密，请输入口令”。
7. **状态**：`local` 的 running / lastAt / lastBytes / count / lastError 实时更新；设置存在 `backup.xml`（键名用英文），文件夹地址也存这里。
