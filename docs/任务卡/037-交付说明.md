## 完成内容

- 云端、所选本机文件夹改用 `resound-state.zip(.enc)`、`days/resound-day-YYYY-MM-DD.zip(.enc)`、`features/<内容 SHA-256>.bin(.enc)`。新备份入口不再调用 full/inc 生成或 keep 清理；034 代码保留，旧格式恢复入口继续可用。
- 每次读取目的端清单，从数据库一致性副本按表名、主键、列名稳定序列化 JSON 行，比较每天的 SHA-256。首次上传全部天，之后只上传新增或变化的天；不依赖本机基准。声纹文件按内容去重，清单丢失后也能复用已有同内容特征。
- 状态最后发布。WebDAV 使用 PUT 临时文件后 MOVE；覆盖旧日分卷前用服务器 COPY 保留指纹寻址的 `.previous-*` 副本。SAF 使用校验临时文件、旧文件改名、新文件改名的流程；正式文件缺失的窗口可读 previous。中断时旧清单仍能按指纹读取旧内容，连续中断后重试也不会覆盖该恢复副本。
- 清单记录待删除路径；隐私删除、临时旧版本清理中断后，下次先重试。只有新状态提交后才删除本次移除的日分卷。keep 不再截断历史。当前内容仍需要的恢复副本保留到后续内容变更再清理。
- 清单保存 `startedAt`，新格式成功备份的跨度达到 7 天后才清理根目录已识别的英文旧备份。不会因数据库里的最早记录很旧而首日就清理；不碰中文旧目录或其他文件。
- `cloudSummary` / `localSummary` 返回天数、全部有效分卷字节数、时间、实际上传量和密钥/加密标识。上传量计本次 PUT 的分卷内容，不含 HTTP 请求头、服务器 COPY 或读取流量。
- `restoreAllFromCloud` / `restoreAllFromLocal` 已实现。单文件导出为外层 ZIP，内部是同一分卷结构；开启加密时内部各文件独立加密，外层仍是 ZIP。`restoreFrom` 按内容识别新格式，也继续识别旧 ZIP/full/inc。
- 新手机尚无口令时也能先选中加密备份文件夹，再向恢复接口传入口令。

## 表归属

所有时间戳按 `Asia/Shanghai` 归天。跨午夜记录按起始时间归属，不拆一行；修改旧记录会重新上传它所属的那天。

| 分卷 | 表 | 归属依据 |
| --- | --- | --- |
| 日分卷 | `segments`、`transcript_lines`、`memory_events` | `startAt`；segments 只含元数据，无音频 |
| 日分卷 | `memory_items`、`ask_conversations` | `createdAt` |
| 日分卷 | `ask_messages`、`skill_cards`、`skill_runs` | `at` |
| 日分卷 | `reviews` | `generatedAt`，保留记录本身的生成日 |
| 日分卷 | `asr_usage`、`llm_usage` | 已存的 `day` |
| 日分卷 | `asr_attempts`、`app_power`、`battery`、`heartbeats`、`watchdog` | `at` |
| 状态 | `voiceprint_people`、`voiceprint_samples`、`voiceprint_exclusions` | 全局声纹关系；样本向量及元数据一起保留 |
| 状态 | Room schema 版本、清单、配置、密钥、技能、提示词、特征文件名映射 | 全局当前状态 |
| 不备份 | `embeddings`、`lines_fts`、`events_fts`、`items_fts` 及 FTS 影子表 | 当前 App 重建；Room 内部表由空库自动创建 |

统计/运行记录选择保留全部历史，不做 30 天裁剪，避免诊断记录被时间窗口静默移除。所有表都从当前 Room schema 重建，不执行备份携带的建表 SQL。

## 设置和密钥审查

配置按 SharedPreferences 文件名组织到 `settings.json`，保留 boolean/int/long/float/string/string-set 类型：

- `transcribe`、`local-asr`、`capture`、`ui`、`review`、`push`、`diary`、`digest`、`setup`、`backup`、`ask-selection`。
- `files/skills/` 和 `files/prompts/` 沿用项目认可的技能/模板路径；按现有文件锁和 AtomicFile 读取。
- 排除纯运行时文件：`transcribe-queue`、`push-retries`、`digest-state`、`diary-sync`、`imports`（导入队列）、`privacy-spool`、`ask-suggestions`（生成缓存），以及系统/WorkManager 内部偏好。
- `backup` 不保存旧基准引用、上次运行统计和错误；`local-asr` 不保存下载进度/实际运行状态。这些不是用户配置。

`secrets.json` 按 store + key 保存解密值：

| 容器 | 内容 |
| --- | --- |
| `digest-secrets` | 模型、整理、技能等所有已存在 key |
| `push-secrets` | 全部推送通道凭据 |
| `backup-secrets` | 坚果云应用密码 |
| `transcribe` | `encryptedKey`、`customEncryptedKey`；使用现有 ASR Keystore alias 及相同 AES-GCM 编码 |

坚果云账号、接口地址和模型名随普通设置保存。`backup-encryption-secrets` / 备份口令不导出。读取已有密钥失败会中止备份，避免写出貌似完整但缺密钥的状态。

未加密也包含密钥，`includesSecrets=true`、`encrypted=false`；界面需使用该标识提示。恢复逐项覆盖：备份没有的设置项、密钥和本机备份口令全部保留；不强制关闭坚果云备份。旧格式恢复也取消了清密钥、关闭备份的行为，只清除旧推送重试队列。

## 恢复步骤

1. 下载状态以及全部清单引用；校验归档大小、归档 SHA-256、日分卷行数据 SHA-256、状态内部文件 SHA-256、声纹内容 SHA-256。固定路径若已被未完成上传覆盖，可读取旧指纹对应的恢复副本。加密文件尝试本机口令/用户输入口令。
2. 私有暂存目录用 `CaptureDatabase.open` 建当前 Room 空库，按列名写入行。旧版本缺列使用 SQL 默认值；未声明 SQL 默认值的必填列使用类型零值。高于当前版本拒绝并提示升级。
3. 全部插入后检查外键，重建三张 FTS，执行 `integrity_check`、WAL checkpoint。相关 SQLite 连接全部可写打开。
4. 校验通过后，先在 `noBackupFilesDir/before-restore/` 留新格式、自包含的当前快照，再暂存恢复数据、关库、重启。下次启动仍在 Room/设置仓库初始化前完成替换；提交标记支持中断后重放。
5. 设置和密钥按项合并，密钥重新用当前手机 Keystore 加密。embeddings 空表随当前库创建；现有启动流程 `EmbeddingScheduler.start` 后台补算，模型/电量条件沿用现有策略。

恢复前快照包含配置和密钥，保存在 App 私有 noBackup 目录，成功备份后清理。它没有另加备份口令加密。临时明文工作目录在操作结束后清理。恢复不会恢复录音文件、本地推理模型文件或系统授予的 SAF 权限；换手机需要重新下载模型、重新授权目标文件夹。备份口令不随备份转移，新手机后续加密备份需设置口令。

## 负责人真机验收与边界

本卡没有操作手机、没有连接真实坚果云。以下由负责人接入界面后执行：

1. 本机文件夹先备份两次，核对天数及实际写入量；修改今天/旧日待办，确认只更新对应分卷。SAF 服务商需支持文件改名；拒绝改名时应报错，保留旧内容。
2. 开关加密，各生成一份备份；验证恢复后模型、转写两套凭据、全部推送通道、坚果云账号/密码可用，备份开关符合备份设置。Robolectric 的密钥合并用测试适配函数验证，真实 Android Keystore 解密与重新加密仍需真机验收。
3. 先在目标手机填一个备份没有的密钥，再恢复，确认它保留；输入错误口令、提供损坏日分卷时，确认原数据库不替换。
4. 从文件夹及单文件分别恢复，核对日期/记录数量、中文关键词搜索、声纹人物/样本；观察后台向量重建。本机原来存在的录音文件不会被本卡删除，但备份本身不携带录音。
5. 真实 WebDAV 验证同目录 COPY、覆盖 MOVE、HEAD、临时文件清理与中途断网恢复；目前证据为 MockWebServer，不宣称真实坚果云兼容性已验收。
6. 换手机先选择加密文件夹再输入口令；确认能恢复，再重新授权本机备份文件夹、下载模型并设置后续备份口令。

`ui/`、`MainActivity.kt`、所有约定文件均未修改。界面仍需 Claude 接入新 Summary/恢复全部入口，并将旧格式恢复单列；约定中的 keep/full/inc 与旧版“密钥不备份”注释仍未动，由约定负责人统一更新。没有接口签名变更需求。
