## 一、先回答“为什么不准”（必须有数据支撑）

逐条验证下面的怀疑，每条给出数字结论（成立 / 不成立 / 部分）：
1. **一组里混了好几个人**：现在按（录音段 × 说话人编号）算一个声纹。云端转写的说话人编号常常把两个人合成一个，**本地转写（SenseVoice）根本没有说话人编号**，整段录音（可能长达 5 分钟、好几个人）只算一个声纹 → 我的声音被别人“冲淡”。用录音重新按小窗口（如 1.5～3 秒、本地人声检测切）算声纹，看同一组内部的离散度。
2. **样本被污染**：自动补样本门槛（≥0.80 且 ≥3 秒）可能把混了别人声音的片段加进了“我”的样本，样本越多越不准。检查 40 条 auto 样本和 47 条手动样本各自与“我”中心的距离、彼此一致性；有没有明显离群的。
3. **早期录入方式不一致**：10-24 之前的朗读录入用的是 VOICE_RECOGNITION 音源（会压低远处人声），日常录音用 MIC，两种声纹对不上（已在 a9b2cbf 改成 MIC）。看手动样本里按时间前后分两批的分数差异。
4. **打分方式**：现在是跟“我”的中心比余弦，阈值 SURE 0.65 / MAYBE 0.45。对比几种：中心、样本 Top-k 平均、样本最大值、分窗口投票；用已标注数据（手动“这是我”= 正例，`voiceprint_exclusions` 和标成别人名字的 = 负例，电脑 `say` 合成 / 外放媒体段 = 负例）画分数分布，给出最优方法和阈值、以及对应的召回 / 误认率。
5. **太短、太吵、外放**：短于多少秒的片段基本没法判断；外放媒体段（`playbackMillis > 0`）是否在拉低或干扰。
6. **其他你在数据里看到的原因**。

## 二、改进（有把握的直接做，在后端 voiceprint 包内）

按上面结论做，建议方向（以数据为准，可以改）：
- 对**没有说话人编号或一组太长**的录音，按小窗口算声纹、窗口级判定“我 / 不是我 / 拿不准”，再映射回每一句（按时间重叠）。
- 样本库**清理与防污染**：自动补样本只收“窗口级”高置信、单人、≥2 秒的片段；离群样本自动剔除（不删用户手动标的，只降权或标记）；样本上限与新旧淘汰规则。
- 换成数据证明更好的打分方式和阈值（阈值放成常量，交付说明写清怎么得来的）。
- 提供一个**重新计算**入口（后端函数 + WorkManager 任务）：用新方法把最近 N 天（录音还在的）重新判一遍“我”，录音已删的保留原结果。界面按钮由 Claude 加，交付说明里写清楚调用方式。
- 不改 `VoiceprintContract.kt` 签名；确需新增接口，写在交付说明里由 Claude 加到约定。
