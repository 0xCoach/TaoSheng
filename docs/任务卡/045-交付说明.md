# 045 外接麦克风交付说明

分支：`codex/045-external-input`。后端已实现，`ResoundApp` 已装配 `AppGraph.inputs`。未操作手机，未修改 `ui/`、`MainActivity.kt`、约定文件或 `AudioSource.kt`。

## 做了什么

- `AndroidInputDevices` 用系统输入列表和 `AudioDeviceCallback` 更新设备，手机麦克风合一并排第一，外接按本进程观察到的接入顺序排列。过滤电话、回环、调谐器、回声参考设备；USB 重复项合并，同耳机 LE/SCO 合并并优先 LE。
- 稳定 key 使用类别与设备名，蓝牙可获取地址时附带地址；蓝牙共用 `Bluetooth` 类别，避免 LE/SCO 切换改变 key。指定设备断开时保留保存的名字及离线条目。
- Phone / AutoExternal / Device 存到 `inputs` 设置，默认 Phone；加入卡 037 设置备份及旧归档白名单。恢复后随 Application 装配重新读取。
- `ExternalAudioSource` 与手机来源共用录音实现。手机也显式选内置麦，避免插入外设后把系统默认输入误标成手机。外接使用 `setPreferredDevice`，录音后核对实际路由，首帧通过核对才更新 `status.using`，运行中也持续检查。
- 尝试 16k 单声道及设备公布的采样率/单双声道组合；PCM16 流经跨 read 保留相位的积分平均重采样和混单声道，统一输出 16k、480 采样帧。Busy 期间清空转换余量，避免恢复后拼入旧帧。
- 蓝牙 API 31+ 从通信输出列表找到同耳机，调用 `setCommunicationDevice`；API 29/30 使用 SCO 兼容路径。停止、失败、取消均释放录音和本次通信路由。自己的通信模式不触发通话礼让，真实响铃/电话、其他录音及系统静音仍让出。
- `CaptureService.listen` 接入串行切换器：旧来源取消并正常 `finish` 后才开新来源；外接异常立即回手机，不等 `MIC_RETRY_MS`。同设备离开后 3 秒内不重新进入，期间继续录手机；失败的设备不在后台反复重开，选择或目标端口变化后再尝试。
- 片段来源写入暂存 `.source` 文件，再写入 `SegmentEntity.sourceId`，保留进程重启后编码的来源信息；历史无元数据暂存仍按 `mic` 处理。
- “我”按待处理片段的 `sourceId` 选择样本：先排除本片段样本；同设备可信人工样本达到 3 条、30 秒时只用这些，否则使用全部可信人工样本。保留卡 044 的自动样本/待复核样本排除规则。朗读录入仍归属手机，其他人物不改。无需数据库迁移。
- 值班日志数据库新增 `type="InputSwitched"`，记录设备名称与原因，诊断导出可查看；日统计计数规则不变。

## Claude 需要配合

1. **蓝牙权限入口**：清单已加入 `BLUETOOTH_CONNECT`、`MODIFY_AUDIO_SETTINGS` 和 API 30 以下的旧蓝牙权限。Android 12+ 在“录音与后台 → 录音输入”选择蓝牙设备，或 AutoExternal 将使用蓝牙时，请申请运行时 `BLUETOOTH_CONNECT`；恢复备份后、重新开始录音前也检查。拒绝时后端会回手机并提示。授权后调用现有 `inputs.choose(...)` 会重新枚举设备。
2. **日志约定/UI 缺口**：当前 `CaptureContract.kt` 的 `WatchdogEventType` 没有 `InputSwitched`，`VerifyScreen.kt` 又穷尽匹配枚举。遵守本卡禁区，本次没有修改两者。请 Claude 添加该枚举项并补“录音输入切换”文案；届时仓库映射会自动展示已存记录。现版本统计页暂不展示该新类型，但数据库和诊断导出完整保留，不冒用 MicBusy 等旧类型。

## 真机验收（负责人）

- 小米 14 Pro：插 Type-C 大疆接收器，分别选 Phone、AutoExternal 和指定 DJI。靠近外接麦/遮住手机麦对比，检查回放、转写和片段 sourceId，确认名称与实际声音来源一致。
- AirPods：授权蓝牙后选择耳机，验证真正从耳机收声；切回手机、暂停、停止后确认通信路由释放。若有 LE 耳机，另验证 LE 优先与双 profile 去重。API 29/30 SCO 兼容路径也未做真机测试。
- 录音中插拔、断电、蓝牙断连及 3 秒内反复插拔：当前有效语音正常保存，手机立即接续，稳定后再回外接；检查提示、watchdog 和 sourceId。低于原有 1 秒有效人声门槛的片段仍按原规则不保留。
- 外接和手机录音中分别来电话/接电话，以及其他 App 开始录音：回响让出，不把自己的蓝牙通信模式当成来电；通话结束后恢复，必要时设备失效回手机。
- 退出重开、备份恢复：选项与离线名字保留；蓝牙权限仍由新设备独立授权。

## 限制与遗留

- 蓝牙权限 UI 和 InputSwitched 枚举/UI 是上述明确待接项；本卡没有越过界面/约定禁区。
- 外设没有暴露稳定身份时只能依赖产品名：同名 USB 设备、无地址的同名蓝牙设备无法可靠区分；产品名变化、蓝牙地址从不可读变为可读时可能需重新指定设备。App 启动时已连接多个设备，无法追溯启动前谁最后插入，以系统首次枚举顺序为准。
- `InputStatus` 只有非空 using，没有“未录音”字段；暂停/等待路由验证时保留上次已确认来源，新来源只在收到核对通过的音频帧后发布。
- 重采样采用简单积分平均，真实驱动兼容性及蓝牙通话音质须以上述真机结果为准。
