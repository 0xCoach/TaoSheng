# 卡 132 · 新手上手底层信号交付说明

## 做了什么

- 实现 `LocalOnboarding`，在 `ResoundApp` 装配 `AppGraph.onboarding`。版本沿用当前分支的 0.2.21。
- 所有状态、关闭标记、统计写入独立的 `onboarding` SharedPreferences；未加入新旧备份白名单，Android 系统备份仍保持禁用。向导完成的 `ui` 偏好由界面处理。
- 通过 Room 通知观察非空转写：首次读取已有数据时取最早句子的 `startAt`；首次读取为空、随后入库时记录观察到入库的当前时间。仅保存一次，删除原话、重新转写或重启不会重置；保存后停止首次时间查询。
- 保活提示复用 `CaptureNotifications.interrupted`，覆盖已有 Watchdog、开机/升级、恢复提醒入口；即使没有通知权限也保存中断事实。
- 说话人提示只针对本机转写，且 `speakers-enabled` 关闭或模型未就绪。最近 48 小时某一录音段内至少有两个可靠标签，或已识别出 `speakerPersonId > 0` 的其他人，才提供提示。不跨段累计，不使用 `uncertain:*` 占位符，不使用空白句子或主动语音输入作为多人证据。
- 首次转写超过 72 小时且从未成功备份时提示备份。本机备份、手动导出、云端备份成功都记录本机永久事实；升级时兼容已有 `localLastAt` / `lastAt`。切换备份目录/账号后仍记得曾成功过。
- 提示顺序固定为 KeepAlive → Speakers → Backup；关闭后在本机永久隐藏。设置变化、证据删除立即更新，时间门槛与证据过期复用转写仓库已有分钟心跳，最多约一分钟刷新；没有新增轮询、数据库表或迁移。
- 问题记录导出新增本地统计。保留既有敏感信息脱敏，只对固定耗时字段名避免误遮挡；同时修复导出在环境音模块未装配时访问未初始化字段的问题。

## 界面对接

- 读取 `AppGraph.isOnboardingReady`、`firstTranscriptAt`、`tips`，关闭提示调用 `dismiss`。
- `record` 累加 `wizard_shown`、`mic_granted`、`mic_denied`、`key_saved`、`key_skipped`、`key_from_clipboard`、`wizard_done`、`wizard_skipped`。未知输入只累计 `other`，不保存原字符串；新增统计名称需同步扩充白名单。
- 完成或跳过调用 `wizardFinished()`；它幂等保存第一次完成时间，不代替 `record("wizard_done")`。完成后首次转写输出 `first_transcript_after_wizard_ms`；若试说已先出结果再完成，耗时为 0，未完成或尚无转写时为“未记录”。
- KeepAlive 表示“曾意外中断”，恢复录音不会消除这个历史事实，由用户关闭提示。Speakers 与 Backup 根据当前条件自动消失。
- 未修改 `ui/`、`MainActivity.kt`、任何 `*Contract.kt` 或 `AudioSource.kt`。

## 真机需要注意

由负责人在小米 14 Pro 上验证，当前未安装或进行真机验收：

1. 全新数据试说与已有转写升级，观察首次转写信号；在试说前后完成向导各检查一次问题记录中的耗时。
2. 系统意外停止后经过现有 Watchdog/恢复入口，检查保活提示；手动暂停与停录时段应沿用现有逻辑，不触发该入口。
3. 有可靠多人结果时切换本机/云端转写、说话人开关和模型状态，检查提示出现与消失。仅有不确定标签应不提示。
4. 成功完成本机或云端备份后检查提示消失，切换目录/账号与重启后不再提示；关闭各提示后重启仍隐藏。
5. 换机恢复时 `onboarding` 状态应重新建立；是否弹向导由界面的 `ui` 完成标记决定。

## 遗留与边界

- 无需要修改约定签名的事项，向导和提示界面待 Claude 对接。
- 不主动启动说话人模型推理来猜测多人，没有可靠现存结果就不提示。
- 升级前若旧版已经清除了全部本机备份成功时间，无法追溯那个历史成功；本版开始单独保存“曾成功”标记，避免再次丢失。
