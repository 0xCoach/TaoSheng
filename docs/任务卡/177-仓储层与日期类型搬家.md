## A 段：约定换日期类型并搬家

1. 先录基线：对每个要改的约定，找出它的全部实现和全部调用方（含界面、测试、假实现 `ui/preview/Fake*.kt`），列成清单放 `docs/任务卡/177-证据/A-调用清单.md`。
2. 按清单逐个约定改：换类型 → 改实现 → 改调用方（界面只做机械适配）→ 编译 → 跑相关测试 → 提交。一个约定一个提交，方便审核和回退。
3. 日期换算必须等价，重点防这几类错：
   - 时区：原来用 `ZoneId.systemDefault()` 的地方，换成从 `ZoneProvider` 取或由调用方传入；同一个调用链里只取一次时区，不要一半用系统默认一半用传入的。
   - “某天的起止毫秒”：`LocalDate.atStartOfDay(zone)` 与 kotlinx 的 `atStartOfDayIn(zone)` 在夏令时切换日的行为要对照（国内无夏令时，但代码不能假定）。写对照用例：同一批日期在 `Asia/Shanghai`、`America/New_York`（含切换日）、`UTC` 下，新旧算出的起止毫秒相同。
   - 星期：`java.time.DayOfWeek` 与 `kotlinx.datetime.DayOfWeek` 的序号和周起始；停录时段、预约重复规则里用到，逐一对照。
   - 文本格式：约定里若有把日期转成字符串存库或进备份的地方（如 `toString()` 得到 `2026-11-13`），新旧输出必须逐字相同。
4. 约定文件搬进 `shared/src/commonMain/kotlin/`，**包名不变**。搬不过去的（仍含 `File` 写入、`Uri`）留在 `:app`，在交付说明里说明原因。
5. `CaptureContract.kt` 里卡 172 新加的 `CaptureController.level: Flow<Float>`（带默认实现）保持原样。
