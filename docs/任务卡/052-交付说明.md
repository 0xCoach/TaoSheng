# 卡 052 交付说明

## 做了什么

- 增加本地预览通道偏好，默认关；当前版本是否预览由版本名判断。双文件各自先查魔搭、失败再查 GitHub，每次请求超时 15 秒，互不影响，按 versionCode 取大。正式来源拒绝预览版本名。
- 保存版本所属来源目录，下载、差异包和进程重启恢复都沿用正确目录。关闭预览通道会清掉该通道待下载/待安装的状态和通知，不降级已安装版本；已提交系统的安装不强行中断。
- 预览通道后台周期为 1 小时，正式为 6 小时；切换立即重排，开启立即检查。关闭自动检查时取消周期任务，启动与切换均不自动请求。通过 Application 生命周期监听，每次回到前台都走启动检查；正式保留 1 小时节流，预览不节流，旋转屏幕不额外检查。
- 预览通知显示“涛声 0.2.12 预览版 1 可以更新”，正文仍为说明第一行。跳过、稍后和通知去重仍按 versionCode。
- 强制装前快照改为 `files/pre-update/<毫秒时间>/` 最近三份，先完成新快照再删最旧的；兼容卡 051 单份目录及中断遗留目录。数据库、偏好快照与安装拦截机制沿用。
- 主进程和本地转写子进程均安装未捕获异常处理器，写 `files/crash/`，最多十条，再交回原处理器。记录版本、时间、线程、异常类名以及类名/行号；不记录异常 message、方法名和源码文件名，包含有限深度的 cause/suppressed。
- `LocalProblemReports` 导出版本、设备、通道、十条闪退、全部现有诊断及最近五十行更新诊断。全文遮掉 `sk-` 凭证及至少 32 位的十六进制/Base64 类长串。文件放在 `cache/problem-reports/`，复用现有 FileProvider；无上传逻辑。
- Gradle 支持 `-PpreviewNumber=1`，只追加版本名后缀，不修改 versionCode。未给参数时版本名不变。
- 发布脚本增加 `--preview`、通道校验、预发布创建/更新及固定 `preview-channel`。正式和预览的差异包基线都包含最近五个正式/预览发布，排除固定通道。所有整包/差异包先上传，通道说明最后上传；预览写入限定为 `preview/` 和 `update-preview.json`，设有断言。

## 稳妥处理与边界

- 现有诊断实际含有少量自由文本：片段保存错误曾带异常 message，守护详情可能带设备名称。因此导出时将片段错误改成有无记录、守护详情置空、转写最后错误改成布尔状态；数据库原记录和界面展示不变，步骤及数字保留。
- 自定义线程名可能包含用户文字，闪退仅保留常见系统线程名；其他显示“自定义线程”和线程 ID。调用链限制为八层、每层最多 128 帧，避免异常处理器无限展开。
- `export()` 不自动清掉闪退提示，界面在成功导出或用户关闭提示后调用 `dismissCrashNotice()`。已看时间持久化，重启不再重复提示。
- `--dry-run` 改为完全离线，不访问 GitHub/魔搭、不读凭证。默认无旧包；需验差异包时重复传 `--base-apk <旧包>`，最多五个。真实发布仍自动获取远端基线。
- 本卡没有改 UI、MainActivity、约定签名或数据库版本，没有新增依赖。

## 界面怎么接

1. 先检查 `AppGraph.isUpdaterReady`，从 `AppGraph.updater` 收集 `previewChannel`；开关调用 `setPreviewChannel(enabled)`。用 `isPreviewBuild` 判断当前版本小字，显示版本名时将 `-preview.` 换成“ 预览版 ”。
2. 先检查 `AppGraph.isProblemReportsReady`，从 `AppGraph.problemReports.lastCrashAt` 收集未看闪退时间。关闭提示调用 `dismissCrashNotice()`。
3. 协程里调用 `AppGraph.problemReports.export()`，成功后用 `FileProvider.getUriForFile(context, "${context.packageName}.files", file)` 取 URI；系统分享 Intent 使用 `ACTION_SEND`、`text/plain`、`EXTRA_STREAM`、`FLAG_GRANT_READ_URI_PERMISSION`，用 chooser 交给用户选择。不要用 `file://`。
4. 提示内点导出时，导出成功后调用 `dismissCrashNotice()`；导出失败保留提示并展示简短错误。不要另加启动检查，Application 已负责冷启动/热启动。
