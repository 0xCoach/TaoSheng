## 改动清单

### shared 纯规则（平台无关，零 android 依赖）

- `projects/ProjectActivity.kt`：统一时间线聚合——marks/关联事件与待办/决定/灵感及条目/经事件传递的条目/跟进合并去重（同一事实合并为一卡、保留来源计数），按事实发生时间倒序；行动分桶（pending/open/done/stalled），跟进归并到其指向的条目/灵感/决定，超期或多次提醒标 stalled。
- `decision/DecisionChains.kt`：决策演变链——`topicKey` + `supersededBy` 并查集分组，每条链选当前有效决定；同主题多条 Active 记为潜在冲突**只展示不自动废止**。
- `analysis/AnalysisData.kt`：`AnalysisType.PhaseReport` + 内置项目阶段报告模板（约定 `{"report":…}` 信封）；`AnalysisContract.displayText` 剥模型 JSON 信封（优先键命中 + 递归值扫描 + 长叶兜底，修掉了所有分析结果显示 `{"answer":…}` 的既有缺陷）；`runsForTarget`/卡死恢复查询。
- `decision/DecisionData.kt` / `data/MemoryDao.kt` / `inbox/IdeaData.kt`：项目范围一次性查询、事件→条目求交、关联回填（`fillNullProjectBySourceEvent/Item`、灵感 `projectId` 只填 NULL）。

### app 编排层

- `AnalysisRepository`：模板按名补种（老库也能拿到 PhaseReport）；`start()` 同目标同类型 Pending/Running 去重复用（防重复付费）；`failStaleRunning` 启动恢复（ResoundApp 接入）；`projectMaterial` 加决定含演变状态/灵感+轨迹/待办/跟进 + `windowStart` 窗口参数；水位 `sourcesJson` 照旧。
- `ProjectRepository`：`activity()`/`actions()` 调 shared 规则；`link()` 时把挂入事件/待办的来源决定、挂入灵感的 projectId 只填 NULL 回填——不覆盖已有归属。
- `DecisionRepository.reaffirm`：确认仍有效——写修订痕（`revisedAt/revisionNote`），不动 Active 状态、不生成新行。
- `GroundedQA.ask(projectId)`：项目作用域证据收集（marks/决定/灵感/关联事件与待办/跟进，`topicWords` 相关性过滤），来源编号与证据强度不变；`reply.content` 经 `displayText` 剥信封后再进 `EvidenceGuard`——全局问答同路径受益。

### UI（沿用 RsCard/RsType/胶囊/深色体系）

- `ui/projects/ProjectLink.kt`：可复用「所属项目」区块——已挂显示项目名+解除，未挂显示「挂到项目 ›」+ 项目选择弹层。
- `ui/today/TodayScreen.kt`：事件详情（EventSheet）与待办详情（ItemSheet）各挂一处，修掉 Event/Item 零写入者缺口。
- `ui/projects/ProjectScreen.kt`：项目详情重构为六分区——**概览**（本阶段进展、决策/否决/关联计数、最近变化、最近报告、标记胶囊、关联清单）｜**时间线**（统一事实卡，"N 个来源"计数）｜**行动**（待确认/进行中/已完成/卡住分组，卡住含超期红标，行内完成）｜**决定**（演变链分组、当前有效/已被替代/待确认冲突徽标、来源+变更依据、确认仍有效/否决/撤回带理由弹层）｜**报告**（本周/本月/全部窗口+确认弹层含用量提示、生成中状态、重开历史报告零重复调用）｜**问答**（项目作用域提问，"全部出自本项目记录"徽标、编号来源）。
- `ui/analysis/AnalysisScreen.kt`：报告结果卡同样走 `displayText`。
