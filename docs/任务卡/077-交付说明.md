## 已实现

- `AppGraph.importKinds` 提供预选、上次选择、带类型导入、按日/按记录观察、改类型和重新生成。沿用约定签名；执行期间任务卡追加的 `startBatch(...)` 已实现。
- 预选顺序：分享来源中可见的小米通话目录、文件名“通话”或电话号码 → 通话；明显不同的左右声道 → 通话；否则上次选择；首次默认会议。双声道探测检查前 90 秒，两侧有效能量及绝对相关性；相同声音的音量差、反相不作为通话线索。
- 会议/普通沿用原分人流程，不固定人数；培训固化 `separateSpeakers=false`；单声道通话的本地聚类传 `numClusters=2`，绕过单人预判。豆包正常请求后，客户端用声纹相似度把整份文件的编号归并到至多两组，不按编号猜身份。
- 双声道通话按左右声道分别解码、VAD、切段、转写，每侧不再调用分人。认人仍执行；唯一一侧确认是本人时统一标“我”，另一侧标“对方”，无法确认时保留“左声道/右声道”。原话按时间排序，同一时刻左侧在前。已按声道认人的原话不会被课堂模式的身份屏蔽规则隐藏。
- 三个内置模板 `import_meeting`、`import_training`、`import_call` 使用现有技能卡字段格式，隐藏、手动触发、不进定时技能调度。非普通类型强制生成一份纪要，不再让模型判断是否够资格；没有有效原话时保存明确说明无可用内容的卡。
- 长录音按约 25 分钟或约 18,000 字符（含行标注）分块，下一块带前块末句作衔接，再分层合并。各块的决定、结论、约定、行动、作业另做程序合并，防止最后一次模型汇总丢掉已有小结中的这些内容。
- 原有事件整理继续执行。纪要只把原话明确标为“我”的行动送进 `Pending` 待办；提示词带已有待办，要求同一行动沿用原文，确定的重复通过现有 `mergeInto` 合并，保留用户删除、编辑及状态。
- `import_records`、段关联、声道/人数设置及 25→26 迁移已加入，导出 Room schema 26；迁移统一加入 `CaptureDatabase.MIGRATIONS`。记录纳入现有按日增量备份，关联和纪要卡能往返恢复。
- 全组文件入库且各段转写、认人完成后，由持久化 Worker 自动生成。状态为 `Transcribing → Summarizing → Done`；转写或纪要失败显示 `Failed`，支持重试。进程重启会恢复待处理纪要；提交检查记录修订号和原话，删除期间返回的旧模型结果不会复活内容。
- 删部分段立即删除旧纪要，剩余部分重新生成；全删则记录及纪要一并删除。隐私范围删除、部分原话删除和失败段删除均覆盖。
- 改类型会删除旧卡；需要重新分人时把相关片段重新放入转写队列，保留已有事件引用。改培训直接清除说话人身份；普通不再生成纪要。
- 批量导入可按录制时间排序，将前后间隔 ≤5 分钟的文件合成同一条记录和一份纪要；缺录制时间的按选择顺序接在前一个结束时间后。`merge=false` 时各自一条，使用调用方提供的开始时间。队列中的合并信息持久化保存。

## 豆包接口核对

核对了官方 [说话人分离最佳实践](https://docs.volcengine.com/docs/doubao-voice/speaker-separation?lang=zh) 与 [流式识别接口](https://docs.volcengine.com/docs/DoubaoVoice/LargemodelstreamingautomaticspeechrecognitionAPI?lang=zh)。项目使用 `sauc/bigmodel_nostream`，公开参数未列出固定人数；不能把 AUC 的场景参数当成当前接口的固定人数能力。因此未传猜测字段，采用客户端声纹归并。

## 上下文与费用

- 25 分钟是时间上限，字符上限会使密集对话更早分块；原话不做截尾。常见一小时录音约 3 个小结请求加 1 个总纪要请求，密集原话或很长的小结会增加请求数。多人标注、时间戳和模板也占上下文。
- 粗估一小时中文录音，纪要额外约 **3万～5万输入 token、4千～1万输出 token**；这是估算，实际以服务端 usage 为准，已计入“技能”用量。事件整理与 ASR 另计。
- 若配置的输入/输出价格分别为每百万 token `P入`、`P出` 元，纪要约为 `(0.03～0.05)×P入 + (0.004～0.01)×P出` 元/小时。没有套用某家模型的固定单价，也没有实际请求收费模型测量。
- 单次原话约 18,000 字符外加模板、前句、已有待办；接入模型需有足够上下文。双声道分别转写，ASR 用量按实际送出的两侧片段累计。

## 边界与遗留

- 为支持改类型后重新分人，**有导入记录关联的临时片段保留至生成后 3 天**；原始分享副本仍在切段完成后清理，旧式无关联导入保持原来的清理规则。三天后或用户主动清理原声后，需要重分人的改类型会明确失败并提示重新导入；不需要重分人的改类型、纪要重新生成仍可使用原话。临时音频不随数据备份恢复。
- 声纹窗口不足或提取失败时，单声道通话保留原分人结果，并在记录 `error` 中说明没有强行合成两人。自定义 ASR 若只返回整段文字、没有说话人和细时间戳，无法据此恢复精确轮流发言。
- 双声道是信号线索，不是语义鉴定；开头长静音、只在后段出现左右差异可能漏判，立体声音乐也可能提供相似线索。最终类型仍由用户每次确认。分享方不提供目录信息时，不能凭 URI 数字推断小米文件夹。
- 待办精确重复会合并，语义改写依靠模型沿用已有待办要求；未把“同一行中的多个不同动作”粗暴合成一条。真实模型是否持续遵守仍需验收。
