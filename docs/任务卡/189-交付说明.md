## 做了什么

- `PipelineScheduler.offer` 收拢安卓执行机会；所有入口使用唯一 `PipelineGate`。Gate 在 shared 中处理锁、锁后重判、周期撞锁成功、手动/实时重试和回顾可取消等锁。
- shared 的 `PipelineCoordinator` 注入阶段与单调时钟，统一转写→声纹→整理、间隔整理跳过条件、force/manual 与重试汇总。`AndroidPipeline` 只适配现有 Runner、设备条件、声纹稳定锁和进度。
- `DigestRunner.runOutcome` 明确返回 Done / NothingToDo / Retryable / NeedsUser；取消仍抛 CancellationException。原 `run(force, manual): Boolean` 保留。主流程分为密钥快照、内存回复重放、缓存核对、在途保护、可整理分批、逐批执行与记录。
- `TranscribeWork.kt` 只保留 Worker、输入兼容和前台通知；系统请求安排独立为 `TranscribeScheduler.kt`。删除 `PipelineInProcess.kt`，功能归入唯一入口。
- 一轮诊断持久化一个 UUID；开始与结束覆盖同一行，保留七天/2000 行，附阶段耗时、等锁、结果与原因。回顾外层超时/跳过也更新同一行。无到期任务/自动撞锁不伪造执行记录、不记尝试。

## 改前/改后入口

| 入口 | 改前 | 改后 |
| --- | --- | --- |
| transcribe-periodic / digest-periodic / digest-timed-guard | 各自唯一周期请求，Worker 各带模式 | 升级取消三者；pipeline-periodic 每 15 分钟给机会，offer 用 PipelineDue 选当前到期模式 |
| transcribe-now | Worker 自行拿锁、执行、更新手动历史 | 同一 offer；保留 full 输入、manual 标签、加急及原排队策略 |
| transcribe-early | Worker 实时模式执行 | 同一 offer；实时开关在入口检查，原加急/攒批/原位提升保留 |
| digest-timed-recovery | 时间点补漏 Worker | 保留唯一请求与联网约束，offer 锁后读取 pendingTimed |
| 心跳/亮屏/接电/打开 App | PipelineInProcess 单独分支 | trigger 仅启动协程，调用 offer |
| 闹钟 | 广播→PipelineInProcess | 同一 PendingIntent 链，广播交接→offer，前后续下一次唤醒 |
| 回顾前 | beforeReview 自行等锁并执行 | offer(review) 等唯一锁；原外层十分钟额度仍包含等锁 |

周期请求无网络约束，实际执行按每个模式采样网络：这样本地转写可在断网下运行，联网整理由到期规则等待。手动/实时的原网络约束保持。闹钟以 `nextAlarm(intervalAt, timedAt)` 取有效候选最小值；现有设置的 Interval/TimePoints 互斥，未启用的候选传 null，保持模式行为。
