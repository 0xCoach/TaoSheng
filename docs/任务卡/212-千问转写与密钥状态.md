## 1. 千问接口实测结论（11-20 Claude 用测试密钥实测，证据在 `docs/任务卡/212-证据/`）

- 地址：`https://dashscope.aliyuncs.com/api/v1/services/aigc/multimodal-generation/generation`（北京老地址，**不用业务空间编号**即可用）。
- 请求（JSON，`Authorization: Bearer <key>`，`Content-Type: application/json`，不加 SSE 头）：
  ```json
  {"model":"qwen-audio-3.1-asr-flash",
   "input":{"messages":[{"role":"user","content":[{"type":"input_audio","input_audio":{"data":"data:audio/ogg;base64,...."}}]}]},
   "parameters":{"format":"ogg","speaker_diarization_enabled":true,"vocabulary":{"涛声":4}}}
  ```
  m4a 用 `data:audio/mp4;base64,` + `"format":"m4a"`；wav 用 `audio/wav` + `wav`。ogg/Opus 原样能收。
- **返回结构有重复嵌套**：`output.sentences` 和 `output.output.sentences` 都有；`output.sentence` 是把整段拼成的一句（**不要用**）。只认顶层 `output.sentences`（缺了再看 `output.output.sentences`）。时间单位**毫秒**，`speaker_id` 从 0 起，词级也有 `speaker_id`。`usage`：`duration`（秒）、`input_tokens`、`output_tokens`、`total_tokens`（顶层 `usage` 与 `output.usage` 都有，读顶层，缺了读 `output.usage`）。
- **不开说话人分离时没有 `sentences`**，只有 `output.sentence`（整段一句）+ `words[]`（每词 `text`、`punctuation`、`begin_time`、`end_time`）+ `output.text`。要自己按词切句（见 3.2）。
- 同一段音频两次返回分句可能不同；有一次文字里带“跟， 下周”这种标点后多余空格。
- **超过 5 分钟不报错，静默只转前 5 分钟**（302 秒音频返回 usage.duration=300，后面的话丢了）。
- 正好 300 秒：正常，约 15 秒返回，73 句，约 5900 token。
- 密钥错：HTTP 401，`{"code":"InvalidApiKey","message":"Invalid API-key provided."}`。
- 官方文档说明的其他错误：429 / `Throttling*`（限流）、5xx；内容审核不过为 400 + `DataInspectionFailed`（以 code 判断，不以文案判断）。

## 2. 设置：自定义里分“接口格式”，两套配置各存一份

- 新增平台无关枚举（`:shared`）：`CustomAsrApi { OpenAi, Qwen }`，默认 `OpenAi`。
- 两种接口**各存一份**地址、模型、密钥、地址写法（`CustomEndpointMode`）、附带热词开关；切换接口时载入那一份，不用重填（做法参考 #52 豆包普通/Agent Plan 两种 Key 分开存）。
  - 现有 `endpoint`/`model`/`endpointMode`/`customPrompt`/`customEncryptedKey` **原样作为 OpenAi 那份**，不搬数据、不改字段名。
  - Qwen 那份用新字段（如 `qwenEndpoint`/`qwenModel`/`qwenPrompt`/`qwenEncryptedKey`）。首次切到 Qwen 时**预填**地址 = 上面的北京地址、模型 = `qwen-audio-3.1-asr-flash`，热词默认开；用户可改。不做新加坡快捷项。
  - Qwen 一律按“完整地址”原样请求（用 `fullEndpoint()` 校验），不做自动匹配、不拉取模型列表。
- OpenAi 那份新增“说话人格式”：`CustomSpeakerFormat { Auto, Diarized }`，默认 `Auto`（即现在的 verbose_json → json 行为，不变）。
- 请求头（卡 116 `TranscribeHeaders`）仍按 `TranscribeSource.Custom` 一组，两种接口共用，不拆。
- `identity()` 要包含接口格式和说话人格式（配置变了要能区分）。

## 3. 千问请求与解析（`:shared`，新文件如 `net/NetQwenAsr.kt` + `net/QwenTranscription.kt`）

### 3.1 请求
- 读整段音频转 base64 data URI（5 分钟 ogg 约 0.9 MB、m4a 约 2～3 MB，内存可接受；不要为此引入新库）。
- `parameters.format` 按 `AudioUpload.format`（ogg / m4a / wav）；`speaker_diarization_enabled` = `separateSpeakers`。
- 附带热词开关打开时发 `vocabulary`：热词去重、去空白后按现有顺序（`Hotwords` 合并结果的顺序即频率/优先顺序）取前 **500** 个，权重统一 4；不用超级热词（50）。热词为空不发该字段。
- 不发 `language_hints`（让模型自动识别，中英混说更稳）。
- **发送前查时长**：`durationMillis > 300_500` 直接抛不可重试错误，文案“这段超过 5 分钟，千问接口转不了”（正常切段不会触发，属防御）。
- 超时沿用 `CustomAsrProvider` 现有的那套长超时网络客户端。

### 3.2 解析
- 有 `output.sentences`：每句 `begin_time`/`end_time`（毫秒）→ `AsrSentence`；`speaker_id` 按首次出现顺序重编 `"0"`、`"1"`…（与卡 196 规则一致）；关掉区分说话人时全部 null。坏句（end ≤ begin、文字空）丢弃，超时长截断，按开始时间排序。
- 没有 `sentences`：用 `output.sentence.words` 切句——词文字 + `punctuation` 拼接，遇到句末标点（。！？!?；; 和 …）断句；单句超过 60 字且遇到逗号也断；句子时间取首词 begin 到末词 end；无说话人。`words` 也没有时退回 `output.text` 一条（0～时长）。
- 返回 `AsrResult` 时带上 token 用量（见第 6 节）。

### 3.3 错误分类（千问）
- 401/403 或 code `InvalidApiKey` → `AsrError.Auth`（“鉴权失败，请检查密钥”）。
- 429 或 code 以 `Throttling` 开头、5xx → 可重试（现有 Server 类）。
- code `DataInspectionFailed` → **不可重试**，记为“没转成”，文案“内容没通过千问审核，这段跳过”；不要进入自动重试循环（核对 `TranscribeRunner` 的重试逻辑，确认不可重试错误不会被反复调度）。
- 其余 4xx → 不可重试的协议错误，`detail` 带服务返回的 `code`（不带音频、不带密钥）。

## 4. OpenAI 分说话人（#48）

- `CustomSpeakerFormat.Diarized` 时：`response_format=diarized_json`，加字段 `chunking_strategy=auto`，**不发 prompt**（OpenAI 的 diarize 模型不收）。
- 返回 `segments[]` 带 `speaker`（如 "A"/"B"）、`start`/`end`（秒）——现有 `customTranscription` 已能解析，核对一下即可，补一个用例。
- 服务拒绝 `diarized_json`（4xx 非 401/403/429）时**不静默退回**：抛不可重试错误，文案“这个模型不支持分说话人，请把说话人改成自动”。`Diarized` 不参与卡 196 的“记住只支持 json”。

## 5. 密钥状态与测试结论（#56）

- 新增（`:shared` 数据类/枚举，Android 设置实现）：
  - `CustomKeyState { None, Saved, Verified }`：当前接口那份**真的存了密钥**才是 `Saved`；只有地址和模型 → `None`。请求头里有非空值也算“有凭据”（与现有逻辑一致）。
  - `CustomCapability { Speakers, TimedText, TextOnly }`：3 秒测试通过时记下——Qwen → `Speakers`；OpenAi + Diarized 通过 → `Speakers`；OpenAi + Auto 且 verbose_json 成功 → `TimedText`；退回 json 才成功 → `TextOnly`。
  - 测试通过 → `Verified` + 记下能力；**地址、模型、密钥、接口格式、说话人格式任一改变 → 清掉验证和能力**。每种接口各记各的。
- `hasKey`（“能不能用”）语义保留，修掉“只填地址模型就当密钥已保存”的混用：界面改用 `keyState` 显示密钥框；`hasKey/ready` 仍决定能否转写（本地自建服务可以无密钥）。
- `saveCustomAll` 的保存结果要能告诉界面“这次是否真的存了密钥”（返回值或状态流，任选，写进约定）。
- 验证状态和能力**不进备份**（恢复后一律未验证）；接口格式、两套配置、两套密钥、说话人格式、热词开关**进备份**（照卡 190 的设置备份分类，守卫测试要过）。
