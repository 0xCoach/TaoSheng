# 设备播放记录与外放归属

上游可独立合并的「播放检测 + 外放归属」：不开通知使用权时，外放片段整理会标「手机在外放」；用户打开「记录播放标题」并授权后，标注可带上 App 和节目标题。屏幕时间采集、每日推送、今日卡片、问问 `apps_during` 不在本范围。

## 功能

- **记录播放标题**（默认关）：独立于屏幕时间。关闭时播放事件零写入；打开后若系统里已有正在播放的媒体会话，立即补记为开始。
- **通知使用权**：打开标题开关但没有通知使用权时，原话设置页显示「去开启」。不读通知内容。系统撤销授权时保留已有历史，并记一段缺口。
- **外放标注**：麦克风片段扬声器外放满 3 秒时：
  - 能匹配到播放记录 → `外放：可能是 某App《标题》` 或 `外放：可能是 某App`
  - 否则一律 `外放：手机在外放`
  - 不再出现「来源未知」「前台 App 兜底」或「在用」情境行。
- **基础层播放检测**（默认开启，不需要任何权限）：在原有 `PlaybackMonitor` 上扩展出可订阅的 `StateFlow<PlaybackState>`，区分「任何媒体在放」和「可能走扬声器外放」，应用级单例，录音输入以后也能订阅（见下文）。外放判定规则不变。
- **整理时带上 App 与播放信息**（默认开）：独立于「整理时参考地点和环境音」。关掉后普通整理和重新整理都不查播放记录，提示词只保留 `外放：手机在外放`，不出现 App 或节目名。读取门控在 `LocalSituationLookup` 一处：只有「记录播放标题」开且本开关开才查库；关掉标题开关后，以前记下的节目名也不会再进提示词。
- **一步选择**：被跳过转写的外放片段，原话页是「只转写」和「转写并整理」两个按钮。一次写入 Pending，并分别把 `playbackDigest` 写成 1 或 2。已转写、仍暂不整理的片段，保留「参与整理」补救按钮。
- **外放内容也参与整理**（默认关）：和外放声音时不转写放在同一设置容器。新片段落库时，外放占一半以上的按此开关写初始 `playbackDigest`（关=1，开=2），普通片段写 0。外放声音时不转写关掉、外放片段自动转写时，这个开关同样生效。
- **新开关只影响打开之后录下的片段**。旧数据的 `playbackDigest` 保持 0，不回填。用户主动重新整理（`RedoFactory`）不加 `playbackDigest` 过滤。

## 设置位置

「原话与转写」页外放区域：「外放内容也参与整理」紧挨「外放声音时不转写」；「整理时带上 App 与播放信息」在「记录播放标题」下方，只在标题开关开启时显示。两个新开关都是用户设置，随设置备份。

## 以后录音输入怎么订阅

播放状态现在是应用级单例，装配在 `AppGraph.playback`（`ResoundApp.onCreate` 同步赋值，主进程内随时可读）。两个入口：

1. **被动订阅**（推荐给蓝牙让路这类要响应变化的场景）：
   ```kotlin
   scope.launch {
     AppGraph.playback.state.collect { state ->
       // state.playing：任何媒体在出声（含耳机/蓝牙），蓝牙麦克风让路看这个
       // state.speakerPlaying：可能走扬声器在出声，外放判定看这个
     }
   }
   ```
   首个订阅者出现时系统回调才会注册并发布真实状态；订阅时立即收到当前值（无订阅期间保持的最后一个值，上游启动后会立即重算纠正）。协程取消即退订，无需任何 close。
2. **一次性读值**（录音服务现行做法）：`AppGraph.playback.state.value.speakerPlaying`。注意：若全进程无人订阅，流不会被刷新，`value` 可能是旧值或初始全 false；需要新鲜值的消费方自己保持一条订阅（参照 `CaptureService.onCreate` 的写法）。

不要自己 new `PlaybackMonitor`（会双份注册系统回调）；判定不要绕过 `state` 流另读 `isMusicActive`。`playing` 与 `speakerPlaying` 语义不同：外接输出（耳机/蓝牙 A2DP）在放时 `playing=true` 而 `speakerPlaying=false`，蓝牙麦克风让路必须用 `playing`，用外放布尔会漏检耳机播放甚至造成路由自激。

## 数据库 34→37

沿用已定的三步迁移和五张表结构，本范围不改 schema。屏幕时间四张表在本版本中是空表；播放断连缺口仍写在 `screen_coverage_gaps`（source=`playback`）。隐私删除仍会清这五张表。

当前 `CaptureDatabase.VERSION = 37`。升到最新版本的测试断言用 `CaptureDatabase.VERSION`。

## 真机注意事项

- 目标机：小米 14 Pro（澎湃 OS）。通知使用权是系统特殊权限，应用里只能跳转，不能代开。
- 关闭「记录播放标题」时不应写入播放行；打开时若正在外放播客，应立即出现一条开始记录。
- 不开通知使用权时，外放片段整理标注为「手机在外放」。
- 关掉「整理时带上 App 与播放信息」后，整理提示词只有「手机在外放」，即使库里已有节目名。
- 需要看的界面：设置 → 原话与转写（记录播放标题、整理时带上 App 与播放信息、外放声音时不转写、外放内容也参与整理）；原话页外放跳过态的「只转写 / 转写并整理」，以及已转写暂不整理的「参与整理」。
- 两个新开关只影响打开之后录下的片段。
