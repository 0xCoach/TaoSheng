# 102 交付说明

## 修复范围

- `LocalBackupFiles.access`、`setLocalFolder`、导出的写入与回读阶段均记录诊断；保留异常类名，系统原因按白名单提取，不写原始异常消息、堆栈、URI、路径或文件内容。未识别的消息记为 `reason omitted`，避免提供方把隐私混进日志。
- 持久授权抛 `SecurityException` 后继续实测本次授权；成功才保存文件夹，并设置 `sessionOnly=true`。新进程没有该临时标记，且未找到持久读写授权时，返回 `NeedsReauthorize`。
- 选择文件夹时创建随机命名的两字节探测文件，写入、读回、删除全部成功才接受。不以 `canRead/canWrite` 为拒绝条件；失败会尽力清理探测文件。
- 输出流按 `wt → w → rwt` 尝试；空流或明确的模式不支持/模式无效才回退，权限、空间等其他错误不盲目重试。文件完整写入并关闭后校验 SHA-256；写入失败与写后读回失败分别提示，失败不会触发成功后的历史清理或快照清除。
- 对根目录不做厂商或 URI 路径特判，通过实际探测判断是否可用。不能创建、写读删除探测失败或模式耗尽时提供位置不可用提示；授权丢失或探测遇到 SecurityException 时提供重新授权提示。
- 单文件导出与导入不依赖已选备份文件夹，失败不修改文件夹访问状态。不申请所有文件访问权限。

## Contract 和界面交接（尚需 Claude 接入）

本卡明确允许的 `BackupContract.kt` 变更为追加两个有默认值的字段，既有构造调用可继续使用：

- `folderAccess: LocalFolderAccess?`：未选且未发生访问错误为 null；`Ok` 为授权可用；`NeedsReauthorize` 为持久授权丢失或实际访问被拒绝；`Unsupported` 为位置不可写。状态在仓库初始化、刷新或实际访问时检查，不是系统权限变化监听器。
- `sessionOnly: Boolean`：仅本次进程临时授权有效。应提示重启后重新授权。`Ok` 不代表持久授权成功，应同时看此字段。

新增 `app.resound.backup.LocalBackupFolderContract`，显式请求 READ、WRITE、PERSISTABLE、PREFIX 四个授权标志，输入输出与 `OpenDocumentTree` 一致。

**按本次“不改 BackupPage.kt / 不写 ui”的限制，现有界面尚未接入此选择器，因此现有入口还不会主动附加这些标志。** Claude 需将 `BackupPage.kt` 的 `rememberLauncherForActivityResult` 中 `ActivityResultContracts.OpenDocumentTree()` 替换为 `app.resound.backup.LocalBackupFolderContract()`；回调无需修改。授权状态展示也由 Claude 完成。底层兼容逻辑已生效，但完整的选择器修复要在这一行接入后才生效。

## 诊断获取

- 新增 `BackupDiagnostics`，参考现有更新诊断实现，写入应用私有 SharedPreferences `backup-diagnostics` 的 `runs`，最多保留 50 行。
- 每行含时间戳、阶段（persist/access/setLocalFolder/open-模式/export-write/export-readback/probe）、异常类名及脱敏原因。
- 已在 `RoomCaptureStatsRepository.exportDiagnostics()` 和 `LocalProblemReports` 接入。鸿蒙用户复现后点击现有“导出诊断记录”，通过系统分享发送文本给负责人；问题报告也包含这些记录。无需 adb 或额外存储权限。
