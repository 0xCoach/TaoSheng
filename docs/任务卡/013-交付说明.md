## 实现

- 5 分钟硬切保留尾部 1 秒原始样本，新段起点同步回退 1 秒；自然 2 秒静音结束不变。连续半小时输出六个最长 5 分钟段和一个约 6 秒尾段。重叠可能产生少量重复文字，未做跨段文本去重。切段只解决音频连续性，不承诺模型自动把所有段整理为同一事件。
- AudioPlaybackCallback 加输出设备变化监听，过滤通知、闹钟、导航等 usage；API 33+ 尝试直接路由，拿不到时用输出设备列表保守排除耳机/蓝牙/USB/远端输出。回调随录音服务释放。
- 按实际样本累计片段外放占比，含前滚和硬切重叠；>=50% 且开关开启时存 SkippedPlayback。外放元数据在 PCM spool 同名 sidecar 保存，正常结束完整保存，进程死亡时最多欠计未刷新的约 1 秒外放时间；未知旧暂存片段按正常转写处理。
- 数据库 v8 新增 playbackMillis 默认 0，Migration 7→8。跳过片段不进入转写/整理队列；1 天后沿用清理流程删音频，诊断汇总数量。原话页已有的“仍然转写”按钮接通 Pending + runNow，已删音频不重新入队。
- AppGraph.playbackSkip 提供默认开启的持久化设置接口。**设置开关界面仍需 Claude 接入**，本次遵守分工不改 UI；手机当前默认开启。
- 版本更新为 versionCode 2 / 0.1.1-验证版。

## Android 能力边界

官方说明 getAudioDeviceInfo 已在 API 36 废弃，原因是路由信息未被填充；普通 App 播放回调身份匿名化，不能用公开 API 可靠读取其他播放器 UID。实现对空路由提供上述保守降级，未使用隐藏 API 或申请系统权限。当前源码没有本 App 音频播放器；未来新增播放器时需另接自播放排除标志，不能声称已支持任意自身播放器识别。

参考：https://developer.android.com/reference/android/media/AudioPlaybackConfiguration

外放过滤尚未在真机播放视频、插拔耳机完成端到端验收；路由缺失时外接设备存在会保守放行转写，避免误跳过真人说话。不是对所有机型/播放器都精确的声源识别。
