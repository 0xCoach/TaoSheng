# 任务卡 006：声纹——认出“我”

## 目标

每段录音转写完后，在手机本地用声纹判断哪些句子是负责人（“我”）说的，写进转写句。整理（大模型）拿到的原话里，负责人就显示为“我”，提取出的待办归属才准。全程本地计算，声音不上传。

## 约定（Claude 已写，不要改签名）

- `voiceprint/VoiceprintContract.kt`：`VoiceprintRepository`、`VoiceprintState`、`VoiceprintThresholds`。
- `transcribe/TranscribeContract.kt` 的 `TranscriptLine` 新增 `speakerScore`。
- 在 `AppGraph` 加 `voiceprint: VoiceprintRepository` 并在 `ResoundApp` 装配（AppGraph 可以改，只加这一项和一个 `isVoiceprintReady`）。
- **不要改 `ui/` 和 `MainActivity.kt`**，界面由 Claude 做。

## 技术方案（已定）

1. **模型**：说话人特征（embedding）用开源中文模型，优先 3D-Speaker 的 CAM++ 中文版（`3dspeaker_speech_campplus_sv_zh-cn_16k-common`，sherpa-onnx 发布的 onnx，Apache-2.0）。放 assets，交付说明写来源、版本、大小、许可。
2. **运行方式二选一，由你实测决定并在交付说明写理由**：
   - A. 用项目已有的 `onnxruntime-android` 直接跑模型，自己用 Kotlin 实现 80 维 Kaldi fbank（与 sherpa-onnx 的预处理一致，需和 Python 参考实现逐值对齐，误差写进说明）；
   - B. 引入 sherpa-onnx 安卓库。注意它自带 onnxruntime 的 .so，会和现有 `onnxruntime-android` 冲突；必须解决（例如把 Silero VAD 也改用 sherpa-onnx 的实现并去掉旧依赖，或确认可共存），且不能让现有人声检测行为变化。
   安装包体积增加控制在 40MB 以内。
3. **何时算**：转写成功（Done）后、录音被删之前。按“(录音段, 云端说话人编号 speakerTag)”分组：把这组所有句子的音频拼起来（只取句子起止范围内的声音，去掉静音），≥1.5 秒才算特征，和“我”的样本比余弦相似度，结果写到这组每一句。
4. **“我”的样本**：存每条样本的特征向量（不存原始音频），用所有样本的平均作为“我”的代表（可再加最高分匹配，实测取优）。`markMe`：把那组声音加为样本；`markNotMe`：该组清空“我”，并记为排除，以后同一组不再自动标。`enrollPcm`：直接用传入音频建样本。
5. **写结果**：分数 ≥ `VoiceprintThresholds.MAYBE` 时写 `speakerName = "我"` 和 `speakerScore`；低于则 speakerName 不写（保持 null），speakerScore 照样记下。样本还不够（`ready == false`）时不比对、不阻塞后续流程。
6. **和整理的衔接**：`segments` 加“声纹已处理时间”。`DigestRunner`（`digest/DigestRunner.kt`）挑句子时，只要声纹 `ready` 就等该段声纹处理完再整理；没 ready 则照旧不等。这处改动很小，可以改。
7. **数据库**：升到 v4，写 Migration 3→4（transcript_lines 加 `speakerScore REAL`；segments 加声纹处理时间；新表存样本：id、来源（line/enroll）、来源句子或组、向量（BLOB 或 JSON）、时长、创建时间；排除组表）。迁移测试要覆盖 1→2→3→4 整条链。
8. **跑在哪**：放进现有 `TranscribeWork` 的流程里，转写后、整理前；同样一次只跑一轮。

## 先离线验证再上手机（必须）

在 `tools/voiceprint-probe/` 用 Python（sherpa-onnx 或 onnxruntime）先测：
- 用 macOS `say` 的 3~4 个中文音色各合成几段话，当作不同的人；用其中一个音色的 3 段做“我”的样本；
- 输出同人 / 不同人的相似度分布，给出建议阈值（替换约定里的 0.62 / 0.50 时在交付说明里提出，由 Claude 改约定）；
- 再用手机上真实录音（`adb exec-out run-as app.resound` 读 `files/segments` 下的 ogg）看看分数是否合理。
