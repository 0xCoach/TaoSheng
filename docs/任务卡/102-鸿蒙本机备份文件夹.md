# 102：鸿蒙手机本机备份、导出提示“本机文件夹无法访问，请重新选择”

## 现象

- 用户反馈：在鸿蒙系统（兼容安卓应用的那种）上，选择备份文件夹、立即备份、导出一份都用不了，界面提示“本机文件夹无法访问，请重新选择”。用户的理解是“要先给文件夹授权，缺权限时应弹出授权请求”。
- 负责人手上没有鸿蒙机，**根因没在真机上确认过**。目前只在代码里找到了几个可疑点。

## 代码里的可疑点（Claude 已读）

1. `LocalBackupFiles.access {}` 把所有异常都吞成 `INACCESSIBLE`，`AndroidBackupRepository.setLocalFolder()` 也用 `catch (_: Exception)` 吞掉。真实原因完全看不到，这是第一个要改的。
2. `select()` 选完文件夹后马上调用 `takePersistableUriPermission(读 | 写)`。有些系统的文件选择器不带“可持久授权”标志，这一步就会抛 `SecurityException`。`OpenDocumentTree` 也没有显式请求可持久、可写的授权。
3. `folder()` 用 `DocumentFile.canRead()/canWrite()` 判断能不能用。部分系统的文件提供方不报告写入标志，导致明明能写也被判成“不可访问”。
4. `export()` 用 `openOutputStream(uri, "wt")`。部分文件提供方不支持 `"wt"` 模式（会抛 `FileNotFoundException`，或者返回空）。“导出一份”走的是 `CreateDocument`，本来不需要文件夹授权，却也报同样的错，很可能就是这个原因。导出后的回读校验同理。
5. 安卓 11 及以上不允许选存储根目录或 Download 根目录本身，界面提示里写的是“建议在 Download 里新建 Resound”。鸿蒙的选择器可能允许选根目录，但选了之后写不进去。

## 修改要求

按“兼容各家系统的文件选择器”这一类问题来修，不要只针对鸿蒙写特殊分支。

1. **先能看到原因。** 在 access、setLocalFolder、export 这几处，把真实异常的**类名和系统给的简短原因**记进现有的诊断日志（参考仓库已有的诊断写法）。不记文件路径、URI、文件内容。界面文案不变。
2. **选文件夹**：通过自定义 `ActivityResultContract` 或 Intent，显式加上 `FLAG_GRANT_READ_URI_PERMISSION | FLAG_GRANT_WRITE_URI_PERMISSION | FLAG_GRANT_PERSISTABLE_URI_PERMISSION | FLAG_GRANT_PREFIX_URI_PERMISSION`。`takePersistableUriPermission` 失败时不立刻判死，继续用本次授权试写。能写就保存文件夹，并标记为“授权只在本次有效”，下次重启后需要重新授权。
3. **用实际试写代替 `canWrite()` 判断**：在文件夹里建一个小探测文件，写入、读回、删除；三步都成功才算可用。`canRead/canWrite` 只作参考，不能单独判死。
4. **写文件**：`openOutputStream` 依次尝试 `"wt"` → `"w"` → `"rwt"`；遇到“模式不支持”就换下一个，其他错误照常抛出。读回校验失败时，区分“写进去了但读不回”和“写不进去”，各给不同的中文提示。
5. **权限丢失的状态和错误类型要区分开**（界面由 Claude 做，你只提供状态和数据）：
   - 在 `LocalBackupState` 加一个字段，例如 `folderAccess: Ok | NeedsReauthorize | Unsupported`，并写清注释。
     - `NeedsReauthorize`：已保存的授权不在 `persistedUriPermissions` 里，或者试写时报 `SecurityException`。
     - `Unsupported`：选了根目录这类不可写的位置，或者多种写入方式都试过还是失败。
   - 错误文案按原因分开：
     - 授权失效：“备份文件夹的授权已失效，请重新授权”
     - 位置不可写：“这个位置不能写入，请在 Download 里新建一个文件夹再选”
     - 其他：保留“本机文件夹无法访问，请重新选择”
   - 不要在 `BackupPage.kt` 里加新界面；如果需要改 Contract，在交付说明里写清楚。
6. 不申请“所有文件访问”（MANAGE_EXTERNAL_STORAGE）这类大权限。

## 测试（适度）

新增 `LocalBackupAccess102Test`，用 5～8 个用例，模拟各种文件提供方的行为：
- 不支持 `"wt"`、支持 `"w"` → 导出成功
- `canWrite()` 返回 false 但实际能写 → 选择成功
- 持久授权抛 `SecurityException` 但本次能写 → 选择成功，并标记授权只在本次有效
- 授权丢失 → 状态为 `NeedsReauthorize`，文案正确
- 不可写的位置 → 状态为 `Unsupported`，文案正确
- 诊断日志只含异常类名和原因，不含 URI 或路径
