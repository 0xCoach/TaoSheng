# 030 交付说明

分支：`codex/030-push-review`

## 做了什么

- 新增日报正文生成：Markdown 使用日期、星期、导语和栏目列表；纯文本使用 `【栏目】`。按原栏目顺序输出，跳过空栏目，“一句话”只作导语，缺少时回退到 `brief`。
- 远端日报标题为 `回响 · 10月23日回顾`。通用网址选择 JSON 时沿用现有消息外壳，`body` 为纯文本完整版，新增 `review: {date, brief, sections: [{title, lines}]}`，不包含事件出处。
- 每日回顾通过 `ChannelNotifier` 内部重载传递日报：本地通知保持原标题和 `brief`，远端按各通道格式使用完整版。`Notifier`、所有约定文件签名均未修改。
- 通道测试读取 `ReviewRepository.recent()` 的第一条。有日报时标题加 `测试 · `，成功返回 `已发送 10月23日的回顾`；无日报时保留原测试消息及成功文案。日志记录实际标题。
- 主动测试不受每日回顾推送开关、通道订阅主题和通道启用状态限制，沿用原主动测试行为。读取日报失败时返回明确错误，不伪装成“没有日报”。
- 重试队列保留完整日报结构，恢复后仍按目标通道格式生成正文；兼容没有 `review` 字段的旧消息。
- 只修改后端装配、推送、回顾实现及相关测试，没有修改 `ui/`、`MainActivity.kt`，没有变更依赖。

## 怎么验证的

使用 JDK 21，只运行本卡新增的 `ReviewPushTest`，共 4 个测试：

1. Markdown / 纯文本格式、导语与空栏目处理、JSON 结构、重试载荷序列化及旧载荷兼容。
2. 有日报时选最近日期；关闭每日推送、通道及订阅主题后仍能主动测试；成功文案、日志、失败后重试保留日报。
3. 没有日报时保留原测试正文、成功文案及日志。
4. 真实仓库定时推送路径中，本地使用简洁摘要，两个远端通道分别使用 Markdown / 纯文本完整版。

```sh
JAVA_HOME=/opt/homebrew/opt/openjdk@21 ./gradlew :app:testDebugUnitTest --tests app.resound.push.ReviewPushTest assembleDebug
```

结果：`BUILD SUCCESSFUL in 40s`，4 个测试全部通过，无失败、无错误；未跑全量测试、未重复回归。首次命令因沙箱禁止写 Gradle 缓存而在启动阶段退出，单次提权后完成上述验证。
