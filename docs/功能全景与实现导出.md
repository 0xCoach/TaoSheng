# 声声不息 功能全景与实现导出

> 给 Opus 分析用。分三层：**上游原生（M0 基线）/ 我方新增（M1/M2/M2+/R4）/ 本轮可靠性修复**。
> 每项标注验证状态（真机实测 / 单测 / NOT_TESTED）。仓库 `D:\ts-link`，分支 `dev/m0-m1-m2`，包名 `app.resound`。

## 0. 架构总览

- Kotlin + Compose，minSdk 29 / targetSdk 35 / compileSdk 36；手工 DI（`AppGraph`），无 Hilt。
- `:shared` KMP 模块：Room 库（`CaptureDatabase`，v38，37+ 条迁移）、DAO/实体、纯规则（供 iOS 复用，禁 android/java 引用）。
- `:app`：录音前台服务、转写/整理流水线、UI、WorkManager 调度、spool/对账。
- `:devices`：外设插件。
- 本地 ASR 在独立进程 `app.resound:local_asr`（sherpa-onnx，CPU/SM8650-NPU 两档模型）。
- 时间统一 `platform.NowMillis` 接口注入；并发全部结构化协程 + Mutex，无阻塞锁。

## 1. 上游原生能力（M0 基线，`v0.4.0` 固定）

全天录音 → VAD 人声段（`segments` 表，状态机 Pending→Running→Done/Failed/Skipped*/Abandoned）→ sherpa SenseVoice 本地识别（中/英/日/韩/粤，Int8 量化）→ `transcript_lines`（句级时间戳+说话人）→ 整理管线产 `memory_events`/`memory_items`（待办/约定/决定等类别，Pending→Accept 确认流）→ `reviews` 每日回顾、`things` 寻物、`topics` 专题、`day_diary` 日记、技能卡片、`embeddings` 向量检索、声纹分人（pyannote 3.0）、环境音判定（`env_sounds`，媒体声跳过）、原声保留策略、重做（重转/重整理 `redo_snapshot`）、WebDAV 备份恢复、WorkManager 批量转写（`TranscribeScheduler`/`TranscribeRunner`，`heavy` Mutex 串行重活：环境音→分人→识别互斥）、失败分级退避（`attempts/nextRetryAt/firstFailedAt`，网络类不耗重试次数）。

## 2. 我方新增功能（M1/M2/M2+）

### M1 提供方与诚实降级
- OpenAI 兼容服务管理：自定义 base URL/model/key，多提供方切换、连通性测试、超时与失败归类。
- 未配置时如实显示「等待配置服务」，无静默降级到付费云、无暗 fallback。
- 每日用量聚合/报告（`asr_usage`、`usage` prefs）。

### M2 第二大脑骨架
- **IdeaInbox 灵感收件箱**（`ideas` 表 + IdeaRepository）：语音灵感自动入库，手动标记/分类/合并，指纹去重，成熟后转待办/项目。
- **ProjectMemory 项目记忆**（`projects`）：长期项目关联录音/灵感/待办/决策。
- **AIAnalysis 分析**（`analysis_runs`）：对录音/灵感/项目/整天发起深度分析，结果带模板与来源追溯。
- **AgentBridge 外派**（`agent_tasks`/`agent_endpoints`）：深度研究/调研/写需求派给外部 AI；**仅建 Pending 待确认任务，用户确认才出网**，端点密钥走 Secrets。
- 无 AI 全流程可用：手动标记/分类/项目/建任务/导出不依赖 LLM。

### M2+ 耐用记忆层
- **决策记忆**（`decisions`）：生效/被否决/被替代/撤回四态 + topicKey 同主题冲突检测 + confidence（Sure/Likely/Tentative）+ 原话/条目/事件/灵感四级证据外键 + 修订链。
- **主动跟进**（`followups`）：发现「说过要做没下文」的事，限频（FollowupRules）、AI 建议标注非承诺、`followup_events` 触发工作流。
- **统一收集箱**（`capture_items`）：ACTION_SEND/SEND_MULTIPLE 收 text/link/image/audio，文件复制进私有目录，**图片本地 OCR**，可挂灵感/项目/原话；`extracted` 字段三态（Saved/Extracted/Analyzed）。
- **工作流规则**（`workflow_rules`/`rule_runs`）：手动/定时/事件 → 通知/建待办/跑分析/派任务（派任务仍只建待确认）。
- **修订与撤销**（`revisions` + MemoryCorrector）：纠错留痕可回退。
- **落地问答**（GroundedQA）：跨库检索 + 每条结论带来源编号（原话行/事件/灵感/决策），无证据明说。
- **本地只读 MCP**（`mcp_clients`）：电脑 AI 经本机令牌认证只读查询记忆，可按项目限权。

## 5. 设备与性能事实

- 真机 = **PGU110 / SM8475（骁龙8+ Gen1，ColorOS 系）**，非此前记录的小米 14 Pro。
- `npuSupported()`=SDK≥31 且 SOC==SM8650 → 本机正确隐藏 NPU 选项；Sherpa QNN 仅出 SM8650 二进制，硬件无解。SM8650 机型上 NPU 选项自动出现、App 内下载即用（~162MB 模型）。
- 本地 CPU 转写吞吐 ≈ 3.4 段/分钟；`heavy` Mutex 串行为刻意设计（并发 CPU 推理只会互相抢核+降频）。
- 241 段/3h 积压已于 22:04 全部消化完毕。
