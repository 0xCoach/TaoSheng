# 定时整理补漏与鸿蒙后台延迟排查

## 交付范围

基线：PR #39 已在 GitHub 合并，主干提交 8b5c5ce。该 PR 修复 D3200 音频与补传，不包含本次定时整理修复。
本次在 fix/timed-digest-recovery 分支实现“指定时间点”整理补漏；间隔整理模式保持原规则。未修改 UI、MainActivity 或 Contract 签名，无数据库迁移。

## 已确认的代码问题

1. 旧闹钟接收器把执行窗口截到计划时间后 30 分钟，窗口过期直接跳过。网络恢复或后台任务真正获得执行机会较晚，也会在 Worker 中再次被判定过期。
2. 进程重启只计算严格晚于当前时间的下一次闹钟，未持久化核对过去时间点是否执行过。
3. 到点流水线返回临时失败时，旧 Worker 仍返回成功，不执行退避重试。

以上是源码确认的可靠性缺口；目前没有连接设备，未获取用户鸿蒙机型、系统版本及问题记录，不能认定某一缺口就是此前手机上那次故障的唯一原因。

## 修改后的行为

- 保存配置代次、开始跟踪时间及已结束时间点，进程重启后仍能发现漏点。只合并补做最近一个到期时间点，避免逐个补发历史任务。
- 闹钟负责正常唤醒；应用启动、回到前台、录音服务已有的每分钟心跳，以及独立 15 分钟 WorkManager 周期任务负责补漏。周期任务执行时间仍受系统调度约束，并不承诺每 15 分钟准时运行。
- 补漏任务要求联网，使用唯一任务 KEEP 防止重复排队；所有入口在流水线锁内再次检查凭据，避免重复执行。
- 临时失败保留凭据并退避重试；取消或进程中断不提前消费凭据。成功或原流程判定的不可重试错误结束本轮。密钥、余额、存储保护等不可重试错误仍由原提示处理，避免无限调用；修正后可手动整理或等待下一时间点。
- 完成记录只覆盖开始时选中的时间点，执行期间新到的时间点不会被误标完成。修改配置会切换代次，旧任务的完成结果不会覆盖新设置。
- 首次升级从升级启动时开始跟踪，不追溯启用前的时间点；后续已跟踪的漏点可跨午夜、跨进程恢复。
- 清空时间点或切回间隔模式时撤销补漏任务。
- 问题记录增加：发现待补任务/等待联网、闹钟唤醒、等待流水线、开始及延迟、临时失败、执行中断、本轮结束。

## 鸿蒙真机验收

尚未安装到手机、未发布安装包。需用真实手机验证：
1. 设置未来时间点，保持联网，前台到点执行一次。
2. 熄屏并断网超过 30 分钟后恢复网络；允许后台调度或打开应用后应补做，而非“已错过，跳过”。
3. 到点前停止进程，到点后重新打开；应发现待补任务，重开页面不重复整理。
4. 执行中断后重开；已保存结果沿用现有数据去重，剩余内容继续处理。
5. 查看问题记录，区分无唤醒、等待网络、流水线忙以及模型错误。

系统强行停止应用、禁止自启动或完全不提供后台执行机会时，应用无法保证准点运行；重新打开后的补漏不依赖准点唤醒。鸿蒙上的后台权限入口需按实际系统版本核验。
