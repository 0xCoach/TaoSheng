# 卡 231：共用核心起点——平台插口归位、共用建库配置、功能权限入口、总装骨架

## 背景

共用层（`:shared`）已有大量规则、协议和数据表，但"把它们装起来跑"的装配仍在 `:app`：平台插口容器 `PlatformServices` 定义在安卓侧，建库配置（迁移、四组回调）写在 `AndroidCaptureDatabase.kt`。本卡是共用层装配的第一步，为后续把转写、整理、问问、推送执行器逐张迁入共用层打地基。**安卓行为必须完全不变。**

先读：`AGENTS.md`（尤其"为以后 iOS 复用"十条和"官方服务预留"三条）、`docs/任务卡/137-交付说明.md`、`shared/src/commonMain/kotlin/app/resound/platform/PlatformPorts.kt`、`app/src/main/java/app/resound/platform/AndroidPlatform.kt`、`app/src/main/java/app/resound/data/AndroidCaptureDatabase.kt`、`shared/src/commonMain/kotlin/app/resound/data/CaptureDatabase.kt`、`shared/build.gradle.kts`、`app/src/main/java/app/resound/ResoundApp.kt` 中 `onCreate` 的平台装配段。

## 要做的

1. **`PlatformServices` 移入共用层**：放 `shared/src/commonMain/kotlin/app/resound/platform/`，包名保持 `app.resound.platform`，字段与现有一致（now、zone、logger、keyValueStore、files、dispatchers），再加第 3 条的 `entitlements`。安卓的具体实现（`SystemNow`、`AndroidLogger`、`PrefsKeyValueStore` 等）留在 `:app`。调用方 import 不变或只改最少。
2. **共用建库配置**：在 commonMain 提供一个对 `RoomDatabase.Builder<CaptureDatabase>` 的统一配置函数（名称自定，如 `configureCapture()`），集中完成 `addMigrations(*CaptureDatabase.MIGRATIONS)` 与四组回调（`SearchIndex`、`ImportRecordSchema`、`ThingSchema`、`PendingDigestSchema`，顺序与现在完全相同）。安卓 `CaptureDatabase.open(context, name)` 改为调用它，驱动选择（`AndroidSQLiteDriver` + 主库的 `QueryStatsDriver`）、`filePath` 赋值、默认库名、`BackupRestore`/`DayVolumeRows` 的调用方式都不变。
3. **功能权限入口（只建入口，不接任何调用点）**：在共用层定义可扩展的高级功能枚举（如 `ProFeature`，先放：更多推送通道、Markdown 每日笔记、高级导出、每日/每周回顾）与接口（如 `Entitlements.has(feature): Boolean`，可附一个变化通知 `Flow`）。安卓实现为"全部可用"。本卡**不改任何现有功能的判断逻辑**，以后所有"是否可用高级功能"的判断都只能走这个入口。注释用中性说法（"高级功能是否可用"），不写定价、平台或收费方案。
4. **iOS 建库入口**：仅在 iOS 目标（`taosheng.ios=true` 时）给两个 iOS 源码集加 `androidx.sqlite:sqlite-bundled:2.6.2`（安卓不加），在 iOS 源码集提供 `openCaptureDatabase(path: String): CaptureDatabase`：`Room.databaseBuilder<CaptureDatabase>(name = path)` + `BundledSQLiteDriver()` + 查询协程上下文 + 第 2 条的统一配置，并设置 `filePath`。确认 Room KSP 为 iOS 目标生成了 `CaptureDatabaseConstructor`。
5. **总装骨架**：在共用层新建 `app.resound.runtime`，提供 `CoreRuntime`（持有 `platform: PlatformServices`、`database: CaptureDatabase`）和创建函数（如 `createCoreRuntime(platform, database)`）。安卓 `ResoundApp.onCreate` 用它创建，`AppGraph.platform` 等现有字段保留并从中取值（不删、不改语义、不改初始化顺序，`:local_asr` 进程的提前返回逻辑不受影响）。后续卡会往 `CoreRuntime` 里加转写、整理等执行器；本卡只放这两样，不要提前搬其他东西。

## 不要做

- 不改 `ui/` 包、`MainActivity.kt`、`*Contract.kt`、`AudioSource.kt` 签名。
- 不改数据库表结构、`CaptureDatabase.VERSION`、迁移内容、偏好键名。
- 不迁移转写、整理、问问、推送、调度执行器（后续卡做）。
- 不升级任何依赖版本，不引入 Hilt。

## 验收

- 安卓：老库升级与打开正常（沿用现有迁移测试，断言用 `CaptureDatabase.VERSION`、建库用 `CaptureDatabase.MIGRATIONS`）；四组回调仍生效（全文搜索、导入记录、事情表、待落库整理）；`AppGraph.platform` 初始化时机不变。
- 新增测试适度（5–10 个）：统一配置函数确实挂上迁移和四组回调（可用 jvmTest 建内存库验证 FTS 表与触发器存在）；`Entitlements` 安卓实现全部为可用；`CoreRuntime` 创建后字段正确。
- 必跑：`python3 tools/check_shared.py`、`./gradlew :shared:check`、`zsh tools/check_ios.sh`（iOS 真机与模拟器编译，含新加的 iOS 建库入口）、`./gradlew :app:assembleDebug` 和本卡相关的安卓单测。JDK 用 21（`/opt/homebrew/opt/openjdk@21`）。
- 交付：在本分支提交（中文提交信息，不推送），写 `docs/任务卡/231-交付说明.md`：做了什么、怎么验证、真机注意事项、遗留问题；并列出后续把执行器搬入 `CoreRuntime` 时你看到的阻碍。
