# main 自动检查红叉修复

2026-11-14，负责人授权解决 main 检查失败。

## 根因与修复

- `MemoryRepository177Test`：仓储已接收时区与时钟，但当天日期及待办日期归一化仍读系统默认值，旧快照在上海时区生成，GitHub UTC 环境相差 8 小时。安卓适配改用已传入的时区与时钟；测试固定时钟，系统设为 UTC、仓储注入纽约时区。旧夹具原字节保留，仅在断言处明确修正待办午夜时间戳，其他输出继续逐字比较。
- `UpdateRemoteTest`：类成员 `check(Boolean)` 是检查正式/预览更新，遮蔽了 Kotlin `check(Boolean)`。坏包删除、超大残留包删除及说明卡 HTTP 状态检查均误触更新请求。修正这三处为 `kotlin.check`，没有修改摘要算法、校验门槛或重试次数。
- 更新测试辅助客户端明确不给真实预览源，避免测试意外访问生产服务；新增超大残留包和说明卡下载请求路径检查。

## 本地验证

- 修复前单独运行坏包测试，复现“预期完整性错误、实际网络错误”；日志确认下载后意外调用更新检查并访问真实预览源。
- 修复后：更新模块及记忆仓储 26 项定向测试全部通过；`:shared:check` 通过，其中 JVM 测试 192 项通过。共用与设备边界检查通过，`git diff --check` 通过。
- 未更改 shared/devices 共用代码，无需新增 iOS 编译验证。

## 交付边界

修复推送 main 后由 GitHub 完整检查确认。未重新发布 APK、未安装手机；已发布 0.3.0 安装包不变。后续版本真机可抽查待办日期修改、应用更新下载及设备说明卡获取。
