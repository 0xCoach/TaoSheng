# 卡 112 交付说明 · 采集健康（Claude 接手）

起因：11-09 15:23–17:37 麦克风“假运行”约两小时（服务在跑、波形不动、无录音），手动重启才恢复。
Codex 草稿（分支 codex/112-mic-health，提交 fa4f71b，未合并）经其自审有 4 个问题，本卡改为从原版代码出发、只做最小修复。

## 修了什么

1. **连续全零判故障**（主因）：原来 `read()` 返回正数就算“有数据”，全零也算。现在连续 20 秒数字全零（被系统静音/让麦期间不计时）就结束本轮，由采集服务重开。真实麦克风再安静也有底噪，一个采样非零就清零计时。
2. **重开无效时提醒并放慢**：连续 3 次因全零重开、中间一次真声音都没有，发一条“麦克风收不到声音”通知，之后每 60 秒重试一次（原来 3 秒），不反复折腾；收到真声音后自动撤掉通知、恢复正常节奏。
3. **读取卡死在让麦期间也有上限**：原来被静音时看门狗不计时，读取卡住就永远出不来；现在让麦期间 10 秒、平时 2 秒。
4. **查不到录音配置不再当成“未静音”**：保留系统回调给的值，避免刚被占就误报“已恢复”。
5. **蓝牙让麦**：蓝牙录音占着通话模式时，发现别的应用要录音（不含本应用、不含系统唤醒词），整轮让出（释放录音、通话路由、模式），等别人用完再接回来，期间状态为“别的应用在用麦克风”。不报错退出，所以不会被换回手机麦克风后回不来。
6. **“自动”不选蓝牙**：自动只选 USB / 有线，都没有用手机麦克风；蓝牙需在列表里指定。界面文案同步改为“接上 USB 或有线麦克风就用它”。

草稿里没带过来的：首次启动也等“完全没人录音”的闸门（会卡在等待）、独立诊断心跳写库（另议）、“中断标记永不清除”的全零判定。
