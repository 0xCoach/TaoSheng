## 背景

“关于 → 问题反馈 → 导出问题记录”现在不含任何整理（digest）与大模型（LLM）链路信息。用户遇到“大模型返回的格式不对”时，导出记录里找不到能定位原因的证据。

## 要做

在导出文本里加一段 **“整理与大模型诊断”**（`diagnostics/LocalProblemReports.kt` 装配处，与现有各段同风格），内容：

1. **最近整理状态**：上次整理时间、最近错误类型（`LlmError` 名）与固定文案、是否有在途批次及其句数；待整理句数。
2. **重试与放弃**：格式失败计数（`fail-*`）、本地保存失败计数（`local-*`）汇总；最近被放弃批次的句数与时间（如已有记录）。
3. **当前模型配置**：服务商名称、模型名、服务地址（只留协议+域名+路径，不含查询参数）、是否开启备用切换、备用列表的服务商与模型名。**不写密钥、不写自定义请求头的值**（名称也不写）。
4. **用量摘要**：最近 3 天按用途的调用次数、prompt / completion token（`llm_usage_v2`）。
5. **最近大模型响应摘要（新增记录，环形保留最近 20 条，存本地偏好或小表，不进备份）**：时间、用途（整理/回顾/问问/技能…）、服务商+模型、耗时、HTTP 状态、`finish_reason`（是否因长度截断）、响应字符数、是否为合法 JSON、解析出的事件数 / 条目数、是否命中空结果或全被过滤、归类的错误类型。**不保存任何原话、提示词或响应正文。** 在 `LlmClient` / 整理与问问的解析处埋点，失败和成功都记。
6. **备用切换记录**：最近一次切换的时间、主→备模型、原因、冷却状态（`LlmFailover`）。

## 规则

- 整段过现有 `scrubProblemReport` 脱敏；另加测试：导出文本里不出现密钥样式串、不出现自定义请求头值、不出现测试数据里的原话文字。
- 不改变整理、问问的任何行为和提示词；埋点失败不得影响主流程（吞掉异常）。
- 不新增依赖、不新增数据库版本（如需表，优先用偏好存 JSON 环形缓冲）。

## 必测（5～8 个用例）

- 导出含新段落，字段齐全；无数据时显示“暂无”。
- 响应摘要环形保留 20 条；截断、非 JSON、空结果各记对。
- 脱敏：密钥、请求头值、原话不出现。
