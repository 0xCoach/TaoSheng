# 195：打点与重点区域交付说明

## 数据与兼容

数据库 37→38，新建 `marks`：自增 `id`、Unix 毫秒 `at`、`beforeMillis`、`afterMillis`、可空 `label`、`source`（Recording / Playback / Topic）、`createdAt`、可空且唯一的 `topicMarkId`。`at` 有索引；事件与打点不建外键，按左闭右开时间区间重叠计算。

专题采用双写：`RoomTopicStore.mark` 在同一事务内写旧 `topic_marks` 和通用表；专题撤销、删除同步清通用表。原专题接口、修订号、续做检查保留。迁移将旧专题打点补为默认前 120 秒、后 60 秒；日卷恢复也执行幂等补齐，旧包没有 marks 时照常恢复。既有专题数据和 UI 读取方式保持兼容。

## 给 Claude 的界面接口

本卡不改 `ui/`、`MainActivity.kt` 或已有 `*Contract.kt`。新增具体实现通过 AppGraph 装配，未新增必须由界面实现的接口。

- `AppGraph.marks.recording(label?)`：按注入时钟打点，返回持久化 `MarkRow`，使用其 `id` 撤销。专题现有按钮继续调用 `AppGraph.topics.mark()`，自动双写。
- `AppGraph.marks.playback(sourceStartAt, positionMillis, durationMillis, label?)`：真实时刻 = 音源真实起点 + 播放位置。若播放的是裁剪音频，必须传裁剪后的真实起点；若播放器给的是句内偏移，就传这句对应音源起点。位置不能小于 0 或超过音源时长。
- `AppGraph.marks.undo(id)`：普通打点删除；专题打点转调原 `topics.unmark(topicId, topicMarkId)`；重复撤销已删除项无副作用。
- `AppGraph.marks.observeDay(from, until)`：Flow，调用方按所用时区计算当天起止；返回与当天相交的打点区间，包括跨午夜范围。
- `AppGraph.marks.forSegment(segmentId)`、`forEvent(eventId)`：按录音段或事件的真实区间查询打点。用于事件“📍有打点”、原话高亮、播放器刻度。区间由 `MarkRow.startAt/endAt` 提供。
- `AppGraph.markSettings.range` / `setRange(beforeMillis, afterMillis)`：前、后独立设置，均 30 秒～10 分钟；默认前 2 分钟、后 1 分钟。只影响新打点，旧范围不变。偏好文件 `marks` 已归为用户设置备份。
- `MarkFeedback.text(at)`：本地时区“已记下 HH:mm 的重点”。界面可追加“可撤销”，并保存返回 id 连接撤销按钮；后台 Toast 不显示不存在的撤销按钮。

快捷入口：长按图标聆听中为“加待办 / 记一下 / 暂停 / 开专题”，仍最多四条，保留旧专题编号校验。通知非专题聆听时为“加待办 / 记一下 / 暂停”，暂停时保留“开专题”。小组件不改布局，聆听中把原“开专题”动作位切到“记一下”；停止/暂停时仍为“开专题”。复用既有小组件渲染器和接收器。Claude 若需同时放两个按钮，可沿用接收器 `start` 与 `mark(topicId=0)` 动作；最终布局由 Claude 决定。

## 整理提示词前后

此前：专题将标记映射到“最近一句”，每日整理不读打点。

现在：`MarkPrompt` 位于 shared，输出本批真实时间范围内的打点区间、标签、与区间相交的原话编号；不附入其他批次编号。普通整理和重新整理通过同一个 `SituationPrompt` 适配器读取；专题提取用本批从 1 开始的编号，纪要和口播稿用现有 `L数据库编号`。专题口播原话补带已知说话人。

规则要求重点事件摘要更完整、保留 2～4 句带已知说话人的关键原话、点明“用户标记的重点”；不足两句就只用已有原话，未知说话人不猜测，标签仅为资料。专题继续标“★ 重点”；无原话的区间不虚构。输出格式与推送字段不变。

未改每日整理的 batch identity、进行中凭据、已收到响应的落盘/重放逻辑；新打点不导致已完成或已缓存的请求自动重发。已整理内容需用户发起重新整理才能体现后来新增的打点。

## 原声、隐私与备份

`TranscribeDao.starredAudio` 同时返回与打点区间重叠的录音段，复用既有原声保留/预览/清理流程及 `originalKeepStarred` 开关。关闭此开关后仍按既有保留天数处理；主动包含重点的清理沿用原行为。

按时间、最近 N 分钟、单段、批量、这段别记和全部删除在同一数据库事务内清除对应时刻的通用和旧专题打点。没有录音段的事件也按事件时间清打点。清除依据打点时刻是否落在删除区间，不删除仅因前后扩展范围相交而属于其他时刻的标记。marks 按 `at` 纳入每日备份卷。
