# 066 · 本地转写热词同音纠正交付

在 `preview-0.2.13` 上完成。保留 065 的在途改动，数据库由其 21 顺延到 22。未 git commit、未推送、未连接或操作手机；未改 ui/、MainActivity、Contract 文件、AudioSource、模型或识别运行库。

## 做了什么

- `transcribe/local/LocalHotwordCorrection.kt`：离线同音纠正、常用词保护、热词拼音缓存和首读音索引。仅接收至少两个汉字的完整热词；含英文、数字、标点的热词整个排除。按 Unicode 码点计长度。
- 两侧逐字无声调拼音必须完全相同，多音字任一读音相交即匹配；ü 与 u 保持不同。找不到读音不猜测。句内从左到右匹配，不跨标点、空格、英文或数字；同位置最长优先，同长多候选不替换，也不退回短词。原文已是热词或在常用词表内时保留。
- `ConfiguredAsrProvider.kt` / `local/LocalAsrProvider.kt`：沿用现有 `AndroidHotwordSettings.merged()` 回调（手工词与声纹人物名），仅本地 CPU/NPU 结果返回后纠正。普通录音和本地导入共用路径。豆包、自定义云端没有接入该步骤。
- `AsrProvider.kt`：`AsrSentence` 增加默认 null 的 `originalText`；`TranscribeRunner.kt` 将其写入 `TranscriptLineEntity`。仅发生替换的句子保留整句原识别文本，时间戳、说话人字段保持原样。
- `data/TranscribeDao.kt`：实体新增可空 `originalText`。`CaptureDatabase.kt` 新增 21→22 迁移并接入统一 `MIGRATIONS`；生成 `app/schemas/app.resound.data.CaptureDatabase/22.json`，保留 065 的 21.json。
- `PipelineTimes` 每段有热词时记录“同音纠正 N 处”，含零次，不写词或句子内容。
- 热词快照改变时重建索引，单字读音缓存复用；词表/多音字资源进程内只加载一次。

## 库、词表及许可

- TinyPinyin 官方固定提交 `b65acaaff3553da583c71ee15dac8f7ded443219`，Apache-2.0。旧 Maven 坐标在现有仓库不可用，原样引入全部 12 个 Java 文件至 `app/vendor/tinypinyin/java/`；已按 Git blob 校验一致。`app/build.gradle.kts` 增加源码目录及其 Apache-2.0 依赖 `org.ahocorasick:ahocorasick:0.4.0`。
- TinyPinyin 的默认单字读音以 MIT 的 mozillazg/pinyin-data 0.15.0 补充全部多读音字及 BMP 外汉字，共 23,548 条。
- 常用词表取 MIT 的 jieba 字典中频率最高的 15,000 个纯汉字多字词，包含“黎明”。
- 资源位于 `app/src/main/assets/homophones/`。4 份许可均随 APK 分发；来源、加工规则、SHA-256 见 [第三方记录](../third-party/066-本地同音纠正.md)，本地生成脚本在 `docs/third-party/homophones/generate.py`，已验证生成结果逐字节一致。

## 性能实测与真机注意

桌面 Robolectric/JVM，200 个热词、400 字片段（含 20 处纠正），预热后采样 100 次：中位数 **0.404 ms**，P95 **0.946 ms**。这测量纠正算法，不含模型推理、SharedPreferences 写日志或 Room 落库；不是手机性能结果。首次进程词表加载未独立计时，不能将测试输出的首次实例调用值当作冷启动耗时。

负责人真机验收：升级后确认原数据仍在，添加/删除热词和声纹人物名后分别试 CPU/NPU 与本地导入；检查“承改→城改”“黎明不变”、诊断里的计数，以及长段/首次加载耗时。云端路径不做本地纠正。此次没有手机证据。

## 遗留与边界

常用词表是频率保护，无法做语义判断；所有声调被忽略、多音字任一读音可匹配，会有一定误改可能，常用词保护也可能跳过真正的错字。`originalText` 已持久化供追溯，本卡遵守界面和 Contract 禁区，未添加 UI 展示入口；如需查看原句，后续由界面负责人接入。旧历史转写不回溯纠正。
