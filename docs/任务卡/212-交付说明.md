# 卡 212 交付说明

本卡完成非界面部分，分支 `codex/212-qwen-asr`。不改 `ui/` 和 `MainActivity.kt`，不推送，不操作手机，不调用真实转写服务。按本轮用户约束，不访问 GitHub 议题，背景采用任务卡中的议题摘录及本地实测 JSON。

## 实现

- 自定义转写新增 `CustomAsrApi.OpenAi / Qwen`，两套地址、模型、密钥、地址写法和热词开关独立。原 OpenAI 字段名与数据保持原样；Qwen 默认北京完整地址、`qwen-audio-3.1-asr-flash`、热词开。Qwen 强制完整地址，不探测路径、不拉取模型。
- Qwen 通过现有长超时客户端发 JSON；音频整体 base64，按 ogg/m4a/wav 填 MIME 与 format。热词 trim、去空、按原顺序去重，取前 500 个，权重 4。未开启热词或没有热词时不发 vocabulary；不发 language_hints / SSE。
- 超过 300500 毫秒在读取/发送音频前报不可重试错误。优先读 `output.sentences`，缺失才读嵌套层；毫秒时间、坏句丢弃、截断、排序，说话人按有效句在响应中的首次出现编号；关分人时全部为 null。无 sentences 时按词和句末标点切句，超过 60 字遇逗号也断；无词退回 text。
- Qwen 鉴权失败为 Auth，限流和服务端故障为 Server；审核失败与其他协议错误不可重试。审核失败留为 Failed、nextRetryAt=null，连续再跑队列也不会再发送。错误只带安全错误编号，不保存服务文案、音频或密钥。响应读取取消继续传播取消异常。
- OpenAI 新增 `CustomSpeakerFormat.Auto / Diarized`。Auto 保留 verbose_json → json 和 30 天缓存行为；Diarized 发 diarized_json + chunking_strategy=auto，不发 prompt，不回退或写入 json 缓存。拒绝时明确提示改为自动。
- Qwen 和 OpenAI 自定义结果清理汉字之间及中文标点旁的多余空白，保留 `Hello world`、`用 Kotlin 写` 等混排空格。豆包、本地解析不变。
- 密钥状态独立于可用性：只有实际保存的密钥或非空请求头凭据才显示 Saved；只有地址、模型仍是 None。无密钥的自建服务仍可使用。测试通过显示 Verified 并记录实际格式能力；地址、模型、密钥、接口格式、说话人格式、请求头变化清除相关结论。切换接口后及切回原接口均需重新测试，两套配置和密钥仍保留；切换期间的旧测试结果失效。
- 验证结论和能力仅在当前进程内按接口保存，不写偏好或备份，重启、恢复后需重新测试。两套配置、两套密钥、说话人格式、热词开关正常备份；密钥仍走解密导出、重新加密恢复。
- 数据库 43 → 44：asr_usage 新增 inputTokens/outputTokens，默认 0；唯一新增迁移在 MIGRATIONS 注册，重复执行会检查列是否存在。自动转写、3 秒测试、重新转写、待办语音输入成功收到 token 后累加；无 token 的服务不改变 token 统计。不增加价格。
- 搜索历史新条在前、去首尾空白、去重前移、最多 10 条，支持删单条和清空。以 Mutex 串行保存后发布 StateFlow，已装配到 AppGraph，进设置备份。

- 上述地址/模型 getter 读取当前接口，类型保持兼容。界面收集 customApi，切换后重新载入输入框；模式和热词开关已有 StateFlow。Qwen 页面不展示自动地址或模型列表入口。
- `CustomSaveResult(keySaved: Boolean, keyState: CustomKeyState)`：keySaved 表示本次非空新密钥已实际写入；空密钥输入保留已存密钥，不表示清除，使用 clearKey 清除当前服务的当前接口密钥。keyState 可显示本次保存后的状态。提交失败抛错，不发布未落盘的地址/模式。
- `CustomKeyState { None, Saved, Verified }`；密钥框使用此状态，不能再使用 hasKey 文案。hasKey/ready 继续用于“能否转写”。测试通过后状态流已更新。
- `CustomCapability { Speakers, TimedText, TextOnly }`：Qwen、OpenAI Diarized 为 Speakers；OpenAI Auto 的 verbose_json 成功为 TimedText，json 成功为 TextOnly。表示接口格式能力，不代表 3 秒单人音频已证明多人准确率。
- identity 已包含接口格式和说话人格式。请求头仍共用 `TranscribeSource.Custom` 一组。
