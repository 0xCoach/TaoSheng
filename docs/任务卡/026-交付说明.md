# 026 交付说明

完成日期：2026-10-24。分支：`codex/026-search`。只改后端，未修改 `ui/`、`MainActivity.kt`、任何 `*Contract.kt` 或 `AudioSource.kt`。未操作手机，未推送远端。

## 做了什么

- 数据库升级到 11：增加三张 FTS4 表、`embeddings` 和消息的 `actionJson`。全文索引按相邻中文二字切分，英文数字按词；查询使用相同切分、绑定参数和 MATCH。不同关键词 OR，同一关键词的二字词 AND。
- 插入、修改、删除通过 SQLite 触发器同步索引，覆盖 DAO 和直接 SQL 写入。原话保留时间、说话人过滤；事件与条目保留时间、类别、状态及软删除过滤。
- 事件/条目有关键词时：全文结果按原有时间倒序取前 20，向量按余弦相似度取前 20，用等权 RRF `1 / (60 + rank)` 合并去重，返回前 10。`semantic_search(query, from?, to?)` 仅查向量，事件和条目一起按相似度排序。模型未就绪或加载失败时静默跳过语义，全文索引本身不需要网络。
- `Embedder` 隔离模型实现。BGE 使用保留大小写的 BERT WordPiece、最多 512 token、CLS 池化及 L2 归一化；512 维向量以 little-endian float32 存储。事件输入为标题、摘要、要点，条目为类别、内容；原话不计算向量。
- WorkManager 在启动、整理落库、模型首次就绪、确认新增后触发补算，另有 15 分钟周期兜底。每个任务最多 64 条，逐条确认“正在充电或电量严格大于 30%”；有积压时串行追加下一批，避免正常补算触发指数退避。快照已经变化/删除时丢弃计算结果，之后重新补算。
- `propose_change` 只生成待确认卡片：条目完成/接受/忽略，新建待办/备忘，修改/清除截止时间，事件标重要/取消。每轮最多一个操作，已有目标必须先检索到。显示文案由本地根据实际记录生成，执行参数与状态保存在 `actionJson`，重启可恢复。
- `confirmAction` 在同一事务内检查 Pending 和目标快照、修改数据、置 Done；重复确认无副作用，失败回滚并置 Failed，给出中文原因。`cancelAction` 只置 Cancelled，之后无法执行。状态更新沿用现有 `doneAt`、`statusChangedAt`、接受排序逻辑。
- 新建条目因原表要求关联事件，会同时创建一件“问问新建”事件，条目状态为 Accepted；卡片明确说明这一行为。`due` 省略代表无截止时间，`item_due` 的 `due: null` 表示清除。
- `askAbout` 以一个串行命令新开会话，从当前数据库取所选事件/条目、事件标题摘要和最多 40 句原话，只附在第一轮。整体文本有预算，原话单句最多 900 字；不使用调用方传来的旧摘要。上下文引用纳入现有引用编号系统。
- 云端仍只收到有界的相关检索结果（每次约 6000 字）或所选记录上下文；向量计算、全库候选比较全部在本机完成。

## 迁移规则

- `MIGRATION_10_11` 为旧消息添加可空 `actionJson`，旧问答内容与引用不变。
- 新建 FTS4 表后，迁移事务中把全部已有原话、事件、条目灌入索引，再由触发器维护。软删除事件仍可能有全文索引行，但所有对外查询都过滤掉；事件软删除时清除它及所属条目的向量。
- 内容修改会使对应向量失效；类别修改也使条目向量失效。时间、状态、重要标记不参与向量文本，查询仍实时过滤。
- 向量表在迁移时留空，模型就绪并满足电量条件后分批补算历史。版本号随向量记录保存，更换模型会重新补算。
- 新库通过 `SearchIndex.callback` 创建同样的触发器。生产入口 `CaptureDatabase.open` 已登记迁移与回调；直接创建测试数据库时也应加此回调。
- Room 导出文件：`app/schemas/app.resound.data.CaptureDatabase/11.json`。已通过 Room 实际开库校验 10→11 和 1→11 整链，旧数据保留、历史全文命中正常。

## 一次真实问答对比

电脑上实际下载并校验上述模型，用 ONNX Runtime CPU 跑了三条合成记录：交通票据、晚饭、周末运动。只向 DeepSeek 发起 **1 次**请求，只上传命中的一条合成记录及改前空结果；密钥仅由脚本读取，未输出或落库。未读取手机数据库。

同一问题：“关于报销，我要准备什么？”检索关键词：“报销”。

| 对比 | 结果 |
| --- | --- |
| 改前 LIKE | 0 条，没有“报销”字面文本 |
| 改后本地语义 | “交通票据 / 明天把车费发票交给财务”排第 1，余弦约 0.40088；晚饭 0.29164，运动 0.22625 |
| DeepSeek 实际回答 | “改前：没找到。改后：准备车费发票并整理票据，明天交给财务[^1]。” |

复现脚本与结果：`tools/search-probe/probe.py`、`tools/search-probe/result.json`。这是本地模型检索 + 单次云端回答对比，不是 Android 真机或云端多轮工具协议的端到端验收。无额外模型调用。

- Claude 直接使用既有 `AskMessage.action`、`confirmAction(messageId)`、`cancelAction(messageId)`、`askAbout(source, question)`；没有提出约定签名变更。卡片应在消息保存后（真实正数 id、非 streaming）允许操作，并根据 Pending/Done/Cancelled/Failed 显示状态。
- 本卡禁止手机操作，以下交由负责人以后验收：澎湃 OS 后台下载/续传与调度、首次安装后历史补算、充电及 30% 电量边界、断网本地检索、实际 ARM64 ONNX 速度与内存、卡片重启恢复与点击反馈。

- 向量结果是相似候选，没有硬阈值，不保证每条都相关；提示词已要求核对原话、不能把近邻当作确定事实。BGE 超过 512 token 会截断；二字全文检索不是 LIKE 子串检索，建议中文关键词至少两字。
