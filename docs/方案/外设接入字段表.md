# 外设接入：说明卡与文件插口字段表（草案，待负责人过目）

> 0.2.21 用。三层接法：普通麦克风走系统，不用插件；实时传输设备写一张**说明卡**（配置文件，不写代码）；带存储的设备再加一个**文件插口**（轻量代码插件）。其余设备走文件导入。
> 第一版只做蓝牙；说明卡留 `transport` 字段，以后加 Wi-Fi 不推倒重来。

## 一、说明卡（一个 JSON 文件，一台设备一张）

### 1. 基本信息

| 字段 | 例子 | 说明 |
|---|---|---|
| `id` | `folotoy-ble` | 唯一编号，只用小写字母、数字、横线 |
| `name` | `FoloToy 开发卡` | 给人看的名字 |
| `version` | `3` | 说明卡自己的版本，远程参数表靠它判断要不要更新 |
| `minApp` | `0.2.21` | 最低需要的涛声版本，太旧的 App 不加载 |
| `status` | `verified` / `trial` | 已真机验证 / 试用（界面标“试用”） |
| `transport` | `ble` | 传输方式；第一版只认 `ble` |

### 2. 怎么认出设备（满足任一条即可）

| 字段 | 例子 | 说明 |
|---|---|---|
| `match.namePrefix` | `["Omi", "Friend"]` | 蓝牙广播名前缀 |
| `match.serviceUuid` | `19b10000-e8f2-537e-4f6c-d104768a1214` | 广播里带的服务编号 |
| `match.manufacturerId` | `0x0059` | 厂商编号（可选） |

### 3. 连接参数

| 字段 | 例子 | 说明 |
|---|---|---|
| `mtu` | `247` | 连接后请求的包大小；不填用系统默认 |
| `bond` | `false` | 是否需要配对 |
| `keepAliveSec` | `0` | 有的设备要定时发心跳，0 表示不需要 |

### 4. 实时声音

| 字段 | 例子 | 说明 |
|---|---|---|
| `audio.service` | `19b10000-…` | 声音所在的服务 |
| `audio.notify` | `19b10001-…` | 订阅这个通道收声音包 |
| `audio.write` | `19b10003-…` | 发命令用的通道（没有可不填） |
| `audio.start` | `{"type":1,"cmd":0}` 或 `"hex:0100"` | 开始收音要发的命令；可写成“按包外壳组装”或直接写字节 |
| `audio.stop` | 同上 | 停止收音 |
| `audio.codecRead` | `19b10002-…` | 有的设备要先读一下才知道是什么声音格式；读到的值用 `codecMap` 对照 |
| `audio.codecMap` | `{"1":"pcm16","20":"opus10","21":"opus20"}` | 读到的编号对应哪种格式 |
| `audio.codec` | `opus20` | 不读的话直接写死格式 |
| `audio.sampleRate` | `16000` | 采样率 |
| `audio.channels` | `1` | 声道数 |

**声音格式第一版支持**：`pcm16`（16 位）、`pcm8`、`mulaw`、`opus10` / `opus20`（Opus，每帧 10 / 20 毫秒）。

### 5. 包外壳（设备发来的每个包长什么样）

一个包按顺序拆成若干段，每段写清楚是什么：

| 字段 | 例子 | 说明 |
|---|---|---|
| `frame.fields` | 见下 | 从前到后的字段列表 |
| `frame.payload` | `rest` 或 `{"lengthFrom":"len"}` | 剩下的全是声音，或由长度字段决定 |
| `frame.fragment` | `{"indexField":"frag","restartAt":0}` | 一帧声音分几个包发时，怎么拼回去 |
| `frame.opusPerPacket` | `one` / `lengthPrefixed` | Opus：一个包一帧，或一个包里多帧、每帧前面带长度 |

`frame.fields` 每一项：

| 子字段 | 例子 | 说明 |
|---|---|---|
| `name` | `seq` | 名字（供别处引用） |
| `bytes` | `2` | 占几个字节 |
| `endian` | `le` / `be` / `probe` | 字节顺序；`probe` 表示连上后用 `probe` 命令试出来（声云就要这样） |
| `const` | `"hex:AA55"` | 固定值（比如开头标记），对不上就丢弃这个包 |
| `role` | `seq` / `len` / `crc` / `type` / `cmd` / `frag` | 这个字段的用途 |
| `crc` | `{"algo":"crc16-xmodem","over":["len","payload"]}` | 校验算法和覆盖范围；第一版支持 crc16-xmodem、crc16-modbus、crc32 |

例：Omi 的包外壳 = `seq`（2 字节小端）+ `frag`（1 字节）+ 声音。
例：声云的包外壳 = 开头标记 + `seq` + `len`（小端）+ `crc`（crc16-xmodem，覆盖 len+数据）+ `type` + `cmd` + 声音。

### 6. 其他能力（可选）

| 字段 | 例子 | 说明 |
|---|---|---|
| `battery` | `standard` 或 `{"service":…,"read":…}` | 标准电池服务，或自定义读法 |
| `clock` | `{"write":…,"format":"unix32le"}` | 给设备对时的命令；格式支持 unix32le / unix32be / bcd |
| `offline` | `none` / `files` | 断开后设备会不会自己存：`none` 不存（断开就切别的输入）；`files` 存成文件，由文件插口补传 |
| `filePlugin` | `sonicloud` | `offline=files` 时，用哪个文件插口 |

### 7. 说明卡不能做的事（安全边界）

- 不能联网，不能读写手机文件，不能弹界面。说明卡只是数据，核心照着它收发蓝牙，审核成本很低。
- 字段超出上面的范围就当成无效卡，不加载，并在问题记录里写原因。

## 二、文件插口（一小段代码，只管“列文件、下载”）

插件只要实现下面几件事，其他全由核心做。

| 方法 / 字段 | 说明 |
|---|---|
| `capabilities.resume` | 能不能从文件中间某个位置接着下载。不能，核心就整个文件重下 |
| `capabilities.delete` | 能不能删设备上的文件 |
| `capabilities.checksum` | 设备能不能给出文件的校验值（没有就只比大小） |
| `list()` | 列出设备上的录音：编号、名字、大小、开始时间（设备时钟）、时长（可选）、格式 |
| `download(file, fromOffset)` | 从某个位置开始下载，一块一块交给核心 |
| `delete(file)` | 删设备上的文件。**只在核心确认文件已安全存好、校验通过后才会调用** |

核心统一负责：排队、断点续传、校验、不重复导入（与分享导入、文件夹导入一起去重）、存好才删、格式转换、对时换算、通知、权限、保活。

插件不能联网（与说明卡一样）。确实需要联网的设备要在插件里声明并在界面上写明，由负责人逐个审核（第一版没有这种插件）。

## 三、断开后补传（单台设备）

1. 实时收音时，每个包按手机收到的时间记账；断开时记下“断开时刻”，重连时记下“恢复时刻”。
2. 重连后，如果说明卡里 `offline=files`，就调用 `list()`，找出时间跟“断开时刻 → 恢复时刻”重叠的文件。
3. 只取重叠的那一段（前后各多留 2 秒防止漏字），转成普通录音片段进转写队列；已经实时收到的部分不再重复。
4. 设备时钟不准时：用连接时 `clock` 对时记下的偏差换算；没有对时能力的设备，按文件结束时间对齐。
5. 补传完成、校验通过、设备支持删除时，才删设备上的文件。
