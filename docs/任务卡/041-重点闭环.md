# 卡 041 · 重点闭环：用户重点与“要紧”分开，问问能查，回顾跟进

负责人定（10-24）：现在的“重点”只是一个星号，还混着大模型自动标的“要紧”。改成：**你亲手标的才叫重点**，之后问问能查、每日/每周回顾会持续跟进。界面 Claude 已在 main 做好（5f2b46d），本卡做后端。

**约定**：`digest/MemoryContract.kt` 已加 `MemoryEvent.starred` / `starredAt`、`setStarred(eventId, starred)`、`starredEvents()`；`importantEvents()` 保留，含义为“大模型标的要紧”。签名不要改。
**分支 / 工作树**：`codex/041-starred`，`~/Developer/resound-codex-041`。

## 一、数据

1. 库 **13 → 14**：`memory_events` 加 `starred INTEGER NOT NULL DEFAULT 0`、`starredAt INTEGER NULL`。迁移时**所有现有事件 starred = 0**（以前用户标的和模型标的混在 important 里，分不清；负责人知道要重新标）。`important` 列保持原样，只由整理写入。
2. 备份分卷按列名写行，新列有默认值；确认旧分卷能恢复（跑 `DayVolumesTest` 里相关用例）。
3. `setStarred(id, true)`：写 starred=1、starredAt=now；同一事务里把这件事下 category 为 待办/备忘、status=Pending 的条目改为 Accepted（沿用 `setItemStatus` 的规则：放到“进行中”最前面）。`setStarred(id, false)`：starred=0、starredAt=NULL，不动条目。
4. `starredEvents()`：deleted=0 且 starred=1，按 starredAt 倒序，最多 500，组装方式同 `events(date)`（含条目、repeats）。所有返回 `MemoryEvent` 的地方都要填 starred / starredAt。
5. 用户手动 setImportant 的老接口：界面已不再调用；问问的 propose_change 里 `event_important` 改为 `event_star`（见下）。

## 二、问问能查重点

1. `assets/prompts/ask-tools.json`：
   - `search_events` 加可选参数 `starred_only`（boolean）：只查用户标了重点的事；不带关键词时按 starredAt 倒序返回。结果每条加 `starred`（bool）、`starred_at`。
   - `get_day` 结果里每件事加 `starred`。
   - `propose_change` 的 `event_important` 操作改名为 `event_star`（参数 `id`、`starred`），`AskChanges` 相应改为调用 `setStarred`。
2. `assets/prompts/ask.md` 补两句：用户问“我标的重点 / 标过星的 / 重点里”时用 `search_events(starred_only=true)`；回答一般问题时，同等相关的结果里优先引用用户标了重点的事。`important`（要紧）是模型判断，不要说成“你标的重点”。
3. 离线工具 `tools/ask-probe` 若有工具表副本，同步更新。

## 三、回顾跟进

1. **每日回顾**（`review/ReviewPrompt.kt` + `assets/prompts/review.md`）：
   - 输入的每件事加 `starred`；当天**用户标了重点的事必须出现在“要紧的”**（若超过 3 条，“要紧的”上限放宽到 5 条，标星的优先）。
   - 新增输入 `starred_stale`：标星满 3 天、仍有未完成（Accepted/Pending）的待办或约定、且标星之后没有新的相关进展（简单判定：这件事的条目在标星后没有任何变为 Done，并且之后没有新事件的标题/摘要与它语义相似 ≥ 0.80——向量没就绪就只看条目）的事，最多 3 条。回顾里在“值得留意”栏写一句“你 X 月 X 日标过重点的「标题」，还没进展”。不新增栏目。
2. **每周回顾技能**（`assets/skills/weekly/`）：fields 新增 `starred` “本周你标的重点”（Bullets：每条写这件事 + 后来的进展或“还没进展”）；输入里把本周标星的事（starredAt 在本周）及其条目状态带上。技能 version +1（已有“我的版本”的用户会看到“官方有更新”）。
3. **每日记忆文档**（`push/DailyMemory.kt`）：事件里加 `starred`，Markdown 时间线里标星的事在标题前加 ★。

## 四、必测（6～10 个）

1. 13→14 迁移：旧行 starred=0、important 不变；旧分卷恢复。
2. setStarred：标上时 Pending 待办变 Accepted，取消不动条目；starredEvents 按 starredAt 倒序、只含 starred。
3. 问问：`search_events(starred_only=true)` 只返回重点；`event_star` 改动卡确认后生效。
4. 每日回顾输入：当天标星的事带 starred；starred_stale 判定（满 3 天、未完成、无进展才入选）。
5. 每周回顾技能 schema 校验通过、version 递增。
