# 卡 134：整理被大模型拒收（400）时不再卡住整条队列

## 起因
用户问题记录：待整理 3844 句，最近错误 http=400、1.7 秒返回，被当成“服务暂时不可用”反复重试同一批；
换模型（含 DeepSeek 官方）也一样。400 不进格式失败计数，既不拆小也不放弃，后面所有批次永远轮不到。

## 改动
- 400/413/422 视为“拒收”（`LlmException.rejected`），按服务端原文挑固定文案：内容不合规 / 太长 / 其他；原文不入日志。
- 整理遇到拒收：本轮先发一句测试话。
  - 测试话也被拒 → 配置问题：停下，提示去设置“检测”，不丢任何原话，不触发退避重试。
  - 测试话正常 → 内容问题：对半拆小重试，最小 8 句；拆不动的那几句标为已整理（原话保留），后面照常。
  - 测试时断网等 → 按原错误稍后重试。
- 备用切换：拒收仍会试备用模型，但不让主模型进冷却，免得连累问问等功能。
