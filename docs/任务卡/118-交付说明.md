# 卡 118 交付说明

## 做了什么

- 新增 `devices/core/`：严格 JSON 说明卡解析、中文审卡摘要、三种 CRC、包拆装、端序试探、序号丢包统计、分片重组、音频解码与标准帧转换。
- `CardParser` 校验未知字段/枚举、重复 JSON 键、UUID、版本、命令、长度/分片/CRC 引用及关联条件；错误包含字段路径和中文原因。JSON 沿用字段表：`mtu/bond/keepAliveSec/keepAlive/frame` 在根对象，声音通道在 `audio`，`opusPerPacket` 在 `frame`。`match.serviceUuid` 接受单个完整 UUID 或数组；厂商编号接受整数或 `0x0059` 字符串。
- `FrameCodec` 严格校验常量、长度、CRC；CRC 覆盖所列字段的原始字节，不重新编码参与校验。未锁端序时不交付包；两种端序都成立时保持未锁定。支持自增发送序号、接收序号绕回、重复/迟到包丢弃、分片中断丢整帧。
- `AudioDecoder` 解 PCM16 小端、PCM8 无符号、μ-law；复用已有纯 Kotlin `PcmInputConverter` 转 16 kHz 单声道，持续切成 480 采样帧。PCM16 的半个采样、双声道和帧余量均可跨包保留。Opus 支持一包一帧、每帧 1 字节长度两种封装，先校验整包长度再解码。
- 唯一依赖 `android.*` 的新增类是 `AndroidOpusDecoder`：MediaCodec Opus，含 OpusHead/CSD、缓冲区排空、实际输出格式读取、EOS、重置与资源释放。实际输出可能是 48 kHz，按实际值重采样。
- 新增 `assets/devices/omi.json`、`sonicloud.json`，均为 `trial`。没有实现蓝牙、远程卡管理或文件插件。
- 未改 `ui/`、`MainActivity.kt`、任何约定签名、现有转换器及 `app/build.gradle.kts`。没有新增依赖，没有更新 App 版本。

## 两张卡的协议依据

核对日期：2026-11-09。任务卡提到的 `docs/调研/开放录音硬件协议调研.md` 不在当前分支，直接查阅以下公开原文。

### Omi

- [PROTOCOL.md：GATT、Codec IDs、Audio packet framing、Sample rate](https://github.com/BasedHardware/omi/blob/main/sdks/device/PROTOCOL.md)：服务/通知/编码读取 UUID；实际编码号为 **0=PCM16、1=PCM8、20=Opus10、21=Opus20**；16 kHz 单声道，3 字节包头。
- [固件 transport.c：push_to_gatt](https://github.com/BasedHardware/omi/blob/main/omi/firmware/omi/src/lib/core/transport.c)：`packet_next_index` 每个包递增，前两字节小端，第三字节是从 0 开始的分片号。卡按这个顺序声明。
- 广播名 Omi/omi/Friend 作为匹配补充，主识别依据为公开 GATT 服务。电量使用标准电池服务。不发送未经协议支持的开始/停止命令。
- 协议没有提供可直接抄录的完整 Omi 抓包；分片用按固件格式构造的测试包验证，不称为真机抓包。

### 声云

- [BLE 通讯协议：第 2、3、3.1、5、7.3、9 节](https://github.com/SonicloudTech/sonicloud_opensdk/blob/main/pnote-web-win%26Mac-demo/docs/协议.md)：AE20/AE21/AE22；`MAGIC + SEQ + CRC + LEN + DATA`；CRC-16/XMODEM 覆盖 LEN 原始字节和 DATA；TYPE=1，开始 CMD=0、声音 CMD=1、停止 CMD=2；电量查询 TYPE=0/CMD=3 用于探测。
- [Android SDK 文档：开始录音回调说明](https://github.com/SonicloudTech/sonicloud_opensdk/blob/main/pnote-sdk-flutter-demo-main/android%20SDK开发文档(最新版本)-2026.04.23.md)：实时 Opus、16 kHz、单声道、40 字节一帧。
- 测试保留第 7.3 节原始 **36 字节真实 TX 帧**：SEQ=3、LEN=30、CRC=0x209E、TYPE=2/CMD=2、offset=0、文件名 `note20260710-162938.wav` 加 NUL。验证拆包结果和反向组包一致。
- `offline=files`、`filePlugin=sonicloud`，插件交给卡 120。

### 声云长度语义与当前约定的边界

实际 LEN 是整个 DATA 的长度，包含 TYPE/CMD；`PayloadSpec.LengthFrom` 约定却是字段之后的载荷长度。为保持约定签名和语义，声云卡只声明前 **6 字节外壳**，将整个 DATA 留作 payload，CRC 即 `len + payload`。不能把 TYPE/CMD 声明为外壳字段后仍直接按 LEN 读取声音，否则真实样例会多读两个字节。

通用组包规则：卡显式声明 Type/Cmd 字段时填入这些字段；都未声明时，`CardCommand.Framed` 的 TYPE/CMD 放到 payload 前两字节，一同计入 LEN/CRC。Raw 完全原样返回。这样声云 ACK 只有 TYPE 时也可以完成外壳校验。

卡 119 在声云接入时还必须分流 DATA：只把 `TYPE=1 && CMD=1` 的 `payload.drop(2)` 送给声音解码；文件名、控制应答、状态及单字节 ACK 不能当声音。当前约定没有通用的“音频消息选择条件、载荷子字段”配置，不能在核心写品牌判断来假装自动完成。若要全部由卡表达，建议 Claude 后续扩展消息选择/载荷偏移约定；本卡未改签名。

## 卡 119 / 121 可用接口

均位于 `app.resound.devices.core`。状态类按连接独立创建，串行调用。

| 类 / 方法 | 用法 |
|---|---|
| `CardParser(currentAppVersion).parse(json): Result<DeviceCard>` | 卡 121 的 `DeviceCards.parse` 直接委托。宿主传实际安装版本；支持当前版本的 `-preview.N` 后缀。卡的 minApp 必须为三段数字。 |
| `describeCard(card): String` | 中文审卡摘要：识别、通道、格式、命令参数及字节示例、外壳顺序、CRC 范围、分片、离线插件。字节示例从 SEQ=0 起，探测字段暂按小端，并非实际连接发送序号。 |
| `FrameCodec(frameSpec)` | 每个连接各一份；默认包/重组载荷上限 1 MiB。字段宽度 1–4 字节，字段数至多 64。 |
| `probeCommands(): List<ByteArray>` | 未锁定时生成探测请求；Framed 产生两种端序候选（去重），按超时依次尝试，不要一口气重复发送。 |
| `probe(response): Endian?` / `lockedEndian` | 对**完整应答协议包**试两种顺序，仅唯一通过时锁定。探测不消耗接收序号。 |
| `accept(packet): DecodedFrame?` | 输入一个完整协议包；返回无符号字段值 `Map<String, Long>` 和载荷。分片尚不完整、坏包、未锁端序等返回 null。 |
| `encode(command): ByteArray` | Framed 补常量、序号、LEN、CRC；Raw 原样。Probe 未锁定时拒绝普通 Framed 命令，用上面的探测入口。 |
| `diagnostics: FrameDiagnostics` | 累计 `received/lost/crcFailures/discarded`。lost 是包序号缺口，不是音频帧数。重复/迟到按半序号空间比较，重连必须新建实例。 |
| `discardFragments()` | 丢弃未交付分片。无末片标志，停止/断开时不会强行交付末帧。 |
| `AudioDecoder(codec, sampleRate, channels, packing, opus)` | PCM 不用提供 opus；Opus 注入 `AndroidOpusDecoder(codec, channels)` 或测试假实现。 |
| `AudioDecoder.accept(payload): List<ShortArray>` | 只喂已经剥掉协议消息头的声音，每个结果 480 采样。 |
| `finish()` / `reset()` / `close()` | 正常结束排空平台尾帧；丢包重置上下文与余量；finally 释放。尾部不足 480 的 PCM 不补零。 |
| `OpusDecoder` / `DecodedPcm` | 可替换的平台接口；实现报告实际采样率、声道数，允许暂时无输出或一次输出多块。 |
| `Crc.compute(algo, bytes): Long` | XMODEM、MODBUS、CRC32；Long 承载无符号 CRC32。 |

注意：`FrameCodec.accept` 的输入边界是完整协议包。声云协议第 9 节说明 BLE Notify 可能包含半帧/多帧，卡 119 需按 LEN 先缓存拆出完整包；AE22/AE23 分开缓存。Omi 则一条 Notify 就是一片，不能丢掉这个边界。包序号丢失或损坏导致声音缺口时，应重置 `AudioDecoder`，不要把缺口前后不足 480 采样的声音直接拼接。

## 真机注意与遗留

1. **声云音频仍须真机确认**：公开 SDK 写了 40 字节一帧，但本次协议没有明确 Opus 时长、通知内是否多帧/带前缀。卡中的 `opus20 + one` 是试用候选，不能宣称已证实。只有抓到 TYPE=1/CMD=1 的真实音频载荷并成功播放，才能决定是否改用 `lengthPrefixed`；若固件实际为“固定 40 字节多帧”，当前 `OpusPacking` 没有对应表示，需 Claude 增补约定，不可猜成长度前缀。
2. 声云 AE21 文档标为 WRITE_WITHOUT_RESPONSE；卡 119 使用 `DeviceLink.write(..., withResponse=false)` 或按发现的 characteristic 属性选择。现有卡约定没有单独的写模式字段。所有命令一次 GATT 写入，不拆。
3. Omi 的分片结束靠下一帧 `restartAt=0` 确认，会延迟一帧；断开最后一帧丢弃。若下一首片之前发生丢包，上一帧也丢弃，优先避免拼错。
4. Android MediaCodec Opus 仅编译验证，电脑测试用假实现；负责人在小米 14 Pro 验证连续声音、长时间采样时长、停止排空、重连释放与恢复。没有安装设备或做真机验收。
5. 当前构建仍是仓库原有 **0.2.20 / versionCode 58**。两张卡最低版本 0.2.21；实际 0.2.20 宿主会按要求拒绝加载，负责人合并发布升到 0.2.21 后才可加载。测试显式传入 0.2.21，没有绕过版本检查。
6. 蓝牙传输/通知组帧/消息分流交卡 119；离线文件插件交卡 120；`DeviceCards` 列表、开关、签名与远程加载交卡 121。试用卡启用规则不在本卡解析器里执行。
