# 硬件接入与协议适配

涛声既能使用手机麦克风，也能把外接录音设备的声音送入转写、整理、待办和记忆流程。本文说明 0.3.0 的现有适配、验证状态，以及厂商和开发者怎样参与。

## 用户：哪些设备可以接入

下表区分“已有实现”与“经过真机验证”。试用适配不等于所有硬件和固件都已稳定兼容。

| 设备 | 接入方式与已有能力 | 状态与限制 |
| --- | --- | --- |
| 普通蓝牙耳机、有线 / USB 麦克风 | 使用手机系统提供的音频输入 | 取决于手机系统与设备；蓝牙耳机通常走通话音频通道，不包含专用设备的文件补传与控制 |
| Omi | 内置说明卡：BLE 实时收音、标准电量读取 | 试用；当前说明卡未提供离线补传，不能据此推断所有 Omi 型号和固件均兼容 |
| ADeus ESP32-C3 | 内置说明卡：BLE 实时收音，8 kHz 单声道 PCM | 试用；仅对应这套协议配置，当前说明卡未提供离线补传 |
| 安克／飞书录音豆 D3200 | 内置驱动：BLE 实时收音、离线补传、录音控制、录音豆与充电盒电量、存储查询 | 试用；官方构建真机验收待完成，详见下节 |
| 可导出音频文件的录音设备 | 将录音文件分享或导入涛声；也可配置文件夹自动导入 | 无需专用协议适配；不代表可实时收音或远程控制设备 |
| 原内置声云适配 | 0.3.0 已移除 | 依赖该适配的用户请暂缓升级；历史版本介绍不代表当前支持 |

使用专用设备时，在设置中找到“专用录音设备”，按设备页面完成发现、配对及输入选择；页面展示的操作以实际驱动能力为准。遇到问题，请提供 App 版本、手机系统、设备型号、固件及复现步骤。

## 录音豆 D3200：能力与验证情况

驱动由贡献者 [@xhp1211](https://github.com/xhp1211) 维护，源自 [PR #30](https://github.com/0xCoach/TaoSheng/pull/30) 的适配工作，已整合为涛声的独立设备驱动。

- **已有实现**：实时声音输入、离线录音补传、开始 / 暂停录音、电量与存储查询；设备页按能力展示相应状态和操作。
- **已有外部测试记录**：原 PR 的独立验证包在 realme 手机、录音豆主固件 04.92、盒固件 1.2.2 上测试过短句补传与回放、状态刷新、开始 / 暂停、手动暂停后的重连保持等。这些记录不能代替迁移后的官方构建验收。
- **灯光限制**：Android 经典蓝牙灯控只对 04.92 发送命令，不属于跨平台通用能力；暖橙灯效仍待肉眼验收。盒外 USB 接电时，充电盒状态未能实时反映。
- **仍待验证**：官方构建真机验收、长时间收音、全量历史补传、进程重启及长时间断连续传、其他固件、iOS。实时与补传的 v1 录包及完整真机报告也待补齐。

最新驱动限制以 [D3200 驱动说明](../devices/src/commonMain/kotlin/app/resound/devices/plugins/d3200/README.md) 为准。试用时请保留原设备录音，确认导入与回放结果后再按需清理。

## 厂商与开发者：选择接入方式

| 路径 | 适合情况 | 需要提供或实现的内容 |
| --- | --- | --- |
| 系统音频输入 | 能作为普通耳机或麦克风工作的设备 | 验证手机系统可选中设备输入，以及断开后的行为 |
| 设备说明卡 | 协议公开，数据帧与能力可由现有说明卡机制表达 | 广播和服务信息、音频编码、帧结构、采样率、控制与状态字段；不能仅凭设备名称认定兼容 |
| 驱动插件 | 需要握手、加密、复杂控制或文件传输的专用协议 | 将厂商协议转换为涛声统一的设备模型，声明实际能力，提供测试和维护人 |
| 音频文件导入 | 暂不具备直连条件，但能导出音频 | 可读取的文件格式、导出或同步方式 |

### 统一适配规范，减少重复开发

涛声提供设备说明卡和驱动插件的适配规范，约定设备能力、音频数据、状态和控制的接入方式。现有 Omi、ADeus 和 D3200 使用各自的协议，通过说明卡或插件转换成共用设备模型。

- **复用现有能力**：按规范接入后，可继续使用现有的设备管理、转写、整理、待办和记忆流程，减少重复开发。
- **方便核心维护**：品牌与固件的专属逻辑集中在对应适配模块中，减少对核心代码的改动，便于独立排查和更新。
- **方便后续扩展**：新增设备沿用同一套接口和能力声明；确需新增公共能力时，再集中完善接口和兼容方案。

具体设备支持哪些功能，仍以适配实现和对应型号、固件的验收结果为准。

### 发起接入讨论

在 [GitHub Issues](https://github.com/0xCoach/TaoSheng/issues/new) 提供以下资料即可开始讨论，不要求一开始就完成驱动：

- 品牌、型号、硬件版本、固件版本，以及期望支持的手机系统。
- 目标能力：实时收音、离线补传、录音控制、电量、存储或其他功能；注明不支持的项目。
- 可分享的协议文档或 SDK、蓝牙服务与特征、音频格式、握手认证方式、文件传输规则和断连续传行为。
- 可用于联调的测试设备、可公开的样例录包，以及后续维护联系人或 GitHub 账号。

不要在公开议题中粘贴密钥或个人录音；提交录包前先确认内容适合公开。

### 实现与验收

- 共用驱动位于 `devices/src/commonMain`，品牌与固件特例放对应插件目录。驱动通过平台提供的连接、存储、密码等接口工作，不直接访问安卓系统、网络或界面。
- 仅声明真正实现的能力。读取不到的状态显示未知；取消、断开、重复请求和续传都需要有明确处理。
- 插件交付包含维护人、实时与补传录包及回放测试、真机报告。报告逐项区分实测、未测和不支持，不以电脑测试代替手机与硬件验收。
- 验收至少检查实际收音与回放、音频完整性、断开重连、补传与续传、录音控制和状态一致性，并记录手机、App、设备与固件版本。跨平台代码编译通过不等于 iOS 真机已通过。
