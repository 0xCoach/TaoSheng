# 卡 129 · 开源 / 协议公开的录音硬件调研，并预填设备说明卡

- 工作目录 `~/Developer/TaoSheng-129`，分支 `codex/129-device-cards-survey`（从 `plan/0221` 拉出）。**不改 `ui/`、`MainActivity.kt` 和任何约定文件**。
- 版本：进 0.2.21 或之后。这是调研 + 数据，不写新的接入代码。

## 背景

0.2.21 已有通用蓝牙接入：一台设备一张“说明卡”（JSON，放 `app/src/main/assets/devices/`），核心照卡收发。现有 `omi.json`、`sonicloud.json`（试用），`folotoy.json` 是占位（它的实时声音走 Wi‑Fi）。字段定义见 `app/src/main/java/app/resound/devices/DeviceContract.kt` 和 `docs/方案/外设接入字段表.md`；解析校验见 `devices/core/CardParser.kt`；之前的调研见工作区里的 `docs/调研/开放录音硬件协议调研.md`。

负责人要：搜市面上**开源或协议公开**的主流录音硬件（AI 吊坠、录音卡、录音笔、开发板参考设计等），**能从公开资料明确确认协议的**，预填成说明卡。

## 要做

### 1. 调研（写成 `docs/调研/开源录音硬件说明卡调研.md`）
- 覆盖面：Omi（各代：DevKit、CV1 等）、Friend 系、Limitless、Bee、Plaud、声云、FoloToy，及 GitHub / 社区里有公开 BLE 音频协议的其他项目（ESP32 / nRF52 参考固件、开源 AI 吊坠、Seeed XIAO 类录音参考设计等）。自己再搜，不限于这份名单。
- 每个设备一行表格：名称 · 是否开源 / 许可证 · 实时音频是否走 BLE（还是 Wi‑Fi / 只走厂家云）· 服务与特征 UUID · 声音格式（PCM/μ-law/Opus 帧长）· 包外壳（头部字段、分片、校验）· 开始/停止命令 · 电量 · 离线存储方式 · **能否写成说明卡（能 / 部分 / 不能）及原因** · 资料链接（必须是源码、官方文档或固件仓库的具体文件/行，不接受二手博客当唯一依据）。
- 只走厂家云、协议加密或资料不足的，写明“不能”，不要猜。

### 2. 预填说明卡
- 只为调研结论“能”的设备写卡，放 `app/src/main/assets/devices/<id>.json`，**`status` 一律 `trial`**，`minApp` 为 `0.2.21`。
- 每个字段都要能在资料里找到出处；在调研文档里逐字段列出处（不要写进 JSON）。拿不准的字段宁可这张卡不写。
- 现有 `omi.json`、`sonicloud.json` 按调研结果核对：有错就改并在交付说明写清，没把握的不动。`folotoy.json` 不动。
- 不写需要代码插件才能工作的部分（比如文件同步）；需要的话在调研里写明“需插件”。

### 3. 校验
- 加一个测试：遍历 `assets/devices/*.json`，全部能被 `CardParser` 解析通过（`trial` 卡也要能解析），id 不重复。
- 对写了包外壳的卡，若资料里有真实抓包或固件里的示例帧，用它做 1 个解码测试；没有就不编造示例。
