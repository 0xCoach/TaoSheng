## 要做

### 1. 抽出统一的“云端存储”
现在 `WebDavClient` 被 `AndroidBackupRepository`、`BackupRestore`、日记同步等直接使用。抽一个内部接口（名字自定，如 `RemoteStore`），覆盖现在用到的全部操作：列出、上传、下载、删除、存在判断、`VolumeStore`（按天分卷）、日记上传、保留份数清理等。`WebDavClient` 实现它；新写 `S3Client` 实现它。上层只依赖接口。行为不能变：现有坚果云用户的备份、增量、分卷、恢复全部照旧。

### 2. 自定义 WebDAV
`BackupConfig.endpoint` 现在默认坚果云地址。改为按 `BackupState.webDavUrl` 取。允许 https；http 只允许局域网地址（10.x / 172.16–31.x / 192.168.x / .local）。坚果云 = 固定地址的 WebDAV。

### 3. S3（自己实现，不引入 AWS SDK 或其他大依赖）
- 用现有 OkHttp 实现 AWS 签名 V4（SigV4）。操作：PutObject、GetObject、HeadObject、DeleteObject、ListObjectsV2（要处理分页）。
- 支持路径式和虚拟主机式（`S3Settings.pathStyle`），对象键加上 `prefix`。
- WebDAV 现在“先传临时名再 MOVE”的保护，S3 上用单次 PUT 即可（S3 单次 PUT 本身是原子的）；不做分块上传，单个对象超过 5 GB 给明确错误。
- **手机时间不准**：服务器返回 `RequestTimeTooSkewed` 等时间相关错误时，错误说明写“手机时间不准，请到系统设置里打开自动设置时间”，不要只说“上传失败”。其他常见错误（密钥错、桶不存在、无权限、区域不对）也各给一句人话。
- 本机测试用 MinIO：Docker 走 Colima，拉镜像要走代理 `host.lima.internal:7897`（见负责人本机约定）。测完删掉容器。

### 4. S3 预填服务商（先调研再写）
调研并在 `s3Presets` 里给出（每项：名字、地址模板、常用区域、地址格式、一句话提示，以官方文档为准，交付说明里附链接）：
阿里云 OSS、腾讯云 COS、华为云 OBS、七牛云 Kodo、Cloudflare R2、AWS S3、Backblaze B2、MinIO（自建），最后一个固定为 `id="custom"` 的“自定义”。哪家实际不兼容 SigV4 或有坑（比如只支持虚拟主机式），写进 hint 和交付说明。

### 5. 设置迁移与密钥
- 老用户：没有新字段时 `cloud = Nutstore`，账号密码沿用。
- S3 的私有访问密钥、WebDAV 密码只进系统安全区（与现有坚果云密码同一处理），**随备份一起备份、恢复**；恢复后三选一的选择和地址也一起恢复。
- 切换存储类型：旧的设置保留但不再使用；切换后下一次备份写到新位置。云端历史恢复点列表按当前选择读取。

### 6. 推送借用
`push/` 里 Markdown 文件夹推送的 `useLinkedNutstore` 改为“借用备份所选的云端存储”（兼容旧配置：旧值为 true 时等同借用）。借用 S3 时写到同一个桶、`prefix` 下另一个目录（目录名沿用现在的推送目录）。单独填仍只支持 WebDAV。字段改名会影响推送设置页，在交付说明里写清楚界面要怎么接。
