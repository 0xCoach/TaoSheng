# 任务卡 027：每日回顾定时修复（后端，小卡）

## 现象（Claude 已在手机上查清）

10 月 23 日 19:35 负责人手动生成过一次回顾。22:00 的定时任务按时运行了（WorkManager 里 `daily-review` 的 period_count=1、无错误），但 `RoomReviewRepository.run(date, scheduled = true)` 里 `dao.daily(date)` 查到 19:35 那条就**直接复用并推送**，19:35 之后的 31 件事没进回顾。

另有两处隐患：
1. `ReviewWork` 用 `LocalDate.now()` 定日期。手机睡眠时任务可能推迟到 0 点以后才跑，那时会去生成“新的一天”（空的），前一天的回顾就丢了。
2. 说明书 4.9 要求“22:00 之后说的话补进第二天”，现在按自然日 0 点切。

## 要做的

1. **回顾的时间窗**：日期 D 的日回顾覆盖 `(D-1 的回顾时刻, D 的回顾时刻]`，回顾时刻 = 设置里的 `dailyAtMinutes`（默认 22:00）。`ReviewPrompt.input` 里给模型的日期说明相应写清“昨晚 22:00 到今晚 22:00”。手动 `generateNow(date)` 用同一个时间窗。
2. **定时任务算对日期**：目标日期 = 最近一个“已到的回顾时刻”所在的日期。例如回顾时刻 22:00：在 22:00–23:59 运行 → 当天；在次日 0:00–21:59 运行 → 前一天。
3. **复用规则**：定时运行时，只有当已有回顾的 `generatedAt` ≥ 该日回顾时刻（也就是本轮定时之前那次失败重试已经生成过）才复用；否则重新生成并覆盖（`save` 已是 REPLACE）。手动生成照旧总是重新生成、不推送。
4. 推送沿用现有的 `notifier.send`（025 合并后会带 topic，本卡不用改这里的签名；如果合并时冲突，以 025 的签名为准，topic 传 `DailyReview`）。

## 测试（适度，共不超过 5 个）

时间窗边界（21:59 的事算当天、22:01 的算第二天）；定时在 23:00 / 次日 00:30 运行时的目标日期；早于回顾时刻生成的旧回顾会被重新生成；回顾时刻之后生成的会被复用。`./gradlew assembleDebug` 通过。**不要跑全量测试，不要反复重跑。**
