# 任务卡 025：推送通道（PushPlus、企业微信机器人、Server酱、通用网址）（后端）

## 背景与已定方案（负责人已拍板）

说明书 4.10：统一推送接口、多通道可选；每个通道可选推什么、用什么格式；有推送日志、失败重试、“测试一下”。本期先做四种：**PushPlus、企业微信机器人、Server酱、通用网址（Webhook）**。手机本地通知照常发，通道是额外转发。界面由 Claude 做，**本卡不改 `ui/` 下的文件**。

## 约定（Claude 已写，签名不要改）

- `push/PushContract.kt`：`PushKind`、`PushTopic`、`PushFormat`、`PushField`、`PushChannel`、`PushLog`、`PushChannels`。
- `push/Notifier.kt`：`send` 加了 `topic: PushTopic? = null`。`LocalNotifier` 已适配签名（topic 先不用）。
- `AppGraph`：已加 `push` / `isPushReady`，在 `ResoundApp` 里赋值。

## 要做的

1. **存储（本卡不改数据库）**：通道配置存 SharedPreferences `push`（JSON 数组），密钥类字段（`PushField.secret = true`）用现有的 Keystore 加密方式单独存，配置里只存引用。日志存 `push` 里的环形 JSON，保留最近 100 条。把 `push` 加进备份的设置白名单，但**密钥不进备份**（恢复后需重填，交付说明写明）。
2. **四种通道的字段与发送**
   - PushPlus：token（密钥）、可选 topic（群组编码）。`https://www.pushplus.plus/send`，template 随格式（txt / markdown / json）。
   - 企业微信机器人：webhook 地址（密钥，只允许 `https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=`）。text / markdown 两种（选 JSON 时按 text 发）。
   - Server酱：SendKey（密钥），`https://sctapi.ftqq.com/<key>.send`，正文 desp 支持 Markdown。
   - 通用网址：地址（只允许 https）、可选请求头 Authorization（密钥）。POST JSON：`{"title","body","topic","deepLink","at"}`；格式选 Text/Markdown 时 body 相应。
   - 所有请求：不跟随跳转、10 秒超时、响应体最多读 64KB；按各家的返回码判断成功（PushPlus `code==200`，企业微信 `errcode==0`，Server酱 `code==0`，通用网址 2xx）。错误文案给人看，**不含密钥和完整地址**。
3. **分发**：做一个 `ChannelNotifier : Notifier`，先调本地通知，再把 topic 匹配、已启用的通道各发一份（并行、互不影响）。失败用 WorkManager 重试（最多 3 次，指数退避，需联网），每次结果写日志。`AppGraph` 里原本给回顾用的 Notifier 换成它。topic 为 null 时只发本地通知。
4. **接上现有推送点**：每日回顾 → `DailyReview`。整理完新事件、待办提醒目前还没有发送点，先不加（`NewEvent`、`TodoReminder` 只在约定里预留，交付说明写明）。
5. `test(id)`：发“回响 · 测试推送 / 如果你看到这条，说明通道可用”，结果写日志。

## 测试（适度，共不超过 8 个）

四种通道各一个请求组装测试（用假服务器，检查地址、正文、格式）；返回码判定；失败重试入队；密钥不出现在 `summary`、日志和错误文案里。`./gradlew assembleDebug` 通过。**不要跑全量测试，不要反复重跑。**

**允许一次真实发送**：用负责人自己的 PushPlus 发 1 条测试消息验证。token 在 `~/.config/pushplus/token`，只能由脚本读取，**不得打印、写进日志或提交**。其他通道不做真实发送。
