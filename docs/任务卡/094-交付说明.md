# 094：首页连续右滑删除

## 原因和修改

- 分组内事件按位置复用组件；`deleteArmed` 随事件 ID 重建，但 `pointerInput(Unit)` 仍持有旧状态，造成后一条事件的删除确认与界面不一致。复现测试中第一条删除后，第二条无法显示确认提示。
- 原实现通过异步 `Animatable.snapTo` 累计拖动距离，连续输入可能读到尚未更新的位移。改为同步累计手势距离，动画仅用于显示回弹。
- 手势监听、阶段与确认计时器绑定事件 ID；新拖动重置距离，不继承上一轮回弹位置。保留两次右滑、3 秒确认期限、左滑两段操作。
- 用户明确要求排查修复首页交互，本次 UI 变更限于共用 SwipeRow；未改 Contract。

## 验证

- SwipeDelete094Test 三项通过：连续删除三条、行身份变化与确认超时后重试、快速连续滑动。
- 测试使用合成行，不操作手机真实事件。真实记录的删除效果留给用户复测。
