# 合并多条记录 — 交付说明

日期：2026-11-08　　基线：upstream/main（b2e0885）　　版本：versionCode 55 / versionName 0.2.17（本次未改动）

## 做了什么

在「今天」页的多选里加了「合并」：把选中的多条记录替换成一条，把这几件事各自关联的识别后文本（不重新转写）合起来重新发给大模型分析，做完可一键撤销。

**界面层不在本 PR 内**（界面归上游维护者）。本 PR 只提供数据与操作层；界面需要的入口、参数与行为约定写在 PR 正文的「界面需要的接口」一节。

### 功能规则

- 合并至少要两条事件，否则任务失败。
- 只发选中这几件事自己的原话（按 eventId 关联），不按时间范围取料，中间没选中的事不会被顺带重做。
- 原话不重新转写，所以原声过期也能合并。
- 只允许合并前后挨着的事：两件事相隔超过 30 分钟（常量 `MERGE_MAX_GAP_MS`）不让合并，引擎二次校验，不只靠界面。
- 原来标了重点的，合并后仍是重点；已确认、已完成的待办保留并改挂到新事件，不重复出现在待确认里。
- 合并事件覆盖全部参与的原话行；撤销能把事件、待办、原话归属完整还原。
- 模型没合成一条（返回多条或缺 `merged`）时任务失败，旧数据不动。

### 两个容易踩的坑（已处理）

1. **不能复用「只重新整理」**：重做按时间范围取料，会把中间没选中的事件顺带重做；重做提示词规则也是「按话题切分多条」，不会输出单条。所以新增 `RedoScope.Merge` 和独立提示词。
2. **加新 scope 必须同时改所有 scope 判断点**：`scope != DigestOnly` / `scope != TranscribeOnly` 这类写法在加了 `Merge` 后含义会变（转写就绪校验会把合并任务卡死）。已全部换成 `scope.transcribes` / `scope.digests`。

## 真机需要注意什么

需要维护者在手机上确认：

1. 选 2 条相邻记录合并，新事件的标题与摘要由模型重新生成，不是两条标题拼接；
2. 合并后原话页里这几句原话都指向新事件；
3. 原来标了重点的，合并后仍是重点；已确认 / 已完成的待办跟着挂到新事件；
4. 撤销后能还原成原来的两条，原话归属与待办回到原处；
5. 选两条相隔超过半小时的记录，合并被拦下并说明原因；
6. 中间还有没选中的事时，那件事应当单独留着、互不影响。

## 遗留问题

- 30 分钟间隔是硬阈值（`MERGE_MAX_GAP_MS`）。「会议」+「会后结论」若相隔 40 分钟就合不了，需要时改这个常量。
- 合并事件的时间范围是所有参与原话的首尾，中间未选中的事件仍独立存在，时间线上会重叠。界面前置提示，但不阻止。
- 技能卡重建只用参与行的原话，当天其它原话不在上下文里——与「重做」一致，不在本次范围。
- 模型可能写成拼接标题（「会议」「会议（续）」）。提示词已要求写完整标题，人工可在事件详情里改。
- 没有做数据库迁移，`0.2.17` 与本 PR 数据库版本相同，可直接覆盖安装。
