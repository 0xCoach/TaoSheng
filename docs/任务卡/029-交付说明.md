# 029 交付说明

## 做了什么

- 仅后端：未改 `ui/`、`MainActivity.kt`、任何 `*Contract.kt` 或 `AudioSource.kt` 的签名。
- 云端备份改为 `retain(30)`，明文 `.zip` 与加密 `.zip.enc` 合计保留最新 30 份，按文件名时间排序；不是按 30 个自然日清理。日记及临时文件不参与保留策略。
- 实现 `remoteBackups()`：兼容旧版分钟文件名和新版毫秒/随机后缀文件名，返回时间、字节数、加密标记，新版本在前；过滤非法日期、临时文件和目录外地址。
- 实现指定备份恢复：下载 → 解密（如需）→ ZIP 白名单、散列和 SQLite 完整性校验 → 在隔离副本上通过现有 Room 迁移链验证 → 保存本机快照 → 登记待恢复数据 → 请求自动重启。启动时在业务数据库和设置仓库初始化前替换，提交标记支持中断重放。数据库版本比 App 新时明确拒绝；旧版本走既有迁移链，不做破坏性重建。
- 恢复前快照为 `noBackupFilesDir/before-restore/<随机编号>.zip`，完整写入后才允许登记恢复；下次成功备份后清理，备份失败保留。快照只保存在本机私有目录，不上传。
- 备份加密默认关闭。开启后整包使用 PBKDF2-HMAC-SHA256（210000 次、16 字节随机盐）派生 AES-256-GCM 密钥，12 字节随机 nonce、128 位认证标签，头部也参与认证。口令通过 Android Keystore 包装后本地保存，不进归档、不上传。安全区读取失败不会降级为明文上传。
- 恢复优先试本机保存的口令，再试本次传入的口令；错误返回“口令不对”。`setEncryption(null)` 仅关闭后续备份加密，旧加密文件仍按普通保留策略保留。
- 新增 `LocalPromptTemplates` 并装配 `AppGraph.prompts`：三个模板有中文名称/说明，占位符从默认文本扫描；空文本、缺必需占位符拒绝保存，覆盖文本原子写入 `filesDir/prompts/<id>.md`，reset 删除覆盖文本。
- 整理、回顾、问问改为每次执行时读取 `PromptTemplates.text(id)`，不再缓存启动时的 Markdown。模板读写与备份取文件共享互斥锁。
- 自定义模板进入备份与本地快照；恢复旧备份时清掉本机多余的自定义模板，以免混用。其余设置沿用原安全白名单：capture、digest、diary、push；录音、密钥容器和未知设置不入包。
- 每晚日记仍独立上传明文 Markdown，不受整包加密及 30 份保留策略影响。

5. 加密往返、随机盐、错误口令和篡改拒绝，失败清理解密输出。

8. 空模板和缺必需占位符保存失败，不覆盖现有文本。

## 真机需要注意什么（由负责人实测）

本次禁止操作手机，因此以下不声称已在小米 14 Pro 验证：

- Android Keystore 持久化口令、重启后加密开关与本机口令恢复。
- 澎湃 OS 下恢复后自动拉起 App，以及录音/队列服务恢复运行。
- 大数据库/低存储空间下的恢复耗时与空间需求。下载、解密、迁移副本、本机快照会同时占用空间。
- 三个模板修改后下一次任务采用新文本；界面显示列表、错误口令、恢复确认及恢复默认操作。

**密钥不在备份里。恢复后需重新填写转写 API Key、大模型 API Key、推送凭据、坚果云应用密码；如仍需加密备份，还需重新设置备份口令。** 同机恢复也清除这些本机凭据，自动备份关闭，重新配置后再开启。云端旧加密包仍需记住原口令。

本地恢复前快照沿用普通 ZIP 格式，仅在 App 私有 `noBackupFilesDir` 中保存，不受云端备份加密开关控制。
