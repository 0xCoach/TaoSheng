## 一、已定方案：按天分卷（逻辑增量，不依赖本机基准）

### 1. 云端 / 本机文件夹的布局（全英文）
```
Resound-Backup/
  resound-state.zip(.enc)          ← 当前状态，每晚覆盖（坚果云自己会留历史版本）
  days/resound-day-YYYY-MM-DD.zip(.enc)   ← 每天一个分卷
  features/<sha256>.bin(.enc)      ← 声纹特征文件，一个文件一份，只增不改
```
本机文件夹同样结构（`Resound-Backup` 换成用户选的文件夹本身）。

### 2. 每张表归到哪
- **按天分卷**（按记录自身的时间戳归到那一天，北京时间）：`transcript_lines`、`segments`（只元数据，不含音频）、`memory_events`、`memory_items`、`skill_cards`、`reviews`、`ask_conversations`、`ask_messages`，以及能按时间归天的统计/运行记录（`asr_attempts`、`asr_usage`、`llm_usage`、`skill_runs`、`app_power`、`battery`、`heartbeats`、`watchdog` —— 这些可以只保留最近 30 天，旧的不备份也行，你定，写进交付说明）。
- **状态分卷**（`resound-state`）：没有自然日期或全局性的：`voiceprint_people`、`voiceprint_samples`（样本元数据，引用 features）、`voiceprint_exclusions`、Room 版本号；**全部设置文件**（现有白名单 + 之前排除的：transcribe、local-asr、capture、ui、review、push、diary、digest、setup 等，逐个过一遍，只排除纯运行时缓存/锁/队列）；技能文件 `files/skills/`、提示词 `files/prompts/`；**全部密钥**（见第 4 条）；以及一份**分卷清单** `manifest.json`：每个日分卷的日期、文件名、大小、内容指纹（行数据的 SHA-256）、schema 版本。
- **不备份、恢复后重算**：`embeddings`（语义搜索向量，恢复后后台重建）、三张 FTS 表（恢复后 rebuild）。
- **声纹特征文件** `capture.db.voiceprint-features/`：按文件内容 SHA-256 命名放 `features/`，云端已有同名就不传（天然增量）；状态分卷里记录“本机文件名 → sha”映射。

### 3. 每晚怎么传（不需要本机基准）
1. 读远端的 `resound-state` 里的分卷清单（读不到 = 远端没有分卷备份，当作空清单；**换手机、清缓存后也走这条**）。
2. 本机按天把每张按天表的行序列化（按主键排序、列名+值的稳定 JSON），算每天的指纹；和清单比，**只上传指纹不同或远端没有的那几天**（通常是今天和昨天；改了旧记录的那天也会被重传）。
3. 上传缺的声纹特征文件。
4. 最后写新的 `resound-state`（含新清单）——**先传日分卷、后写状态**，中途失败不会出现“清单指向不存在的分卷”。
5. 本机删除了某天的全部记录（隐私删除）→ 远端那天的分卷也删掉，清单里去掉。
6. 第一次（远端什么都没有）自然就是把所有天都传一遍；之后每晚只传变化的几天。

### 4. 密钥和账号
- 状态分卷里放一个 `secrets.json`：所有 `SecretStore` 里的值（模型、转写、推送通道、坚果云应用密码、备份口令除外）**解密后的明文**，按 store 名 + key 组织。
- **加密开着**：整个分卷用备份口令加密（现有 `BackupEncryption`），密钥随之受保护。**加密关着**：照样备份密钥（负责人要方便），但 `BackupSummary.includesSecrets=true`、`encrypted=false`，界面会提示“备份里有密钥，建议开启加密”。
- 备份口令本身不进备份（忘了口令没法解，放进去没意义）。

### 5. 恢复（`restoreAllFromCloud` / `restoreAllFromLocal`）
1. 下载状态分卷 + 清单里全部日分卷 + 全部特征文件，逐个校验指纹；加密的用口令解（本机记得的口令或用户输入的）。
2. 在暂存目录**用当前 App 的 Room 结构新建一个空库**，按列名把各分卷的行插进去（分卷的 schema 版本比当前低时，缺的列用默认值；比当前高 → 拒绝并提示升级 App），然后 rebuild FTS，`integrity_check`（注意：可写打开，见 091bc23 的教训）。
3. 走现有的替换流程（关库、替换、重启），**但不再清空密钥**：用状态分卷里的 `secrets.json` 写回各 `SecretStore`；备份里没有的那几项，**保留手机上现有的**。设置文件同理：备份里有的覆盖，备份里没有的保留。坚果云账号/密码恢复后备份开关保持原样（不要强制关掉）。
4. 恢复完后台重建 embeddings。
5. 恢复前照旧在本机留一份快照（已有逻辑）。

### 6. 旧格式和迁移
- 第一次用新方案备份时，远端/本机已有的 033/034 旧文件（`resound-full-*`、`resound-inc-*`、`resound-*.zip`）**保留不动**，旧的恢复入口仍能用；新方案稳定运行 7 天后（以清单里最早日期 + 状态分卷时间判断），自动删掉 `Resound-Backup/` 根目录下的旧格式文件（不碰 `days/`、`features/`、旧中文目录）。
- `keep`（保留几天）对新方案不再适用：分卷就是全部历史，不删。`setKeep` 保留但不再影响分卷。
- 卡 034 的页差异代码：新方案稳定后可以删；本卡先不删，只是不再被调用。

### 7. 导出一份（`exportTo`）
导出成一个单文件 zip：内部就是上面的目录结构（state + days + features），方便拷到新手机用“从文件恢复”。`restoreFrom(uri)` 识别这种单文件并走第 5 条的恢复。

### 8. 状态
`BackupState`/`LocalBackupState` 的 lastBytes 写本次实际上传量；`remoteCount`/`count` 写“多少天”。`cloudSummary`/`localSummary` 读清单返回。

## 二、必测（新增 10～15 个，`app.resound.backup.*` 全部通过）

1. 行序列化稳定：同样数据两次指纹一致；改一行只影响那一天。
2. 首次全传；第二次只传今天；改了 3 天前的一条待办 → 只传那天 + 今天。
3. 远端清单为空（模拟换手机/清缓存）→ 全部重传，不报错。
4. 先传分卷后写状态；中途失败时远端清单仍指向完整的旧分卷。
5. 恢复：空库 + 按列名插入，记录条数、内容和原库一致；FTS 能搜到；声纹特征文件齐全。
6. 低版本分卷（少一列）能恢复，高版本拒绝。
7. 密钥：备份里有的写回；备份里没有的保留手机现有值；加密关着时 includesSecrets=true。
8. 隐私删除某天 → 远端那天分卷删除。
9. 导出单文件 → 从文件恢复成功。
10. 旧格式文件 7 天后自动清理，且不碰 days/、features/。
11. **真机相关**：所有 SQLite 校验用可写打开（FTS4 integrity_check 在安卓上要写）。
