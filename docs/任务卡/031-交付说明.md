# 031 · 技能框架交付说明

## 实现内容

- 实现 `SkillRepository` 后端，`AppGraph.skills/isSkillsReady` 装配完成。列表顺序为两个 Core 占位、三个官方技能、个人技能；Core 保持启用且设置不可改。
- 官方定义采用 `formatVersion: 1` 的 JSON 与独立要求文件；校验 id/key、字段类型、时间/星期、卡片日上限。三个要求分别为 250 / 263 / 259 字。
- 用户时间、开关、推送、预设与要求独立保存；写入使用 `AtomicFile`。支持复制个人版本、来源版本提示、字段 key 只增不删、字段结构变更自动递增版本。
- 固定本人归属规则、北京时间日历、热词和字段输出规范；输入放入转义后的 `<untrusted_data>`。支持 Day / Week / SinceLastRun、MeOnly、约 4 万字原话上限；引用只接受本次行号，Quotes 由程序回填原文、身份和时间。
- 新增 `skill_cards`、`skill_runs` 与 11→12 迁移。原有表的导出 schema 完全不变。卡片保留生成时字段/名称/图标；同实体保留 id 更新、相交会议扩展时段、跨卡合并保留实体别名；软删除不复活，日上限在事务内检查。
- Daily 使用带网络约束的一次性唯一 WorkManager 任务；计算最近时间，支持星期限制、仅补当天、网络失败隔 10 分钟重试一次。AfterDigest 经注入钩子排队；按上次运行间隔与增量范围执行。每技能每天自动最多六次，手动不限，单技能失败不阻断其他技能。
- 试跑返回预览，不保存卡片、不推送，但记录运行与实际 token；格式错误最多重试一次。自动首次新卡按技能设置推送，合并更新不重复推送。
- `files/skills/` 中有效定义、要求、覆盖文件加入坚果云备份与恢复；恢复旧备份时清除本机旧技能覆盖，避免混用。凭据不进入技能文件。

## 遗留与方案说明

- 现有 `llm_usage` 没有用途列，而任务卡要求不得改其他表。因此实际 token 仍累计到原表当天总量；`skill_runs.purpose = skill:<id>` 保存按用途可追溯的明细与 30 天用量，未改动原表。如果后续要求直接在 `llm_usage` 按用途查询，需要单独确认 schema 变更。
- 运行记录保留完整最近 30 天，且至少保留最近 500 行，以免只留 500 行导致较多个人技能的 30 天统计少算。
- 离线样本仅有一天内容，不能用它验收完整周趋势；真机调度、通知跳转及云端备份未操作手机验证。
