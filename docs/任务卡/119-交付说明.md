# 卡 119 交付说明

## 做了什么

- `AndroidDeviceLink` 实现连接、MTU、服务发现、读取、整条命令单次写入和多收集者通知。主线程处理 GATT 回调，Mutex 排队并等待对应回调；包括无响应写入也等安卓发送完成回调。订阅登记后，后续读写先等待 CCCD 完成，防止开始命令早于通知订阅。超过 MTU 的命令直接拒绝，不拆写。超时、取消未完成操作、断开或通知积压会作废整条连接，避免迟到回调串到下一项；通知 Flow 以 `AudioSourceException(Disconnected)` 结束。
- `ManagedDevices` 实现 `Devices`：按已启用说明卡的名字前缀、广播服务 UUID、厂商 ID 任一条件匹配，未知设备和关闭的 trial 卡不显示；搜索 30 秒自动停止。按 `bond` 决定是否等待系统配对成功，保存地址、卡 ID、名字；forget 删除本应用记录，不擅自解除系统配对。
- 安卓 12+ 声明 SCAN（neverForLocation）和 CONNECT；安卓 10/11 声明旧蓝牙管理和前台搜索定位权限。缺权限、蓝牙关闭、系统搜索失败都返回错误，不崩溃。
- 新增 `InputKind.CardDevice("专用录音设备")`。已记住、说明卡已启用且有 audio 的设备出现在输入列表；自动不选，只能指定。录音服务运行且选择该设备时才连接。连接等待/重试期间保持手机录音；设备产出标准帧才变为可用，复用 `InputSwitchLoop` 切换和 3 秒冷却。断开即时回退，3 秒后后台尝试重连；停止录音、改选、关卡或忘记设备都会取消旧链路。
- `CardAudioSource` 读取 codecRead，订阅、探测端序、写时钟、start，经卡 118 的 FrameCodec/AudioDecoder 输出 16 kHz 单声道、480 采样 PCM。停止前尽力发送 stop（有 1.5 秒上限），关闭解码器和链路。复用卡 112 的 20 秒全零判故障、2 秒有效声音超时；BLE 数据录音不申请系统通话路由、不占手机麦克风。
- 按卡调度心跳；标准/自定义电量读取以及协议电量查询首次进行，之后每 5 分钟一次。可选 GATT 电量读取在子协程中进行，避免阻塞声音解码。
- `NotificationFrames` 按 LengthFrom 拼半包/拆多包，Rest 保留通知边界。声云独立 `SonicloudLive` 插件只把 TYPE=1/CMD=1 的声音交给解码器；控制、文件和电量应答不当声音。CRC 错误或序号缺口重置解码余量，避免跨缺口拼帧。端序候选按超时依次探测。
- 每台设备独立装配卡 120 的 `DeviceSync` 和文件插件；首次连接、重连均调用 onLinked，连接结束取消旧补传协程。记录实际 GATT 断开时间、恢复时间和已知时钟偏差，补传进度映射 `DeviceState.backfill`；缺口在补传入口返回前保留，未完成传输继续由卡 120 数据库恢复。
- 配对信息及缺口保存在 `devices` 设置；加入现有备份。`device-cards` 只备份 `enabled:*` 开关，不备份远程表/签名缓存和请求限频时间。读取新备份后下次启动恢复。
- 每条连接累计收到包、丢包、CRC 失败、解码失败数，每 5 分钟及结束时写现有问题记录的诊断日志。设备用地址 SHA-256 的短标识，不写原始地址、名字、声音或数据包。
- 卡 121 的生产装配改为注入卡 118 `CardParser(实际安装版本)`，不再用临时解析器加载生产卡。FoloToy 空 match 占位卡会被严格解析器隔离并记录 bundled_invalid，不编造蓝牙音频协议。

## 界面接点（Claude）

- 搜索、停止、配对、忘记：`AppGraph.devices`；分别观察 `found` 和 `devices`。`DeviceState` 提供状态、电量、最近错误、补传进度。
- 搜索还没有设备时也需要报错，因此额外通过 `AppGraph.deviceScanError: StateFlow<String?>` 暴露全局搜索/配对错误。没有改 `Devices` 约定签名。
- 卡列表及试用开关仍用 `AppGraph.deviceCards.cards / setEnabled`。Omi、声云卡默认 trial 关闭，用户明确打开后才参与搜索和录音输入列表。
- 设备页搜索前请求安卓 12+ 的 SCAN、CONNECT；安卓 10/11 前台搜索请求 FINE_LOCATION。现有输入页只给普通蓝牙耳机请求 CONNECT，专用设备也需要纳入权限请求。底层不会自行弹权限界面。
- `AppGraph.inputs` 已合并专用设备，不需要另建输入列表。key 为 `CardDevice:<地址>`，录音片段 sourceId 使用相同 key。未选设备不保持连接，所以 connected=false 表示当前没有有效音频链路，仍可点击指定。
- 当前只自动补断开区间；卡 120 的“导入全部历史文件”仍是后续界面入口，不在本卡添加按钮。

## 真机注意与遗留

1. 当前仓库仍是 **0.2.20 / versionCode 58**，Omi/声云卡 minApp=0.2.21，实际本构建会按要求拒绝加载。负责人统一发布升版后再走设备页验收；本卡没有改版本、降 minApp 或绕过检查。测试显式使用 0.2.21 解析卡。
2. **没有安装手机，没有 BLE 真机验收。** 以假通道、Omi 和声云协议卡为本次验证基础。FoloToy 已查明实时音频走 Wi-Fi，现有卡没有匹配/音频定义，不作为 BLE 录音验证设备。
3. 小米 14 Pro 上需验证权限拒绝/撤回、关闭蓝牙、扫描配对、指定录音、播放可听音频、断开后手机持续录音、重连切回、取消后停止收音/释放 GATT、锁屏持续录音和电量。标准电池服务不存在时电量保留未知，不能假报 0%。
4. Omi 用实际 codecRead 验证 PCM/Opus 和分片；声云仍需实测 Opus 帧长/封装、AE22 通知边界、无响应单写、实时收音与文件补传并行。卡 118 的 `opus20 + one` 仍是试用候选，若固件是固定 40 字节多帧，需要 Claude 扩充卡约定后适配，不猜成长度前缀。
5. **声云当前卡没有 clock，文件插件也没有可靠修改时间**。因此传 null 偏差，卡 120 会安全跳过无法可靠定位的自动补传并记录原因，不会拿重连时间冒充文件结束时间。fake 测试验证缺口调用准确，不等同于声云真机补传已通过。
6. 现有 CardClock 只有写，没有读取旧设备时钟：本实现成功写 unix32 后保存秒级量化偏差；BCD 明确定义为 UTC 的 YY/MM/DD/hh/mm/ss 六字节。补旧文件只使用断开前保存的偏差，不用重连后新写的时钟推算旧文件。需要读取旧时钟、时区/响应格式或更精确往返校准的设备，须 Claude 扩充约定。两张现有卡均未声明 clock。
7. Android GATT 的实际回调顺序、MTU 协商、系统配对及 MediaCodec Opus 只能由真机最终确认。单次命令大于实际 MTU-3（最大 512 字节）明确失败，不拆包；设备必须协商足够 MTU。
8. 没有改 UI 或 MainActivity；设备页、权限弹窗和枚举图标需按上述接点接入。没有推送远端。

安卓实现依据：[GATT API](https://developer.android.com/reference/android/bluetooth/BluetoothGatt)、[蓝牙权限](https://developer.android.com/develop/connectivity/bluetooth/bt-permissions)。设备协议沿用卡 118/120 已核对的官方材料。
