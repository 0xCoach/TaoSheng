## 一、相似灵感自动合并

1. **对象**：`memory_items` 里 category = 灵感（以后可扩到“关键信息”，本卡只做灵感）。
2. **数据库 12 → 13**：`memory_items` 加 `mergedInto INTEGER NULL`（被并进了哪条）、`noMerge INTEGER NOT NULL DEFAULT 0`（用户拆出来过，以后不再自动并）。写迁移；备份分卷按列名写行，新列有默认值，旧分卷能恢复（跑一下 `app.resound.backup.DayVolumesTest` 里与 schema 相关的用例确认）。
3. **怎么判断相似**：用现有的本地语义向量（`search/` 包的 `EmbeddingStore` / `LocalEmbedder`，条目已经有向量）。新灵感出现后（整理完一轮之后的钩子，或向量补算完成后），和已有的独立灵感比余弦相似度：
   - ≥ 0.86 直接并入最相似的那条（并入“更早的那条”，让最早说出的为主条）；
   - 0.78～0.86 之间**不自动并**（宁可不并也不乱并）。
   - 阈值先按这个，交付说明里用几组合成例子（同一想法换说法 / 相关但不同的想法）实测，必要时微调并说明。
   - 向量还没算好（本地模型没下载完）时先不并，等算好后再补做。
4. **合并后**：被并的条目 `mergedInto = 主条 id`，不删除；主条的 `repeats` = 1 + 并入它的条数（查询时算，不必存）。`items()`、`dayItems()` 等列表**只返回独立条目**（`mergedInto IS NULL`），主条带上 `repeats`。主条内容不改写（不调大模型）。
5. **`mergedItems(id)`**：返回并进这一条的所有条目（带各自的 `sourceLineId`、时间），按时间先后。
6. **`unmerge(id)`**：把这一条拆出来（`mergedInto = NULL`，`noMerge = 1`），以后不再自动并它。
7. **删除 / 隐私删除**：主条被删时，并入它的条目里最早的一条升为新的主条（其余改指向它）。

## 三、每日心力 `dayMoods(from, to)`

按天聚合当天事件（**排除场景为“媒体”“旁人”的事件，以及被删除的**）：
- `minutesByEmotion`：每个事件按 (endAt - startAt) 计入它的 emotion，向上取整到分钟，最少 1 分钟；emotion 为空的不计。
- `mainEmotion`：分钟最多的那个。
- `energy`（0～100）：每个事件给一个效价 v：愉快 +1、兴奋 +0.9、平静 +0.3、紧张 -0.4、焦虑 -0.6、烦躁 -0.7、疲惫 -0.7、生气 -0.8、低落 -1；权重 = 分钟数 × (intensity ?: 3) / 3。当天 E = Σ(v×w)/Σw，energy = round((E + 1) / 2 × 100)。没有可计的事件为 null。
- 返回 from..to 每一天一条（没有事件的日子 energy = null、空 map），按日期先后。用 Flow，事件变化时自动更新。
- 写一个小函数单测效价换算。
