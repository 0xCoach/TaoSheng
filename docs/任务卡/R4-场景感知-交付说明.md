# R4 场景感知录音 — 交付说明

## 做了什么

新增 `SceneEngine`（shared 纯函数）统一录音准入决策，输出仍走既有 `pauseUntil/resumeCapture` 通道——停录时段、会议覆盖、MicBusy 让麦、孤儿找回等已验证链路零改动。

| 场景 | 实现 | 说明 |
| --- | --- | --- |
| NORMAL | 既有录音链路 | 不变 |
| MEETING | 沿用专题系统（TopicPolicy.overridesQuiet） | 不重复开发 |
| IDEA_CAPTURE | `IdeaRepository.markMoment` + 设置页"记灵感" | 片段内 60s / 指纹双重幂等 |
| QUIET_HOURS | 既有 QuietSchedule 停录时段 | 不变 |
| PRIVACY_PAUSED | 新增 `privacyPaused` pref + PRIVACY intent | `manualPausedUntil=MAX` 复用全部遗留数学：闹钟跳过、漏录排除、守护静默 |
| MIC_INTERRUPTED | 既有 MicBusy/MicYield + 占用方归因 | 决策层仅标场景标签 |
| RESOURCE_LIMITED | 新增资源信号（低电未充电/thermal≥MODERATE）→ `deferHeavyWork` | 录音照常落盘；EarlyTranscribe 原有电量/温度门独立保留 |

- `scene_sessions` 表（迁移 40→41）：记暂停类与资源受限场景起止，kind/source/startedAt/endedAt/reason；进程重启用 `endedAt IS NULL` 恢复。MicInterrupted 沿用 watchdog 事件、Meeting 沿用 topic_spans，不重复建行。
- `AndroidScene`（AppGraph 装配）：信号采集（电量/热/专题/停录/占用）→ `SceneEngine.decide`；`track()` 在每次 reconcile 写会话。
- `CaptureService`：`reconcilePause` 改走 `scene.decide`；新增 `PRIVACY` action（服务自己写 pref，幂等）；`RESUME` 清 `privacyPaused`；`plannedPause` 同源。
- 设置 → 录音与后台 → "场景感知"：总开关、当前场景+原因、隐私暂停开关、记灵感、最近场景记录。**越权提示：AGENTS 分工里 ui/ 归 Claude，本卡按专项指令做了最小实现，后续可再由 Claude 精修。**

## 优先级与默认值

隐私暂停 > 手动定时暂停 > （会议覆盖）> 停录时段 > 录音。任何自动规则都不能恢复隐私暂停；通用 RESUME 是用户动作，视为显式恢复。
总开关 `sceneAware`（默认开）只控制新派生项：场景标签、会话记录、资源延后；**关掉后录音指令与旧 `capturePausePlan` 完全一致**（测试 L 覆盖）。停录时段是既有用户规则，不被总开关关掉。

## 真机注意 / 遗留

- 隐私暂停语义：进入时覆盖 manualPausedUntil 为 MAX，解除时清零——若之前还有未到期的定时暂停会被清掉（边界情况，可接受）。
- 隐私暂停期间应用被杀：重启缺口在 watchdog 里记为 Killed 上界估计（manualUntil=MAX 时 recordingGaps 已排除；若暂停中途被杀再恢复，残余区间按上界计入）。
- `deferHeavyWork` 目前只进入决策与会话记录；转写/整理的延后沿用 EarlyTranscribe 独立门，未统一接线（有意保守）。
- 场景会话结束时间为近似值（进程死后续开会话在新一次 reconcile 关闭）。
- 测试矩阵中依赖真机交互的项（蓝牙重连不恢复隐私、电话抢占归因 UI 呈现）标 BLOCKED/待实测；逻辑层已由单测与本次真机路径覆盖。
- 未做 Wear OS/健康数据（按指令不进核心 APK）。
