## 状态流转

1. 运行中进入停录段：取消当前录音协程并走原有收尾，释放麦克风/唤醒锁，保留服务、心跳与前台通知。状态 `Paused`，`pausedUntil` 为有效结束时间；停录结束比手动暂停晚时才带 `quietName`。
2. 手动暂停另存 `manualPausedUntil`；升级时从旧 `pausedUntil` 迁移一次。两种暂停取较晚者，相等时显示手动暂停。
3. 用户点恢复（首页或通知）：写当前合并段的 `quietSkipUntil`、清手动暂停、刷新 active 为 null、恢复录音。自动闹钟/计时器使用 RECHECK，不会写跳过标记；下一段照常生效。
4. 改、删、开关规则：立即通知已有服务重新决定；没有剩余手动暂停就恢复。有手动暂停则继续到其截止时间。
5. 用户主动 Stopped：规则仍可计算和保存，但不启动服务；时段内 start 直接暂停，不先拿麦克风。停止后排队的 RECHECK 也不会把录音重新打开。
6. 闹钟：进入/离开边界用精确闹钟；无权限或权限被撤回时退为 `setAndAllowWhileIdle`。服务仍有原暂停计时器和心跳兜底。全天无间隙的规则合并视为持续停录，没有虚假的离开边界。
7. 守护：进入记录 `Paused`（如“停录时段：睡眠，至 07:00”），恢复记录 `Resumed`。暂停心跳 running=false；被杀恢复时只记录本应录音的缺口，跨多个停录段的真实缺口分段落库。

## 真机待验与遗留

由负责人验证以下事项：

- 23:00 前开始录音，跨夜至 7:00：夜间麦克风释放、前台通知保留、到点恢复；锁屏和省电状态下再验证一次。
- 首页恢复、通知“现在恢复”均只跳过当前合并段，次日晚再次停录；手动暂停早于/晚于睡眠结束的两种情况。
- 时段内开录、停止、关闭/删除当前规则、修改结束时间，检查首页状态和通知及时变化。
- 改时区、改系统时间、撤销精确闹钟权限，检查重新定时和降级后的恢复；无精确闹钟权限时边界可能被系统延后，心跳仅为兜底。
- 时段内重启手机、更新应用或系统杀进程：后台不会强行新建麦克风前台服务。已有前台服务被系统彻底销毁后，结束时提示用户恢复；这与“保留服务过夜自动恢复”是不同场景，不能保证系统杀进程后自动拿回麦克风。
- 检查守护日志/漏录统计不把睡眠时间记入缺口；当前规则参与恢复时的缺口估算，仍是上界估计，没有额外保存历史规则版本。
- 停录规则随现有 capture.xml 备份；恢复后重启应用核对规则与默认规则不重复。

无待处理的编译/单测错误；真机尚未验证。UI 和约定文件的并行改动属于负责人，本卡未修改或撤销。
