# 卡 210 交付说明：鼾声中断去重、更新少点几次、声音详情图放大与列表折叠

## 1. 鼾声中断被重复记录（程序问题）
- 现象：用户 11-19 截图里 02:00 连出 3 条、02:17～02:18 连出 10 条“鼾声中断”。
- 原因：处理器每 2 秒把最近 120 秒重扫一遍，按“开始时刻”去重。缓冲从前面滑出时，安静段中间的格子会被当成新起点（安静段里有窗口带鼾声分 ≥0.10 时满足判定），同一次中断换个起点又记一条。模拟一次真实中断被记 6 条，结束时刻都相同。
- 修法：
  - `SnoreBreaks.find` 只认安静真正开始的那一格（前一格在缓冲里、相连且不安静）；
  - `insertBreak` 同一结束时刻（那一声爆响）只存一条；
  - `recompute` 时合并已存重复（同一结束时刻留最早开始的）；后台维护对 3 天前的夜晚仅在有重复时重算一次。
- 影响：每晚中断次数、周报、给医生的一页、中断提醒都会随重算变准。
- 测试：`Night210BreakTest`（滑动重扫只记 1 条、重复识别），原 `Night203Test`、`NightInference204Test` 不变，203 评估数据结果不变。

## 2. 版本更新要点很多次

- 点“安装”被忽略时记一行原因（状态、安装包是否对得上、未知来源权限）。
- 测试：`UpdateEngineTest.retryFromFallbackReinstallsWithoutDownloading`、`UpdateDiagnostics210Test`。

## 3. 声音详情图放大缩小、最响片段、列表折叠
- 声音详情图：放大后上方出现整夜总览条和取景框（可拖、可点跳）；下方细看，双指缩放、双击“整夜 → 1 小时 → 10 分钟 → 整夜”、单指横拖平移（整夜时不拦面板滑动）、长按滑动看读数（几点几分几秒 · 比背景响多少分贝 · 是什么）；刻度随缩放变（小时到 1 分钟）；有录音的位置顶上标圆点，点了回听；“最响 HH:MM”一键跳过去并播放，没存录音就说明。数据用已有的 5 秒响度点，不改数据库。
- 最响片段：新事件类型 `Loud`，至少比背景高 15 分贝、彼此隔 15 秒以上，整夜只留最响 3 段，每段前 6 秒到后约 8 秒；挤掉的连录音一起删；7 天后录音过期，不进统计。判断逻辑在共用模块 `LoudPicker`。
- 列表：待确认置顶、默认展开；其余按类别一行（鼾声段数与总时长、中断次数与每小时次数、咳嗽、梦话、最响、醒来、放声音、没记录），点开原地展开；中断排成时间小胶囊；播放改为左侧 40dp 圆钮，“是 / 不是”在右侧胶囊，两类按钮左右分开；点某一条图自动移过去。
- 纯计算在共用模块 `NightZoom`（缩放、平移、逐级、刻度、读数、最响），供 iOS 复用。
- 测试：`NightZoom210Test`、`LoudPicker210Test`；`Night210ShotsTest` 出浅色/深色整夜、展开中断、最响放大截图（只供人工查看）。

## 4. 文件夹录音点“转写”后显示“原文件不在了”（11-19 用户反馈）
- 现象：时间线上没转写的通话录音，点“转写”后变成“原文件不在了”。
- 查到的问题：`FolderBackfillRunner.pump` 读文件或入队时任何异常（授权、读取、格式、文件变动核对……）都被吞掉并一律标成 Missing，不留任何记录，所以界面说法不可信、问题记录里也查不到原因。用户的问题记录里 200 条 `kt:39 FileNotFoundException` 是声纹特征缓存未命中被误记成失败，把失败记录占满，和通话录音无关。
- 已改：失败交给平台分类（原文件不在了 / 文件夹需要重新授权 / 涛声自己的说明如“暂不支持这种格式”“文件仍在写入” / 读取失败），按录音 id 存在偏好里，界面显示具体原因，非授权、非缺文件的可直接“重试”；问题记录新增“文件夹导入失败（最近 30 条）”，只记扩展名、原因、异常类别和涛声自己的固定说明，不记文件名（含姓名号码）；声纹缓存未命中不再记失败。不改数据库。
- 根因待定：装上后再点一次“转写”，导出问题记录看“文件夹导入失败”一节。
- 测试：`FolderProblem210Test`（格式原因可重试、授权与缺文件区分、诊断不含姓名号码），原 `CallRecording199AndroidTest` 12 条通过。

## 5. 备份天数说法、删除导入的说明（11-19 用户确认）
- 备份页“共 618 天的记录”改为“记录跨 618 天（最早 2025年3月）”：天数是按日期分卷的个数，导入的旧通话录音按当年日期归档，会让天数很大。`BackupSummary.firstDay` 从日分卷名取，不改备份格式。测试：`BackupHistoryTest` 加最早一天断言。
- 删除导入：用户提出“删通话录音不应删原录音，只删转写和整理结果”。现状本就如此——文件夹只有读权限，原文件从不动；删除后触发器把这条放回“未转写”，可再转。但说明写成“录音、原话……会一起删除”，像连原录音也删。已改：文件夹导入的写清“手机里的原录音不动，这条会回到‘未转写’”；分享导入的写“涛声里存的录音……；你分享进来的原文件不受影响”。

## 6. 鼾声中断可回听、人工确认（11-19 用户提出）
- 原先中断只记起止，没有录音。现在处理器发现中断后等那一声后 8 秒，存“安静开始前 5 秒 → 那一声后 8 秒”整段（最长约 76 秒，最近窗口缓冲由 90 秒加到 120 秒），挂到这次中断上；7 天后删，点“是”长期保留。
- 列表：中断胶囊有录音的带 ▶，点了图移过去并播放；选中的那次下方出现“这段是鼾声中断吗？不是 / 是”（6 秒可撤销）；点“不是”从次数里去掉（重算时排除），标了不是的可在“标了不是的”里改回。中断反馈不进个人判断器训练（只学鼾声、咳嗽）。旧版本记的中断没有录音，选中时说明“这次没存录音”。

## 8. 坚果云同步文件夹推得过频（11-19 用户反馈，bug）
- 现象：设了“有新内容就推、至少隔 30 分钟”，16:22 之后每 2～5 分钟一次“同步文件夹 · 更新 0 个文件”。
- 原因一：文档类通道（同步文件夹、Notion）的摘要（技能卡片、回顾）每出一张就立即同步一次，`SubscriptionPlan.changed(summary=true)` 直接排到“现在”，不看间隔；下午连续出卡就连续同步。
- 原因二：`FolderSync.run` 每次先在云端建目录，没有任何文件要传也会发请求，“更新 0 个文件”照样占坚果云请求次数。
- 已改：摘要按间隔合并（“有新内容就推”用它的间隔，其他方式至少 15 分钟），已排着的不往后推，摘要同步后记 `lastSummaryAt`；同步文件夹没有要传/删的、目录建过就不连网，出错后清标记下次重建目录，换目的地时也清。设置页说明按通道与方式改写。
- 测试：`SummaryGap210Test`、`FolderSyncIdle210Test`；`Rules154Test`、`DayThread204Test` 通过；`Subscription042Test` 中“手动后 1 秒出回顾立即同步”的时钟按新规则拨后 15 分钟，其余断言不变，14 条通过。

## 9. 备份变慢（11-19 用户反馈）
- 原因：历史备份每次对每个日分卷问一次存储“对象还在不在”（`View.exists` → `store.exists`）。导入旧通话录音后日分卷从二十来个变成 618 个，本机每次 600 多次 SAF 查询；坚果云同理，每晚 600 多次 HEAD，也是限流来源之一。
- 已改：`objects/` 一次列清后对照；列出来为空而恢复点有引用时退回逐个查询，避免误判全部重传。`BackupHistoryTest` 加断言：无变化时不再逐个查询对象。
- 成功也写一行诊断（本机/云端、耗时、天数、上传与合计字节），问题记录里“备份诊断”能看到每次多久。

## 10. 豆包接入方式加 Agent Plan（#52，11-19 用户定方案：放在“豆包”下）
- 官方文档（火山方舟 Agent Plan 语音模型）核对：流式语音识别 2.0 走 `wss://openspeech.bytedance.com/api/v3/plan/sauc/bigmodel_nostream`，请求头 `X-Api-Key`（订阅页专属 Key）+ `X-Api-Resource-Id: volc.seedasr.sauc.duration`，与现有豆包接法一致，只差路径的 `plan/`；文档未列套餐专用错误码；额度用完若开了超额后付费会自动按量计费。
- 实现：`DoubaoConfig.plan()` 由普通地址推出套餐地址；`DoubaoAsrProvider` 每次按开关取地址；设置新增 `doubaoPlan`，Key 另存 `planEncryptedKey`（两种 Key 切换不用重填），转写身份带 `:plan`；Key 进备份（`asrKeys`），恢复过滤同名单。失败照常报错，不退回按量接口。
- 界面：豆包下“接入方式：普通 API / Agent Plan”，说明 Key 来源与计费；密钥标题随之变；用量行选 Agent Plan 时写“套餐内”，不按单价估算。中英文 README 已写。
- 测试：`DoubaoPlan052Test`（地址推导、请求走 /plan/、头与资源编号不变、普通 API 不受影响）；`DoubaoAsrProviderTest`、`CustomHeaders116Test`、`PreferenceBackup190Test`、`BackupSecrets078Test` 等通过。未用真实 Agent Plan Key 实测，待 #52 提出者或负责人用预览版验证。
