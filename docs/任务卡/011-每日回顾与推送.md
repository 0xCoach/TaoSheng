# 任务卡 011：每日回顾 + 推送通道

## 目标

每天 22:00 自动把当天整理好的事件和提取项汇总成一份“每日回顾”：手机通知推送**简洁版**，App 里看**详细版**。语气客观记录，不评价、不说教。

## 约定（Claude 已写，不要改签名）

- `review/ReviewContract.kt`：`ReviewRepository`、`DailyReview`、`ReviewSection`、`ReviewState`。
- `AppGraph` 只加 `review: ReviewRepository`、`isReviewReady`，在 `ResoundApp` 装配。
- **不要改 `ui/` 和 `MainActivity.kt`**（界面由 Claude 做，通知点击后打开 App 即可，详细页 Claude 来接）。

## 方案（已定）

1. **数据来源**：当天 `memory_events`（未删除，跳过场景为“媒体”“旁人”的）和 `memory_items`（含状态）。**不重新读原话**，只用已整理的结果，省钱。当天事件为 0 时不生成、不推送。
2. **生成**：一次大模型调用，复用 `digest/LlmClient` 和整理用的服务与密钥（默认 DeepSeek），输出 JSON。提示词放 `assets/prompts/review.md`（App 名用 `{{APP_NAME}}`）。栏目和顺序固定：
   - `一句话`：1 句，概括这一天；
   - `要紧的`：重要且需要跟进的（来自 important 事件、有截止时间的待办/约定），≤3 条；
   - `发生了什么`：按时间顺序，每件事一句，≤8 条；
   - `待办`：今天新增且仍未完成的待办/约定（含截止时间），≤6 条；
   - `值得留意`：反复出现的话题、未闭环的事，≤3 条；
   - `灵感`：今天的灵感，≤5 条；
   - `心力`：一句话描述今天的情绪与精力走势（依据事件的 emotion/intensity），没有足够依据就省略。
   每条带对应事件 id（模型从输入编号里选，越界丢弃）。空栏目去掉。`brief` ≤ 60 字。
3. **存储**：数据库升 **v7**（Migration 6→7）：`reviews` 表（id、类型 daily/weekly、开始日期、结束日期、brief、sections JSON、生成时间、模型）。同一天重复生成时覆盖。
4. **定时**：WorkManager 每天在 `dailyAtMinutes`（默认 22:00）附近触发，需联网；当天已生成则只推送不重生成；没密钥时记 `lastError`=“还没填写大模型密钥”。设置存 SharedPreferences（不含密钥）。
5. **推送通道（统一接口）**：新建 `push/Notifier` 接口（`suspend fun send(title, body, deepLink: String?)`），本卡只实现**本机通知**一个通道；新建通知渠道“每日回顾”（默认重要度，**不能**复用录音常驻通知的最低优先级渠道）。通知标题“{App 名} · 今日回顾”，正文为 brief，点击打开 App 并带 extra `open=review&date=YYYY-MM-DD`（MainActivity 由 Claude 处理）。`pushEnabled=false` 时只生成不推送。以后加 PushPlus 等通道只需新增实现。
6. 用量计入 `llm_usage`。错误用固定中文文案。

## 离线验证（用真实数据，负责人已授权把相关片段发给 DeepSeek）

`tools/review-probe/`：只读拉手机库（`adb exec-out run-as app.resound cat databases/capture.db*`），用同一提示词生成 10-23 的回顾，结果写进 `tools/review-probe/results.md`，人工检查：栏目是否齐、事件 id 是否真实、有没有编造或评价性语言。原始数据放 `private/` 并加入 .gitignore。密钥在 `~/.config/resound/deepseek.key`，只让脚本读，不得输出。
