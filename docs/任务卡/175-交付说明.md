## Room 2.8.4 的 API 可行性

在线 [KMP Room 指南](https://developer.android.com/kotlin/multiplatform/room) 当前已使用 Room 3 示例，因此以下结论同时核对了 **Google Maven 2.8.4 官方源码包**，没有据新版本猜旧版本行为。源码版本与 SHA 见文末。

| 现有写法 | setDriver 后的准确情况 | 第二段改法及依据 |
|---|---|---|
| `openHelper`、Room `query`/`compileStatement`、`beginTransaction/endTransaction/setTransactionSuccessful/inTransaction` | 无 SupportSQLiteOpenHelper；旧入口抛异常 | `useReaderConnection` / `useWriterConnection` → `usePrepared` 或 `prepare`/`bind*`/`step`/`get*`；绑定从 1 开始，取列从 0 开始，资源用 use 关闭。[RoomDatabase API](https://developer.android.com/reference/kotlin/androidx/room/RoomDatabase)、[SQLite 迁移说明](https://developer.android.com/kotlin/multiplatform/sqlite) |
| `Migration.migrate(SupportSQLiteDatabase)` | 驱动路径调用 connection 重载；未实现时通用路径抛 NotImplementedError | 32 段改为 `migrate(SQLiteConnection)`，SQL 原文保持，仍由 MIGRATIONS 统一注册；迁移已经在 Room 事务内。[Migration API](https://developer.android.com/reference/kotlin/androidx/room/migration/Migration) |
| `Callback.onCreate/onOpen(SupportSQLiteDatabase)` | 驱动路径调用 connection 重载；旧签名不能作为跨驱动保证 | 四组回调与建表/索引/触发器 helper 全部用 SQLiteConnection。[Callback API](https://developer.android.com/reference/kotlin/androidx/room/RoomDatabase.Callback) |
| `@RawQuery(SupportSQLiteQuery)` | **并非一设 driver 就必然失效**：本次 2.8.4 KSP 的 ReviewDao_Impl 已通过 RoomSQLiteQuery.copyFrom → RoomRawQuery 桥接 | 为清除安卓类型，换 RoomRawQuery(sql) 的绑定回调；保留 observedEntities、Flow 和 SQL。普通 `db.query(SimpleSQLiteQuery)` 则受上一行的旧 query 限制。[RoomRawQuery API](https://developer.android.com/reference/kotlin/androidx/room/RoomRawQuery)；本次生成代码的 `materialChanges` 已核实 |
| `withTransaction` | 2.8.4 官方源码仍调用 beginTransaction/旧 openHelper，不能保留到 driver 模式 | `useWriterConnection { it.immediateTransaction { ... } }`；保持取消回滚、嵌套语义及挂起 DAO，避免持读连接再升级写连接。[事务说明](https://developer.android.com/kotlin/multiplatform/room)、2.8.4 源码 `RoomDatabase.android.kt:2040` |
| `runInTransaction` | 2.8.4 有 `performBlocking` 驱动分支，Android 上可以继续使用；不能一概说失效 | 为多平台接口统一仍建议转挂起 writer 事务；不能把同步 API 外面随意套 runBlocking。[RoomDatabase API](https://developer.android.com/reference/kotlin/androidx/room/RoomDatabase)、源码 `RoomDatabase.android.kt:771` |
| `invalidationTracker.createFlow` | 保留，为 common API | 保留初始发射、表集、节流/去重规则。[InvalidationTracker API](https://developer.android.com/reference/kotlin/androidx/room/InvalidationTracker) |
| `Observer/addObserver/removeObserver` | Android 上仍可用，不是 driver 禁用项；不是 common API | 若按本卡清掉安卓数据库 API，LocalSituationLookup 的 Observer 转 createFlow；其他六处通知 token 对照，不能直接删监听。[InvalidationTracker API](https://developer.android.com/reference/kotlin/androidx/room/InvalidationTracker) |
| 裸连接写入后的通知 | 外部连接不会自动满足全部观察通知约定 | 优先 Room 管理的 writer 连接；2.8.4 useWriterConnection 正常返回会 refreshAsync，绕开 Room 的写入另核验通知。`refresh` 是库内部限制 API，不作为业务替代。[通知文档](https://developer.android.com/reference/kotlin/androidx/room/InvalidationTracker)、源码 `RoomDatabase.kt:500` |
| `setQueryCallback`、auto-close、`createFrom*` | **2.8.4 的 Builder 在 driver 模式明确 require 拒绝这三类配置** | 产品没有这些配置依赖；本卡旧查询采集器第二段要用测试 driver/statement 包装替代。不要照搬较新 Builder 文档的支持状态。[Builder 官方入口](https://developer.android.com/reference/kotlin/androidx/room/RoomDatabase.Builder)、2.8.4 源码 `RoomDatabase.android.kt:1771` |

一个容易误判的细节：sqlite-framework 2.6.2 的 AndroidSQLiteDriver.open 返回 SupportSQLiteConnection；Room 2.8.4 的 Migration/Callback connection 默认实现碰到它会转发旧重载。这是已查到的版本特定桥接，不改变上表迁移方向，也不能据此认为 Bundled 或 iOS 会转发。[Android 驱动官方源码](https://dl.google.com/dl/android/maven2/androidx/sqlite/sqlite-framework-android/2.6.2/sqlite-framework-android-2.6.2-sources.jar)、[Room 官方源码](https://dl.google.com/dl/android/maven2/androidx/room/room-runtime-android/2.8.4/room-runtime-android-2.8.4-sources.jar)。

### 多进程

Manifest 仅 LocalAsrService 声明 `:local_asr`；ResoundApp.database 是 lazy，onCreate 第 62 行在该进程提前 return，LocalAsrService 无 CaptureDatabase/AppGraph 数据库访问。因此本仓库当前没有发现两个进程同时打开 capture.db 的路径；这是代码审计结论，未做手机进程跟踪。

Android WAL 支持并发连接不等于跨进程 Room Flow 自动通知。若未来子进程也读写库，必须另验进程间锁、busy、关闭及通知；enableMultiInstanceInvalidation 是 Android 专属，不能承诺 iOS 复用。官方没有对本 App 多进程行为的特定保证。[Android SQLiteDatabase/WAL](https://developer.android.com/reference/android/database/sqlite/SQLiteDatabase)、[Room 多实例通知](https://developer.android.com/kotlin/multiplatform/room#multi-instance-invalidation)。

### 备份、检查点、恢复的替换设计（尚未实现）

当前 BackupArchive.snapshot 不是单拷主文件：它持 IMMEDIATE 写锁复制主库与 WAL，在隔离副本上 checkpoint(TRUNCATE) 再切 journal_mode=DELETE。PreUpdateBackup 的 FULL 检查点之后仍复用这一流程；BackupRestore 先验证/迁移副本，再关闭原库并在重启前替换；DayVolumeRows 还直接开副本、灌入分卷、重建 FTS。

推荐保留上述顺序与格式，使用 Room writer 的 immediateTransaction 持锁复制；文件路径作为参数/接口传入，不再从 SupportSQLiteDatabase.path 取。副本用同种 SQLiteDriver 单独打开，prepare PRAGMA、step 后检查 busy=0 和返回模式，关闭后才清理副本 sidecar。恢复的隔离迁移、完整性/外键校验、关闭全部旧连接、原子提交/回滚和重启顺序不变。不得对正在用的主库删 WAL，不用 VACUUM 重排页面；检查点不放在活跃事务内。DayVolumeRows 的 foreign_keys 开关必须限制在同一个写连接，最后复查外键。

依据是仓库现有备份实现与 [官方 SQLite 连接/statement/资源管理 API](https://developer.android.com/kotlin/multiplatform/sqlite)、[Room writer 事务 API](https://developer.android.com/reference/kotlin/androidx/room/RoomDatabase)。**官方对本项目“写锁中复制主库+WAL”的跨驱动完整配方未找到**；以上是拟迁移设计，必须在第二段用并发备份测试和旧 ZIP 恢复实测，不能视作已完成。
