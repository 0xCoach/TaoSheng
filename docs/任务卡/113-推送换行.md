# 卡 113 · 推送消息换行（所有通道）

- 工作目录 `~/Developer/TaoSheng-113`，分支 `codex/113-push-newline`（从 `plan/0220` 拉出）。只改 `push/` 包和对应测试，**不改 `ui/`**。
- 版本：进 0.2.20。

## 问题

用户反馈：推送出去的消息没有换行，例如每日总结整段挤在一起。

已知原因之一：每日总结正文由 `push/ReviewPushBody.kt` 用单个 `\n` 拼接各条；PushPlus 的 markdown/html 模板、钉钉 markdown 等会把单个换行当空格。但**不要只修每日总结**：所有主题（每日总结、每周回顾、待办提醒、约定提醒、技能卡、记录推送等）× 所有通道都要检查。

## 要做

1. 找出所有推送通道（`PushKind` 全部取值）在 Text / Markdown / Json 三种格式下最终发出去的正文，逐个确认“每一行在对方 App 里是不是独立一行、空行是不是还在、列表是不是还是列表”。
2. 修法按通道写在**一个地方**：发送前按通道和格式把通用正文转换成该通道能正确显示换行的写法（例如 markdown 的硬换行、html 的 `<br>`、纯文本保持 `\n`）。每个通道的规则以其官方文档为准，在代码注释里写上文档链接。
3. 不要破坏现有的：标题、加粗、链接、Telegram 的 HTML 转义与 4000 字截断、飞书卡片、钉钉/飞书签名、Webhook 签名（签名要对转换后的最终正文算）。
4. Markdown 文件夹（写 .md 文件）和 Notion 不是“消息”，只确认没被这次改动影响。

## 必测（5～10 个用例即可）

- 一段含多行、空行、列表的正文，经 PushPlus（markdown、txt）、企业微信 markdown、钉钉 markdown、飞书、Telegram 转换后的结果各 1 个用例。
- Webhook 签名基于最终正文。
- **真实发送**：可以用负责人的 PushPlus（token 在 `~/.config/pushplus/token`，不要打印出来）真实发送**最多 3 条**，标题以“【涛声测试】”开头，确认微信里换行正常。其他通道不真实发送。
