## 本次实测与边界

- 在 `~/.config/resound/deepseek.key` 找到已存在密钥；2026-10-30 用它只读查询 `/models`、`/user/balance`，均 HTTP 200。返回模型为 `deepseek-flash`、`deepseek-v4-pro`；余额包含预期字段、币种 CNY。没有输出密钥、账户金额，没有推理调用。
- OpenRouter 公开 `/api/v1/models` HTTP 请求成功，核对了模板中的两个 ID、价格、上下文及工具/JSON 支持字段；没有查询私人账户。
- 其余服务商没有使用账户凭证实测，表格为文档核对。没有为找密钥扫描浏览器、钥匙串或无关业务配置。
- 方舟 CLI `auth status` 在执行前触发旧版本状态迁移，被工作区沙箱拒绝；没有修改 CLI 状态，转读官方网页核对。
- Kimi 开发文档的定价表本次无法抽取，已改由[官方发布公告](https://www.kimi.com/news/kimi-k3-1-pro)及[官方定价详解](https://www.kimi.com/resources/kimi-k3-1-pro-pricing)交叉核对人民币单价，未采用转售商报价。
- 保存用户自填余额接口仍按人民币元解释；本卡未扩展 `BalanceTemplate` 的币种、缩放、表达式或额外请求头签名。非元/需计算/需签名接口不预填，避免误报金额。

## 与后台适配有关的协议差异

- [DeepSeek 思考模式](https://api-docs.deepseek.com/zh-cn/guides/thinking_mode/)默认开启；本 App 的日常整理和问问显式关闭。方舟保留原有关闭思考行为。
- [Kimi K3.1 限制](https://platform.kimi.com/docs/guide/kimi-k3-1-pro-quickstart)：不能关闭思考，固定采样值；后台省略 temperature，设置 low 强度及 max_completion_tokens。工具轮次保留 reasoning_content，不显示为回答。
- [GLM 5.3](https://docs.bigmodel.cn/cn/guide/models/vlm/glm-5.3-flash)：仅 enabled，保留 thinking 内容，流式工具加 tool_stream；使用官方建议的 temperature=1 / top_p=0.95。
- [MiniMax 对话补全](https://platform.minimax.cn/docs/api-reference/text-chat-openai)：M3.1 强制思考，M3 可关闭；设置 reasoning_split=true，把思考分离出来；使用 max_completion_tokens。当前字段表未列 response_format，因此该平台不发送此字段，仍按提示要求 JSON，并由现有严格解析/重试处理不合规结果，不能声称它提供强制 JSON 保证。
- [硅基流动 Chat API](https://docs.siliconflow.cn/docs/api/chat-completions-post)：所选 Qwen/DeepSeek 混合思考型号使用 enable_thinking=false；它的 max_tokens 单独约束最终回答。
- [混元思考模式](https://cloud.tencent.com/document/product/1823/131208)：hy3/hy4-preview 使用 low 并扩大输出预算；Hy3 工具场景会把 low 映射为 high，仍保留 reasoning_content。
- [百炼思考配置](https://help.aliyun.com/zh/model-studio/deep-thinking)：qwen-flash / qwen-plus 使用 enable_thinking=false。OpenAI 推荐的 GPT-5.4/5.6 使用 none 强度，流式输出使用 max_completion_tokens。
- 仅思考型号的本地输出上限设为 16384 token，控制一次调用的开销；长推理仍可能触发上限或超时，模型检测与真机任务验收需留意。代码适配和 MockWebServer 测试不等于 12 家真实推理均已通过。
