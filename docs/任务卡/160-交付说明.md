## 搬迁与边界

- `SkillContract`、`TopicContract`、`ReviewContract` 原包名迁入 shared；公开日期改为 kotlinx.datetime，专题星期也改为共用类型。安卓展示和旧仓库入口做显式转换，其他约定文件签名未修改。
- 技能输入的范围、原话裁剪、身份标签、语音输入标签、周回顾材料、日历与固定提示词进入 `skills/core/SkillInput`；数据使用卡 152 的 TranscriptLineData / MemoryEventData / MemoryItemData 快照。
- SkillOutput、SkillJson、SkillGateJson、SkillGateRules、SkillDrafter 规则进入 shared。安卓同名门面保留旧调用入口与 JSON 规范化；共用 JSON 使用 SharedJson / WireJson。门槛仍区分缺省、null 和显式设置。
- `SkillExecution` 承接原 LocalSkillRepository 的自动/手动/试跑、按事件发生日补跑、串行互斥、格式重试、调用前及逐卡门槛、删除保护、日上限、用量与取消留痕；`SkillDrafting` 承接草稿轮数、编号、格式重试与记账。凭据、服务商对象、通知和环境声音装饰通过安卓端口提供。
- `SkillMergeRules` 在 shared 计算时段闭包、最早卡编号、别名、出处合并和删除保护；SkillDao 在原 Room 事务中读取、应用删除列表和保存结果，事务边界与 SQL 不变。
- `SkillSchedule` 的日期、星期、自动次数、当天补跑和十分钟重试计算进入 shared。SkillCardPush 的标题和正文渲染进入 shared；OutputTime 和小数格式化作为回调传入，保留系统时区及原小数格式。
- `TopicRulesRepository` 承接原 RoomTopicRepository 的全部编辑流程：开始回看、暂停/恢复、结束/延长、周期预约、预览扩展闭包、合并、保留用户改动、剪段、取消、重新生成、提醒去重和恢复。冲突计算及星期规则在共用 TopicPolicy。
- TopicGeneration 的专题上下文、提示词、纪要字段校验、合成事件、口播稿完整字段/值/出处和字数进入 `TopicGenerationRules`。安卓 TopicGenerator / TopicEngine 保留 Room 实体转换、模型异常适配、与现有 DigestRunner / ImportSummary 协作、事务提交及旧结果 revision 复核。
- ReviewContract 日期收尾已完成，RoomReviewRepository、推送、日记、环境声音展示及 UI 调用方均已接入。

安卓仍负责 Worker、闹钟、通知、assets、AtomicFile、Room、系统日期展示、凭据与实际网络调用。SkillFiles 的文件锁、原子写入及落盘后发布顺序保持原样；没有把现有同步文件 API 改成阻塞协程。TopicBatches 的服务商拒收/格式异常协调仍留安卓，沿用既有分批器；未搬动范围外 importer 或 ask。

## 新接口

| 接口 | 安卓实现/装配 | 约束 |
| --- | --- | --- |
| SkillDefinitionStore | SkillFiles；注入共用执行器 | 定义状态、设置、要求、复制/保存/删除；不暴露 File/Context |
| SkillInputStore | RoomSkillInputStore 包装 SkillDao | 原查询顺序与上下界；跨层仅共用快照 |
| SkillRunStore | RoomSkillRunStore 包装 SkillDao | 运行记录、增量起点、事务合并、保留用量；保留原 DAO SQL |
| SkillModel | LocalSkillRepository 内适配器 | ready、system/user 请求和 SkillReply；服务商/密钥不跨层 |
| TopicStore | RoomTopicStore 包装 TopicDao / MemoryDao | 包含事务端口；在同一事务内复核、保留条目、替换生成物和更新恢复凭据 |

共用新增 SkillCardData / SkillRunData / SkillReviewData，以及专题 row/span/mark/group 快照。时刻均为 Unix 毫秒，卡片归属日期持久值为 epoch day，编号为 Long。执行器用 NowMillis；专题时区用 ZoneProvider；固定北京时间的技能继续使用 Asia/Shanghai。没有隐式创建平台实现，没有新增或升级依赖。

Room 实体与共用快照的返回类型不同，因此采用显式适配器实现存储接口，没有给 Room 实体加平台无关外观，也没有改表、索引、迁移或备份格式。
