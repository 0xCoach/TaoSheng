# 卡 233 交付说明

## 共用设置

- `PlatformServices` 新增 `KeyValueStores` 和 `SecretVault`。原 `keyValueStore` 仍可用。安卓按原名打开偏好组，组内通过同一个编辑器提交。本次提交返回失败时，恢复涉及的旧值，再向上报告失败。
- `LlmProviderSettings` 管理模板解析、旧配置迁入、服务商的增删改选、密钥、自定义请求头、免 Key 判定和变更回调。安卓注入原有同步访问、地址解析、余额建议、问问兼容记录和技能清理，连接测试、拉取模型和用量记账继续由安卓调用。
- `TranscribeConfiguration` 接好已有的转写设置规则，统一管理来源、语言、间隔、两套自定义配置及四种转写密钥。`HotwordPreferenceStore` 管理手工热词的读写和归一化。整理偏好通过原有的 `DigestPreferenceStore` 接入分组存储。

## 安卓升级兼容

| 配置 | 继续使用的存储 |
| --- | --- |
| 服务商 | `llm-providers` 的 `saved`、`activeId`、`placeholder`。服务商列表仍是原字段的 JSON 数组，`templateId` 仍可为 JSON null。 |
| 整理密钥及请求头 | `digest-secrets` 的 `key-<id>`、`headers-<id>`，Keystore 别名 `resound-llm-aes-v1`。OpenCode 会话沿用 `opencode-session`。 |
| 转写 | `transcribe` 的 `source`、`localLanguage`、`interval` 等原字段。OpenAI 与千问分别使用原有的地址、模型和地址模式字段。热词仍是原顺序的 JSON 字符串数组。 |
| 转写密钥 | `transcribe` 的 `encryptedKey`、`planEncryptedKey`、`customEncryptedKey`、`qwenEncryptedKey`，Keystore 别名 `resound-asr-aes-v1`。 |
| 转写请求头 | `transcribe-header-secrets` 的 `headers-<来源>`，Keystore 别名 `resound-asr-headers-aes-v1`。 |

安卓三个安全存储组均通过 `SecretStore` 操作。转写原有的加密代码采用相同布局，即 Base64.NO_WRAP 编码的 12 字节 IV、AES-GCM 密文和认证标签。升级测试按旧布局写入夹具，再从新实现读取各组及不同别名的密文。读取后比较存储内容，编辑模型或间隔后重开比较其余设置，确认其他密文字段原样保留。组内提交失败测试覆盖 SharedPreferences 已更新进程内存的情况。原子批次覆盖原本成组保存的服务商列表与选择，以及转写的地址、模型和地址模式。密钥另行提交时沿用旧顺序。

## 保留在安卓的部分

- 安卓继续负责 SharedPreferences、Keystore、模板资产装载、UUID 和 OpenCode 会话生成。`URI` 地址校验及局域网分类沿用现有实现，保留安卓对完整地址、局域网和 OpenCode 的请求行为。
- `local-asr` 的偏好监听、本地模型进程、下载和 NPU 检测保留在安卓。转写探针及格式缓存继续使用原来的序列化和指纹，保留原机的已验证标记。新装与升级的识别仍取自 PackageManager。
- 整理执行器后续需从安卓注入客户端、时钟、诊断、整理状态存储和调度。迁移时需要把批次预算、慢速计数、JSON 流支持、模型故障转移和输入预算的持久化接入共用层，并保留 `inflight` 和 `digest_pending` 的请求凭据、防重发与恢复流程。

## 真机验收

在小米 14 Pro 上以同签名覆盖安装，保留应用数据。核对服务商顺序、当前选择、模型、热词和识别语言，有秘密头的整理和转写各做一次连接测试。分别切换豆包普通 API 与 Agent Plan、切换 OpenAI 与千问，确认各自沿用原凭据。Robolectric 使用测试 AES 密钥，手机系统 Keystore 的实际解密需由负责人验收。
