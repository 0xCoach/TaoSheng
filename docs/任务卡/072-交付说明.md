# 卡 072 寻物后端交付说明

当前状态：后端、数据库、接入和自编验证已完成；**真实原话模型验证与独立“寻物”用量分类待确认，整卡尚未验收完成**。开发分支 `find-things`，不推送。不改 `ui/`、`MainActivity.kt` 或现有约定文件。

## 做了什么

- 数据库24→25，新增 `things`、`thing_records`、`thing_watch_state`，迁移只在统一 `MIGRATIONS` 注册。正式物品只从已确认记录生成，保存当前状态、最后一次确认的放置位置、历史、待确认标记。
- `RoomThingRepository` 实现确认/忽略、事务内批量确认、sameAs归到原物品/新建、改名按名称和别名归并、手动拆分与20秒降级、Typed/Voice直接确认入库、归还、改名、归属、编辑及删除。手动 Placed/Lent 必填位置/借用人，降级草稿需界面补齐后提交；语音继续使用现有 `AppGraph.todoVoice`。
- 新建/更新待确认时过滤当前已确认同位置；两小时内同名同动作更新原卡；延迟旧原话不反向覆盖较新的待确认。
- `ThingWatcher` 在产出新原话的转写轮结束时触发，启动也补跑；最后一次触发后防抖30秒，单消费者与互斥锁确保串行。80句一批、20句已处理参考、200件已知物品；不用关键词预筛选；排除导入及卡070疑似/标记媒体。
- 水位与结果同事务提交。失败保留水位和固定批次上界，累计三次才跳过并写 watchdog 问题记录。关闭自动找及重新打开时跳过关闭期间原话；在途请求也会检查开关版本，避免关掉后重新插入。
- 新增可编辑/恢复默认的 `things` 提示词“找东西放哪了”，复用整理的服务与 `LlmClient.chatJson`。目前用量暂计现有“其他”，原因见遗留项。
- 仅 explicit 主动“记一下”结果发“寻物”LOW渠道通知，无声无震动，点击 Intent 带 `open=things_pending`；未获通知权限时不影响存储，不主动弹权限。
- 数据库触发器统一覆盖删原话、重转写删旧句、删事件（含软删除）和按时段删除：待确认清除，已确认原话文字保留且引用置空。请求期间删改原话会复核依据，旧请求不复活已删数据。
- 分卷备份将 things/水位放 global，记录按 at 放 dated；已验证导出、重建、恢复。
- “问问”新增 `find_things(query?,place?)`：当前已确认状态、最后位置、最近5条已确认记录及单独未确认记录；新物品待确认也能查，sameAs不确定会标明。引用保持 `AskSource(kind=line)`，没有原话id不编造引用。提示词要求先查物品，查不到/过旧再搜原话，回答含时间和未确认状态。
