# D3200 迁移版真机验收与本地修复

已完成作者要求的七项实测及实时/补传各一段真实通信样本。结论是可提交评审，附已知限制；不写成所有情形均无故障。用户于2026-11-14授权随PR公开两份已审查真实通信；旧私人样本及派生夹具不在本提交中。

测试设备：D3200 主固件04.92、充电盒1.2.2、realme Android手机。官方对照为未修改的app.resound / 0.3.0-preview.10 / 75；本地修复基于main 6bcf05c3 / 0.3.0 / 77，以app.resound.validation独立安装。官方及旧bean包均保留，未清数据或删除设备录音。

## 发现与修复

1. 默认灯光下官方实际8.62秒短句完整，关灯下三轮均握手成功但没有声音。迁移驱动漏读SPP普通音频，灯控回执读取器会丢弃它。修复为连接持有BLE/SPP独立读取器，普通协议帧和QC回执分别分流，关闭或初始化失败时释放读取任务。修复后关灯实时8.9秒、关灯补传10.112秒均由用户确认完整、速度正常、数字齐全；实时灯灭也经肉眼确认。
2. 手动补传任务改由应用持有，离页继续；显式暂停等待清理并保留续传记录，阻止重复启动。列表和顶部来源改用真实状态，显示任务项/字节进度，缓存明确非当前值。录音中补传保留StateConflict错误码，真机显示先在设备上停止保存的提示。
3. 采用现有驱动设置声明补充主/盒固件及灯控范围，真机显示04.92/1.2.2；通用只读行限制宽度并右对齐，长值不挤压标签。必要界面修改由用户授权；未新增品牌专属页面、核心品牌判断或约定签名。
4. 真机曾出现SystemForegroundService启动超时。WorkManager runtime/testing从2.10.0同步升至2.10.5，采用官方启停竞态维护修订。之后连续8项及多次暂停/恢复未复现；有限观察不证明唯一根因或消除所有系统异常。

## 两份真实通信及回放

11月14日重新采集两段，用户已试听确认全部声音只含固定测试短句和静音，完整、速度正常，无私人或旁人谈话。旧36秒私人样本和派生重组v2均排除，不作为作者所需原始记录。

- 实时：原始连接/握手/实时请求，连续4848个20ms包，96.96秒（大部分为等待静音），含三次真实周期状态刷新。原始逐字节前缀保留至最后音频包，不包含人为关闭连接后的取消错误。
- 补传：独立新建并保存的19.36秒测试文件，968包齐全。原始逐字节前缀在该文件最后一包结束，排除之后历史文件声音；保留握手、设备信息和真实文件列表。
- 对原始导出只作文件边界截取，前缀等于原始字节开头，协议字段、密文、包序号、校验和及回调分片均未改写；不是合成设备响应或重组夹具。
- 官方ReplayHarness与正式D3200Driver两项通过（1.185秒）：实时3232个480采样PCM帧，补传154880字节且解密SHA-256一致。两个完整预览均经FFmpeg解码无错误，用户已核对全部声音。
- 本地测试使用固定捕获的公钥/共享会话材料与真实HKDF/AES，Opus为结构占位；真实声学解码由FFmpeg及用户试听另验，不验证新的ECDH。
- 长实时样本的三次状态刷新由适配器在原始录包写屏障处调用正式驱动已注册的刷新任务。原因是ReplayGattLink立即泵送通知，不推进真实墙钟。没有改驱动/Harness，没有掩码忽略写入，也没有编辑录包来迁就测试。

原始通信保留设备序列号、盒地址、文件时间及可还原的测试声音，用户于2026-11-14明确授权随PR公开；仅共享本次两份通过声音审查的前缀及其回放属性。
