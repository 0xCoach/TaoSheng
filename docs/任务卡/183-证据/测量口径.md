# 卡 183 测量口径

- 基线产品取自 `df43e70`，数据库结构始终从已提交的 33.json 创建。全为合成数据，不读取用户数据库或备份。
- SQLite 为本机 Python sqlite3 的 3.53.4；计划和耗时不能冒充小米系统 SQLite 的结果。真正 Room 迁移、结构校验和行为回归另有 Robolectric 验证。
- 文件库、WAL、synchronous=NORMAL、foreign_keys=ON；无 ANALYZE 统计，所有模式复制同一初始库。初始 50,000 段、500,000 原话、200 个 Done 专题、2,000 条导入记录。
- 每 1,000 段有 980 Done、10 Pending、5 Failed、3 Running、2 Empty；Done 中 10 段尚未处理声纹。原话只关联 Done 段，约 0.1% 带语音输入信息。导入有 20 条请求整理，均摄入完成。200 个历史专题各有一个区间，已有原话已归入正确事件；所以迟到探测须证明“没有”，不会用 EXISTS 提前命中掩盖成本。
- 历史压力种子没有填充 50 万条 FTS 内容；种子完成后安装旧新装夹具里冻结的全部 15 个真实触发器。50 轮新增原话均执行正常触发器。这里衡量候选 B-tree 索引及相同触发器下的新增写入代价，不测历史 FTS 检索性能。FTS 结果由原 175 查询夹具单独覆盖。
- 每轮依次：保存 Pending 段；保存环境音；事务内删除该段原话、写一条原话、转 Done、记录 attempt 和用量。三个提交各自计写入墙钟；初始读取一次，每次段写入与转写完成后各读取一次，相关查询累计 101 次，逐次读完，不合并失效通知。
- A 的相关累计查询为队列、声纹、失败段；B/B1 为迟到原话；C 为导入待整理。基线和最终组合读取全部五项；单个候选不重复测与它无关的累计订阅。各模式仍执行相同 150 次提交。
- 原始 JOIN 的无索引迟到查询首轮实测 25.55 秒。为拆开查询写法与索引本身的收益，连续负载的两端固定使用相同的等价 CROSS JOIN 顺序；无索引端仍逐行扫描原话，索引端可按区间检索。原 JOIN 单次证据单独保留，不能把“查询改写 + 索引”全算成索引本身。
- 单次列是一次实际完整查询；累计列是实际 101 次之和，不用单次乘次数冒充。全仓库相关 SQL 另记录计划及 3 个实测样本，中位数用于定位优化器退化；UPDATE/DELETE 在 savepoint 内实际执行再回滚，避免污染后续种子。
- 所有普通单元测试与编译另记耗时；本目录长时间 SQL 压力基准显式运行，不加入普通测试任务。不得把 Python 压力基准当作真实 Room 开库或手机省电比例。

过程记录：第一次完整基准因原 JOIN 的单次成本很大而主动中断，保留单次值；调整辅助脚本时曾有一处 Python 转义语法错误，导致旧命令误启动，已按精确 PID 单次审批停止。旧进程在 SQLite 返回时才收到中断，故它的 traceback 曾写入同一日志；最终采用各模式 JSON 为数值证据，不把中断那轮当完成结果。后续临时库文件名加入进程 ID，防止同名文件混用。
