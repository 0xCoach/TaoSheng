## 现状

- 专题录音里已有“记一下”：`topic_marks`（`TopicMarkRow(topicId, at)`），通知栏、桌面小组件、长按图标快捷菜单在专题进行中可用（`QuickRules` 的 `MarkTopic`）；生成纪要时把“用户标记的重点时刻”和离它最近的一句原话交给模型，要点前标“★ 重点”（`topic/core/TopicGenerationRules.kt`）。
- 平时全天录音、回放时都不能打点；打点只对准一句话，不是一段区域；每日整理不看打点。

## 目标

### 1. 随时能打点
- 新表（如 `marks`）：时刻 `at`、前后范围（毫秒，默认前 2 分钟、后 1 分钟）、可选短标签、来源（录音中 / 回放 / 专题）、创建时间。专题里的“记一下”继续写 `topic_marks` 并**同时**写一条通用打点（或改为只写通用表、专题读通用表，二选一，交付说明写清；旧 `topic_marks` 数据迁移或兼容读取，不能丢）。
- 入口（底层动作 + 给界面的接口）：
  - **录音中**：通知栏常驻“记一下”按钮（专题不在进行时也有）；长按图标快捷菜单加“记一下”（`QuickRules.entries` 在聆听中时提供；注意快捷菜单条数上限）；桌面小组件在非专题时也能“记一下”（与“开专题”的位置怎么安排写进交付说明，界面由 Claude 定）。
  - **回放时**：播放器提供“在当前位置打点”的接口（按播放的原话时间换算成真实时刻）。
  - 打点后给一条轻提示（如“已记下 14:32 的重点，可撤销”），撤销接口。
- 范围可调：设置里“打点前后各包含多久”（30 秒～10 分钟），新打点生效。

### 2. 整理时重点区域写得更细
- 每日整理（`DigestRunner` / 重新整理 `RedoFactory` 共用的上下文）：把落在本次整理时间段内的打点区间交给模型（区间起止、标签、区间内的原话编号）。规则：与打点区间重叠的事件写得更细——摘要更完整、保留 2～4 句关键原话（带说话人），点明“用户标记的重点”；**不得编造录音里没有的内容**；区间里没有原话就照常处理。
- 专题纪要：沿用现有“★ 重点”，但改为按**区间**而不是最近一句；区间内的内容展开写、附关键原话。
- 规则文字放 `:shared`（提示词规则对象），加提示词规则测试；整理请求的去重凭据（AGENTS.md 官方服务第 3 条）不能弱化。

### 3. 原声跟着重点保留
- 与打点区间重叠的录音段，原声保留规则视同“标星的重点”（`originalKeepStarred` 打开时不过期删除），复用 `transcribe/OriginalRetention.kt` 的规则，不另起一套。

### 4. 给界面的数据
- 按天 / 按录音段 / 按事件查询打点（时刻、区间、标签），供：时间轴事件上的“📍有打点”标记、原话页高亮区间、播放器进度条上的打点刻度。
- 事件与打点不建外键，按时间重叠计算即可（纯规则放 `:shared`，加测试）。

### 5. 隐私与备份
- 隐私删除（按时间、最近 N 分钟、这段别记、单段、批量、全部）一并删除对应时间的打点；新表进按天备份卷，旧备份包缺这张表照常恢复。
- 新增的偏好键按卡 190 规矩归类，守卫测试要过。

## 不要做

- 不做“重点区域重新精听 / 重新转写”（依赖原声，后面再议）。
- 不改界面文件；不改现有专题纪要以外的整理输出格式（只是更细，不加新字段到推送格式，推送沿用事件正文）。
