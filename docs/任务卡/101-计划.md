# 101 · minSdk 降到 28 —— 实现计划

目标：把 `minSdk` 从 29 降到 28，让 App 在 Android 9（目标设备，arm64-v8a）上能编译、安装、不崩。`targetSdk=35`、`compileSdk=36`、`ndk abiFilters(arm64-v8a)` 全部不动。本卡只改底层（录音服务 / 任务队列 / 推送 / 转写等），**不碰 `ui/` 包和 `MainActivity.kt`，不改 `*Contract.kt`、`AudioSource.kt` 的签名**。

## 关键设计决策（含理由）

1. **前台服务按版本分叉**：三参 `startForeground(id, notif, type)` 与三参 `ForegroundInfo(id, notif, type)` 都是 API 29 才有（前台服务类型）。在 `SDK_INT < 29` 走双参重载。`startForeground` 双参在 29+ 已废弃，调用点用 `@Suppress("DEPRECATION")` 压警告而不改逻辑。理由：这是 minSdk=28 的硬坎，29 上行为完全不变。
2. **NewApi 用 `@RequiresApi(N)` 抽私有方法，而非全局关 lint**：运行时已有 `if (SDK_INT >= N)` 守卫，逻辑一律不动；把调用新 API 的那段抽成私有方法并标 `@RequiresApi(N)`（`androidx.annotation.RequiresApi`，经 `core-ktx` 已在 classpath），调用处仍按 `SDK_INT` 分支进入。理由：任务卡明确禁止 `lint { disable += "NewApi" }`；`@RequiresApi` 比满屏 `@SuppressLint` 干净、可被 lint 验证分支正确。
3. **验证命令带 JDK 路径覆盖**：`gradle.properties` 里 `org.gradle.java.home` 是 macOS 路径（`/opt/homebrew/opt/openjdk@21`），本机（Linux）不存在。本机验证一律加 `-Dorg.gradle.java.home=/usr/lib/jvm/java-21-openjdk-amd64` 覆盖；负责人在自己 Mac 上则用原路径。理由：不改仓库里的 `gradle.properties`（那是负责人机器的真实路径），只在命令行覆盖。
4. **`assembleDebug` 不触发 lint**：`assembleDebug` 只编译，NewApi 不会让它失败；真正会因 NewApi 报错的是 `lintDebug`。为确保“守卫补注解”真的生效，验证要**同时**跑 `assembleDebug`（硬指标）和 `lintDebug`（确认 NewApi 清零、没有被全局关闭）。理由：任务卡的硬指标是 `assembleDebug`，但 NewApi 的意义只有 lint 能体现。
5. **不改 `TranscribeWork.kt`**：实读后发现 `TranscribeWork.getForegroundInfo()` 已用双参 `ForegroundInfo(3003, notification)`，**不含** `FOREGROUND_SERVICE_TYPE_DATA_SYNC`，无需改动。任务卡把它列进来是按文件名预估；以代码为准，本计划不动它，但在步骤里留验证点。
