# 卡 110：整理返回格式不对时，拆小重试

## 背景
大模型整理一批原话（最多 300 句）时，偶尔回答写到一半被截断（输出上限用完），解析失败报 `LlmError.Format`（“大模型返回的格式不对”）。
- 自动整理：`DigestRunner.digest()` 失败 3 次就放弃这一批（`MAX_FORMAT_FAILURES`，标成已整理，原话只留在原话页）。
- 重新整理：`RedoEngine.run()` 里任意一批失败，整次重做失败。
本卡：遇到格式错误时，先把这一批拆成两半各自重试，小到不能再拆才按原逻辑处理。

## 方案（已定，照做）
1. 新增纯函数（放 `DigestPrompt` 或新文件 `DigestSplit.kt`，包 `app.resound.digest`）：
   `fun splitForRetry(lines: List<TranscriptLineEntity>): Pair<List<…>, List<…>>?`
   - 句数 < `MIN_SPLIT_LINES = 40` 返回 null（不再拆）。
   - 在第 25%～75% 句之间，找相邻两句间隔（后一句 startAt − 前面已出现的最大 endAt）最大的位置切开；并列取最靠中间的。
2. 重新整理（`RedoEngine.run`）：`digest(batch, …)` 抛 `LlmException` 且 `type == LlmError.Format` 时，用 `splitForRetry` 拆两半，按顺序分别整理（可递归），结果按时间顺序拼回；拆不了就照原样抛出。进度文字保持“重新整理 i/N”（N 是最初批数），不用为拆出来的小批改文案。
3. 自动整理（`DigestRunner`）：一批第一次遇到 Format 错误时，若能拆，就改为先整理前一半（后一半留给后续轮次或同一轮继续，二选一，以改动最小、不破坏现有 `pendingDigest` 缓存和 `inflight` 记录为准）；拆不了的小批才走原来的“失败计数 3 次后放弃”。每个半批有自己的 identity，缓存逻辑不要改。
4. 只改上面说的逻辑，不改数据库结构、不改界面、不改提示词、不改 `LlmRequestOptions`。

## 测试（适度，3～5 个用例）
- `splitForRetry`：少于 40 句返回 null；在中间段最长停顿处切开。
- 重新整理：第一次整批返回 Format，两半各自成功 → 整次重做成功，事件来自两半。（`Redo071Test` 里照 `engine()` 写法构造假 digest）
- 自动整理：大批 Format 后会拆开再整理，不会直接计入放弃。（`DigestRunnerTest` 或新测试类）
