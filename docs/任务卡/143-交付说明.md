# 卡 143：录音豆样板驱动交付说明

本卡在 `codex/143-d3200-driver` 上迁移 PR #30（xhp1211），以 Claude 前置提交 `b686096`、`60fcafa` 为基线。驱动为 4 级 `d3200`，状态 Trial，维护人 xhp1211。未改界面、`MainActivity`、`CaptureService`、Manifest、既有约定签名或数据库结构；前两个文件的前置改动来自 Claude 的独立提交。

## 做了什么

- 共用插件只通过会话的 GATT、密码、Opus、存储、时钟和经典串口接口工作。协议、分帧校验、设备状态、序号、加密编排、实时流、离线列表与续传、控制、历史区间和 Ogg 页规则都在平台无关 Kotlin 中。
- `DeviceInputs` 支持说明卡和注册插件；音源目录允许选择插件。说明卡仍使用原匹配优先级、音源键、连接/补传路径。`withDevice` 可使用现有连接租约管理设备，未收音时创建临时连接，完成后释放；`syncDevice` 可手动检查离线录音，即使自动补传关闭也可调用。卡 144 可在同一 App 模块调用这两个入口，并使用 `lastDeviceStatus` 标注缓存读数时间。
- 实时帧把 PCM、设备时间、来源、当时的时钟偏差和回执目标一起排队；设备时间或时钟偏差未知时不提供时间。归档来源格式为 `<现有音源键>:<设备文件编号>:<该次来源首帧偏移毫秒>:<手机接收墙钟毫秒>`；同一原文件的不同收音会话可区分，前缀仍对应原设备和原文件。没有 origin 的说明卡帧仍走原有手机时间/音源编号规则。
- 只在 `processed` 后累计覆盖；正常收尾写入本设备的 `session.store`，丢弃收尾不把待提交区间当作完成。恢复时按来源锚点查已入库片段和 spool，时钟偏差未知时取所有可能时间的安全交集，再按 20 ms 向内取整；锚点无法可靠恢复时宁可补传重叠，也不跳过无法证明保存的音频。
- 文件适配层把 `liveCovered` 和恢复覆盖写为现有 `device_transfers` 的已导入区间，队列扣除后下载缺口；下载保留设备原件。沿用现有断点、持久化和导入逻辑，按驱动声明增加新录音优先排序。文件头提供的实际包数用于判断完成，不把列表估算大小当作实际完成长度。裸 Opus 缓存在队列中支持续传，导入前流式封装为 Ogg。
- Android 经典串口通过 RFCOMM 连接，连接超时 8 秒后关闭 socket；取消/断开关闭 socket。广播厂商数据由插件匹配解析并暂存，连接后写入该设备 `session.store`；平台按当前设备的存储空间读取地址，驱动不自行扫描或建蓝牙连接。灯控仅 04.92 发送，使用会话 `keepAlive(2000)` 续发，其他固件只提供默认模式。
- 连接状态读数按原读取时间缓存；断开和重启可恢复快照，不把恢复时间写成设备读取时间。充电盒读数仍可能是设备转报的旧值。`GuardedConnection` 转发 `processed` 和 `captureFinished`，否则默认空实现会吞掉回执。
- 品牌导入和编号只在插件和装配目录 `app/src/main/java/app/resound/devices/android/DriverCatalog.kt`。边界脚本仅对此**完整路径**允许品牌引用，邻近文件仍拒绝；没有整行白名单或整个目录豁免。

## 协议字节核对

- GATT 服务 `020cf5da-0000-1000-8000-00805f9b34fb`，写 `7777`、通知 `8888`；帧长度小端，校验为帧前各字节之和低 8 位。只允许原命令白名单；灯控的 SPP 准备使用固定帧。
- P-256 公钥为 `04 || X || Y`，握手核对 32 字节 ECDH 结果；HKDF-SHA256 的 salt 和 info 都是 `01 02 03`，输出 32 字节。文件头的 46 字节密钥材料用 AES-CTR 解封并核对 `soundcored3200`；音频 CTR 使用 nonce 前 12 字节加 `序号 × 10` 的 4 字节大端计数器。
- 传输单位 166 字节：4 字节小端序号、1 字节标志、160 字节密文、1 字节尾部；解密后每包校验为 20 ms Opus。重复包丢弃，跳号报错并保留可续传位置；断点向前重读一包并过滤已保存包。
- `0101` 信息体的固件、序列号、电量、存储及录音状态按原偏移解析。序列号字段位于信息体偏移 8、长度 16；有效值使用 `IdScope.Global`，缺失/无效时使用平台替代身份。字段依据为原 PR 所参考的 [Soundcore 协议笔记 §6.1](https://github.com/tacshi/Soundcore/blob/f01a19c227aac0cee9a7c851b3f6b69cf5540a24/PROTOCOL.md#61-device-info-09-ff--type01-id01)。不在日志或交付说明写具体序列号、地址或密钥。

## 遗留与边界

本次没有设备实测，也没有 iOS 编译或 iPhone 验证；假通道不证明无线电、MediaCodec、真实串口或全天稳定性。其他固件、长录音、全历史、冷启动以及充电盒盒外读数仍待实测；暖橙仅有原 PR 的协议回执，物理灯效未验收。iOS 不提供经典串口，且 BLE 实际最大写入长度不足时会明确报错，不能由 Android 的 MTU 偏好推断 iOS 可用。

当前旧界面尚未展示插件设置、双部件状态读取时间或临时控制入口；卡 144 应按能力模型接入上述通用方法，断线快照应明确显示读取时间。录包和迁移版真机报告仍待贡献者补充；原 PR 的实测不能当作本提交的实测结果。
