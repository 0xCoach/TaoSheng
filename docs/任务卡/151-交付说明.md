# 卡 151 交付说明：网络层换 Ktor

## 实现范围

在 `codex/151-ktor-network` 实施。大模型 chatJson / SSE、余额查询、模型列表、自定义转写、豆包 WebSocket 默认使用 Ktor。保留旧 OkHttp 链路供预览期回退；未推送、未操作手机、未连接真实服务商、未读取真实密钥。

shared 的 `app.resound.net` 包新增：

- 可注入引擎的 `networkClient`、超时设置、有限正文读取、请求头处理与客户端/引擎关闭。
- 大模型请求选项、JSON 请求/响应、状态码分类、SSE 行解析、工具分片合并、思考字段和用量。诊断通过 `NetworkTrace` 插口回到现有安卓记录器。
- 余额字段/币种解析、模型去重排序、路径候选选择、局域网地址判定、自定义转写 multipart 与正文解析。
- 豆包首包、音频/结束包、大端整数编解码、响应大小限制、错误分类、增量分句合并。gzip 解压、音频准备/文件读取、连接 ID 随机数、耗时记录由安卓传入。
- `WireJson` 是基于 `SharedJson` / `JsonElement` 的窄适配层，保持旧 Android JSON 的数字字符串、null、转义和字段顺序；commonMain 没有 org.json。

`LlmPreset`、`HeaderEntry` 从 MemoryContract 原样拆出到 shared；AsrSentence / AsrResult / AsrError / AsrException / DoubaoConfig / TranscribePolicy 原样移入 shared。类型的包名、签名和语义均未改；MemoryContract 只移除原声明。File-bearing AsrAudio、AsrProvider 仍留安卓。

安卓公开入口函数/构造函数签名保持不变。ServiceHeaders 保留 Keystore、会话 ID 存储；余额保留 SharedPreferences 缓存和提示；LlmInputBudget、服务商切换与现有调用方保持原状。HttpAwait 留给旧实现及范围外调用；新链路不用它。

未修改 ui、MainActivity、数据库或 devices；未迁移推送、备份、更新、地点、录音上传、本地模型下载。

## 依赖与版本

采用 Ktor **3.3.3**：commonMain core / websockets，androidMain okhttp，jvmTest mock；只有 `taosheng.ios=true` 时才配置 iosMain darwin。门禁仅增加卡片指定的 5 个坐标及 iosMain 依赖块识别。

理由：3.3.3 是 Kotlin 2.2 系列构建的最后一个稳定 3.3 补丁版；其源码使用 Kotlin 2.2.21，3.4.3 已使用 Kotlin 2.3.0。本项目不升级 Kotlin 2.2.20，采用同一 metadata 版本的 3.3.3，并以真实 common metadata / Android / JVM 编译验证兼容性。未声称采用最新的 Ktor 总版本，也未开启 iOS 编译。

来源：[官方版本表](https://ktor.io/docs/releases.html)、[3.3.3 版本清单](https://github.com/ktorio/ktor/blob/3.3.3/gradle/libs.versions.toml)、[3.4.3 版本清单](https://github.com/ktorio/ktor/blob/3.4.3/gradle/libs.versions.toml)。

Ktor 的默认传递依赖会升级 OkHttp，首次本地对照因此出现 MockWebServer 4.12 找不到 okhttp3/internal/Util。app / shared 已显式锁住 **OkHttp 4.12.0、coroutines core 1.9.0、Kotlin stdlib 2.2.20**，防止影响范围外组件。没有改原有库的声明版本；Ktor 自身新增的 kotlinx-io 等依赖随其解析。

## 超时与传输设置对照

以下单位均为秒；0 表示无限。write 保留调用方原 OkHttp 设置（默认 10 秒），没有错误地跟着 read 变成 180/480 秒。

| 链路 | connect | read | call | 重定向 / 连接失败重试 |
|---|---:|---:|---:|---|
| 默认 LLM（含 SSE） | 10（原 clientFor 覆盖构造器的 15） | 180 | 200 | 关闭 HTTP/HTTPS 重定向；保留原 retry（默认 true） |
| 手动待办、寻物的短 LLM | 10 | 外网保留传入值；局域网至少 180 | 保留传入的 20 | 同上 |
| 余额 | 保留，默认 10 | 保留，默认 10 | 默认 15 | 关闭重定向；保留 retry |
| 模型列表 | 默认 10 | 默认 10 | 局域网 60，其他 25 | 默认关闭重定向；显式传入客户端保留其设置 |
| 自定义转写 | 10 | 480 | 每个候选请求 480 | 关闭重定向；retry=true |
| 豆包 | 15 | 0 | HTTP call 默认 0；业务超时为 max(90s, 30s + 音频时长×1.5) | 关闭重定向；retry=false |

LLM 的多个候选地址共用一次总 call deadline，不因 404/405 换路径而重新计时；模型列表/自定义转写沿用每个候选单独 HTTP call 的上限。原有自定义 OkHttp 客户端的代理、TLS、write timeout、retry 等配置继续传入引擎。

Ktor 默认增加的 Accept / Accept-Charset / User-Agent 已按旧请求处理，同时保留用户显式自定义值。JSON Content-Type 保持 `application/json; charset=utf-8`。HTTP 响应消费在 execute 作用域中，取消覆盖读正文阶段；SSE 在行循环和文本回调前检查取消；关闭客户端同时释放所属引擎。

豆包使用 Ktor WebSocket API。Ktor 3.3 的 OkHttp 引擎会丢失非 401 握手失败的响应，并将取消变成慢关闭；`AndroidSocketControl` 包装引擎提供的 WebSocket factory，传递安全的状态分类并立即 cancel。原 256 KiB 上传队列背压和等队列排空由插口保留，终态到来可停止等待；音频预记用量仍在首个音频包发送之前执行一次。

## 回退开关

`AppGraph.configureNetwork(platform.keyValueStore)` 在 ResoundApp 创建基础插口后调用一次：

- 键：`net.legacy_okhttp`
- 存储：platform 的 KeyValueStore（Android `platform` SharedPreferences）
- 默认 false：Ktor；true：旧 OkHttp。
- **修改后重启生效**。Claude 后续做开发者选项界面，本卡没有改 UI。

旧 LlmClient / 自定义转写 / 豆包及旧余额 fetch、旧模型列表保留一个版本；0.3.1 再删。

## 边界、真机注意与遗留

- 安卓 URL 语法仍用原 URI 边界校验以避免放宽非法地址；地址候选/局域网规则已共用。Keystore、缓存、音频解码/文件流、gzip、网络异常的平台类型识别留安卓适配层。
- 本卡不把协议运行所需的 File/Context 传入 shared。iOS 尚需实现音频来源、gzip、NetworkSocketControl、耗时插口、异常映射和 AppGraph 对应装配；Darwin 的连接/读写超时及 retry 并不具备与 OkHttp 完全相同的语义，不能仅凭依赖配置宣称等价或 iOS 可用。
- JSON 解析使用 SharedJson 的标准 JSON 语法，不承诺接受 org.json 历史上的非标准宽松语法；正常服务商 JSON 已做新旧对照。未对真实服务商兼容性作结论。
- 安卓 HTTP 每次操作拥有独立 Ktor 引擎/连接池，避免 close 影响复用的原客户端；这会减少跨次请求的连接复用，可能增加建连开销。业务结果与超时不变，真机需关注高频请求耗电和耗时。
- 负责人后续在小米 14 Pro：分别用开关 false/true 重启，检查整理与先思考、问问工具/流式、模型检测/列表、余额、自定义转写（自动/完整地址/热词）、豆包长音频/增量分句/鉴权/限流与取消，核对中文提示、时间、用量、耗时记录及自动切换。运行时真实服务商与手机未验收。
- 旧实现到 0.3.1 清理；上述旧测试失败留对应任务。无数据迁移或数据重建。
