# 低置信转写复核（R4）- 交付说明

## 做了什么

- `shared/.../transcribe/TranscriptReviewRules.kt`：本地识别不出置信分，改用可观测信号给原话行打可疑标记（纯 Kotlin、无平台依赖）：
  - `SuspiciousDensity` 语速异常（>7 字/秒，或 ≥4 秒只出一两个字）
  - `RetriedSegment` 所在段重试过（attempts>1）
  - `LowSpeakerScore` 分了人但声纹分 <0.35
  - `CorrectedText` 同音纠正改写过的行（弱信号，权重最低）
- `transcript_lines` 新增 `reviewedAt`（迁移 37→38，一条 ALTER）；`TranscribeDao.reviewLines` 关联 `segments.attempts` 出近 14 天未复核行，`markReviewed` 打时间戳。
- `TranscriptReviewRepository`（app/transcribe）：行投影→规则过滤→按权重排序；`observeCount` 供角标。
- 助手 Hub 新增「复核」入口卡（沿用 M2+ EntryCard 先例）；`TranscriptReviewScreen` 列表页：时间、原文、说话人标签、标记 chips、「已读」。
- `isAssistantReady` 纳入 `transcriptReview`。

## 怎么验证的

- `:shared:jvmTest TranscriptReviewRulesTest` 4/4 过（正常行不标/稠密稀疏都标/重试低声纹分标/纠正弱信号+权重排序）。
- `assembleDebug` 过。真机（PGU110，SM8475）：迁移无异常；助手 Hub 显示「复核 218 条待复核」；页内按权重列出真实可疑行（短句误识别为日语「はい。」、残句「how and」等）；点「已读」后该行立即出列，`reviewedAt` 落库生效。

## 真机需要注意什么

- 复核是“标记待人工看”而非“自动改”：听不准的原话仍要到原话页重转/改；本版未接「跳转原话」与「一键重转」入口，下版补。
- 说话人列直接显示原始标签（0 / uncertain:xxx），偏技术化，后续可换成人名。
- 设备实为 SM8475（骁龙 8+ Gen1）：`npuSupported()` 正确返回 false，NPU 选项隐藏——非缺陷，SM8650 机型上自动出现。

## 遗留问题

- 复核判定靠启发式，无 ASR 置信分（引擎不输出）；阈值（7 字/秒、4 秒/0.35 分）按常识定，可随真实误标率调。
- 「已读」不可撤销；未做批量已读/筛选。
- 未跑 `tools/check_shared.py`（本机无 Python）与 `check_ios.sh`（无 Xcode）；新 shared 文件无任何平台引用，合规由构造保证。
- `.tmp-npu/`（PC 侧 SM8650 模型临时目录）本地保留、未入库，供日后换机直接推入。
