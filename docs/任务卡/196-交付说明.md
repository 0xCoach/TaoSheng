# 卡 196 交付说明

## 实现

- shared 解析 `segments`：秒换毫秒、裁到录音时长、丢弃非法/空段、按起点排序。有效段为空才沿用原来的顶层 text 及错误映射。
- 段内清除 `[mm:ss] 说话人N：` / `说话人N：` 前缀；不混入顶层文字。纯 text 返回保持原样（只去首尾空白）。
- speaker / speaker_id 支持字符串和整数，按有效段在原响应中的首次出现顺序映射为 "0"、"1"；排序不重新编号。无字段为 null。关闭分人时仍保留逐句时间，所有标签为 null。
- 默认 verbose_json；400/415/422 或其他带 response_format 错误的 4xx 立即在同一地址重传同段录音一次，改用 json。401/403/408/429、5xx、网络失败和超时不触发退回。既有 404/405 地址候选规则保留。
- 只有 json 重试成功且能解析后才记住能力；重传沿用音频、模型、热词、请求头和超时。每次上传仍调用原来的 beforeAudio；文件可重新打开，不把长录音全部装进内存。借用既有进程级 Ktor 客户端，由 execute 释放本次响应。
- `custom-asr-formats` 保存实际接口地址的 SHA-256 指纹及毫秒时间，无明文地址、模型或密钥；按卡 190 排除备份。30 天到期或系统时钟回退后重新探测。通过设置保存修改地址、模型或地址模式时清空；相同设置重存不会清空。旧请求遇到配置已变不写回。

## 与豆包路径一致性

- `TranscribeRunner` 逐条加录音起点，保存 startAt/endAt/text/speakerTag；分人开关来自录音对应配置，经 AsrAudio 传给自定义解析。
- `LocalVoiceprintRepository` 按 `VoiceprintAudio.groupKey` 的 `tag:<speakerTag>` 聚合句子，再走窗口、候选“我”/熟人匹配；没有按 Custom/Doubao 区分来源。无标签按单句处理。
- 原话页 `speakerKey` / `speakerLabel` 使用同一标签，数字显示 +1；连续同说话人句子可归入同一气泡，底层仍为逐句记录。
- `ExportText` 按各句真实时间生成 SRT，按 speakerName 或 speakerTag +1 显示人物；整理通过 PromptSnapshots / SkillInput 使用相同时间和标签。
- 不需要界面配合；未改 UI、MainActivity、约定签名、数据库、豆包或本地转写。
