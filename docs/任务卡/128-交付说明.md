# 卡 128 · 更新前备份提前到下载完成后

## 做了什么

- 整包下载或增量组装后统一通过 `verifyReady` 校验，再进入 `Ready`；在同一个 IO 任务中自动执行更新前备份。
- 成功后通过现有 `AndroidUpdateStore` 持久化 `preBackupFor`（安装包 SHA-256）和 `preBackupAt`（备份完成时间）。预先备份失败或协程取消只记诊断，保留 `Ready`，不显示备份错误。
- 下载后的备份继续持有原有 `gate`；用户此时点安装会等待其结束，成功则复用，失败则按安装流程重试，不并发启动两份备份。
- 安装时仅复用 SHA 相同、时间未回退且未满 6 小时的记录。缺失、过期或 SHA 不同时重新备份，失败仍显示“更新前备份没成功，没有安装”。安装阶段补做备份成功也更新记录，供取消后再次安装使用。
- 诊断增加 `pre_backup ms=… result=ok/cancelled` 或 `failure=…`，以及 `install_backup reused=true/false backup_ms=…`。复用时本次备份耗时为 0，预先备份实际耗时看 `pre_backup`。
- 当前版本已为 0.2.21（versionCode 61），未调整版本；未改 `ui/`、`MainActivity.kt`、约定文件签名和 `UpdateState`。

## 真机需要注意什么

1. 小米 14 Pro 上分别下载整包/增量包，确认进入可安装状态后自动备份；备份完成后点击安装，不再出现安装阶段的备份等待。
2. 备份尚未完成时点击安装，应等待同一次备份结束再交给系统；预先备份失败时仍可点击安装，并触发重试。
3. 系统确认框取消后，在有效期内再次安装应复用；满 6 小时或换安装包应重新备份。核对更新诊断中的 `reused` 和耗时。
4. 安装前仍保留包校验及向 PackageInstaller 写包；系统确认框的实际响应时间、系统权限和澎湃 OS 行为需要真机确认。本次未安装手机、未发布安装包。

## 遗留问题与界面配合

- 无已知代码阻塞。真实备份文件、系统安装确认和升级后数据完整性待负责人在手机验证。
- Ready 期间的备份不展示进度，也没有“已经备份好”状态字段。界面文字由 Claude 调整；如需展示备份完成标识或等待状态，由 Claude 决定是否扩展约定，本卡未添加。
- 沿用 `platform.backup` 的成功语义：本机快照失败会抛错；可选本地/云端备份的失败、超时处理保持原样。
