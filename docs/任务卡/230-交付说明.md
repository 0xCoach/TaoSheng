# 卡 230 交付说明：开始专题已成功却提示“没开始成功”

## 起因
11-24 负责人反馈：0.5.7 开始培训专题时提示“没开始成功，请再试一次”，但专题实际已经开了。

## 原因
专题写进库后，仓库先更新“当前专题”，再排钟、发通知（`TopicRulesRepository.changed`）。界面一看到有进行中的专题，就把“开始面板”换成“进行中面板”（`TopicSection`），开始面板的 `rememberCoroutineScope` 随之取消。
旧写法用 `runCatching` 包住 `start()`，把这次取消也当成失败，于是提示没开始成功；同时面板没有收起，“上次用的专题类型”也没记下。会议、培训、通话各类专题都会出现，取决于后续步骤快慢，是个竞态。

## 做了什么
- 新增 `TopicStartLauncher`：开始专题放在不随界面取消的作用域里跑，结果回来再提示、收起面板、记下类型；取消不再算失败，真正出错仍提示“没开始成功”。
- 提示改用 applicationContext，面板换掉后照样能弹。
- 点击时先记下所选类型，结果回来时用这个值，不读之后可能变了的界面状态。

## 怎么验证的
- 新增 `TopicStart230Test`（2 个）：
  - 复现旧问题：面板作用域在开始途中被取消，旧写法回报失败；新写法回报成功（topicId 正确）。
  - 真正抛错回报失败；被取消时不回报。
- App 的 topic 包测试全部通过；全量单元测试见 0.5.8 发布记录。

## 没验证的
- 没在真机上点过，手机锁屏。
