# 卡 141 交付说明

## 完成范围

运行路径已从 `ManagedDevices` 切换为 `DeviceInputs → DeviceHub → CardDriver`。保留旧 `Devices` 界面接口、录音输入键、配对配置和补传算法；只有指定设备正在录音时才建立连接，收到第一块有效 PCM 才发布为可用。

- `:devices/commonMain/app.resound.devices.card` 新增说明卡驱动、实时流、文件适配器及平台身份包装器。无平台依赖、无新依赖升级。
- 每张启用卡生成 `card:<id>` 驱动，`tier=Card`；Verified 对应 Stable、Trial 对应 Trial。未启用卡不匹配。名字前缀、服务 UUID（忽略大小写）、厂商编号仍是任一命中；扫描遇到多张匹配卡仍沿用旧的卡列表优先顺序。
- `CardLiveAudio` 保留原通知订阅、端序探测、格式读取、写时钟、开始命令、心跳、电量轮询、拆包/CRC/丢包/解码统计和停止命令顺序。`start()` 启用流，随后由唯一收集器订阅 `frames`，订阅先于开始命令。Opus 只从会话工具箱创建，丢包时关闭并重建，再清空转换器余量。
- 输出仍为 16 kHz、单声道、每块 480 个 PCM16 采样；设备没有声音时间戳时 `deviceTime=null`，不冒充设备时间。全零 20 秒和无有效声音 2 秒的阈值保持不变；桥接层继续更新 `CaptureHealth.lastSoundAt`，保留原全零错误提示。
- 电量映射为 `BatteryPart(part=1, percent, readAtMillis)`，可选电量服务读失败不阻止收音。
- `CardFiles` 把旧插件列举、下载及删除映射到 `DeviceFiles`；确认操作为空，`confirm=false`；允许删除对应 `Reclaim.Manual`，否则 `Reclaim.Never`。有校验能力但未指定算法时明确拒绝，不默认为校验通过。
- 删除 `ManagedDevices.kt`（包含 `DeviceAudioBus`）、`CardAudioSource.kt`；`LinkedDevice` 原接口原样独立成文件。`AndroidDeviceRadio` 的扫描/连接路径删除，只保留系统配对操作为 `AndroidDeviceBond`。
- `createDevices` 装配桥接类，扫描只用 `AndroidBluetoothCenter`，连接只用平台 `HubConnector`。`ResoundApp` 改持有桥接类型，`AndroidInputDevices` 仅替换类型和键函数；`AppGraph` 原来的 `Devices`/错误流装配继续使用。
- `HubSession` 对已关闭的解码器移除跟踪引用，避免长时间录音反复丢包重建时保留已释放实例；会话取消仍关闭尚未释放的解码器。

## 范围核对与兼容办法

未修改任何既有 `*Contract.kt`、`AudioSource.kt` 签名。未改数据库/Schema、`ui/`、`MainActivity.kt`、`CaptureService` 或其他录音服务。未改 `DeviceSync`/`DeviceSyncStore`、`RemoteDeviceCards`、`DeviceCardsWork`。未接 PR #30，未做录包。

新增适配类型只在说明卡路径使用：

- `CardLink`：委托原 `GattLink`，由平台连接包装器提供 `DeviceIdentity`、初始化完成回调及原始故障状态；共用驱动不解析地址。身份使用原 `AndroidDevicePlatform.legacyIdentity`，值仍为 `android:CardDevice:<地址>`、`PlatformLocal`。
- `CardDeviceLink`：给旧文件插件/`DeviceSync` 的通道兼容包装，写入仍由平台通道检查最大长度，不拆包。
- `AndroidGattLink.disconnectedAt`：只读透传原底层的断开时间，无新系统操作；AndroidDevicePlatform 的连接实现未改，仅替换旧键函数引用和注释，不触碰录包接线。

原 `devices` 配置文件的 `paired` 数组及 `address/cardId/name/gapStart/clockOffset` 字段原样保留。已有配对记录启动即展示，首次实际连接时登记中枢选择；原音源键仍为 `CardDevice:<地址>`。不需要数据库迁移或重建。

## 行为对照表

| 旧行为 | 新实现位置与保持方式 |
|---|---|
| `select` + `recording(true)` 才连接当前指定设备 | `DeviceInputs` 的目标流；未选中、停止录音、改选、禁用卡会取消整个目标中枢并关闭连接 |
| 连接等待期间继续手机麦克风 | `consume` 首块有效 PCM 才发布 Feed 和 Live；仅 Hub Connected 或 Backfilling 不算音源可用 |
| `audioSource(key)` 的键、名字及失联异常 | 同名桥接方法；未就绪/不是当前目标抛原 `AudioSourceException` |
| 有界广播，消费过慢不能静默丢声音 | 桥接 Feed 有界 64，结束信号独立保存；通知缓冲仍为 128，溢出触发断开重连 |
| 断开时撤销可用并由手机接管 | 中枢断开取消旧声音流，Feed 结束；原 `InputSwitchLoop`/录音服务直接继续工作 |
| 断开记 `gapStart`，已有缺口不覆盖 | 包装的断开流先记原底层时间；驱动/连接失败用注入时钟，清理前保存，重试不覆盖 |
| 首次连接也调用补传入口，但不乱扫历史录音 | 初始化完成后走 Backfill 租约调用原 `DeviceSync.onLinked`；首次配对、断点恢复判断仍由原算法执行 |
| 重连补传必须用旧时钟偏差 | 连接初始化前取旧行；写新时钟后仍传旧 `clockOffset`、旧缺口起点及恢复时刻，完成后再保存新偏差 |
| 补传进行中断开可续做 | Backfill 租约随连接失效取消；取消时不清缺口，原数据库进度与源文件保留规则不变 |
| 实时声音与补传共用连接 | LiveAudio 租约保护启动；通知持续收集不长期占用租约，补传使用 `hub.withConnection(..., Backfill)`；系统 GATT 串行队列仍生效 |
| `devices` 状态/电量/补传进度供旧界面使用 | `render` 换算 Hub 状态；电量取部件 1，进度仍收集原 DeviceSync 流；没有首帧时不得显示可用 |
| `startScan`/`stopScan`、30 秒窗口、最多 100 条发现 | `DeviceInputs` 收集唯一蓝牙中心并限制窗口/列表；重开搜索清空发现和全局错误，权限失败通过 `lastError` 返回 |
| 只能配对已发现且已启用的设备，避免重复配对 | `pair` 检查发现/卡状态，按地址避免重复任务；系统 Bond 完成后再次核对启用状态，再写原配置 |
| 忘记设备与配对取消 | `forget` 取消在途配对，删除原配置和设备行，取消连接并清理中枢选择/存储 |
| 卡被禁用或远程卡缺失不连接、旧配对仍保留 | 发现立即过滤；已配对行显示“设备说明卡不可用”，恢复启用后重新按当前选择运行 |
| 连接异常持续重试 | 交给卡 140 中枢的既定退避：3/6/12/24/48/60 秒；其故障停用与持久化规则也开始生效 |
| 诊断统计与匿名设备标签 | 共用流记收包/丢包/CRC/解码统计，平台仍用地址 SHA-256 短标签写 UpdateDiagnostics，不记录声音内容 |
| 停止/改选后停止设备声音并关闭链路 | 流 finally 发原 stop 命令，限时 1.5 秒；释放解码器、补传协程和中枢连接 |

## 遗留与边界

- BLE、MediaCodec、心跳、电量实际服务兼容性及澎湃 OS 后台行为尚未真机验收；电脑测试不能代替上述清单，也未宣称 iOS 可用。
- `lostSamplesBefore` 以序号缺口换算：Opus 用卡声明的 10/20 ms（160/320 采样），PCM 用上一完整载荷的字节数/采样率/声道数。可变长包或分片丢失没有足够的设备时间信息恢复精确时长，因此该量是协议估算；不按通知回调次数计时，不补静音，不改变旧录音时间线。
- 没有新增内置文件插件。通用适配器已测试，生产补传在 Backfill 租约内继续调用原插件与 DeviceSync；校验插件需要明确提供算法后才能使用新的文件模型。
- 中枢 140 的递增退避、故障停用规则已随切换生效；旧界面只显示停用错误，重新启用入口仍由卡 144 处理。
