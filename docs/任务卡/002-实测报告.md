# 002 豆包转写方案实测报告

实测日期：2026-10-23（北京时间约 12:29～12:32）。本卡只增加脚本、合成音频与报告，没有修改 `app/`、约定接口或其他项目，也没有进入火山控制台做开通、购买、创建或修改。

## 结论

推荐先用 **B：`volc.seedasr.sauc.duration` + `bigmodel_nostream`，直接传 OGG Opus** 完成批量文字转写，当前 Key 实测可用，无需新增开通。40 秒对话用时 6.400 秒，音频发送仅 0.006 秒，无需公网音频网址或 WAV 转码。

**说话人分离尚未达到业务验收要求。** B 确实返回 `speaker_id`，但两个模式、两种发送速度和 OGG 测试都把 Flo 最后一轮发言错归给 Eddy。可以作为暂定编号，不能据此自动认定真实人物。若必须可靠分人，须先在小米手机真实录音上验收后再决定正式接入。

A、C 均在权限阶段返回 `45000030`。这证明当前 Key 对这两个资源无授权，不能据此断言整个账号未开通，也不能据此判定 base64 或说话人参数不支持。

## B 的速度、模式和准确度

每种组合只跑一次，均开启分人；总耗时从建连前计到最终包及关闭连接，发送耗时从配置包发出后计到最后音频包发出。不含本地音频生成和依赖安装；不是压测或延迟保证。

| 测试标签 | 输入 / 时长 | 发送耗时 | 总耗时 | 服务端确认音频 | 响应包数 |
| --- | --- | ---: | ---: | ---: | ---: |
| B_nostream_fast | PCM / 40秒 | 0.044秒 | 7.157秒 | 40000ms | 201 |
| B_nostream_realtime | PCM / 40秒 | 40.001秒 | 40.426秒 | 40000ms | 201 |
| B_async_fast | PCM / 40秒 | 0.033秒 | 2.635秒 | 40000ms | 17 |
| B_async_realtime | PCM / 40秒 | 40.002秒 | 40.233秒 | 40000ms | 88 |
| B_ogg_fast | OGG Opus / 40秒 | 0.006秒 | 6.400秒 | 40000ms | 202 |
| B_wav_monologue | WAV / 20秒 | 0.003秒 | 3.249秒 | 20000ms | 102 |

六次都收到了带结束标志的完整结果包，未发现服务端错误；快速发送没有按实时速度限流。**结论限于本次 20/40 秒样本**，不能外推为 5 分钟、并发或长期稳定性承诺。[官方流式 API 文档](https://docs.volcengine.com/docs/DoubaoVoice/LargemodelstreamingautomaticspeechrecognitionAPI?lang=zh)仍建议 100～200ms 音频分包及发包间隔；本次快速发送属于探路结果，生产应可配置节流和退避。

- `bigmodel_nostream`：流式输入、按完整语义输出；本次约每输入包返回一包，最终分成 6 句。
- `bigmodel_async`：优化双向流式，只在结果变化时返回；开启 `enable_nonstream=true` 后有二遍识别。本次最终 `additions.source="two_pass"`，合为 3 句，响应更少，快速 PCM 耗时更短。
- 两模式并不对应“实时发送/快速发送”，发送节奏是另一维度。async 本次更快，但其 OGG 路径没有实测，因此优先推荐已验证的 nostream + OGG 路径；可将 async 作为后续候选。

原文在 `samples/dialogue.json`、`monologue.json`。离线分析只去掉标点，并把原文“十点”“三点”归一成“10点”“3点”，其余字词照常计算编辑距离。双人原文归一后 137 字符，独白 67 字符，六次字错率均为 0；没有把合成语音结果当成真实全天录音准确率。nostream 实时与快速结果有逗号差异；async 两次最终文字完全一致；OGG 与 PCM 快速文字一致。不能称所有原始字符串逐字相同。

## 说话人分离实测

B 请求开关：`request.enable_speaker_info=true`、`show_utterances=true`、`ssd_version="200"`；async 另加 `enable_nonstream=true`。这些参数与[官方说话人分离说明](https://docs.volcengine.com/docs/DoubaoVoice/speaker-separation?lang=zh)一致。

双人合成轮次及 nostream PCM 最终结果：

| 原音色 | 原文时间段 | 实际编号 | 判断 |
| --- | --- | --- | --- |
| Eddy 第一轮 | 0.000～10.044秒 | 0 | 与后续 Eddy 一致 |
| Flo 第二轮 | 10.344～20.054秒 | 1 | 此处成功与 Eddy 分开 |
| Eddy 第三轮 | 20.354～28.400秒 | 0 | 正确回到 Eddy |
| Flo 第四轮 | 28.700～37.491秒 | 0 | 错归 Eddy，应与第二轮一致 |

OGG、nostream 实时发送也出现同样的末轮误分。async 将第三、第四轮合在同一个 `speaker_id="0"` 的句子里，也没有正确分开。不能报告为“两人已正确区分”，也不以四轮粗略正确数代替正式 DER。单人 WAV 的 3 句均为编号 0。

以下摘自 `B_nostream_fast.json` 的最终结果，省略词级列表；不是虚构示例：

```json
[
  {"start_time":10280,"end_time":13120,"text":"好的，我会带上测试手机。","additions":{"speaker_id":"1"}},
  {"start_time":28620,"end_time":37380,"text":"没问题，测试结束以后我会把结果发给你，明天一起决定采用哪一种转写方案。","additions":{"speaker_id":"0"}}
]
```

还观察到 async 首句缺少 `start_time`。离线汇总保留该字段为 null，仅在诊断重叠时临时按 0 计算；生产解析应容忍可缺字段，不能因缺少起点丢掉整条转写。

## 音频、时长与费用边界

- 本机 macOS `say`：Eddy、Flo 的 `zh_CN` 音色，双人语速 155、独白 140。四轮对话实际发声至 37.491 秒，补静音至 40 秒；独白发声至 18.223 秒左右，补至 20 秒。没有截断文字。
- WAV 经 ffprobe 确认 `pcm_s16le / 16000Hz / mono`。OGG 由相同 16kHz 单声道源按 `libopus -ar 16000 -ac 1 -b:a 24k` 编码，ffprobe 显示 Opus 解码率 48000Hz，这是实际观察值，不能把它伪写成 16000Hz；请求元数据用 `rate=16000`，服务端成功识别。40 秒容器时长为 40.0065 秒，20 秒为 20.0065 秒。
- 账本先落盘再发包，包含失败不退还：**280.0065 秒，剩余 19.9935 秒**。初次 A 请求 DNS 失败，音频没有出机但仍占 20 秒；随后更换标签经单次审批重试。该初次失败发生在调整合成语速前，不用于后续文字对比。
- 实际向外发起的音频请求合计最多 **260.0065 秒**（含 A/C 各 20 秒已拒绝请求）；B 成功识别 **220 秒**。共 9 个账本记录，8 次请求到达服务端，没有自动重试或超额补测。
- 按任务卡给出的单价保守估算，把 A/C 被拒绝的 40 秒也按成功计费约 0.091 元；B 本身按 1 元/小时约 0.061 元，可能由免费额度抵扣。**未查询账单或当前余额，不把估算当成实际扣费，也未核实“20 小时免费”剩余量。**

凭证只由脚本运行时从指定文件读取；未复制凭证文件，不保存请求头或 base64。输出只提示读取成功和长度；结果仅保存白名单响应头与经过脱敏的服务端响应。没有对火山控制台作任何变更。

## App 接入建议（未改 App）

建议请求到 `wss://openspeech.bytedance.com/api/v3/sauc/bigmodel_nostream`，鉴权头运行时设置 `X-Api-Key`、`X-Api-Resource-Id: volc.seedasr.sauc.duration`、随机 `X-Api-Connect-Id`；不能把凭证打进日志或仓库。

首包示例来自已运行配置：

```json
{
  "user":{"uid":"resound-probe"},
  "audio":{"format":"ogg","codec":"opus","rate":16000,"bits":16,"channel":1},
  "request":{
    "model_name":"bigmodel","enable_itn":true,"enable_punc":true,
    "enable_speaker_info":true,"show_utterances":true,
    "ssd_version":"200","result_type":"full"
  }
}
```

1. 首包用 JSON 配置二进制帧；随后传 OGG 文件的原始字节，不做 base64。本次 OGG 文件 109946 字节，约每包 549 字节直接分割传输；最后一包设置结束位。PCM 对照使用每包 6400 字节，即 200ms。生产 OGG 应按完整容器连续发送并保留头；按页/时间戳分包更利于准确节流，本次字节等分只是探测实现。
2. 每 30～60 分钟仅用于触发任务队列，不等于拼成一个 30～60 分钟请求。先逐文件顺序上传；短到 1 秒的片段可按同一连续场景合并为约 20～60 秒的小批，最长先沿用现有 5 分钟上限，但 **1 秒与 5 分钟端点均未实测**，上线前另验。不要并发堆积。
3. 独立 OGG 文件不要简单字节拼接。若合并，解码到统一 PCM、保留各段绝对时间和间隔映射，再重新编码成一个容器，或持续发送 PCM。只有真实连续对话才合并；无关片段不要为了获得相同编号而硬拼。拼接能力本次未验证。
4. 读取全量最终结果时覆盖同任务结果，避免把中间包重复追加。等服务端最终标志再标记成功，同时保存音频时长、logid、任务 ID；网络中断保持原音频，后续重试需幂等处理，不能把部分文字当成完成。
5. `speaker_id` 作为 **请求内临时标签** 保存，可用 `(转写任务ID, speaker_id)` 作键。跨独立音频、跨请求是否同人并未实测，不能把所有编号 0 当负责人。要跨段真实身份需另外验证声纹方案，本卡没有注册或创建声纹。即便同请求，本次也已有误分，不让大模型把该标签直接升级成姓名事实。
6. 推荐路径暂不需界面配合；若展示说话人，界面应允许“未知/待确认”。真实录音没通过分人验收前，下游事件和记忆提取以文本为主，人物归属保留不确定性。

## 验证与遗留

- 六次 B 结果均核对尾包和服务端完整时长；原始响应及离线汇总在 `tools/asr-probe/results/`。样本 SHA-256 在 `summary.json`。
- 四项本卡离线单元测试通过：预算溢出/重复拒绝及持久化、压缩尾包/错误包解析、凭证组成部分脱敏、字错率不掩盖错字。另检查 WAV/OGG 真实文件及 ffprobe 元数据。未改 Android 代码，不运行无关 Gradle 构建或全量测试。
- 真机需负责人验证：小米 14 Pro 导出的实际 OGG Opus、远场/口袋噪声、真人轮换/重叠发言、1 秒短片和 5 分钟长片、断网恢复与后台批处理。
- 未决：A/C 授权后的直传与分人；B 真实录音的分人质量、跨段身份、快速发送的长期限制与计费；async + OGG。本次不继续花费额度验证这些边界。
