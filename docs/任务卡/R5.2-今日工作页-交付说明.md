# R5.2「今日工作」页 — 交付说明

基线：`dc354cb5`（底栏调换）。本卡把待办页升级为工作聚合页：不是新增模块，而是把已有的待办、跟进承诺、会议任务、完成记录和工作总结集中到一屏。

## 改动

- **待办页新增首个 tab「今日」**（`ItemsScreens.kt`）：默认落点（有待确认时才跳待确认）。
- 一屏五个区块：
  - **今日待办**：`ongoing` 中 dueAt ≤ 今天末的条目（含逾期，按时间排）；可勾选完成、铃铛强提醒、左滑/右滑沿用既有行交互
  - **待跟进**：`followupEngine.observeOpen()`，标题+类型徽标（承诺/待办/灵感/建议——建议标注"不是承诺"）+ 行内「完成」（`markDone`）
  - **会议任务**：`topics.observeHistory()` 取 Meeting/Training/Call 的 `eventId` 集合，与进行中条目求交，按会议分组显示「来自「周例会」」
  - **今天完成**：`doneItems` 中 doneAt/statusChangedAt ≥ 今日 0 点；可撤回完成
  - **工作总结**：今日 `evening_note` 卡预览+查看（`SkillCardSheet`）、本周 `weekly` 卡链接；「生成今日总结」「本周回顾」调 `skills.runNow`，结果按 `SkillRunResult`（Cards/Nothing/Failed）提示
- 空态：各区无内容时整块隐藏/一句提示，页面不空转。

## 设计取舍

- 不新建数据库、不改 Contract；全部复用 `memory.ongoing/doneItems`、`followups`、`topics`、`skills`。
- 「会议任务」口径 = 条目 `eventId` 挂在会议/培训/通话专题的生成事件上；`Normal`/`Script` 专题不算会议。
- 工作总结复用现有技能卡体系（`evening_note` 收工打卡 18:00 定时、`weekly` 每周回顾周日 21:00）；手动生成走 `runNow` 同一管道，不另起报告引擎。
