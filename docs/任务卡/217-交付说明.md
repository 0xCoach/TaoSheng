- 按拼接的会议时间切 10 分钟块，暂停不计时；原话归开始所在块，边界不由文字决定。块内长文本继续按 2400 字预算切分并支持格式/容量错误拆分。
- 每块记录内容指纹、冻结待办上下文、已校验请求结果、提取结果和纪要叶子。改中间一句只重做本块；改最后三句会影响紧邻下一块。全局待办变化不使有效块失效。内容变化后开始重做时读取当时的待办上下文。
- 普通专题以事件要点作为纪要分段；会议、培训、访谈使用原有各自技能提示词的叶子输出；口播稿保留分块原话版，整理版使用汇总结果。前情三句标明仅供理解，不参加本块提取与原话引用。
- 汇总只接收块结果：总长不超过 12000 字一次调用，超长按最多六份逐级收敛后总汇总。决定、行动、关键段落和原话出处继续由本地合并保留；最终事件、待办保存沿用原事务及去重规则。
- Running/Paused 只整理已结束且转写就绪的块，写文件不写事件/待办，不改变会中状态。声纹最多等五分钟，之后可先处理；后续说话人变化按指纹局部重做。
- 会中录音落盘沿用 `runNow` 立即转写入口，不受实时转写开关/间隔设置限制；仍使用原转写网络约束。候选查询把 Running/Paused 纳入专题优先，开放 span 使用空结束时间兜底。转写后、声纹/原话变化后与分钟巡检均可唤醒专题任务。
- 会中、会后使用两个 WorkManager 唯一任务名。会中 Worker 不申请前台；会后仅在实际处理模型任务时申请前台。移除整轮持有声纹稳定锁的做法，避免绕过五分钟等待上限。无网络时也可轻量更新等待进度，模型调用仍受联网检查。
- 会后等待三十分钟无新转写/块完成时提供停滞原因；整理阶段三十分钟没有块或汇总完成时中止、记 FailureNotes 并转 Failed。取消保留已校验请求；单块失败继续处理其他块并在结果中注明缺段。全部块失败时保留旧成果、转 Failed。

## 缓存与入口语义

文件仍在不备份目录 `topic-checkpoints/<topicId>.json`，`format = 3`。同一块仅保留当前指纹的一份结果；汇总键包含有序块指纹、结果和缺段状态。旧格式、缺文件、损坏文件按无缓存处理。整场 `source` 只用于已完成专题的快速跳过检查，不再决定是否清空块缓存。

`regenerate(topicId)` 始终清空全部块和汇总，包括当前 Failed/Ended 状态；旧事件直到新结果提交才替换。删除专题清空文件。文件写入检查专题 revision 和删除代次，旧任务不能覆盖新的重试或删除操作。

`retryFailedBlocks(topicId)` 保留成功块及已校验请求，只补失败、缺失和指纹变化的块；清除主动跳过标记。`summarizeNow(topicId)` 用已有块完成结果，未就绪块标 Skipped，并在事件摘要和纪要中追加 `HH:mm–HH:mm 这段没整理（原因）`。主动跳过的块保留到用户点“补上”。这两个入口均只允许会后使用。

旧版已经完成但没有新块缓存的专题，不因升级或无关转写自动重新调用模型。已有新增未归属原话仍会接续；需要重做旧版成果时用显式重新生成入口。

## 给 Claude 的界面接口

未更改 `TopicContract.kt`。新增平台无关接口 `app.resound.topic.core.TopicBlockActions`，`RoomTopicRepository` 已实现：

```kotlin
suspend fun summarizeNow(topicId: Long)
suspend fun retryFailedBlocks(topicId: Long)
```

`AppGraph.topics` 若仍声明为旧 `TopicRepository`，导入同包扩展 `app.resound.topic.core.summarizeNow` / `retryFailedBlocks` 后可直接调用。原 `regenerate` 对应“全部重新生成”；“重试/补上”请改接新入口。

现有 `observeProgress(topicId): Flow<TopicProgress>` 增加字段，旧字段和可读文本保留：

| 字段 | 类型/单位 | 含义 |
| --- | --- | --- |
| blocksTotal / blocksDone / blocksFailed | Int | 当前时间块总数、完成数、失败数 |
| waitingTranscribe | Int | 等待成功转写的录音段数，跨块去重 |
| waitingVoiceprint | Int | 正在等待认人的录音段数，跨块去重；超过五分钟不再算等待 |
| waitingNetwork | Boolean | 当前没有可用网络 |
| lastProgressAt | Long，epoch 毫秒 | 最近新转写完成、块完成或汇总完成时刻；启动一轮会后等待/处理时初始化 |
| organizedUntil | Long?，epoch 毫秒 | 从第一块连续完成到的位置，不能跨缺块冒报完成 |
| stalledReason | String? | 会后等待三十分钟无进展的可读原因 |
| blockNotes | List&lt;TopicBlockNote&gt; | 每块时间范围、状态、可读要点及原因 |

`TopicBlockNote`：`index` 从 0 开始；`ranges: List<TopicBlockRange>` 是实际录音时段（可能跨暂停）；`state` 为 Waiting / Done / Failed / Skipped；`text` 为要点；`reason` 为等待、失败或跳过原因。`TopicBlockRange.startAt/endAt` 为 epoch 毫秒、半开区间。会中展开要点使用 `blockNotes`，部分完成提示使用 `blocksFailed` 和各块状态；无需新增数据库字段。

## 调用次数与会后时间

以恰好两小时有效会议、12 个时间块、每块提取与纪要均一份请求、汇总输入不超过 12000 字为可比较假设：

| 情况 | 改前 | 改后 |
| --- | ---: | ---: |
| 完整处理总调用 | 12 次提取 + 12 次纪要 + 11 次两两汇总 = 35 次 | 12 次提取 + 12 次纪要 + 1 次汇总 = 25 次 |
| 会后剩余调用（前 11 块已完成） | 35 次集中会后执行 | 最后一块 2 次 + 汇总 1 次 = 3 次 |
| 改一块中间一句 | 可能使全场缓存作废，重来 35 次 | 该块 2 次 + 汇总 1 次 = 3 次 |
| 改一块末尾三句之一 | 同上 | 本块与下一块共 4 次 + 汇总 1 次 = 5 次 |
| 仅勾掉别处待办 | 输入变化可能重做 | 0 次 |

这不是固定计费数：旧流程按字数切分，实际块数取决于原话长度；新流程超长时间块仍会拆分，重试、超长六路汇总也会增加调用。普通专题每块只有提取一遍。按每次模型响应 10～30 秒估算，最后三次串行调用约 30～90 秒，另加尾段转写与调度时间；认人可最多等五分钟，转写积压或断网不能承诺几分钟完成。本次未测真实服务时延。
