# 卡 232：共用层产出 iOS 静态框架，Swift 可直接调用

## 背景

卡 231 之后共用层能编成 iOS 目标代码，但还不能被 Swift 工程链接。本卡让 `:shared` 产出静态框架 `TaoShengCore`（真机 + 模拟器的 XCFramework），并补上 Swift 订阅数据流的最小桥接。安卓行为不变。

## 做了什么

1. `shared/build.gradle.kts`：仅在 `-Ptaosheng.ios=true` 时，为 `iosArm64`、`iosSimulatorArm64` 配置静态框架 `TaoShengCore`，并注册 XCFramework 任务。
2. `tools/build_ios_framework.sh [debug|release] [输出目录]`：一条命令产出 `TaoShengCore.xcframework`。
3. `shared/src/iosMain/.../interop/FlowWatch.kt`：`watchFlow(flow, onEach, onError)` 返回可 `close()` 的订阅，回调在主线程；`firstOf(flow)` 一次性取当前值。
4. `WireJson.Obj.NULL` 导出给 ObjC 时改名 `nullValue`（`NULL` 是 ObjC 宏，原名会让头文件无法解析）；Kotlin 侧名称与行为不变。

## 验证

- 模拟器上用 Swift 小程序调用：`openCaptureDatabase(path:)` 建库，库版本 44、74 张表、16 个触发器、全文索引表都在，日志模式 WAL；挂起函数写入（含中文、可空数字）后读回一致；`watchFlow` 依次收到新值；重启后数据仍在。首次打开并查询约 39 ms，再次约 7 ms。
- 必跑：`python3 tools/check_shared.py`、`zsh tools/check_ios.sh`、`./gradlew :shared:check :app:assembleDebug` 全部通过；`tools/build_ios_framework.sh debug` 产出两个架构。

## 遗留

- 目前整个共用层都导出给 Swift（头文件约 3.2 万行），以后应收窄为一层面向 Swift 的门面，减少编译时间和命名冲突。
- 是否引入第三方桥接插件（如 SKIE）暂不决定；先用本卡的最小桥接。
