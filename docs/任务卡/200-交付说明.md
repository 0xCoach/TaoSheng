## 线索规则与样例

- 输入按 `[dayStart, dayEnd)` 裁剪，时间相同依次为地点、事件、App、播放；跨午夜的段只计交集。
- 同一 App 间隔严格小于 2 分钟合并，实际使用满 5 分钟单列；不足 5 分钟的按本地小时分配，按用时列最多 3 个，其余写“等”。空档不计手机使用时长。“当时在用”复用 `ScreenTimeView.inUse` 的 2 分钟及事件时长五分之一门槛，小时统计复用 `appsDuring`。
- 地点用停留点，两个停留点之间写“路上”；外出时长为非家的停留加路上时长，不把没有定位证据的空白日猜成全天外出。地点数按展示地名去重。
- 事件带 E 编号、地点和当时使用的 App；上一条地点相同则省略重复地点。通话身份来自已有导入记录和原话事件关联，使用 📞，不凭标题猜测。
- 同 App、同标题及副标题的连续播放合并。录音覆盖先取并集，至少 30 分钟的空白展示；已有暂停日志可解释为暂停/停录时段，其余统一“没有录音”。说话时长与首页一样，对当天各录音段的交集求和。
- 通道未开足迹时，地点、路上、事件地点、外出/地点数全部不写；未开屏幕时间时，App、播放、当时在用、屏幕缺口、手机时长全部不写。

## 定稿、修正与推送状态

本地 04:00 后的一次性联网 WorkManager 任务补最近 3 个已经结束的日期；首次升级或新通道补最近 7 天。当天不生成实时线索。失败交给 WorkManager 退避重试，部分文件成功只确认那些已上传的日子；首次补写没有全部成功时不推进初始化标记。

日后 3 个自然日期内重算，内容不变不上传；超过修正期不重查 App、播放或停留点来覆盖封存线索。封存日只核对事件可见性及录音存活信息，以处理永久有效的隐私删除。删除事件和录音影响的事件条目、重叠缺口会清除，无关缺口及既存 App、播放保留；说话总量同步扣除删除录音。关掉订阅的类别也会从封存线索移除，避免旧内容继续暴露。

每通道的既有推送状态 JSON 新增 `dayThreads[日期]`，保存 `writtenAt`、内容 `hash`、结构化线索和录音编号/区间。成功传输之后才确认；WebDAV/S3 沿用文件哈希，Notion 定稿强制比较正文哈希，自定义接口比较线索哈希。没有数据库状态表。目的地变更会清理相应定稿状态并重新补写。

线索用 `<!-- resound:day-thread -->` / `<!-- /resound:day-thread -->` 标记，位于每日文档元信息和标题之后、正文最前方。普通事件重写保留已定稿节；修正期和隐私规则需要变更时替换。旧 `resound:screen-time` 块在重写时清理，包括没有结束标记的旧版块，后面的提醒保留。

凌晨定稿不推进普通订阅的发送游标，不提前发送当天文档、原话或周回顾，也不改变每日足迹/每日屏幕时间各自的按点推送。

## 各通道内容

| 通道 | 订阅任一整理结果后的行为 |
| --- | --- |
| 坚果云 / WebDAV / S3 文件夹 | 每日文件开头增加线索节，沿用同步和内容哈希 |
| Notion | 每日页面增加同一线索节，相同内容不再更新 |
| 自定义接口 | 同一时机额外发 `type=day_context` JSON；即使通道日常格式为文本，也按 JSON 发送此条消息 |
| 聊天类、邮件 | 不额外发送一天的线索 |

`day_context` 使用同一 DayThread，条目的 start/end 转为带偏移的 ISO 时间，例如 `2026-11-17T15:30:00+08:00`。旧 JSON 的时间字段维持原格式；每日记忆 JSON 顶层只新增 `utcOffset`。

## 删除触发接入点

`attachSubscriptions` 原有 Room invalidation 观察负责事件更新、软删除、原话和“这段别记”；本卡同一入口增加 `segments`，覆盖只删录音。变化后继续走原 `recordsChanged`，并排一个联网的线索刷新任务，使 Manual 订阅也能清除已经发出的私密线索。刷新与普通订阅使用同一通道 Mutex 和 PushSyncState，避免互相覆盖状态。首次观察也检查一次，能补上 App 未运行时发生的变化。

`SubscriptionRuntime.run` 的定稿路径负责准备、传输和确认；普通重写也经过相同 section 替换逻辑。封存数据不会因事件变少而恢复旧正文中的被删事件。
