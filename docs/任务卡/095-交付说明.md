# 095：报告按模块复制与问问出处排查

## 复制方式

- “复制全部内容”直接复制完整报告，不进入选择页面。
- “选择部分内容”默认按模块选择：标题/时间、摘要、各栏目、生成时间各为一个模块，可多选、取消、全选和清空；按报告原顺序拼接，不按点击顺序。
- 同页可切换“自由选择文字”，在只读全文中长按、拖动任意范围复制，切回模块保留勾选。
- 日报、全部已保存技能卡、试运行卡片共用实现；原卡片正文的自由选字保留。旧周报已隐藏的环境音明细不会重新混入复制结果。
- 模块预览最多展示四行；复制包含该模块全文，不截断。清空选择后按钮不改写剪贴板。
- 用户明确授权 UI 交互变更；未改 Contract、数据模型或生成提示词。

## 问问：“回答出处不完整，请重新提问”

- 此提示由 `AskEngine` 产生，不是模型直接说的话。`AskCitations.parse` 遇到正文 `[^n]` 无法映射到本轮 sources 时置 invalid，最终结果带错误；AskScreen 优先展示错误，覆盖正常答案展示。
- 已确认追问上下文有缺口：历史消息发送前去除 `[^n]` 标记，只保留正文；旧消息 sources 不加入新一轮。由事件入口带来的 AskContext 也只存在于发起那一轮。因此依赖前文的总结追问可能有正文但缺少可引用的原始依据。
- 本次用户请求排查原因，未改问答逻辑、未发云端测试请求。缺少这次原始模型返回，无法判断实际是旧编号、记录 ID 被误当编号，还是凭空编号；不能将推测当作本次确定根因。
- 建议后续修复：追问时按原记录 ID 重新校验/读取少量相关出处，再重新编号；无效出处可以进行一次有预算上限的修复，不能通过删除校验或随意绑定编号消除报错。已删除的记录不得从旧来源快照重新发送。
