基线：R6.0.1 `1c8c8c5c`（83/1.0.5，rotation@33）；本轮出 85/1.0.7（rotation-min-sdk-version 29）并完成发布收口。

## 做了什么

1. **签名策略定夺：方案 C**——`apksigner sign --rotation-min-sdk-version 29` 重签，把轮换边界从默认 33 降到 minSdk 29。全部受支持平台（API 29+）统一以 **Release 证书**为签名身份；v3 lineage 仍携带 debug→release 轮换链，旧设备无损升级保留。
2. **85/1.0.7 构建+重签+真机验证**：Android 16 真机 84→85 `adb install` 覆盖成功，数据完好；异证书伪造包被系统拒绝（`INSTALL_FAILED_UPDATE_INCOMPATIBLE`）。
3. **发布收口**：GitHub Release v1.0.7 已上传；stable manifest 指向 85/1.0.7，`files` 映射含 1.0.5/1.0.6/1.0.7 三个包；公开 debug 签名资产（v1.0.3 / v1.0.4 / v1.0.4-preview.1）已从 GitHub 删除，本地 `dist/` 保留内部归档。
4. **密钥备份**：release.jks + lineage + debug.keystore + signing.properties + 指纹清单 + 恢复说明打成 AES-256-CBC 加密包，两份独立副本（`~/.config/soundsound/backup/` 与 `D:\backup\soundsound-keys\`）；恢复演练通过（解出包指纹与正式证书一致）。

## ANDROID_10_12_STRATEGY

方案 C（rotation-min-sdk-version 29）：

- **新装身份**：API 29-32 新装/升级后的签名身份都是 release 证书，不再依赖 debug 私钥。
- **旧版升级**：debug 签名的 1.0.3/1.0.4 经 lineage 链可覆盖升级为 release 签名包（v3 轮换验证自 API 28 起系统支持）。
- **Keystore/本地加密**：包升级不动 `/data/data`，App 未做证书绑定的本地密钥，无影响。
- **回退兜底**：若个别 OEM 不认 rotation@29 编码，`dist/` 保留 1.0.5/1.0.6（rotation@33，API 29-32 视为 debug 同证书升级）作救援包。
- **未验证项**：本机无 API 29-32 模拟器/真机，`adb install` 实机验证仅覆盖 Android 16。API 29-32 的 lineage 接受度依据官方文档（v3 轮换验证 API 28+），**未实测，不宣称 FULL PASS**。
