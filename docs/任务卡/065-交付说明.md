## 状态流转

- 录音损坏、无法解码 → `Abandoned`，原因“录音损坏，无法转写”；文件缺失 → `Abandoned`，原因“录音文件已不存在”。停止自动重试，不计入 failed。
- 启动时将旧 `Failed` 中不再自动重试的同类错误转为 `Abandoned`，兼容固定错误文案及最后一次 Audio 错误日志。条件更新保证重复启动不会重置判定时间。
- 忽略采用库内 `Quiet` 状态，不另加忽略列。忽略当前需要处理的 Failed 后清空重试时间；列表通过现有枚举直接显示 Quiet。
- 首次失败超过 3 天仍失败 → `Quiet`，原因“多次转写失败”。恰好 3 天尚不降级。启动、候选选择、批量重试、清理和界面分钟时钟均会维护状态，不依赖联网或配置转写密钥。
- 批量重试只处理维护后剩余 Failed，并保留首次失败时间，避免每轮重新排队把三天期限延后。
- 单段重试只处理 Failed / Quiet / Abandoned，清除错误、判定时间、首次失败时间及重试时间，attempts 归零，变 Pending 并立即调度。文件已经清理时，下轮转为 Abandoned。
- 转写成功清除首次失败时间。队列 failed 仍只统计库内 Failed，首页也直接使用该队列，无需改界面。

## 原声和删除

- `completedAt` 对 Quiet / Abandoned 表示判定时间；按原声设置的保留天数计时，继续遵守收藏和正在读取的保护规则。
- 导入录音的 Quiet / Abandoned 也交给原声保留策略，不再被导入文件原有年龄提前清除；等待自动重试的 Failed 不删。
- 非自动重试的 Failed 可按原声保留策略回收，基准为首次失败时间；Pending、Running 仍保护。
- `deleteFailed` 在数据库事务内复查允许状态，删除文件及段记录，同时删除其转写尝试、原话、声纹样本/排除记录、原话关联事项和仅由该段支撑的事件；共享事件保留。正式数据库已有搜索触发器同步清理索引和相关向量。累计发送用量不回退。
- 文件存在但删除失败时保留记录，不假报删除成功。

## 迁移

只增加 `MIGRATION_20_21`。旧 Failed 的首次失败时间优先取已有失败尝试日志的最早时间；无日志可恢复的旧段在第一次维护时开始计时，不用录制时间推断失败时间。老坏文件的状态转换在启动维护时完成。
