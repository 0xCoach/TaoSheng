## 范围和保留规则

`mergedRanges` 合并相邻/重叠的选中事件时间范围，间隔保留；查询与范围重叠的事件/录音段。`TranscribeOnly` 只取明确选择的段，不替换事件。没有原声的段保留旧原话；全部失效时报明确错误，估算同时提供失效计数供界面禁用重转写。

所有整理批次和相关技能卡生成成功后，才在一个 Room 事务中替换事件、条目、原话归属及技能卡。任一模型请求失败不替换旧事件。取消保留已完成转写，未完成整理不替换事件。事务提交后发生的取消不能把已完成结果伪装为“已取消”。

每个旧重点事件选择时间重叠最多的新事件继承 ★；保留待办/约定中 Accepted、Done、Ignored 的原 ID 和状态，并重新关联新事件。另保护已编辑条目和删除墓碑。去重沿用 `saveDigest` 的保守规则：同类别/任务类别组内，相同文本、相同原话或相同旧事件的条目不重复生成。未处理旧条目随旧事件替换。

手改事件照常覆盖，并计入 `editedEvents`。相关技能卡按候选新事件重新生成；现有卡结构没有独立的“用户编辑过”字段，当前保守保护所有 `manual=true` 的卡（也包括手动触发生成的卡）。不会重新发送技能推送。

## 快照、恢复与并发

- 快照存于应用私有 Room 数据库 `redo_snapshot`，固定 `slot=1`；包含涉及的事件、条目、技能卡、原话及重转写时的段状态。无密钥，不复制音频文件或整个数据库。
- 新任务实际开始时替换上一份快照；一天后删除。`jobs` 的完成项保留一天或至 dismiss。任务列表保存在私有 `redo-jobs` SharedPreferences，模型偏好/速度在 `redo-choices`。
- 保存前后数据用于撤销校验；网络等待期间、重做后有人修改/删除相关记录时，拒绝覆盖或不安全撤销，并给出原因。
- `applied` 标记与替换结果同事务落库：系统中断的未提交任务从头重跑；已经提交但尚未发布完成状态的任务直接恢复完成，避免重复替换/收费。
- 云端失败写入现有失败状态与退避时间，段级指定方式保留供正常队列重试。重做任务本身显示 Failed；后续段转写成功不会暗中重整理事件，用户可再发起整理。
- 撤销不回滚已产生的 ASR/LLM 用量，不撤回外部推送，也不复原已被清理的音频文件。

## 估算口径和界面接入

- 本机：复用正常转写/重做成功时采集的“耗时÷音频时长”，以 0.7 旧值 + 0.3 新值平滑；首次尚无实测时 ETA 为 null，费用为 0。
- 豆包/自定义：经验 ETA = 3 秒 + 可用音频时长÷5。豆包费用读取 `AppGraph.usage.price.asrPerHour`；自定义未配置独立单价，返回 null。
- 整理：每个合并范围按 15 秒做粗估，不含网络拥塞、排队、不同技能数量等误差；总费用无法可靠估计，返回 null。`audioMs` 只计本次存在原声、可重转写的时长。
- ASR 未指定时用 `asr.lastChoice`（从未记忆时随当前设置）；导入的 null 按约定继续使用全局设置。界面确认时调用 `asr.remember`。
- LLM 未指定时优先上次重做选择，失效则回到设置当前预设。现有约定没有独立的“上次 LLM”属性，界面若要直接读取预选值需后续协商接口；本卡未改签名。
- `LlmOption.checked` 保守返回 false：当前设置层没有按预设持久化检测通过状态，不能把“已配置”冒充“检测通过”。
- 需要界面完成选择弹窗、过期/编辑提醒、进度及撤销入口、`EXTRA_REDO_JOB` 跳转。本卡没有修改这些界面。
