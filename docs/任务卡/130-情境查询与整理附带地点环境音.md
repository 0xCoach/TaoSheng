# 卡 130 · 情境查询（地点 + 环境音按时间对齐）与整理时附带情境

- 工作目录 `~/Developer/TaoSheng-130`，分支 `codex/130-situation`（从 `plan/0221` 拉出）。**不改 `ui/` 和 `MainActivity.kt`**；界面（事件卡片显示地点、足迹时间轴挂事件、整理设置开关）由 Claude 做。
- 版本：进 0.2.21-preview.2。

## 背景

声音（原话、整理出的事件）、位置（足迹，`location/`）、环境音（`envsound/`）共用同一条时间线，但目前只有“事件卡片显示环境音”按时间叠在界面上；整理不参考位置和环境音；事件的 `place` 是大模型从说的话里猜的。负责人要求打通。

## 约定（Claude 已写，签名不要改）

- `context/SituationContract.kt`：`PlaceAt`、`SituationLookup`（注释即需求）。
- `DigestSettings.includeSituation` / `setIncludeSituation`（`digest/MemoryContract.kt`，有默认实现）。
- `AppGraph.situation` / `isSituationReady`。

## 要做

### A. 实现 `SituationLookup`，在 `AppGraph` 装配
- `placeDuring`：用 `location/` 现有的停留点与地点分组逻辑（`DayTimeline`/`Timeline`、`PlaceResolver.cached`，**只读缓存，不联网反查**），取与 [start,end) 重叠最长的停留；重叠不足区间 1/3 视为“主要在路上”返回 null。名字优先级：手动名 > 缓存地名 > 地址；“家”按现有判定。足迹没开或没权限返回 null，不抛异常。
- `envDuring`：用 `envsound/` 已存的结果，按时长汇总标签；排除用户标为“不对”的；中文标签沿用现有显示名。
- `staysAt`：在 [from,to) 内找名字包含 `placeName` 的停留段（供卡 131 问问按地点问用；131 会并行开发，若它先需要可自行临时实现同等逻辑，合并时以本卡为准）。
- 性能：一次查询读一天以内的数据；界面会对每张事件卡片调用，需在 IO 线程、单次 < 20 ms 级别，可按天缓存停留点。

### B. 整理时附带情境（开关，默认关）
- `AndroidDigestSettings` 实现 `includeSituation`（存现有整理设置，随备份）。
- 开启时，整理提示里每段（按现有分段/分批，不要每句都加）在开头加一行情境，如 `【当时在：公司｜周围：键盘声、人声嘈杂】`；没有地点或环境音的部分省略；全为空则不加。
- 在系统提示词里加一句说明：情境行只帮助判断场景和地点，事件的 `place` 可以参考它，但以说话内容为准；不要把情境行当成原话。
- 关闭时提示词与现在**完全一致**（加一个测试保证）。
- 合并整理（MergePrompt）、重新整理走同一开关。

## 必测（6～10 个用例）

- `placeDuring`：整段在一个地点、跨两个地点取重叠最长、主要在路上返回 null、足迹为空返回 null。
- `envDuring`：按时长排序、排除“不对”、limit。
- `staysAt`：名字包含匹配。
- 整理提示：开关关时与原文一致；开时每段一行情境、空的不加。
