# 020 人物声纹与本地多人分段

## 功能与接口

- 人物可先命名，样本为零也能建立。原话长按“这是谁 / 输入名字”→ 输入称呼 → 保存并指定；nameAndAssign 复用同名人物，关联本录音同编号原话，录音可用时自动提取样本，过期时仅改身份。
- 设置页每个人独立一张卡片，显示姓名、样本数、有效秒数和学习状态；顶部有添加人物。选择人物弹窗使用 FlowRow，从左到右、再从上到下。原来“人物与声纹 / 清空我的声纹”并排保留。
- 管理支持添加、改名、删除、15 秒录音补样；补样期间临时暂停日常录音，完成、取消、离开前台后恢复，手动停止录音时不强行重启。
- voiceprint_people + 样本 personId；0 为原有“我”。身份需至少 3 段、30 秒有效声音，匹配同时检查相似度 0.65 和第二候选差距 0.08。多人模式不自动将未经确认的声音加入人物样本。手动指定与未知状态不会被自动匹配覆盖。
- speakerPersonId / speakerManual 写入原话；名字用于后续整理、查询。改名更新原话，不追溯改写已生成的事件摘要；删除人物清除声纹与原话身份关联，保留录音、文本、事件。
- 数据库 8→9 保留原声纹、人工“这是我”和排除记录；8 版备份允许校验后通过 Room 迁移到 9。

## 多人分段（试用）

- 复用官方 sherpa-onnx v1.13.8 + pyannote segmentation 3.0 浮点模型 + 现有 CAM++；下载约 7 MB，安装约 6 MB，固定 SHA-256，官方源、按需下载，权重不打包进 APK。
- 本地模式先分段，再按说话人区间转写；不硬设人数，不把额外簇强行塞进三个人。重叠范围标为待确认。
- 不丢弃分段模型认为的静音，整个音频都保留，避免漏掉话头。同标签连续片段合并，再受 ASR 长度上限约束。
- 分段模型与 ASR 运行在隔离进程。云端模式仍使用云端返回的说话人标签；未下载模型维持原流程，管理页可关闭多人分段。
- 修复官方 JNI 回调与 Kotlin invokedynamic 不兼容导致验证包退出：使用显式 Function3 对象保留 invoke(IIJ)Integer。
- 本阶段仍有每段加载、28 秒上限等旧实现；用户已追加下一任务，统一优化模型会话、切段与句子时间，详见后续任务卡。
