# 卡 200：一天的线索（每日定稿）与时区兜底

基线：`codex/199-call-recordings` 2a0e6379（数据库 39）。执行：Codex（Astra）。工作目录 `~/Developer/TaoSheng-200`，分支 `codex/200-day-context`。
**不改数据库**。不改 `ui/`、`MainActivity.kt`，只有两句说明文字例外（见第五节，Claude 已确认可以改）。

## 背景（负责人已定）

坚果云等推送里，**何时、何地、说了什么、听了什么、用了什么** 现在是割裂的：
- 每日文档只有事件时间线；
- 屏幕时间单独一块，只有总数；
- 足迹根本不进文档；
- 事件的地点和“当时在用”也没写。

屏幕使用每分钟都在变，实时拼进文档会反复重传。所以定为：**每天凌晨把前一天定稿成“一天的线索”，写进每日文档开头**。同时修掉“写死北京时间”的问题，对外一律用 UTC 偏移。

## 一、一天的线索（规则放 :shared，纯函数，可测）

新建 `shared/.../context/DayThread.kt`。

输入是某一天 `[dayStart, dayEnd)` 的这些数据：
- 事件：含地点、参与人、场景、是不是通话导入；
- 停留点：起止和地名；
- 前台 App 使用段；
- 设备播放记录；
- 录音缺口和屏幕时间缺口；
- 当天时区段（见第三节）。

输出是 `DayThread`：
- 概览：说话时长、手机时长、外出时长、去了几个地方、几件事；
- 按时间排的条目列表，每条有类型（地点 / 事件 / App / 播放 / 缺口 / 时区变更）、起止、文字、关联的事件编号。

数据来源一律复用现有接口，**不新写查询**：
- `SituationLookup`：地点、App、播放。缺“整天停留点列表”就在接口上加一个带默认实现的方法，照 `appSessions` 的写法。
- `ScreenTimeView.timeline / inUse / appsDuring`。
- 足迹的停留点规则。
- 说话时长用首页现有的统计口径。

合并规则：
- **App**：同一 App 前后间隔 < 2 分钟算一段；一段 ≥ 5 分钟单独一行（`12:10–12:28 📱 小红书 18 分`）；不足 5 分钟的按小时合成一行（`14 点 · 📱 微信 12 分、小红书 10 分`，最多列 3 个，其余写“等”）。
- **地点**：用停留点，不写原始定位点。两地之间写“路上”（`08:30–08:52 📍 家 → 公司（路上）`）。
- **事件**：一行，后面带地点（与上一行地点相同就不重复）和“当时在用”（沿用卡 198 的门槛）。通话导入的事件用 📞。
- **播放**：同一节目连续的合并一行，`🎧 小宇宙《节目名》`。
- **缺口**：一天里 ≥ 30 分钟没有录音段写一行“没有录音”。如果是停录时段或暂停，写明原因；手机关机看不出来，统一写“没有录音”。屏幕时间缺口照卡 198 的说法写。
- 同一时刻多类信息时，顺序为：地点 → 事件 → App → 播放。

Markdown 样子（照这个写，可微调标点）：

```
## 今天概览
说话 2 小时 24 分 · 手机 3 小时 14 分 · 外出 9 小时 · 去了 3 个地方 · 12 件事

## 一天的线索
本节时间为 UTC+8
- 08:30–08:52 📍 家 → 公司（路上）· 📱 高德地图 12 分
- 09:12 💬 安排今天要做的事（E12）
- 09:40–18:05 📍 公司
- 10:30–11:12 💬 发布会彩排安排（E13）· 当时在用 飞书 6 分
- 14 点 · 📱 微信 12 分、小红书 10 分
- 15:40 📞 和 老王 通话（E15）
- 21:05–21:52 🎧 小宇宙《第 87 期：AI 怎么记住你的一天》
```

E 编号沿用每日文档里已有的锚点。

## 二、写进推送（每日定稿）

**写进哪**：
- 每日文档开头，用标记 `<!-- resound:day-thread -->` … `<!-- /resound:day-thread -->` 圈一节，写“今天概览”和“一天的线索”。照现有 `SCREEN_TIME_MARKER` 的写法做替换和保留：文档之后因事件更新而重写时，这一节原样保留。
- **去掉**文档末尾原来的屏幕时间块。屏幕时间已经并进线索，不再重复。注意兼容：已上传的旧文档里有旧标记，下次重写那天时清掉。

**什么时候写**：
- 每天本地时间 04:00 以后写前一天的，用 WorkManager 一次性任务，照 `ScreenTimePushScheduler` 的写法，要求联网。没跑成就下次能跑时补写所有没写过、仍在 3 天内的日子。
- **3 天修正期**：那天之后 3 天内，内容有变化（补转写完、事件改了）就重写那一节。超过 3 天封存，不再日常重算。
- **隐私删除永远优先**：删除事件、删除录音、“这段别记”、隐私删除涉及的日子，无论多久以前，都要重写那一节；数据没了就去掉对应条目。屏幕使用的原始记录系统只保留几天，所以封存后的日子重写时，App 和播放部分沿用已写的内容，只删掉被删的那部分事件和缺口说明。先查清现有删除如何触发每日文档重写，挂在同一个入口上。
- **内容一样就不上传**：写之前比对哈希。每个通道、每天记录 `writtenAt` 和 `hash`，存在推送状态里，照现有 `state.files` 的做法，不进数据库。
- **第一次开启**（老用户升级后，或新建了通道）：补写最近 7 天。

**哪些通道、哪些内容**：
- 文件夹类通道（坚果云、WebDAV、S3）和 Notion：只要订阅了任一整理结果，就写线索节。
- 自定义接口：开了整理结果时，每天同一时机多发一条 `type = "day_context"`。内容是同一个 `DayThread` 的 JSON，所有时间带偏移，如 `2026-11-17T15:30:00+08:00`。
- 聊天类通道（企业微信、飞书机器人等）不发。
- 地点和“路上”只在这个通道开了“每日足迹”时写；App 和播放只在开了“每日屏幕时间”时写。没开的那类整类不出现，概览里对应的数也不写。事件本身跟着整理结果走。

## 三、时区兜底（对外一律 UTC 偏移）

**1. 记住时区变化**：
- 新建 `shared/.../platform/ZoneHistory.kt` 规则，安卓侧在 `ACTION_TIMEZONE_CHANGED` 和 App 启动时检查。
- 时区 ID 变了就追加一条 `{from: 毫秒, zoneId}`，存偏好，随备份走，按卡 190 的守卫归“备份”。最多留 500 条。
- 没有记录时用当前时区。
- 提供两个查询：`zoneAt(at)`；`zonesOn(date)`，返回当天的时区段，日界线按当天 00:00 时所在的时区算。

**2. 对外输出**：
- 每日文档、线索、`day_context` JSON 一律按**那天所在的时区**写时间。
- 时间只写 UTC 偏移：`UTC+8`、`UTC-5`、`UTC+5:30`、`UTC+5:45`。**不写时区名和城市名**。偏移按每个时刻实际的值算，夏令时换季当天也要对。
- 一天里换过时区：在换的时刻加一行“14:20 起为 UTC+0”。
- 每日文档开头写一句“本文时间为 UTC+8”，换过时区就写“本文时间为 UTC+8，14:20 起为 UTC+0”。
- `MemoryFolder.updatedText` 也改成当前时区并带偏移。
- **已有 JSON 字段格式不改**，避免破坏用户已有的接收端。只在每日记忆 JSON 顶层加一个 `utcOffset` 字段，如 `"+08:00"`。

**3. 去掉写死的北京时间**：
- `SKILL_ZONE`（app 与 shared 两处）的所有用法换成“这条数据那天的时区”：按数据的时间点用 `zoneAt`，按日期用 `zonesOn(date)` 的日界线。为了让改动面小，可以保留同名入口，改成函数。
- 提示词里的“时间均为北京时间”“所有时间为北京时间”改成“时间均为当地时间（UTC+8）”，偏移按当天时区填。
- 文件夹说明里的“时间都是北京时间”改成“时间以每天文档开头写的 UTC 偏移为准”。
- **备份分卷 `DayVolumeRows.zone` 不改**：只是内部分包，改了会让已有备份重新分卷。
- App 内界面显示**不改**，仍按手机当前时区。

**验收**：时区为 Asia/Shanghai 时，`parity160` 的提示词夹具**只允许**“北京时间”这几个字变成“当地时间（UTC+8）”，其余一字不差。夹具照此更新，并在交付说明里贴出 diff。
