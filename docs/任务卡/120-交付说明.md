# 卡 120 交付说明

## 已实现

- `DeviceSync`：按插件 ID 查找、全局串行下载、断开区间换算和前后 2 秒裁剪、已登记区间相减，避免相邻补传重复。
- 首次连接不导入历史文件；提供 `importAll`。断开、取消、进程重启后从数据库恢复旧任务；支持续传的插件从已落盘位置继续，不支持的从零下载。
- 文件大小/插件指定算法校验，校验失败最多下载三次。完整下载先保存在 filesDir，再标准化并进入现有导入队列；等待切段成功入库才标记已导入。
- 复用卡 117 指纹：分享/文件夹已经登记的整文件不再导入。切片用任务键去重，完整导入成功后才登记整文件指纹。共享指纹可能表示尚在排队，因此命中指纹时不删除设备原件。
- 仅全文件成功导入且插件支持删除时删除；部分补传保留整份设备录音，避免丢掉未导入部分。失败写入 watchdog 的 `DeviceSync` 问题记录，不含文件名或设备地址。
- 数据库 30→31，新增 `device_transfers` 和 Room schema，进度、区间、导入/删除状态持久化；迁移列表只增加一条。
- wav / ogg / 封装 opus / mp3 / m4a / aac 使用现有 MediaExtractor/MediaCodec 解码，转换为 16kHz 单声道 PCM WAV；裸 pcm16 按 16kHz、单声道、小端转换。全量导入使用实际音频时长，保留列表整秒时长以外的尾部。
- 未修改 UI、MainActivity、任何约定文件签名或 App 版本号。

## 给卡 119 的装配入口

以下均为同模块可访问的 `internal` 类型；本卡不接管卡 119 的连接生命周期。

```kotlin
val sync = DeviceSync(
    deviceKey = address, // 物理设备地址，不能只用说明卡 ID
    root = File(context.filesDir, "device-sync/downloads"),
    db = database,
    plugins = listOf(SonicloudFiles()), // 注册放在插件装配处，核心无品牌依赖
    ingest = deviceImport(context, database, importer as AndroidAudioImporter),
)
// 连接后在受连接生命周期管理的协程内调用；断开时 cancelAndJoin 旧调用，再处理新连接。
sync.onLinked(card, link, gapStart, gapEnd, clockOffsetMillis)
// 用户明确要求导入旧录音：
sync.importAll(card, link, clockOffsetMillis)
```

- `clockOffsetMillis = 手机时间 - 设备时间`。gapStart / gapEnd 是手机毫秒时间，必须同时有值或同时为空。
- `progress: StateFlow<BackfillProgress?>` 映射到对应地址的 `DeviceState.backfill`；null 表示没有活动同步。字节总量可能是估算，接收后向实际长度修正；失败文件不计入 doneFiles。
- 同一物理设备保留一个实例；下载和导入在 IO 调度器执行。断开须取消旧协程，未完成任务下次连接恢复。保活、蓝牙权限和前台服务由卡 119 承接。
- 插件通过额外内部接口 `DeviceFileDetails` 提供手机时间的修改时间、校验算法或输出大小验证。没有可靠时间时记录问题并跳过自动补传；不会用本次重连时间冒充旧文件结束时间。

## 声云协议核对

依据 [官方协议](https://github.com/SonicloudTech/sonicloud_opensdk/blob/main/pnote-web-win%26Mac-demo/docs/协议.md) 第 3、6、7 节及同目录 `recorder/protocol.py`、`recorder/device.py`（MIT），不使用厂家 AAR。

- 请求列表为 **2-0**，返回列表为 **2-1**（任务卡把返回命令写作 list 命令）；按 BE 解析 count/time/size，累积多帧，到 2-18 完成。旧固件已有非空列表后空闲 1.2 秒结束。
- 恢复被截断的扩展名，优先且目前仅请求 `.wav`；2-2 请求严格为 36 字节一次写入 AE21，使用无响应写入。先订阅 AE22，再发命令。
- 通用帧 LEN/CRC 使用官方当前实现明确的小端，CRC16-XMODEM 覆盖 LEN+DATA；支持跨通知拼帧和一个通知多帧。open 发 0-3 电量查询并校验 0-4 应答；不兼容未经证实的大端变体。
- 官方协议和 Python `build_import_request(seq, filename, offset=0)` **均明确存在 4 字节小端 offset**；仍按任务卡设 `resume=false`，是否开放由 Claude 决定。
- 删除为 2-8，参数原样使用列表的 28 字节条目；等待 2-13 状态 0 才记删除成功。旧固件无应答会报失败，不假报成功；没有调用删除全部。
- 列表大小是压缩文件大小，WAV 是设备转码结果，不能直接比较。下载需 2-3 开始、2-5 状态 0 结束，再检查 RIFF/WAVE 和声明长度等于实际长度，解码成功后才可能删除。
- 卡 118 当前分支尚未存在 FrameCodec，因此暂在插件目录实现 `FileFrames`，合并时由 Claude 收拢。

## 真机注意与遗留

- 未进行真机验证。请在小米 14 Pro/声云设备验证通知订阅生效后再发送、36 字节单写、重连取消、WAV 播放、前台保活及删除应答；删除测试用专门的测试录音。
- 声云列表没有修改时间，文件名时间是设备当地时间，并非已验证的手机时间。因此自动补传必须传入可靠 clockOffsetMillis；没有偏差时安全跳过，手动全部导入可使用文件名时间。若要无对时自动补传，需要补充设备修改时间来源，不能凭现有协议准确实现。
- 文件名时间按手机当前时区解析；设备时区不同需要调用方换算偏差。列表 time 为绝对时间戳的固件尚不支持，缺少时长时会记录问题。
- 裸 Opus 没有通用帧边界协议，不能当标准 `.opus` 容器解码；本插件不回退到裸 Opus，以免误导入。七种格式的实际系统解码兼容性仍需真机素材验收。
- 共享指纹沿用卡 117“排队即登记”的语义；命中未完成分享/文件夹任务也跳过，但绝不因此删源。
- 本卡仅提供入口和 Flow，卡 119 尚须装配生命周期、进度、保活；“导入全部”按钮由 Claude 接入。
