## 一、文件名解析（`CallFileNames.parse`，放 :shared，纯函数）

**不按品牌写死格式，按“零件”认**：去掉扩展名后，从文件名里找下面几类零件，顺序和分隔符（`_ - . 空格 @ ( ) [ ] 【】 ＠ ，`）随意。

1. **号码**：
   - 手机号：`(?:\+?86[- ]?)?1[3-9]\d{9}`，前后不能紧挨别的数字。手机号中间带空格或横线（`138 0013 8000`、`138-0013-8000`）也认。
   - 座机：`0\d{2,3}[- ]?\d{7,8}`。
   - 服务号：5～6 位数字，且在括号里或紧跟 `@`（如 `中国联通(10010)`、`@95588`）。
   - 规范化：去掉 +86、空格、横线。
   - **号码先认**，认出来的数字段不再参与时间解析。
2. **时间**：下面都要兼容。每种可能的读法都列为候选，再用参照时间挑（见下）。
   - 连写数字：`yyyyMMddHHmmss`（14 位）、`yyyyMMddHHmm`（12 位）、`yyMMddHHmmss`（12 位，与上一种冲突时都列为候选）。
   - 日期和时间分开：`yyyyMMdd_HHmmss`、`yyyyMMdd_HHmm`、`yyMMdd_HHmmss`、`yyyy-MM-dd HH-mm-ss`、`yyyy-MM-dd HH:mm:ss`（文件名一般不含冒号，但兼容）、`yyyy.MM.dd`、`yyyy年M月d日`、`M月d日`。
   - 只有时刻：`HH-mm(-ss)`、`HH.mm(.ss)`、`HHmm`（4 位且 00:00～23:59）、`H点m分`、`H时m分(s秒)`、`上午/下午/晚上 H点(m分)`、`H:mm`。
   - 毫秒时间戳（13 位，2000～2100 年内）、秒时间戳（10 位，同范围）。
   - 不合法的日期时间（13 月、25 点）不当候选。
3. **方向**：含 `来电/呼入/接听/incoming/in_` 为呼入；含 `去电/呼出/拨出/outgoing/out_` 为呼出；没有为 null。
4. **名字**：
   - 先去掉号码、时间和方向字样。
   - 再去掉固定字样（大小写不限）：`通话录音`、`录音`、`电话录音`、`call recording`、`call_rec`、`callrecord`、`record`、`call`、`voice`、`rec`、`未知号码`、`unknown`、`私人号码`。
   - 最后去掉分隔符和首尾空白。剩下的非空、且不是纯数字，就是名字。
   - 名字里的运营商词（`中国移动/中国联通/中国电信`）保留原样（如 `中国联通(10010)` → 名字“中国联通”，号码 10010）。

**参照时间和挑选**：
- 参照开始时间 = `recordedAt` ?: (`fileEndAt` − `durationMillis`) ?: `fileEndAt`。
- 有完整日期时间的候选，取离参照最近的那个，且相差不超过 36 小时 → `FileName`。都超过时，若只有一个候选也用它（录音被拷来拷去，修改时间可能不准）；多个候选都超过则用参照 → `FileClock`。
- 只有时刻时：日期取参照的日期，在参照日期前一天、当天、后一天三者里取最近的 → `FileNameTimeOnly`。
- 没有时间零件 → 用参照 → `FileClock`。都没有 → `Unknown`，`startAt = null`。
- 跨时区：按传入的 `zone` 解释文件名里的时间。

**必须过的样例**（写成测试，可再加，但总数别超过下面数量太多）：

| 文件名 | 期望 |
|---|---|
| `通话录音@中国联通(10010)20170330120101.mp3` | 号码 10010，名字 中国联通，2017-03-30 12:01:01 |
| `13800138000_20261117153012.mp3` | 号码，无名字，2026-11-17 15:30:12 |
| `通话录音@13800138000_20261117153012.mp3` | 同上 |

## 三、文件夹预览与历史四选一（安卓）

**`preview(tree)`**：
- 先 `takePersistableUriPermission`（和 add 一样）。
- 列出文件（沿用卡 117 的范围：本层 + 一层子文件夹、支持的格式、跳过隐藏和 0 字节）。
- 读每个文件的时长和元数据录制时间。可以复用 `ImportMedia` 的读法，单个文件读不出就时长算 0，不中断。
- 用 `CallFileNames.parse` 得开始时间，算 7 天 / 30 天 / 全部 的数量和总时长。
- `callLike` 是认出号码或名字的个数；`looksLikeCalls` = 路径 `looksLikeCallFolder`，或 callLike ≥ 文件数一半（至少 1 个）。
- 300 个文件内要在 10 秒内返回。结果按 tree 缓存 10 分钟，避免紧接着 add 时再读一遍。

**`add(tree, kind, history)`**：
- 加入瞬间已有的文件按 history 处理：
  - `OnlyNew`：照卡 117 的 baseline，全部记为已见、不入表。
  - `Days7` / `Days30`：窗口内的入 `folder_recordings` 并排进**补转**；更早的入表，状态 `Listed`。
  - `ListAll`：全部入表，状态 `Listed`。
- 之后新出现的文件照常自动导入（卡 117 的“稳定 2 分钟”规则不变），同时入表，状态 `Imported`，挂上 importRecordId。
- **所有类型的文件夹都适用这四个选项**；只有 `kind == Call` 的文件夹才解析通话对方（`call` 字段），其他类型 `call = null`。
- 老的 `add(tree, kind, importExisting)`：false → OnlyNew，true → Days30。老文件夹的偏好里没有 history 的视为 OnlyNew。
- `setHistory`：只扩大范围（例如从 OnlyNew 改成 ListAll，就把加入时的旧文件补进表），不删已导入、不撤已列出。缩小范围时只改记录的选项，不动已有数据。

**开始时间**：
- 通话文件夹用 `CallFileNames.parse` 的 startAt。
- 其他文件夹照旧（录制时间，没有则用修改时间）。
- parse 返回 null 时也照旧。

## 五、补转（历史录音转写）

- 一次只排一个文件进现有导入队列（不并发解码），从新到旧。
- **新通话和用户点的“转写”永远插在补转前面**：补转下一个之前，先看有没有新文件或用户点的。
- `pauseBackfill(true)` 后不再排新的补转（已在转的那一个转完）。暂停状态存偏好，重启后保持。
- 补转期间：
  - 卡 117 的“从〈文件夹〉导入了 N 个录音”通知，对补转的文件不发。
  - 整轮补转完发**一条**：“〈文件夹名〉的 N 个历史录音已转写完”。
  - **补转出的旧日期事件不触发每日足迹、整理结果等推送，也不重算旧日期的每日小结推送**。先查清现有推送在什么条件下发；若导入旧日期本来就不推，写明即可。
- 转写额度：不做预估，界面只显示时长。

## 六、通话对方用到哪里

- **导入记录**：`kind == Call` 且有 `display` 时，导入记录在没有纪要标题前的默认标题为“和 〈display〉 通话”。现有标题规则在 `ImportSummary`/`ImportRecordPresentation` 附近，改动写进交付说明。
- **说话人**：通话导入是两人。声纹认出“我”之后，另一位的显示名用 `display`，替换“说话人 2”。没认出“我”时不猜，照旧。备注改了以后，已导入的显示跟着变：显示时取名，不写死进转写行。如果现有结构只能写死，写明并给出最小改法，停下来问，不要自己改数据结构。
- **整理与纪要的提示词**：只带名字（`label ?: fileName`），**绝不带号码**。只有号码时写“对方”。号码只存本机、只在界面显示。转写服务（云端 ASR）本来就不发文件名，确认一下。
- **搜索**：`search(query)` 搜 `partyName`、备注、号码。号码支持输入后 4 位及以上做后缀匹配，名字用包含匹配。
