# 卡 032 · 更多推送通道 + 每日记忆文档 + 自定义接口

在现有推送框架（`push/` 包）上加 6 种通道。界面是通用的：按 `fields(kind)` 自动出输入框，Claude 已在约定里加好枚举、在界面加好配色，本卡只做后端。

**约定**：`push/PushContract.kt` 的 `PushKind` 已新增 `Feishu / DingTalk / Telegram / Email / Notion / MarkdownFolder`（不要改签名）。
**分支 / 工作树**：`codex/032-push-more`，`~/Developer/resound-codex-032`。

## 一、已定方案

| 通道 | 要填的项（secret=密钥类，进安全区、读回脱敏） | 发送方式 | 成功判定 |
| --- | --- | --- | --- |
| 飞书机器人 | webhook（secret）、签名密钥（secret，可选） | POST JSON；有签名密钥时按飞书规则加 timestamp + sign（HmacSHA256，Base64）；Markdown 用 `interactive` 卡片的 markdown 元素，Text 用 `text` | 返回 `code == 0` |
| 钉钉机器人 | webhook（secret）、加签密钥（secret，可选） | 有加签时 URL 追加 `timestamp` 和 `sign`（HmacSHA256 后 Base64 再 URL 编码）；Markdown 用 `markdown`（title+text），Text 用 `text` | `errcode == 0` |
| Telegram | Bot Token（secret）、Chat ID、接口地址（可选，默认 `https://api.telegram.org`，给代理/反代用） | `sendMessage`；Markdown 用 `parse_mode=HTML`（把标题加粗、换行保留，内容做 HTML 转义，比 MarkdownV2 好处理），Text 不带 parse_mode；超过 4000 字截断并注明“已截断” | `ok == true` |
| 邮件 | SMTP 服务器、端口（默认 465）、账号、授权码（secret）、收件人 | 自己实现最小 SMTP：465 用 SSL，587 用 STARTTLS；AUTH LOGIN；UTF-8 主题（RFC 2047 Base64 编码）；Markdown 格式发 `text/html`（简单转换：标题、加粗、列表、换行），Text 发 `text/plain`。不引入大型邮件库 | 服务器 250 应答 |
| Notion | Integration Token（secret）、数据库 ID | `POST https://api.notion.com/v1/pages`，`Notion-Version: 2022-06-28`；父级为数据库，标题写进数据库的“标题属性”（先 GET 数据库取出 title 类型属性名，缓存）；正文按段落拆成 paragraph 块（每块 ≤ 2000 字，最多 90 块） | HTTP 200 |
| Obsidian / 笔记文件夹 | WebDAV 地址（默认 `https://dav.jianguoyun.com/dav/`）、账号、应用密码（secret）、文件夹（如 `Obsidian/回响`）；提示文字写明“填坚果云账号即可，Obsidian 用 Remotely Save 等插件同步这个文件夹” | 按日期写 `文件夹/YYYY-MM-DD.md`：先 GET（404 视为空），在末尾追加 `## HH:mm 标题` + 正文，再 PUT；目录不存在就 MKCOL 逐级建 | PUT 返回 2xx |

共同要求：
- 复用现有 `PushTransport` 的安全做法：不跟随跳转、10 秒超时、只读最多 64 KiB 响应、错误信息不回显服务端原文和凭据、错误文案用现有那几句（认证失败 / 频繁 / 网络 / 格式）。邮件、WebDAV 的错误也映射成同样风格的中文。
- 校验写进 `PushFields.validate`：webhook 必须 https 且域名对（飞书 `open.feishu.cn` / `open.larksuite.com`，钉钉 `oapi.dingtalk.com`）；Telegram 接口地址必须 https；Chat ID 只许数字和开头的 `-` 或 `@用户名`；邮箱格式；端口 1..65535；Notion 数据库 ID 允许带横线的 32 位十六进制或从链接里提取；文件夹不许 `..`、不许以 `/` 开头。
- 测试按钮（`test(id)`）对每种都能用；格式（Text / Markdown / Json）对不支持 Json 的通道按 Markdown 处理。
- **安卓正则注意**：`}` 和 `]` 一律转义（见 AGENTS.md 末尾），否则电脑单测能过、手机上崩。

## 一·补、每日记忆文档（新推送内容 `PushTopic.DailyMemory`）

负责人要求：除了备份，每天把当天的记忆推到指定位置，让自己的 Agent 再加工、沉淀。约定已改好：`PushTopic.DailyMemory`、`PushChannel.memoryWithLines`、`save(..., memoryWithLines)`、`topics(kind)`（`AndroidPushChannels` 里已有占位实现：Webhook / Email / Notion / Telegram / MarkdownFolder 支持，其余不支持；`memoryWithLines` 目前没存，请补上持久化与读回）。

1. **什么时候推**：每日回顾按时生成成功后（`RoomReviewRepository` 定时那条路径，手动“生成回顾”不推），对订阅了 DailyMemory 的通道推当天文档；回顾失败或当天没内容就不推。窗口与回顾一致（回顾的那一天）。
2. **内容**：
   - Markdown：用 `DiaryRepository.markdown(date, date, includeLines = 通道的 memoryWithLines)`。**同时扩展 `LocalDiaryRepository`**：在回顾之后加“卡片”一节，列当天技能卡（技能名 · 时间 · 标题 · 摘要 + 各字段按类型渲染成 Markdown：要点/清单用列表，原话用引用块）。导出功能也一起受益。
   - 结构化 JSON（给 Webhook）：`{"type":"daily_memory","version":1,"app":"回响","date":"YYYY-MM-DD","generatedAt":…, "markdown":"…", "data":{"review":{brief, sections[]}, "events":[{id,start,end,title,summary,scene,people[],important}], "items":[{id,category,kind,content,due,who,status}], "cards":[{skill,title,summary,at,values{}}], "lines":[{id,at,speaker,text}]（仅 memoryWithLines）}}`。写成一个内部函数，单测覆盖字段齐全。
3. **各通道怎么收**：
   - 自定义接口：POST 上面的 JSON。
   - Obsidian / 笔记文件夹：**整份覆盖**写 `文件夹/YYYY-MM-DD.md`（重推同一天会更新）；其它推送内容仍按上表追加到 `文件夹/推送记录/YYYY-MM-DD.md`，两者分开。
   - 邮件：正文放回顾简洁版 + 一句“完整记忆见附件”，Markdown 作为 `回响-YYYY-MM-DD.md` 附件（multipart/mixed）。
   - Telegram：`sendDocument` 发 .md 文件，caption 放回顾简洁版（≤1000 字）。
   - Notion：每天一页，标题“回响 · YYYY-MM-DD”；Markdown 转成标题 / 列表 / 引用 / 段落块，超过 90 块用 `PATCH /v1/blocks/{page}/children` 分批追加；同一天重推时先查有没有同标题页面，有就归档旧页再建新页。
4. **测试按钮**：订阅了 DailyMemory 的通道，`test(id)` 推“最近一天有内容的”记忆文档（和 030 推最近日报同理）。
5. 推送记录（logs）标题写“每日记忆文档 · 日期”，失败走现有重试。

## 一·补二、自定义接口（Webhook）加强

负责人要能推到自己搭的接收接口（自己的 Agent、n8n、Dify 等）。在现有 Webhook 上加强（枚举标题已改为“自定义接口（Webhook）”）：

- 字段：接口地址、Authorization（secret，可选）、**附加请求头**（可选，一行一个 `名字: 值`，最多 5 个，值算 secret 存安全区；禁止 Host、Content-Length 等）、**签名密钥**（secret，可选：有就加 `X-Resound-Timestamp` 和 `X-Resound-Signature: sha256=HMAC(timestamp + "." + body)`，接收方可验真）。
- **地址**：默认要求 https；但**局域网 / 本机组网地址允许 http**（10.x、192.168.x、172.16–31.x、100.64.0.0/10 即 Tailscale、`.local`、`.ts.net`），因为用户的 Agent 常跑在家里电脑上。其他 http 地址拒绝并提示原因。
- 所有推送内容都用统一 JSON：`{"type":"daily_review|todo_reminder|new_event|skill_card|daily_memory|test","version":1,…}`，在交付说明里写一份给接收方看的“接口说明”（各 type 的字段、签名校验示例代码 10 行以内）。
- 接收方返回任意 2xx 即成功。

## 二、必测（上限参考，总数 10～15 个）

1. 飞书、钉钉签名计算与一组已知值对得上（各 1）。
2. Telegram 请求：HTML 转义、超长截断、自定义接口地址。
3. 邮件：主题 RFC 2047 编码、Markdown 转 HTML 的基本结果；用本地假 SMTP 服务器（测试里起一个 ServerSocket）走一遍 AUTH + DATA。
4. Notion：请求体结构（标题属性、分块）。
5. 笔记文件夹：已有文件时追加、404 时新建、目录逐级 MKCOL（用 MockWebServer 或现有测试里的假服务器）。
6. 各通道 validate 拒绝明显错误的输入；自定义接口：局域网 http 允许、公网 http 拒绝、附加请求头格式。
7. 每日记忆文档：JSON 字段齐全（带/不带原话）；日记 Markdown 含“卡片”一节；回顾定时成功后只推订阅了的通道。
8. 自定义接口签名可被独立算法复核。
