# 卡 034 · 增量备份（云端和本机共用）

**为什么**：现在每晚都传一份完整备份（全部历史）。一份现在约 1MB，按负责人的使用量一年后可能 200～350MB；坚果云免费版每月上传约 1GB，几个月后每晚全量会超额度，本机也越占越大。负责人已同意改为增量。

**分支 / 工作树**：`codex/034-incremental`，`~/Developer/resound-codex-034`。
**约定**：`backup/BackupContract.kt` 的 `RemoteBackup` 已加 `full`、`baseName`；`keep` 的含义改为“保留最近几个恢复点”。签名不要改。界面 Claude 做。

## 一、已定方案：按页比对的“相对本周完整备份”增量

1. **一套 = 1 份完整 + 若干份增量**。每份增量都相对这一套的完整备份计算（**累计差异，不是一天接一天的链**），所以恢复任何一天只需要“完整 + 那一天的增量”两个文件，中间某天丢了不影响。
2. **什么时候出完整备份**：没有可用的本套完整备份、本套完整备份已满 7 天、算出来的增量超过完整备份的 50%、数据库结构版本变了（迁移过）、或本机留的“基准快照”丢失/校验不过 —— 任一成立就出新的完整备份，开始新的一套。其余情况出增量。
3. **数据库差异怎么算**：
   - 现在备份时已经用 `VACUUM INTO`（或现有的快照方式）得到一份干净的数据库文件。出完整备份时，把这份数据库文件另存一份到 App 私有目录作为**基准快照**（`files/backup-base/<完整备份文件名>.db`，只留当前一套的，开新套时删旧的；本机和云端可以共用同一个基准，前提是它们的完整备份是同一次生成的——不是的话各留各的，按完整备份文件名区分）。
   - 出增量时：今天的快照和基准快照**按 SQLite 页大小（读文件头第 16–17 字节）逐页比较**，只收变化的页 + 今天的总页数。增量文件里写：`baseName`、基准的 SHA-256、页大小、今天的总页数、变化页的页号列表和内容、**还原后整个数据库应有的 SHA-256**。
   - 为了让页对得齐：两次快照都用同一种方式生成（同样的 VACUUM INTO / page_size / auto_vacuum 设置）。先用本机真实数据实测一次“隔一天的两次快照有多少页不同”，写进交付说明；如果因为 VACUUM 重排导致差异过大（比如 > 50%），改用不 VACUUM 的在线备份 API（`sqlite3_backup` / Android 的 `SQLiteDatabase` 复制）生成快照再比较，选差异小的那种。
4. **数据库以外的文件**（声纹特征目录、设置文件白名单、技能文件、提示词等）：完整备份里全量；增量里只放**和基准相比内容变了或新增的文件**，以及“被删掉的文件”清单（按完整备份里的清单 + 每个文件的 SHA-256 对比）。
5. **恢复**：选中一个增量 → 自动连同它的 `baseName` 一起下载/读取 → 校验基准 SHA → 套用变化页（数据库长度按今天的总页数截断/扩展）→ 校验还原后 SHA → 套用文件变化 → 之后走**现有完全相同的恢复流程**（迁移、快照、替换、密钥清空、重启）。完整备份的恢复不变。旧格式的备份（`resound-…zip`、`回响-…zip`）一律当完整备份，照常可恢复。
6. **命名**（全英文）：完整 `resound-full-yyyy-MM-dd-HHmm-ssSSS-xxxxxxxx.zip(.enc)`；增量 `resound-inc-yyyy-MM-dd-HHmm-ssSSS-xxxxxxxx.zip(.enc)`，增量里的头信息写 `baseName`（列表时为了填 `RemoteBackup.baseName` 需要读到它：要么把基准的时间戳和随机串编进增量文件名 `resound-inc-<自己的时间>-<随机>__<基准时间>-<基准随机>.zip`，要么列表时额外读一个小的 `.json` 旁注文件——选文件名方案，避免多一次请求）。加密照旧，按文件整体加密。
7. **保留**：`keep` = 保留最近几个**恢复点**（每份完整或增量都算一个恢复点）。清理时先确定要保留的最新 N 个恢复点，再把它们依赖的完整备份也加进保留集合，其余删除。云端只清理 `Resound-Backup/`，本机只清理匹配命名规则的文件。旧中文目录不动。
8. **云端和本机**都用这套逻辑（共用生成与恢复函数，不要写两份）。两边各自判断“本套完整备份在不在自己那边”。
9. **状态**：`BackupState.lastBackupBytes` / `LocalBackupState.lastBytes` 照旧写本次上传/写入的文件大小（增量就是增量的大小），`remoteCount`/`count` 写恢复点个数。

## 二、必测（新增 8～14 个，跑 `app.resound.backup.*` 全部通过）

1. 页差异：只改几行数据 → 增量只含少量页；还原后 SHA 与当天快照一致。
2. 数据库变短（删了数据、页数减少）和变长两种都能正确还原。
3. 增量超过一半 / 满 7 天 / 结构版本变化 / 基准丢失 → 出完整备份。
4. 文件变化：新增、修改、删除的声纹特征文件都能还原。
5. 恢复增量会自动带上它的完整备份；基准 SHA 不符时拒绝并提示“这份增量对应的完整备份已损坏或丢失”。
6. 保留：最新 N 个恢复点 + 它们依赖的完整备份被留下，其余删掉；旧格式文件当完整处理。
7. 加密的增量 + 加密的完整都能恢复。
8. 本机和云端走同一套逻辑各测一条主流程。
