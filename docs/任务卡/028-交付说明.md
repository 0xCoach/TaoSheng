# 028 交付说明：导入录音与热词

## 完成内容

- 已装配 `AppGraph.importer`、`AppGraph.hotwords`，未修改约定文件签名、数据库结构或 `ui/`。`MainActivity` 仅新增 3 行导入和 1 行分享接收调用，复用已有 `onNewIntent`。
- 分享入口支持 `ACTION_SEND`、`ACTION_SEND_MULTIPLE`、`ACTION_VIEW` 的 `audio/*`，读取 stream/data/ClipData 中的 content URI。分享后立即以 64 KiB 缓冲复制到 `cacheDir/import/<UUID>`，再取显示名、音轨时长和录制日期。建议开始时间按“录制日期 → 来源修改时间减时长 → 未知”处理。坏文件删除缓存并返回中文原因，Activity 用 Toast 展示。
- 待确认信息与确认后的队列持久化在 `imports` SharedPreferences。按确认顺序串行处理；WorkManager 追加唤醒任务避免结束瞬间漏掉新文件。通知显示“正在导入 xxx”，取消只作用于该文件，后面的文件继续。进度包含解码百分比、已保存段数及后续排队数。
- `MediaExtractor` / `MediaCodec` 流式解码；跨缓冲保留重采样相位，多声道平均并线性插值为 16 kHz 单声道。复用 Silero VAD、`SpeechSegmenter`、`SegmentEncoder`，保留相同静音门限、5 分钟硬切和 1 秒重叠；补齐文件尾部不足一帧的实际样本。
- 片段时间为确认时间加文件内样本偏移，`sourceId=import`、`Pending`、`playbackMillis=0`。使用导入 ID 和段号作为稳定路径，进程中断重放不会重复入库或重新生成已经转写删除的音频；不同导入及时间重叠仍分别入库。
- 导入结束立即删原文件缓存并触发 `runNow`；已有转写正在运行时追加后续任务，覆盖其快照之后新增的片段。失败或取消前已经入库的片段照常转写，当前未完成片段丢弃。
- 导入片段转写成功后先完成声纹特征缓存和正常识别/补样本，再立即删除音频；无文字立即删除。尚未录入声纹时也会提取特征，后续可从原话补样本，缓存中只存特征值。声纹失败留待重试，仍受三天上限约束。
- 失败音频按本次片段文件生成时间计算三天，避免导入旧录音时被误当成过期。应用启动、每小时独立清理任务、转写开始前及声纹结束后执行清理；过期失败段停止自动重试并提示重新分享。清理无网络/密钥条件，且与上传、声纹读取互斥。
- 手动热词写入 `transcribe.hotwords` JSON 数组，去空白、去重，最多 200 个，每词 1–20 字；人物名随 Room 数据流更新，排除“我”。仓库未发现独立称呼字段，自动词目前只用人物名。合并时手动词优先。
- 自定义 OpenAI 兼容转写在 multipart `prompt` 中加入“可能出现的词：…”，含前缀总长不超过 200 字；本地 SenseVoice 不传热词。
- 整理时在 `digest.md` 对应请求的输入正文前加入“常见人名与专有名词：…”和仅纠正这些词同音错字的限制；原始转写文本不被本地改写。
- `transcribe.xml` 加入备份白名单，但实际只导出热词，不导出加密密钥。恢复时仅合并热词，保留本机现有转写配置及凭证。

## 豆包字段与官方依据

沿用现有流式 2.0 `wss://openspeech.bytedance.com/api/v3/sauc/bigmodel_nostream` 端点，没有切换模型或鉴权方式。使用 `request.corpus.context`，值为序列化 JSON **字符串**，其中包含 `hotwords: [{"word":"词语"}]`。该 nostream 方式支持 5000 词，本实现按手动词在前的顺序截取前 5000 词；没有把双向实时流的 100 tokens 限制误用到当前端点。

官方资料（2026-10-24 核对）：

- [流式语音识别 API：corpus/context 与 nostream 限制](https://docs.volcengine.com/docs/DoubaoVoice/LargemodelstreamingautomaticspeechrecognitionAPI?lang=zh)
- [热词与上下文：直传格式和不同模式容量](https://docs.volcengine.com/docs/DoubaoVoice/hot-words-and-context?lang=zh)

## 限制与遗留

- Android 原生解码、Silero 推理、前台通知及真实 WorkManager 生命周期留待真机验证。单元测试的 receive 使用注入的元数据读取器和内存内容流；不把这部分当成系统解码已经实测。
- 系统可能回收 `cacheDir` 中尚未确认或排队的原文件；此时保留确认信息，开始后给出“临时录音已被系统清理，请重新分享”。
- 三天是逻辑保留上限；系统关机、强行停止应用或延迟 WorkManager 时，只能在下次获准执行时落实删除。转写开始前会先清理过期导入音频。
- 取消或中途失败保留已入库片段的转写结果；不回滚已经完成的片段。手动再次分享产生新的导入，不做内容去重。
- 本地 SenseVoice 不支持热词。本次没有新增称呼设置字段，也没有实现界面。
