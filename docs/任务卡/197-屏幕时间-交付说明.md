# 屏幕时间采集、读取与问问

本 PR 基于上游 `cde55c0d2dd10e4e613b2b7b6791882c7fc4ab32`（含播放记录与外放归属 #47、打点 #44、蓝牙麦让路、远程通知与自定义转写逐句时间 #48）。不改数据库 schema，版本仍是 38。

在「设备播放记录 + 外放归属」之上接回屏幕时间的非界面、非推送部分：UsageStats 增量采集、日报渲染、整理提示词里的「在用 App」，以及问问工具 `apps_during`。播放检测、外放标注和「记录播放标题」开关维持上一份交付，本卡不改它们的写入或读取门控。

## 功能

- **屏幕时间采集**（默认关）：独立于「记录播放标题」。打开后按使用情况访问权限增量拉取 UsageStats 事件，每小时补拉一次；关闭期间不补采，只记缺口。拉取进度（上次成功时刻）不进设置备份。
- **读取与日报**：`ScreenTimeQueries` 实现 `ScreenTimeReader`，查询前先增量拉取；需要播放段时调用 `PlaybackQueries`，不复制查询。`ScreenTimeReports.build` 把使用段、设备播放记录和缺口渲成日报正文/Markdown。
- **「在用 App」情境行**：只有屏幕时间采集开 **且** 「整理时带上 App 与播放信息」开时才查前台使用段；否则不查库、提示词没有「在用」行。它不受「整理时参考地点和环境音」影响。外放标注仍是上一份的三档（有标题 / 有 App / 「手机在外放」），不用前台 App 兜底。
- **问问 `apps_during`**：隐私开关关闭或屏幕时间采集关闭时，查库前直接返回说明，不读事件表。结果里的播放段只有「记录播放标题」开且隐私开关开时才出现。工具定义与返回 JSON 按实际序列化文本验收。

## 隐私与停采的边界

屏幕时间的使用段由事件重放得到。删除、停采、拉取失败都不能只删原始行或只留一句提示，必须让**输出的使用段**也不再覆盖这些时间。

- **锁屏**：系统如果只记下「锁屏显示」却没有「锁屏解除」，不能一直把后面整天判成锁着。锁屏界面本身不产生 Activity `RESUMED`；一旦出现 `RESUMED`，就视为已解锁并开始这一段。
- **删除区间**：删除入口在去掉事件、播放行和旧缺口之后，写入一条不含 App 信息的 `privacy_deleted` 缺口（同一次删除不会把这条新缺口自己删掉）。查询重放时挖掉与这条缺口重叠的使用。停采（`disabled`）和不可补回（`pull_failed`）缺口同样切断重放。
- **在途拉取**：提交入库时以**提交时刻**的隐私下限过滤事件、名称和缺口。还没有 `screen_pull_state` 行时，删除也会插入下限，避免第一次拉取把刚删的事件写回来。
- **关闭期间**：每次关→开都会把这一段停采窗口记下来，不只留最后一对时刻。重新开启时系统查询只读允许采集的子区间，关闭期间的活动既不入库也不被读取。
- **全部删除**：下限停在删除操作的实际时刻，不是 `Long.MAX_VALUE`；之后新事件可以正常采到。全部删除清空 `screen_app_names`；其它删除入口清掉已经没有事件引用的名称行，与事件删除同事务。
- **记录播放标题关闭**：`ScreenTimeQueries` 在具体实现里看当前标题许可，关闭时不查播放表。不改 `ScreenTimeReader` 签名。问问、今日卡片、每日推送都走这条读取路径，因此也不会再把旧节目名读出来发出去。
- **开关原子保存**：一次开/关写入的开关、开闭时刻和停采窗口必须在同一次持久化提交里落盘，提交成功后才改内存状态。中途失败或进程在两次提交之间被结束，重启后不得以「已开」加旧时刻去补采关闭期间。
- **无录音事件删除**：首页「这段别记」对没有关联录音的事件，屏幕数据清理与打点用同一组明确区间；有多段录音时仍只清各段，不把段与段之间一并删掉。
- **停采缺口去重**：同一段已闭合的停采窗口在缺口表里最多一行，成功拉取重复执行不得再插一遍。
- **交错删除裁缺口**：删除只去掉缺口与删除区间重叠的那部分（区间外可裁短或拆开保留）。两次交错删除后，前一次留下、没被第二次覆盖的时段仍受保护，不能被更早的前台事件重放成使用。

## 隐私开关管辖范围

「整理时带上 App 与播放信息」（`DigestPreferenceStore.includeAppPlayback`，默认开）是对外发送 App 名或节目名的唯一闸，出口收在 `AppPlaybackPrompt`：

| 出口 | 还要同时开 | 关闭时 |
|---|---|---|
| 整理/重整提示词「在用」 | 屏幕时间采集 | 不查前台使用段，没有「在用」行 |
| 整理/重整提示词播放标题 | 记录播放标题 | 不查播放记录，外放只标「手机在外放」 |
| 问问 `apps_during` | 屏幕时间采集 | 查库前返回「用户关闭了整理时带上 App 与播放信息」或「屏幕时间未开启」 |

本机日报、数据库和备份里的屏幕事件不受此闸影响。采集开关和开/关时刻进设置备份；`screenTimeLastPullAt` 不进备份。

## 真机注意事项

- 打开屏幕时间采集后，系统设置里还要给涛声「使用情况访问」权限，否则历史能读、新事件拉不进来，查询会带 `usage_access_missing` 缺口。
- 「记录播放标题」仍要通知使用权；与屏幕采集互不影响。
- 小米 14 实测：系统可能只记「锁屏显示」不记「锁屏解除」，规则已按「出现前台恢复即视为解锁」处理（见上节）。
- Linux 开发机没有 Xcode，iOS 编译检查未跑。

## 每日推送

在任意推送通道的订阅里打开「推每日屏幕时间」后，每天到设定时刻（默认 22 点，可选 12/18/20/21/22/23 点整点）把当天屏幕时间日报推到该通道；日报内容直接用采集侧的渲染入口（`ScreenTimeReports.build`），不在推送侧另写一份格式化。

- 手动推送：通道详情里的「现在推一次」也会附带推今天的屏幕时间（返回“已推今日屏幕时间”；当天没有数据时回“今天没有屏幕时间”）。
- 每个通道每天只推一次；推送成功后记当天的“已推”标记，到点不重复发。
- 采集关闭（或读取入口未装配）时定时推送不发空日报：跳过、不写已发标记、下一次排到明天，并在诊断（`FailureNotes`）里记一条跳过原因；手动推送会直接回“今天没有屏幕时间”，不用查诊断。
- 每日记忆文档（订阅了整理结果的通道）：当天文档附「## 屏幕时间」章节（以 `<!-- resound:screen-time -->` 开始、`<!-- /resound:screen-time -->` 结束）；取消订阅或当天无数据时下次同步会自动移除该章节。
- 文件夹或 Notion 通道同时打开屏幕时间和提醒时：更新屏幕时间节只替换这一节，后面的提醒正文保留；只有实际发出的文档里含有该条提醒，才记「已发送」。
- 到点生成屏幕时间如果抛异常，推送任务返回重试，不会当成当天没数据排到明天；用户关闭或当天没有数据时仍跳过，并在问题记录里留下跳过原因。
- 今日页的屏幕时间卡片在小时拉取写入或「这段别记」删除完成后会重新加载，不必离开页面。
- 发出前重核：待发队列里的屏幕时间内容在真正发出前，按原日期和**当前**开关、数据库重新生成；屏幕时间已关闭或读取入口未就绪时生成不出，就丢掉该待发项，并记一条不含 App 名和节目名的问题记录（`push/screen-time-stale-dropped`）；数据被删除后重新生成的是不含 App 名和节目名的零时长日报，附删除缺口说明。文档同步时，每一份将发出且含屏幕时间节的文档都按该文档日期重新生成这一节（那天 0 点到次日 0 点，今天截到现在），生成不出就去掉这一节。
- 自定义接口（Webhook）选 JSON 格式时，另附结构化载荷（`type: "screen_time"`）：当天日期、覆盖截止时刻、总时长、App 时长榜、逐段使用时间线、设备播放记录与覆盖缺口，时间均为带时区偏移的 ISO 字符串；Markdown/纯文本格式只发正文。
- 订阅数据向后兼容：旧订阅文件里没有屏幕时间字段时读成「未订阅」、时刻回落默认 22 点，升级后旧数据不需要迁移。
- 推送是用户主动订阅、发到自己通道的功能，不受「整理时带上 App 与播放信息」开关管辖；日报里的设备播放部分沿用读取接口的门控（通知使用权关时只多一条缺口提示）。

自动化验证：Webhook JSON 载荷逐字节比对样例、重试快照往返保留 screenTime、采集关/入口空时跳过且不发请求不记已发（并断言诊断可见）、无授权仍发 usage_access_missing 缺口、0 点推送不查询、每日文档章节增删、旧格式订阅字节读回默认未订阅（`ScreenTimePushTest`）。真机需要验收：到点推送与「现在推一次」的实际到达、小米后台杀进程后 WorkManager 补推、采集开关切换后订阅页禁用状态。

## 界面

设置首页「记录」分组里，紧挨「足迹」有「屏幕时间」入口，始终显示，不按就绪状态隐藏。

屏幕时间页只放采集开关和使用情况访问权引导。「记录播放标题」仍在「原话与转写」页，不搬过来。页面底部有「整理时带上 App 与播放信息」：屏幕时间采集开或「记录播放标题」开时才显示，两个都关时不显示。它管整理和重新整理时的 App 名、节目名，以及问问里查 App 使用情况；关掉后这些都不发给大模型，仍会标「手机在外放」。全应用只有这一处开关。

「原话与转写」页在「记录播放标题」下方有一行提示：整理时是否带上节目名，在 设置 → 屏幕时间 页底部调整。

「附带情境」（整理时参考地点和环境音）只管地点和环境；App 与播放信息由屏幕时间页底部的开关管。

今日页在屏幕时间采集开启时显示屏幕时间卡片，点开看当天各 App 用时、时间线和设备播放记录。没有使用情况访问权时卡片上有「去设置」，跳到屏幕时间页。
