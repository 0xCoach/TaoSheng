# 卡 149：建 `:shared` 共用模块 + 门禁 + 搬入现成纯净文件

## 背景

负责人 11-12 定：0.3.0 借大版本为 iOS 做准备，分 6 张卡（本卡是第 1 张）。路线依据 `docs/任务卡/137-交付说明.md`：KMP 共用业务规则，安卓界面 Compose，iOS 界面 SwiftUI。数据库、录音服务、本地模型本轮**不动**。

已有先例：卡 139 的 `:devices` 模块（`devices/build.gradle.kts`：androidTarget + jvm，强制开 `compileCommonMainKotlinMetadata` 当门禁；`tools/check_devices.py` 做静态边界检查）。本卡照这个做法建 `:shared`，存放设备以外的全部共用规则。

**总原则：行为完全不变。** 本卡只是“搬家 + 建门禁”，不改任何逻辑、文案、签名。

## 要做的

### 1. 新模块 `:shared`
- `settings.gradle.kts` 加 `include(":shared")`；`shared/build.gradle.kts` 照 `devices` 写：KMP + serialization 插件 + com.android.library，namespace `app.resound.shared`，androidTarget + jvm（单测用），minSdk 29，JVM 17，`jvmToolchain(21)`。
- commonMain 依赖只允许：kotlin-stdlib、kotlinx-coroutines-core（api，1.9.0）、kotlinx-serialization-json（1.9.0，本卡先加上但不必使用）、kotlinx-datetime（选与现有 Kotlin/AGP 兼容的稳定版，本卡先加上，供卡 150 用）。
- 同样强制开启 `compileCommonMainKotlinMetadata`，并让 `compileKotlinJvm`、`compileDebugKotlinAndroid`、`compileReleaseKotlinAndroid`、`check` 依赖它。
- **iOS 目标预留**：加 `iosArm64()`、`iosSimulatorArm64()`，但只在 Gradle 属性 `taosheng.ios=true` 时启用（默认关；负责人正在装 Xcode，装好后由 Claude 打开）。关闭时构建不能因此变慢或报错。
- `:app` 依赖 `:shared`（`implementation(project(":shared"))`）。

### 2. 搬文件（**包名不变**，只换模块，`:app` 里的引用不用改）
放到 `shared/src/commonMain/kotlin/<原包路径>/`。候选：
- 卡 137 列的 A 类 32 个文件（见 137 交付说明“一、A 类候选清单”）。
- 卡 147/148 新写的纯规则：`home/HomeRules.kt`、`topic/TopicTimeline.kt`、`quick/QuickContract.kt`、`quick/QuickRules.kt`、`health/HealthContract.kt`、`health/*Rules.kt`（及 `HealthInputs` 等纯数据）、`settingsearch/*`（除安卓装配）、`capture/CaptureNotificationPolicy.kt`、`capture/CaptureTilePolicy.kt`、`topic/TopicQuickPolicy.kt`。
- 规则：一个文件只有在它**传递依赖的类型也都能搬**时才搬。被卡住时：
  - 若卡住它的是混在大文件里的小枚举 / 纯数据类（如 `TopicKind` 在 `TopicContract.kt` 里、`CaptureState` 在 `CaptureContract.kt` 里），可以把这个类型**原样**挪到同包的新文件（如 `topic/TopicKind.kt`）并搬进 `:shared`——包名、类名、成员一字不改，不算改约定签名；交付说明列出拆了哪些。
  - 其他情况不搬，在交付说明“没搬的文件”表里写清被什么卡住、建议哪张卡处理（150 插口 / 151 网络 / 152 整理 / 153 问问 / 154 其余）。
- 不得为了能搬而改逻辑（例如把 `java.time` 换成别的）——那是卡 150 的事。
- `ui/settings/SettingsIcons.kt` 是界面文件，**不搬**。

### 3. 门禁脚本 `tools/check_shared.py`
照 `tools/check_devices.py` 写（Python 标准库，无第三方依赖），检查 `shared/src/commonMain/`：
- 禁止 import 或正文全限定名出现：`android.`、`androidx.`、`java.`、`javax.`、`org.json`、`okhttp3`、`kotlin.jvm.`（`@JvmStatic` 等注解除外，若用到请说明）、`System.currentTimeMillis`、`synchronized`、`Thread`。
- 检查 `shared/build.gradle.kts` 的 commonMain 依赖只在白名单内。
- 输出中文、违规时退出码非 0；README 式说明写在脚本开头注释里。
- 在 `AGENTS.md`“为以后 iOS 复用”一节末尾加两行：新规则文件放 `:shared`；提交前跑 `python3 tools/check_shared.py` 和 `./gradlew :shared:check`。

### 4. 进度统计 `tools/ios_progress.py`
统计并打印（中文）：`shared` + `devices` 的 commonMain 行数、`app/src/main` 行数、共用占比；按一级包列出共用行数。不计注释空行与否请在输出里写明口径。本卡完成后跑一次，结果写进交付说明。

### 5. 测试
- 搬过去的文件，若 `:app` 里有对应的纯单测（不依赖 Robolectric / Android），一并搬到 `shared/src/jvmTest/`，包名不变；依赖安卓的测试留在 `:app`。
- 只跑：`./gradlew :shared:check :shared:jvmTest`、`python3 tools/check_shared.py`、`python3 tools/check_devices.py`、`./gradlew :app:compileDebugKotlin`、以及 `:app` 里引用了被搬类型的那些单测（列出来跑一次即可）。不跑全量。

## 不做
- 不改任何逻辑、文案、类名、方法签名；不改 `ui/`（`ui/` 里的 import 不用动，因为包名不变）。
- 不改数据库、不升数据库版本、不改依赖版本（新加的 datetime / serialization 除外）。
- 不碰 `:devices` 模块内容（它已是共用模块）。
