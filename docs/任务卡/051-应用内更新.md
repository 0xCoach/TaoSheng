# 卡 051 · 应用内更新（后端）

App 名叫“涛声”（包名仍是 `app.resound`）。所有给用户看的文字都写“涛声”，不要写“回响”“resound”。
约定文件：`app/src/main/java/app/resound/update/UpdateContract.kt`（签名不要改；确需改，在交付说明里提）。
界面（设置 → 关于 → 版本更新页、通知点开跳转、MainActivity 收 `EXTRA_OPEN_UPDATE`）由 Claude 做，**本卡不改 `ui/` 和 `MainActivity.kt`**。

## 一、已定方案（负责人已确认，不要改）

- 只更新正式版，没有测试版通道。
- 先查魔搭，魔搭不通再查 GitHub。
- 有新版：发通知，**用户点了才下载**；下载不限 Wi-Fi，用流量也照样下。
- 下载好：**用户点了才安装**；安装前先备份；安装交给系统（系统会弹确认）。
- 增量更新：优先下差异包，在手机上和当前装着的安装包拼成新版；拼不成或校验不过，自动改下整包。
- 检查时机：每 6 小时一次（后台，需联网）+ 进程启动时一次（距上次检查不到 1 小时就跳过）。

## 二、发布到哪（发布脚本由 Claude 做，本卡只负责读取）

版本说明文件名固定 `update.json`，安装包和差异包放在同一处：

- 魔搭（优先）：`https://modelscope.cn/models/OpenRecode/TaoSheng-releases/resolve/master/<文件名>`
- GitHub（兜底）：`update.json` 用 `https://github.com/0xCoach/TaoSheng/releases/latest/download/update.json`；
  安装包和差异包用 `https://github.com/0xCoach/TaoSheng/releases/download/v<versionName>/<文件名>`

两处的 `update.json` 内容一样。地址写成常量，集中放一处。

### update.json 格式

```json
{
  "versionCode": 26,
  "versionName": "0.2.11",
  "notes": "多行中文更新内容",
  "apk": { "file": "TaoSheng-v0.2.11-arm64.apk", "sha256": "…", "size": 95023988 },
  "patches": [
    { "fromSha256": "…（旧版整包的 sha256）", "file": "TaoSheng-0.2.10-to-0.2.11.patch", "sha256": "…（差异包本身）", "size": 6123456 }
  ]
}
```

- `patches` 最多 5 个：最近 5 个正式版各一个，都直接到最新版。
- 只认 `versionCode` 比当前大的；相等或更小算“已是最新”。
- 读不懂、字段缺失、sha256 不是 64 位十六进制：当作这个来源失败，换下一个来源。

## 三、实现要点

1. **查新版本**：先魔搭后 GitHub，各自超时 15 秒。`check(manual = false)` 失败不打扰用户，只记诊断；`manual = true` 失败给 `Failed` 和一句话原因。
2. **选下载方式**：算手机里当前安装包（`applicationInfo.sourceDir`）的 sha256（约 95 MB，放后台线程，同一版本算一次缓存起来），在 `patches` 里找 `fromSha256` 一样的；找到就增量，否则整包。
3. **下载**：存到 `filesDir/update/`（不要用 cache，会被系统清）。支持断点续传（Range）；下载前检查剩余空间：整包要 1.2 倍大小，增量要“差异包 + 整包”的 1.2 倍。下完核对 sha256，不对就删掉，重下一次，还不对报错。魔搭下载失败自动换 GitHub。
4. **拼包**：差异包格式是标准 bsdiff 4（文件头 `BSDIFF40`，bzip2 压缩，Mac 上用 `bsdiff` 命令生成）。手机上**流式**还原：旧包用 `RandomAccessFile` 随机读，新包边算边写文件，**不要把 95 MB 整个读进内存**。可以自己写 bspatch（百来行），bzip2 用 commons-compress 或等价库。拼好核对新包 sha256 = `apk.sha256`，不对删掉、改下整包。
5. **装前核对签名**：用 `getPackageArchiveInfo(..., GET_SIGNING_CERTIFICATES)` 取新包签名证书，和自己当前的比，不一致删掉、报错。包名必须是 `app.resound`，版本号必须比当前大。
6. **安装前备份**（关键，安卓不能退回旧版）：
   - 一定做：把数据库检查点后复制到 `filesDir/pre-update/`（只留最近 1 份），附上 SharedPreferences 文件；
   - 用户设了本机备份文件夹或坚果云的，再各触发一次现有备份（`backupLocalNow()` / `backupNow()`），等完成，最多等 3 分钟；超时或失败不拦安装，只记诊断；
   - 第一项失败：`Failed("更新前备份没成功，没有安装", info)`。
7. **安装**：`PackageInstaller` 会话安装；安卓 12 及以上设 `setRequireUserAction(USER_ACTION_NOT_REQUIRED)`（能免确认就免，免不了系统会弹）。处理 `STATUS_PENDING_USER_ACTION`（拉起系统确认）、成功、失败、用户取消（回到 `Ready`）。清单加 `REQUEST_INSTALL_PACKAGES`；`canInstall()` 用 `packageManager.canRequestPackageInstalls()`。
8. **通知**：新建通知渠道“版本更新”。标题“涛声 0.2.11 可以更新”，正文取更新内容第一行；点开拉起 `MainActivity` 并带 `EXTRA_OPEN_UPDATE = true`。同一版本只通知一次；`later()` 后 24 小时内不再通知这个版本。
9. **装好以后**：现有 `CaptureBootReceiver` 已收 `MY_PACKAGE_REPLACED` 会恢复录音，不要动它的逻辑。另加：语音输入总开关开着、但 10 秒后无障碍服务没连上（`VoiceInputService.connected`），发一条通知“语音输入记录没在运行，点这里重新打开”，点开系统无障碍设置。启动时发现已是新版，清掉 `filesDir/update/` 里的旧文件。
10. **装配**：仿照现有写法在 `AppGraph` 里加 `updater` 和 `isUpdaterReady`。后台定时用 WorkManager 周期任务（6 小时，需联网），仿照 `review/ReviewWork.kt`。
11. **诊断记录**：每次检查/下载/拼包/安装写一行步骤和数字（来源、是否增量、字节数、用时、失败原因），并入“导出诊断记录”，最近 50 行，仿照 `PipelineTimes`。

## 四、给用户看的错误文案（`Failed.message`，只说结果）

- 网络不通：`连不上更新服务器，稍后再试`
- 空间不够：`手机空间不够，还差 X MB`
- 校验不过（重下后仍不对）：`下载的安装包不完整，稍后再试`
- 签名不对：`安装包签名不对，已删除`
- 备份失败：`更新前备份没成功，没有安装`
- 系统安装失败：`系统没能装上：<系统给的原因>`

## 五、必测（适度：一共 8～12 个，不穷举）

1. 解析 update.json：正常一条；缺字段、sha256 不合法判失败。
2. 版本比较：大才算新；相等算最新。
3. 选差异包：fromSha256 命中走增量；没命中走整包。
4. bspatch：用一对小的合成文件（Mac 上用 bsdiff 生成后放进测试资源）还原出完全一样的字节；坏的差异包报错。
5. 断点续传：下到一半断开，再下从断点接着（用本地假服务器）。
6. sha256 不对：删掉重下一次，仍不对报错。
7. 来源顺序：魔搭失败换 GitHub。
8. 状态流转：Available → Downloading → Assembling → Ready → Installing。

只跑本卡相关的测试，跑通一次就停。
