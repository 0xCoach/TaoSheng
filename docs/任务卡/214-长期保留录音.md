## 1. 到期清理的闸门（最重要）

现状：`LocalOriginalAudio.trim()` 到期照删，不看有没有推出去。

规则：
| 情况 | 到期自动清理 | 手动删（原声管理里清空/按范围清） |
|---|---|---|
| 没有任何“推录音”开着的通道 | 照常删（与现在完全一样） | 直接删 |
| 有，这段已推成功（任一推录音通道核对通过） | 照常删 | 直接删 |
| 有，这段**该推但还没推成功** | **不删，留着等推上去** | 能删，但界面要二次确认（见第 9 节预览计数） |

- “该推”的判定 = 该段在**至少一个**开着推录音的通道的推送范围内（`candidates()` 的规则：since/rangeDays、排除媒体、只推人声）。不在任何通道范围内的（如媒体段被排除、只推人声时的非人声段、早于补传起点的）**不扣留**，照常到期删。
- “已推成功” = 任一推录音通道里该段 `audio=true` 且已通过第 3 节核对（老记录没有核对标记的视为已推成功，不回头补核对）。
- 闸门做成 `:shared` 平台无关纯规则（输入：段列表、各通道订阅和已推集合；输出：扣留集合），`trim()` 调用它；`keepStarred`、`pending(s)`、正在播放等现有排除照旧。
- 另外提供：
  - `heldSummary`：被扣留的段数、天数、字节、最早一天；**扣留满 7 天**（最早一段已超过原定删除时间 7 天）标记需提醒。
  - 手机剩余空间 < 1 GB 且有扣留时，发一条系统通知（每天最多一次），文案“有 N 天录音还没推上去，手机空间不足”，点开进推送设置。用现有通知渠道，没有合适的就新建“录音保留”渠道。
  - `releaseHeld()`：用户点“不等了，直接删”后，把当前扣留的、已到期的段按原规则删掉。
  - 关掉某通道的推录音（或删除通道）时，提供预览：关掉后会有多少段失去保护、将按原声保留规则删除（界面二次确认用）。

## 2. 新目的地：手机本地文件夹

- 新增 `PushKind.LocalFolder`（名字“手机里的文件夹”），能力同 MarkdownFolder（records/incremental/folder/audio）。用系统文件夹选择（SAF 树，复用 `LocalBackupFolderContract` 的取持久授权方式）；只存树 URI 和显示名。
- 同一套内容写入（整理记录 Markdown、原话、录音、逐字稿），路径布局与 MarkdownFolder 相同。授权失效 / 文件夹被删 / SD 卡拔出：报“文件夹不可用，请重新选择”，不扣成功。
- 冲突检查：两个 LocalFolder 通道指向同一树 URI 视为冲突。
- 原 `MarkdownFolder` 显示名改为“同步到网盘文件夹（坚果云 / WebDAV / S3）”；存储名不变（按名字存，老通道不受影响）。

## 3. 推完核对

- 网盘（WebDAV / S3）：**不整段下载**（坚果云下载有月额度）。WebDAV 用 PROPFIND（Depth:0）取 `getcontentlength`；S3 用 HEAD 取 Content-Length。与本地文件大小一致才记 `audio=true` 并写 `verified=1`。服务端不返回长度时，记失败重试，不当成功。
- 手机文件夹：写完整读回算 SHA-256，与原文件一致才算成功。
- 写入用临时名（`.<名>.part`）→ 核对 → 改正式名（WebDAV 用 MOVE，S3 直接写正式键后 HEAD 即可，SAF 用 rename）；中断留下的 `.part` 下次覆盖。

## 4. 整天逐字稿

- 订阅新增 `audioText: AudioText { Daily, PerSegment, Both, None }`，**新通道默认 Daily**；老通道没有此字段时按原 `audioWithText`（true→PerSegment，false→None），行为不变。
- 每天一份：`录音/<日期>/<日期> 逐字稿.txt`，UTF-8 **带 BOM**。格式：
  ```
  2026-11-20 逐字稿
  —— 09:31（录音：2026-11-20 09.31 xxx.ogg）——
  [09:31:07] 我：这件事我来跟，下周一前把方案发给大家。
  [09:31:12] 说话人2：好的，周五前给我初稿。
  ```
  对应录音文件名用该段实际推送的文件名（`path()` 记录的那个）；说话人沿用现有原话文本规则（认出的写名字/“我”，没认出写说话人N）。只包含本通道推送范围内、该天的段。
- 当天的逐字稿在**那天过完后**生成推送；之后该天任何一段原话变化（卡 211 手改、重新转写、声纹认人）→ 按内容哈希变化重推（照 `textHash` 的做法，按天记 `dailyHash`）。
- 隐私删除后该天重生成。

## 5. 隐私删除同步

- `RoomPrivacyActions` 的隐私删除（deleteRecent / deleteRange / forgetSegment / deleteSegments）删段时，对每个推录音通道里有记录的段：删远端/文件夹里**该段的 ogg 和同名 txt**（按记录的 path 逐个删，不做目录删除、不做通配），成功后从记录里移除；该天逐字稿标脏重生成。
- 到期自动清理、原声管理里清空**不**删远端（那是“手机上不留了，网盘里留着”）。
- 删远端失败（断网、通道已删、授权失效）：记入“待删清单”持久化，后台重试；通道已不存在的直接留在清单里。提供 `pendingRemoteDeletes: List<PendingRemoteDelete(channelName, path)>` 和“我已手动删除”清除方法。
