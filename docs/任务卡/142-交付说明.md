# 卡 142：录包与回放交付说明

## 完成内容

- `:devices/commonMain/app.resound.devices.replay` 新增 v1 文本解析、`RecordingGattLink`、`ReplayGattLink`、`ReplayHarness` 和按 UTF-8 字节计数的 `LimitedCaptureSink`。无平台依赖、无新增依赖。
- 录制保留 R/W/w/N/M，平台补录 D；蓝牙异常含取消按原对象重抛并记 E，消费者异常不冒充蓝牙故障，sink 失败不影响正常调用。失败写入保留原始请求，错误说明转成十六进制避免多行破坏格式。
- 回放严格匹配交互顺序、写入模式、通道、字节和长度；报错含行号、期望和实际内容。支持按通道屏蔽零基字节位置、读返回、通知多订阅、写入长度变化、断开与错误重放。截断录包不能通过完整性断言。
- 助手跑 open → 实时 start/收集/stop 或文件 list/read → close，收集帧数/采样数/丢失采样、文件清单和下载块、状态快照及错误。失败保留部分下载，外部取消继续抛出；超时与结束均清理定时任务、连接、解码器。不会 confirm/delete 设备文件。
- Android 仅改 `AndroidDevicePlatform.kt`：读取独立 `device-drivers.captureEnabled`（默认关），新连接可选包装；私有目录 `files/device-captures/<驱动>-<时间>.txt`，单文件上限 20 MiB（含尾注），有界队列落盘，超限停止并写说明。支持列出、禁止删除活动文件、删除已关闭录包；文件操作串行，关闭等待落盘任务结束，取消交接也释放已建连接与文件任务。
- 新增 14 行合成录包，使用现有 `synthetic.json`、CardParser、FrameCodec 和测试 Opus 解码器跑通整条实时声音链路；固定字节向量包含一次序号缺口。
- 新增 `docs/taoecho/录包格式.md` 和 `插件提交清单.md`，包含四项必交物、两段录包要求、公开提醒及真机报告模板。

## 接口与卡 141 / 144 配合

没有改任何 `*Contract.kt` 或 `AudioSource.kt` 签名。新增公开类型都在 replay 包：CaptureHeader、WriteMask、ReplayAction、ReplayError、ReplayedFile、ReplayResult、三种录制/回放工具和 LimitedCaptureSink，直接消费现有驱动约定。它们是本卡工具入口，不替换既有协议或业务模型。

- 卡 141 仍负责运行路径接入新平台连接；本卡未动 `AndroidDevices.kt`、`ManagedDevices.kt`、`CaptureService.kt`、AppGraph、界面、MainActivity 或数据库。现有旧路径不会因本卡自动开始录包。
- 卡 144 可设置 `AndroidDevicePlatform.captureEnabled`，重建连接后生效；调用挂起函数 `listCaptures()`、`deleteCapture(name)`。`DeviceCaptureFile` 只传文件名、字节数、修改时间和 active，不传 File 或 Context。展示、导出分享尚未实现。
- 连接创建时通过中枢已保存的选择取得驱动编号；没有选择时不录匿名包。
- GattLink 未提供断开流和 MTU 变化事件，保持约定不变：平台调用 `recordDisconnected()`；M 记录初始值和每次 maxWriteLength 查询观察到的变化，不增加轮询。`mtu` 字段按任务定义保存最大写入长度；`mode=W/w` 可选扩展保留不同模式的长度。

## 真机与遗留

未做 BLE 真机测试或 iOS 编译，不以电脑回放证明真机/iOS 可用。

小米 14 Pro 在卡 141 接线后需验证：默认关闭不产生文件；开启并重连后生成正确驱动编号的头部；实时声音和补传各录一段；两种写入模式、初始长度与通知原字节正确；自然断开/主动关闭产生 D 并关闭文件；到达 20 MiB 后尾注存在且文件不继续增长；列出、活动文件删除拒绝、断开后删除正常；录制期间收音无明显卡顿。

已知边界：默认按交互立即回放，不做真实时间重演；测试需在单一测试调度上下文运行。录制通知是每个 GATT 收集器观察到的数据，同通道宜统一订阅后内部共享，避免重复记录。状态快照遵循 StateFlow 的合并语义。助手只知道丢失采样和缺口次数，无法从现有 AudioChunk 精确计算 BLE 丢包数。样板使用测试 Opus 解码器，不覆盖真实编解码。文件系统不可写时保留可写下的部分，不保证还能追加尾注；真机需检查存储不足场景。

录包内容不做限制，会公开在仓库；没有夹带真实设备录音、身份或密钥。
