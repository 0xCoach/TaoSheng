# 卡 065 · 转写失败：修不好的自动放弃、可忽略、久了自动降级（后端）

App 名叫“涛声”。在 `preview-0.2.13` 分支上开发。约定（负责人已写，签名不要改）：`transcribe/TranscribeContract.kt` 新增 `TranscriptStatus.Abandoned`、`TranscriptStatus.Quiet`，`TranscriptRepository.ignoreFailed()`、`retrySegment(id)`、`deleteFailed(id)`。
界面（提醒旁的“忽略”、列表里灰色显示、删除/重试按钮）由 Claude 做，**本卡不改 `ui/` 和 `MainActivity.kt`**。

## 一、问题（已查明）

录音读不出来（卡 063 映射为 `AsrError.Audio`，`retryable=false`）失败一次后不再自动重试，但段的状态一直是 `Failed`：“原话与转写”页顶上红字“有 1 段没转成功”永远不消失；点“重试没转成功的”再失败一次；卡 062 的原声清理保护所有 Failed 段，坏文件永远占空间。

## 二、已定方案（负责人已确认三条都做）

1. **修不好的自动放弃（Abandoned）**：失败原因是录音文件丢失、损坏、解码失败（`AsrError.Audio` 及“录音文件已不存在”）时，段状态写成新的库内状态（如 `"Abandoned"`），对外映射为 `TranscriptStatus.Abandoned`，error 给人看的原因如“录音损坏，无法转写”/“录音文件已不存在”。**启动时把现存的同类失败段（status=Failed 且 error 属于这类、且不再自动重试）一次性改成 Abandoned**。
2. **忽略（Quiet）**：`ignoreFailed()` 把当前计入提醒的 Failed 段都标为忽略（新增列，如 `failureIgnoredAt`，或库内状态 `"Quiet"`，你选一种并说明），对外为 `TranscriptStatus.Quiet`。忽略的段**不自动重试**，以后可手动重试。
3. **久了自动降级**：还能修的失败（网络、超时、服务器等）从**第一次失败起超过 3 天**仍没成功的，对外也显示为 `Quiet`、不计入提醒、不再自动重试（error 写“多次转写失败”）。
4. **提醒计数**：`TranscribeQueueState.failed` 只计“需要处理”的失败：Failed、未忽略、未超 3 天、非 Abandoned。`retryFailed()`（“重试没转成功的”）也只针对这些。
5. **`retrySegment(id)`**：把这一段放回队列（清掉忽略标记、attempts 归零），立即跑一轮。
6. **`deleteFailed(id)`**：只对 Failed/Quiet/Abandoned 有效：删录音文件、删段记录（及其衍生数据，若有）。
7. **原声清理**（卡 062）：Abandoned 和 Quiet 的段**按原声保留天数正常清理文件**（从判定时起算）；只保护“还在等待自动重试”的 Failed 段。文件被清掉后，Quiet 段手动重试会失败并转成 Abandoned。
8. 首页录音卡等其他地方如果也用 failed 计数，同步按新口径。

如需数据库升级：20 → 21，按 `CaptureDatabase.MIGRATIONS` 规矩只加一条，迁移测试按 `AGENTS.md`。

## 三、必测（适度，6～8 个）

- Audio 失败 → Abandoned，不计入 failed；启动时迁移旧的同类失败段。
- ignoreFailed 后 failed=0，段为 Quiet；retrySegment 后回到队列。
- 失败超过 3 天 → Quiet、不计入、不自动重试。
- 清理：Abandoned/Quiet 到期删文件；等待重试的 Failed 不删。
- deleteFailed 只删允许的状态。

测试规矩见 `AGENTS.md`：只跑本卡测试，跑通一次就停。编译需 `JAVA_HOME=/opt/homebrew/opt/openjdk@21`。
