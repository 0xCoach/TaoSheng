## 搬家方法（后续卡统一用这个模式）

业务规则和数据库操作常混在一个文件里。做法：
1. 在 shared 定义该包需要的**存储接口**（如 `ThingStore`），只用基本类型、共用数据类、`kotlinx.datetime`；规则/引擎只依赖这个接口和 platform 插口。
2. 安卓里原来的 Room 代码改成实现这个接口（类名可保留 `RoomThingRepository` 等），DAO/实体/SQL 不动。
3. 时间一律用 `NowMillis` / `ZoneProvider` 注入；JSON 用 `SharedJson` / `JsonElement`，换掉本包规则里的 org.json（**输出的 JSON 文本必须与原来逐字一致**，包括字段顺序、空值写法，测试要断言）。
4. 本包约定里的 `java.time.LocalDate` 等换成 `kotlinx.datetime`；调用方（含 `ui/`）做机械转换（`toJavaLocalDate()` / `toKotlinLocalDate()`），**ui 只允许这种机械修改**，不改布局文案交互，交付说明列出改了哪些行。
5. 系统相关（Worker、通知、闹钟、响铃、SAF、SMTP/HTTP 发送）留安卓。
