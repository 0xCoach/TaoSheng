# 设备导入与USB恢复后的后台调度修复

基于官方0.3.1及本地aa09567，用户要求尝试解决两项真实观察：锁屏后新导入等待，以及USB恢复后维护任务ready却等到返回App才开始。原有验收记录保留，不将先前失败改写为成功。必要设置界面沿用此前授权，本卡未改界面或Contract签名。

## 调整

- 已确认录音仍进入原持久化audio-import队列，APPEND_OR_REPLACE顺序、去重、取消和完成凭据不变；补充expedited请求及Android 10/11在doWork前所需的前台通知。保留共享队列以维持普通分享和恢复语义，设备同步仍等真实解码入库完成。额度不足明确退回普通任务，不承诺所有ROM准点运行。
- USB reverse恢复不构成手机互联网连通性变化。电脑工具增加一次性`--connect-phone`模式：先以当前目录凭据验证本机127.0.0.1备份服务，再读取当前Android用户、为指定USB调试手机恢复映射，显式调用指定涛声包的备份就绪IPC。只有收到protocol/enabled/queued结构化确认才报告完成；不监视手机、不打开界面、不修改清理设置。
- Provider只接受无参数的backup-ready调用，Manifest与call内部均检查系统DUMP权限，普通第三方App不能调用；已授权ADB shell可使用。拒绝query/insert/update/delete，不提供文件读取。调用不携带身份、文件ID、清理凭据或账号密码，也不能开启已关闭的清理。Provider创建时不读AppGraph，真正调用时在Binder线程上有界等待冷启动装配，然后从手机配置检查是否启用维护。
- 通道恢复使用独立、KEEP去重的加急任务，旧的普通退避任务不会挡住这次恢复机会，也不会被替换或取消。新的机会失败即结束，回到原普通退避队列；下一次真实连接事件仍可创建新机会。清理仍复用同一连接租约、串行锁、完整备份读回、源SHA、停止/电量/身份/保护/意图/结果核对。
- 加急工作不能附带BatteryNotLow调度约束，因此执行前读取系统电池状态，低电量或无法判定时保留普通退避，不进入维护；普通任务继续保留原网络与BatteryNotLow条件。日常24小时周期保留，首次周期延后24小时，开启时的立即机会单独处理，避免首次两个维护同时开始。
- 新日志只含入队/开始/完成/失败类别、尝试次数和是否恢复事件，无录音内容、名字、密码或设备标识。

AndroidX将有退避或已重试的任务按普通任务调度；仅添加加急标记不能保证重试也加急。因此USB恢复提供新的事件机会，并保留原退避兜底。依据：[AndroidX调度转换源码](https://android.googlesource.com/platform/frameworks/support/+/4e1eeecf6c1d06561d4c086e5529f04428bae9e8/work/work-runtime/src/main/java/androidx/work/impl/background/systemjob/SystemJobInfoConverter.java)、[WorkManager请求说明](https://developer.android.com/develop/background-work/background-tasks/persistent/getting-started/define-work)。

## USB使用

先按既有流程启动只监听127.0.0.1的归档备份服务。每次USB重连或恢复通道时，另执行一次：

```text
python tools/device_archive_usb_backup.py --root <原电脑备份目录> --connect-phone --adb <ADB程序路径> --serial <本次USB手机序列号> --package app.resound
```

独立验证版将package改为app.resound.validation。命令不启动电脑服务、不读取账户给终端、不向局域网开放端口。只有映射恢复不等于任何文件已经备份或允许删除。需要本功能构建；官方旧包没有对应Provider时明确失败。自动清理关闭时仅确认映射与接收，仍保持关闭。
