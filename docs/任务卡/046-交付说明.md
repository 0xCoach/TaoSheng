## 提醒实现

- 统一候选规则：仅 Accepted 的未删除独立待办/约定；前晚包含只定日期的条目，同一目标日期合成一条；开始前仅针对有具体时分的条目。
- 按“条目 id + 截止时间 + 时间版本 + 提醒种类”去重。前晚虽然合并发送，仍按每个成员登记，新增或改期不会连带重发已提醒成员。已发送身份保留，切换开关或状态也不会重复同一时间版本。
- 通知类通道开始前逐条发送并逐条确认成功；第二条失败重试时，不重复第一条。
- 复查发现原实现仅有订阅提醒，因此补上无网络约束的本地 WorkManager 调度，复用 `LocalNotifier` 和现有通知权限。手机通知与外部订阅各自去重，不互相阻塞。
- 数据库修改、提醒设置修改、App 启动都会重排。Worker 执行时重新取当前快照；过期的提前提醒不补发，原有到期提醒仍可补发。后续任务从正在运行的 Worker 后追加，避免取消自身；用户编辑时替换旧排程。

边界：

- WorkManager 不是精确闹钟；澎湃 OS 的休眠、后台限制和通知权限可能导致延迟，真实锁屏到点行为尚未实测。
- 同一旧事件同类条目的重新提取采用保守抑制；原话/内容不变的重复提取也会被拦截。没有引入跨全库的语义“同一件事”判重服务。
- 事件和原话按约定保留，历史已生成回顾/卡片/外发消息不追溯重写；后续生成使用过滤后的条目输入。
- 已有自定义 digest 提示词仍按用户保存的版本使用；如未包含新输出规则，需在设置中恢复默认或自行合入上述规则。
- 网络发送成功但客户端未收到确认、或发送后进程在落盘前终止，无法对所有第三方通道保证跨系统严格 exactly-once；正常成功回执、部分失败重试和时间改动已有本地去重覆盖。
