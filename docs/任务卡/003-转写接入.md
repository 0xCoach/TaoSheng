# 任务卡 003：录音片段接入云端转写（豆包流式识别 2.0）

## 目标

把卡 001 录下的人声片段，按设定间隔批量送去豆包转写，文字存进本地库，界面能按天看到每段的状态和原话。
转写成功（含"没有文字"）的录音 **保留 1 天后删除**；没转成功的绝不删。

方案已由卡 002 实测选定，**必须先读** `docs/任务卡/002-实测报告.md`（尤其"App 接入建议"一节）和 `tools/asr-probe/probe.py`（二进制协议的可用实现）。

## 约定（Claude 已写好，不要改签名）

- `transcribe/TranscribeContract.kt`：`TranscriptRepository`、`TranscribeSettings` 及数据类。
- `AppGraph.kt`：已加 `transcripts`、`transcribeSettings`、`isTranscribeReady`。请在 `ResoundApp.onCreate` 里装配。
- 界面由 Claude 做，**不要改 `ui/` 和 `MainActivity.kt`**。

## 要做的

### 1. 数据库（Room 版本 1 → 2，写 Migration，禁止 destructive）

- `segments` 加字段：转写状态、尝试次数、下次可重试时间、给人看的错误、转写完成时间、服务端 logid、送出时长。旧的 `status = "待转写"` 迁移为 Pending。
- 新表 `transcript_lines`：segmentId、绝对起止时间（片段 startAt + 句内偏移）、文字、speakerTag（云端 `speaker_id`，**只是请求内临时标签**）、speakerName（本卡一律 null）。同一片段重转时先删后写，保证幂等。
- 用量账本：按天累计已送出音频秒数（失败但已发出的也计入），供 `usedSecondsToday/Total`。

### 2. 识别客户端

- 内部先定一个服务商接口（例如 `AsrProvider`：输入音频文件与格式，输出句子列表 + 时长 + logid 或错误类型），豆包流式 2.0 是第一个实现。以后要能换服务商和自建地址，所以地址、资源 ID 不要写死在调用处，集中成配置。
- 豆包实现：`wss://openspeech.bytedance.com/api/v3/sauc/bigmodel_nostream`，头 `X-Api-Key` / `X-Api-Resource-Id: volc.seedasr.sauc.duration` / 随机 `X-Api-Connect-Id`；首包配置照 002 报告（`enable_speaker_info`、`show_utterances`、`ssd_version: "200"`、`result_type: "full"`）。
- OGG Opus 原样快速发送；按 OGG 页边界分包更好。片段若是 `.m4a`（编码回退产物），用 MediaExtractor/MediaCodec 解成 16k 单声道 PCM 再发。
- 只有收到服务端最终包才算成功；中途断开、超时都算失败，不能把部分文字当完成。解析要容忍缺字段（002 发现过缺 `start_time`）。
- WebSocket 可加 OkHttp 依赖（选与现有依赖兼容的稳定版）。

### 3. 任务队列

- WorkManager 周期任务，间隔取设置（30 / 45 / 60 分钟，默认 30）；"只在 WiFi" 打开时约束为不计流量网络，默认打开。`runNow()` 走一次性加急任务。
- 同一时间只跑一轮，**逐段顺序上传，不并发**；按开始时间从早到晚。正在录的片段（还没入库的）自然不会被取到。
- 本卡**一段一请求，不做合并**（合并留到以后另验）。
- 失败按类型处理：网络/超时 → 退避重试；鉴权失败/未授权 → 本轮立即停止，`lastError` 写明"密钥无效或未开通"，不要把所有片段都耗掉重试次数；单段最多 5 次后停在 Failed，`retryFailed()` 清零重放回队列。
- 没填密钥时不跑，`lastError` = "还没填写转写密钥"。
- `queue` 的 `nextRunAt` 取 WorkManager 下次计划时间（拿不到就按上次运行 + 间隔估算）。

### 4. 录音保留与清理

- Done / Empty 的片段，在转写完成满 24 小时后删除录音文件（数据库记录和文字保留），`audioAvailable` 按文件是否还在。清理放进每轮任务里顺带做。
- Pending / Running / Failed 的录音一律不删。

### 5. 密钥

- 用 Android Keystore 生成的 AES-GCM 密钥加密后存本地（不要用已弃用的 EncryptedSharedPreferences）；任何日志、异常信息、诊断导出里都不能出现密钥，错误信息要先脱敏。
- `test()`：用 assets 里一段约 3 秒的测试音频（从 `tools/asr-probe/samples/monologue.ogg` 截一句，转成同样格式）发一次，成功返回"可用，识别出：……"，失败返回给人看的原因。

### 6. 诊断

- `exportDiagnostics()` 的导出里补上：转写队列概况、最近 20 次转写的结果/错误类型/耗时（不含文字原文和密钥）。
