# 卡 057 · 自定义接口（Webhook）按所选格式推送（后端）

App 名叫“涛声”。给用户看的文字一律写“涛声”，只说结果、不讲机制。
界面（格式选项下的说明行）由 Claude 做，**本卡不改 `ui/` 和 `MainActivity.kt`**。

## 一、问题（已查明）

用户给自定义接口选了 Markdown，电脑上收到的仍是 JSON：
- `PushTransport.kt` 的 Webhook 分支不管格式一律 `message.envelope(format).toString()` 发 JSON，格式只影响 JSON 里的 `body` 字段；
- 每日记忆（`memory != null`）时 `envelope` 直接返回记忆 JSON，格式完全不起作用；
- `renderedBody` 是 `if (format != Text) body else body`，文本和 Markdown 没区别。

## 二、已定方案（负责人已确认）

自定义接口按所选格式发**不同的请求体**：

| 格式 | Content-Type | 请求体 |
|---|---|---|
| JSON | `application/json; charset=utf-8` | **与现在完全一致**（已有对接不受影响） |
| Markdown | `text/markdown; charset=utf-8` | Markdown 正文：第一行 `# 标题`，空一行，接正文（回顾用 `review.pushBody(Markdown)`；每日记忆用记忆 JSON 里的 `markdown` 全文，它自带标题就不再加） |
| 文本 | `text/plain; charset=utf-8` | 第一行标题，接正文；去掉 Markdown 记号（`#`、`**`、`- [ ]` 等，链接保留文字和地址） |

三种格式都带请求头（方便电脑端按类型分文件存）：
- `X-Resound-Type`：与 JSON 里的 `type` 一致（daily_review / todo_reminder / new_event / skill_card / daily_memory / test）。
- `X-Resound-Date`：这条内容对应的日期 `YYYY-MM-DD`（回顾、记忆用其日期；其他用发送时的本地日期）。
- `X-Resound-Title`：标题，**用 URL 编码（UTF-8）**，因为请求头不能放中文。
- 签名：照旧，`X-Resound-Signature` 对**实际发送的请求体**签名（`$timestamp.$body`）。

其他：
- `renderedBody` 修正：Text 时去 Markdown 记号，Markdown 时原样；对其他通道（飞书、钉钉、Telegram 等）的效果顺带检查，不能让它们变差。
- 测试推送（`topic == null`）也按格式发。
- 已存的通道配置不迁移，格式保持用户选的。在交付说明里写明：新建自定义接口时界面默认的格式是哪种（看 `ui/settings/PushPage.kt`，不改它）。
- 失败重试的快照（`json()` / `from()`）不变。

## 三、必测（适度，4～6 个）

- Webhook + Markdown：Content-Type 和请求体以 `# 标题` 开头；签名对得上请求体。
- Webhook + 每日记忆 + Markdown：请求体就是记忆的 markdown 全文。
- Webhook + JSON：请求体与改动前一致（拿现有逻辑生成的 JSON 比对）。
- Webhook + 文本：没有 `**`、`#`。
- `X-Resound-Title` 中文标题编码正确。
