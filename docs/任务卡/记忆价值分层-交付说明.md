# 记忆价值分层（R4）交付说明

## 做了什么

给 `memory_items` 增加持久化内在价值分 `valueScore`（0-100），用于整理输入排序/保护和问答证据加权。

- **内在分**：提取时按条目自身属性算，落库（`MIGRATION_39_40` 回填）。公式（`MemoryValueRules.itemScore`，shared 纯 Kotlin）：约定45/待办40/备忘25/其他15；我答应别人·别人答应我+15；有 dueAt+15；有 who+10；非 digest 来源+10；封顶100。
- **父事件加成不落库**：星标+20/重点+10 在查询时实时叠加（用户随时改星标，存库会过期）。`ReviewDao.items` ORDER BY 有效分；事件检索加成 `starred*40+important*25`（`RecordSearch.eventQuery`，与 `MemoryValueRules.eventBonus` 同公式，常量内联进 SQL）。
- **写入点全部算分**：DigestRunner、RoomManualTodos、IdeaRepository、AskChanges、ImportKindEngine、TopicGeneration、RedoFactory（redo 两处顺带补了漏掉的 recordedAt）、WorkflowEngine（经 addManualItem）。
- **消费侧**：回顾条目按有效分排序进 prompt；`ReviewPrompt.input` 给每个 item 序列化 `value` 字段；`ReviewInputBudgetRules.fit` 保护含高分（≥70）条目的事件不被剥要点/截摘要；`GroundedQA` 证据按 valueBonus 重排（上限仍是 12 条，不丢关键项）。

## 已知的存量分歧（非本项引入，记录在案）

- fresh 建库与迁移建库在三张 M2+ 表上有列 DEFAULT 分歧（迁移 helper 写了默认、实体未声明；Room 不校验默认值，运行无差）。统一需要对齐实体 `defaultValue` 并升一版 schema——但会让“某版本期间全新安装过”的库在升级校验时失败，暂缓。
- `CREATE TRIGGER IF NOT EXISTS` 不更新既有触发器：真机若曾装过旧变体（如 `digest_pending_source_deleted`），永远保留旧文本。需要一版“DROP+重建”式修复迁移，列入后续。

## 真机注意

- 迁移只加一列+一次 UPDATE，秒级完成，无重建表。
- `valueScore` 对旧数据是按提取时属性重算的值，不是用户标记；用户改星标只影响实时加成，不回写条目分。
