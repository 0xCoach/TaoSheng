# 卡 143：把 PR #30（飞书 / 安克录音豆 D3200）迁成第一个 4 级样板驱动

## 背景

先读：`docs/方案/外设驱动插口设计.md`（第 4、8 节“PR #30 去向”）、`devices/.../driver/DeviceDriverContract.kt`（不改签名，确需改先停下报告）、`docs/任务卡/140/141/142-交付说明.md`、`docs/taoecho/插件提交清单.md`、`docs/任务卡/137-交付说明.md` 第五节“PR #30 的具体拆分点”、`AGENTS.md` 末尾复用约定。

PR #30 的代码在本地分支 `pr-30`（`git log main..pr-30` 三个提交，作者 xhp1211）。原 PR 说明：`gh pr view 30`；原交付说明：`git show pr-30:docs/任务卡/D3200-协议与灯控-交付说明.md`。

目标：**协议、解密、解码、补传、状态、控制这些成果原样保留**，但按新结构重写成一个 4 级驱动，核心里不出现任何品牌判断。这是以后所有 4 级插件的样板，结构要干净。

## 要做的

1. **驱动放在** `devices/src/commonMain/kotlin/app/resound/devices/plugins/d3200/`（纯 Kotlin），实现 `DeviceDriver`，编号 `d3200`，`tier = Plugin`，`stability = Trial`，维护人 `xhp1211`，显示名“安克 / 飞书录音豆 D3200”，别名含“安克录音豆”“飞书录音豆”，平台 Android + iOS（灯控除外）。
2. **从 PR #30 迁移**（逐文件对照，交付说明里列表说明每个原文件去了哪）：
   - 协议、校验、序号、166 字节单位、命令白名单、握手编排、回执匹配、设备信息解析、下载游标、历史覆盖区间、Ogg 封装规则 → 共用层。`ByteBuffer` / `BigInteger` 换成通用字节工具；ECDH / HKDF / AES-CTR **只用 `session.toolbox.crypto`**，保持原字节约定（HKDF salt/info 为 `01 02 03` 等，以 PR 源码为准）。
   - 蓝牙收发只用 `session.link`；**不自己扫描、不自己连接**；PR 里的 `D3200Coordinator.observe`（从广播读经典蓝牙地址）改为：驱动在 `match` 时可以看到 `Advertisement.manufacturerData`，把解析出的经典地址存进 `session.store`，由平台的 `classicSerial` 使用（地址仍不暴露给驱动以外）。
   - 阻塞式写法（`CountDownLatch`、阻塞队列、`Thread.sleep`、轮询等锁）全部改为协程。
   - 设置（`SharedPreferences`）→ `session.store`。
   - Opus 解码 → `session.toolbox.opusDecoder`；双声道 → 驱动内合成单声道（`AudioChunk` 一律 16 kHz 单声道）。
3. **映射到 TaoEcho 模型**：
   - `identity`：设备报得出序列号就用它（`IdScope.Global`），报不出用平台给的替代身份；固件版本按部件（1 录音豆、2 充电盒）。
   - `status`：两个电池部件（录音豆、充电盒）带充电状态和读取时间；存储总量 / 剩余；设备录音状态。读不到就是 null。
   - `controls`：`setRecording`（开始 / 暂停，带回读确认）、`lightModes` / `setLight`（默认、关闭、暖橙常亮→厂商预设；**仅验证过的 04.92 固件发灯控命令**，其他固件 `lightModes` 只返回“默认”）、`refresh`、`identify`（若协议无此命令则不声明该能力）。
   - `files`：把 PR 的离线补传映射为 `DeviceFiles`（`Reclaim.Never`，保留设备原文件；`confirm` 为空操作，`caps.confirm=false`）；“设备正在录音时不补传、要先停止保存”用 `DeviceException(StateConflict)` 表达。
   - `policy`：`backfillBeforeLive`、`newestFirst = true`、`exclusiveBackfill = true`（按 PR 实际行为设置）。
   - `settings`：“自动开始设备录音”“自动补传”等原设置项用 `SettingItem` 描述（开关）。
   - 灯控走经典蓝牙串口 → 能力标 `AndroidOnlyLight`。
4. **平台层**（`:app`）：
   - 实现 `PlatformExtras.classicSerial`（安卓经典蓝牙 RFCOMM，参照 PR 的 `createInsecureRfcommSocketToServiceRecord` 与 8 秒连接超时），地址由平台根据当前设备和驱动存的经典地址提供；iOS 将来为 null。
   - 前台服务类型加 `connectedDevice`（PR 已有做法，有蓝牙连接权限时才加）。
   - 驱动注册：在装配层的驱动目录里加入 `d3200`（装配层是唯一允许出现插件编号的地方，`tools/check_devices.py` 若因此报错，按“装配层驱动目录文件”加一条**路径级**规则，不加整行白名单，在交付说明写清）。
   - `DeviceInputs`（卡 141 的桥接）目前只面向说明卡；改成面向任意驱动（说明卡 + 插件），录音输入里能选录音豆。**不改说明卡设备的现有行为**。
   - PR 的 `D3200SettingsActivity`、`DeviceOptionsUi`、Manifest 里的 Activity **都不要**（界面由 Claude 在卡 144 按模型自动生成）。
5. **署名**：所有迁移提交的信息末尾加 `Co-authored-by: xhp1211 <xhp1211@gmail.com>`；保留 `vendor/d3200/LICENSE-AllDayRec`（放到插件文件夹或原位置，并在插件文件夹的 README 注明协议参考来源：AllDayRec（MIT）、tacshi/Soundcore 研究）。
6. **插件材料**（按 `docs/taoecho/插件提交清单.md`）：插件文件夹放 `README.md`（维护人、支持固件、已验证项、未验证项，取自 PR 说明）。**录包暂缺**（需要贡献者真机录），清单里标“待 xhp1211 补充”。
7. **测试**：PR 原有 30 个 JVM 测试中与协议、校验、游标、历史、状态、控制策略相关的迁到 `:devices` 的 `jvmTest`，断言不放宽；新增：驱动在假通道上跑一次“握手 → 实时收音 → 状态刷新”和“补传列表 → 读取”，各 1 个（字节向量取自 PR 测试或其交付说明；若没有现成向量，用 PR 的编码函数自行构造并注明）。只跑相关测试。

## 不做

不改 `ui/`、`MainActivity.kt`、约定文件签名、数据库结构、录音服务切段逻辑；不做录包；不碰说明卡驱动的行为。
