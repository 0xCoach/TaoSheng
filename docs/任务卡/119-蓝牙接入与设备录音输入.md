## 要做

1. **`DeviceLink` 的安卓实现**：连接、请求 MTU、发现服务、读、写（一条命令一次写入，不拆分）、订阅通知（Flow）。所有蓝牙回调串行处理（安卓蓝牙一次只能做一个操作，要排队）。断开时 Flow 以 `AudioSourceException(Disconnected)` 结束。
2. **搜索与配对（实现 `Devices`）**：
   - 用说明卡的 `match`（名字前缀 / 服务编号 / 厂商编号）过滤搜索结果，只列出有卡能认的设备；`trial` 卡未打开时不列（交付说明写清楚）。
   - 配对后记住（地址、卡 id、名字），随备份一起备份；`forget` 删除。
   - 权限：安卓 12 起要 `BLUETOOTH_SCAN`（声明 `neverForLocation`）和 `BLUETOOTH_CONNECT`；缺权限时 `startScan` 不崩溃，给 `lastError`。
3. **设备成为录音输入**：
   - 已配对、卡已启用的设备出现在录音输入列表里（新的 `InputKind`，例如 `CardDevice("专用录音设备")`——这是 `InputContract.kt` 里的枚举，**本卡允许只新增这一个取值**），可以像蓝牙耳机一样“指定”。“自动”不选它（与卡 112 一致）。
   - 实现一个 `AudioSource`：连接 → 读格式（`codecRead`）→ 订阅 → 发 `start` → 用卡 118 拆包解码成标准帧 → 断开前发 `stop`。
   - **复用卡 112 的保护**：连续全零判故障、读取超时、断开后由 `InputSwitchLoop` 换回手机麦克风、设备回来自动切回。
   - 心跳（`keepAliveSec`）、对时（`clock`，连上就对一次，记下设备与手机的时差，给卡 120 用）、电量（标准电池服务或自定义读法，每 5 分钟读一次）。
4. **断开与重连**：断开时记下“断开时刻”，重连成功时记下“恢复时刻”。如果说明卡 `offline=files`，调用卡 120 提供的 `DeviceSync.onLinked(card, link, gapStart, gapEnd, clockOffset)`（卡 120 与本卡并行开发；它还没合并时先写一个空实现，交付说明里写清接口）。
5. **诊断**：每台设备记“收到包数、丢包数、校验失败数、解码失败数”，写进现有问题记录（不写声音内容）。

## 不做

Wi-Fi、多台设备自动切换、同一段多设备去重（以后再做）。

## 必测（5～10 个即可，用假的 DeviceLink）

- 假设备按 Omi 卡发包 → 产出标准帧；断开 → 换回手机；重连 → 切回，并调用 `onLinked` 且时间段正确。
- 搜索过滤：没有卡能认的设备不出现；trial 卡关着时不出现。
- 缺蓝牙权限不崩溃。
