### 3. 无代理网络（Wi-Fi 全链路 PASS）

- **根因**：`*.workers.dev` 遭上游 DNS 投毒——手机默认 DNS 与 alidns DoH 均返回 Facebook/Dropbox 假 IP，Wi-Fi+蜂窝一致；非本机配置问题。
- **方案**：Cloudflare 自有域名 `soundsound.gdfactory.cn` 绑定 `soundsound-auth` Worker（`wrangler.toml` `custom_domain`，同 Worker 同 D1，不动父域 `gdfactory.cn` 的另一站点）；`AuthStore.DEFAULT_SERVER_URL` 改默认指向（设备无 `server_url` 覆盖，装包即生效）。
- **真机验证（全局代理已清）**：登录 `owner-kan` → `remote_status=active`、access/refresh 落库；membership 查询→`plan=pro, pro_until=2026-12-19`；用量视图同步正常（服务端 `used_minutes` 已记账）。
- **蜂窝**：设备移动数据为 **IMS-only**（连 baidu 都不通），无通用数据网可测——非 App 问题，待有可上网的蜂窝环境再验。

**owner-kan Pro 恢复**：服务端 entitlements 显示该账号从未有 pro 权益（此前 Pro 属于 e2e 测试账号）。已按之前观测的到期日补 `entitlements` 行（`source=admin`, `capability=pro`, `expires_at=1797675596`，D1 直插，meta 注明恢复原因）。

**会话失效根因**：数据恢复把 `auth.xml` 回滚到备份时状态，内含已轮换/失效的 refresh token → 启动 refresh 得 401 → `AuthGate.invalidate()` 清会话 → 显示游客。属 token 轮换的预期行为，重新登录即恢复。

**遗留**：`pending` 用量队列仅上报当前账号条目；登录前以 `acct=""` 记的 225 段按设计永不上传（游客用量不计入账号额度）——正确但会留在 prefs 中（上限 2000）。

**刷新竞态修复（设备管理登出 bug）**：`authed()` 的 401→refresh 路径 sem锁——账号页自动 `sync()`+`flush()` + 点击 `devices()` 并发 401 时，多个协程拿**同一个 refresh token** 换票；服务端轮换后到者被当重放 → `invalidate()` → 登出。修复：`refreshMutex` + `refreshIfNeeded(failedToken)`——锁内先比对：并发者若已换到新令牌直接复用 `Refreshed`，只有持票者真发 `/auth/refresh`。`refreshNow()` 入口同样串行。
**边缘残留**：进程死亡恰好发生在服务端轮换、客户端落盘之间（毫秒窗）时，refresh token 会变成死票 → 下次刷新 401 → 登出。服务端可对"前一个 refresh_hash"开短窗宽容（rotation grace），暂记为服务端硬化项，未做。
