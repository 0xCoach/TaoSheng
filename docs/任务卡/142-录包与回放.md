# 卡 142：蓝牙录包与回放测试框架

## 背景

先读：`docs/方案/外设驱动插口设计.md` 第 7 节、`devices/.../driver/DeviceDriverContract.kt`（不改签名）、`docs/任务卡/140-交付说明.md`。

目的：没有设备也能测驱动。开发者模式里把真实设备与手机之间的蓝牙通信录下来；测试时用“假通道”按录包回放，驱动照常运行，检查它的输出。负责人 11-11 定：录包内容不做限制（会公开在仓库里，提交模板提醒一句即可）。

卡 141 正在并行改运行路径。**本卡只改 `:devices` 的新包和 `:app` 里 `AndroidDevicePlatform` 的连接创建处（加一层可选包装）**，不要动 `AndroidDevices.kt`、`ManagedDevices.kt`、`CaptureService.kt`，避免冲突。

## 要做的

1. **录包格式**（写进 `docs/taoecho/录包格式.md`，简短）：UTF-8 文本，每行一条记录，第一行是文件头。
   - 文件头：`#taoecho-capture v1 driver=<驱动编号> recordedAt=<UTC 毫秒> note=<可选说明>`
   - 记录：`<相对毫秒> <方向> <服务编号> <特征编号> <十六进制字节>`，方向为 `R`（读，记录返回值）、`W`（带回应写）、`w`（不带回应写）、`N`（通知）、`D`（断开，后两列和字节写 `-`）。
   - 另有 `M <相对毫秒> mtu=<值>` 记录最大写入长度变化。
2. **录制包装**（`:devices` commonMain，`app.resound.devices.replay` 包）：`RecordingGattLink(inner: GattLink, clock: ClockPort, sink: (String) -> Unit)` 原样转发所有调用并逐行写记录；不改变时序和错误（内部抛的异常原样抛出，也记一行 `E`）。
3. **回放通道**（同包，供各驱动测试使用）：`ReplayGattLink(capture: String)`：
   - 驱动发出的写入必须与录包里下一条 `W/w` 的通道和字节一致，不一致抛断言错误，并指出第几行、期望什么、实际什么。
   - 读取返回录包里对应的 `R` 字节；通知按录包顺序推送（可选按相对时间推进，用测试调度器；默认“写入后立即推送其后的通知直到下一条写入”）。
   - 支持“忽略某些写入字节的位置”（如每次不同的随机数、时间戳），用一个可选的屏蔽参数。
4. **回放测试助手**：`ReplayHarness`，给一个驱动和一段录包，跑 `open` → 开实时声音或读文件 → 收集输出（声音帧数 / 采样数 / 丢包、文件列表、状态快照、错误），返回结果对象供断言。
5. **安卓接线**：`AndroidDevicePlatform` 的连接创建处加一个开关（`device-drivers` 配置里的布尔值 `captureEnabled`，默认关）。开启时用 `RecordingGattLink` 包装，录包写入 App 私有目录 `files/device-captures/<驱动>-<时间>.txt`，单个文件上限 20 MB，超过就停止该文件记录并在文件尾记一行说明。提供列出 / 删除录包的函数（界面和“导出分享”由 Claude 在卡 144 做）。
6. **样板**：用合成卡（测试资源里的 `synthetic.json`）手写一段小录包（十几行），写一个回放测试证明整条链路可用；再写一个“写入不一致时报错信息清楚”的测试。
7. **贡献模板**：在 `docs/taoecho/` 下加 `插件提交清单.md`：4 级插件必须交的四样（录包至少两段：实时收音、补传；真机报告模板；维护人；不改核心），并提醒“录包会公开在仓库里”。
