## 已完成

- 新增专题仓库、三张表、状态转换、两分钟回溯、暂停/继续、记一下、延长、预约及按周重复。所有开始、预约、补录和延长的冲突检查在写入事务内完成。
- 进行中的专题覆盖计划停录；尊重录音总开关与用户手动暂停。暂停只关闭专题归属段，期间录音继续按原有规则整理。
- Training 按录音开始时刻关闭分人，旧课堂状态、历史设置和兼容方法保留。通知和原课堂磁贴改为专题入口。
- 专题名切词进入现有热词通道；到期或结束后撤出转写热词，生成该专题时仍带其名称热词。
- 专题结束即触发转写，专题候选优先；结束时还在录制/编码的尾段自然落盘后再次立即调度。没有改变 VAD、自然分片、环境音与声纹判定。
- 日常整理查询排除未取消的专题原话，提交旧整理响应时再次检查归属；专题生成等待转写、声纹与尾段落盘。多批结果只写一个事件。
- Meeting/Training/Call 复用导入纪要模板与同种 `SkillCardRow`；标记时刻和最近原话编号传入纪要。Script 输出完整整理版、原话版，两版字数和朗读分钟数本地计算。
- 事后补支持事件闭包吸附、删除被替换事件、保留用户修改过的待办及星标；剪辑后释放被剪原话，取消时删除合成事件和纪要。生成版本校验阻止旧响应覆盖剪辑、取消或改类型后的状态。
- 固定错误文案、手动重新生成、精确闹钟及权限受限时的普通闹钟兜底、重启/系统时间变化后重新排钟。

## 给界面的约定

入口：`AppGraph.topics: TopicRepository`；就绪检查：`AppGraph.isTopicsReady`。定义集中在 `topic/TopicContract.kt`。

- `current` 为 Running/Paused 专题；另有按天、单专题、预约列表的观察流。
- `Topic` 包含类型、状态、名称、spans、marks、预约起止、repeat、eventId、cardId、error、revision、quietOverride。
- `start(kind, name, durationMinutes)` 返回 `StartResult`：成功有 topicId；quietOverride 表示覆盖计划停录；recordingDisabled 提醒总开关关闭；失败显示 error，不自动开录音。
- `schedule`、`createFromEvents`、`createFromRange` 返回 `Result<Long>`。`previewFromEvents` / `previewFromRange` 返回吸附后的起止、被替换事件的标题与时间、改过的待办数、星标数及冲突信息。确认创建时重新计算预览，避免使用过期数据。
- `pause/resume/end/extend/mark/update/cut/cancel/regenerate/cancelSchedule` 保留任务卡功能。无 Result 返回值的方法发生状态或时段冲突时抛 `TopicException`，message 为可展示的固定文案。
- 签名具体化为 `Long` 毫秒、`List<Long>`、`Set<DayOfWeek>`；未修改既有 `*Contract.kt` 或 `AudioSource.kt` 的签名。
- 时段使用 `[startAt, endAt)`，一句原话按开始时间归属，边界不会分给两个专题。培训改类型作用于专题历史时段的分人策略；已完成的转写不会自动重新调用 ASR。
- `cut` 支持进行中与已结束的专题；进行中剪辑保留原截止时间，最终结束后生成。整个时段被剪空时转 Cancelled。取消/重做时用户改过的条目先解除旧事件外键，防止被级联删除。
- 纪要通知打开 `MainActivity`，Intent extras 为 `open="topic"`、`topicId: Long`。界面需要接入该参数，并通过专题的 eventId/cardId 展示内容。
- 新界面应使用 Training 专题替代旧课堂按钮，用 `regenerate(topicId)` 重新生成专题。

## 通知文案

| 场景 | 文案 / 按钮 |
|---|---|
| 常驻、未开始 | 原暂停/删除按钮保留，第三按钮改为“开始专题”；默认会议、未指定时长 |
| 进行中 | “会议中 · 已 35 分钟 · 11:00 结束”；有名字用名字；按钮“记一下 / 暂停 / 结束” |

| 连续十五分钟无新录音段 | “15 分钟没人说话，要结束专题吗？”；按钮“结束 / 继续录”；同一段安静只提示一次 |
| 预约到点但总开关关闭 | “预约的专题开始了，录音没开”；按钮“打开录音” |
| 通知/磁贴主动开始但录音关闭 | “专题已开始，录音没开”；按钮“打开录音” |
| 主动开始覆盖停录时段 | “专题已开始，这段时间原本设为不录音” |
| 生成成功 | 按类型显示“会议纪要好了 / 培训笔记好了 / 通话记录好了 / 口播稿好了 / 专题整理好了” |
| 生成失败 | “专题生成失败，请重试” |

原磁贴组件名保留，显示名改为“专题录音”；关着时开始，开着时结束。通知动作的 PendingIntent 身份包含 topicId，旧按钮不会控制新专题。冷启动处理动作时直接核对数据库状态。

## 数据迁移与备份

- 数据库 `32 → 33`，新增 `topics`、`topic_spans`、`topic_marks` 及索引、子表级联外键。迁移加入统一 `CaptureDatabase.MIGRATIONS`；导出 schema 为 `33.json`。
- `repeatRule` 为周一到周日的七位位掩码；无重复为 null。每次开始后只生成一个下一次 Scheduled，进程恢复不会重复创建。预约检查也覆盖未来每周重复及周期自身重叠。
- topics 除任务卡业务列外持久化五项恢复元数据：quietOverride、retainedItemIds、starred、quietNotifiedAfter、endingNotifiedAt，分别用于停录提示、保留待办、星标转移与提醒去重。
- 整库备份自然包含新表；按天分卷显式加入三张表。已验证 v32 整库升级、当前整库副本、当前分卷恢复和不含专题表的旧分卷恢复。
- 不新增依赖；专题异常只使用固定文案，未把专题名称或原话写入日志/问题记录。
