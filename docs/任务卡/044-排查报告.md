# 044 · 声纹识别率排查报告

## 结论与数据口径

主要问题是短语音、把整组压成单向量、用单中心概括差异很大的手动样本，以及旧阈值偏高。不能把所有离散组都认定为多人，也不能把自动样本认定为已经混入别人。

本次只使用本地副本与仓库内 CAM++，没有联网、外发、操作手机。报告不含原话、姓名、录音路径、时间戳、记录标识或输入指纹。逐条结果、缓存与输入校验均留在被忽略的私有目录。

- 数据库：643 段、1405 句、816 个声纹组；799 个缓存文件，642 个现存组有有效缓存向量。
- 464 个原录音文件；可对应并处理 569 组，重新计算 883 个有效连续窗口。433 组同时有有效旧缓存和重算整组向量。
- 样本 87 条：“我”手动 39 条、自动 40 条；其他人的手动样本 8 条，仅覆盖 1 个其他人。朗读录入样本 0 条，排除表记录 0 条。
- 手动“我”对应 52 句，但评估按 39 次样本确认去重，不把同组传播的句子当作额外独立正例。5 句人工清空身份不能直接解释成“不是我”。自动命名也不作真值。
- 每个测试组均排除同一录音段的全部训练样本，避免自匹配。最后的生产规则评估只取每条手动样本实际点击的那句，保留无有效窗的失败项，得到同一批 31 正例、8 负例。其他 8 个正例录音不可用，不能声称已验证其分窗收益。
- 人工标注提供的是句/组级弱标签，不是逐窗口听辨真值；以下数字是此快照的离线表现，不是真机验收或全场景准确率。

## 一、逐条怀疑

### 1. 一组混了多个人：部分成立

代码实际按录音段和非空 tag 分组；空 tag 按单句分组，并非所有无编号句子合并整段。37 句无 tag；最大无 tag 句长 28 秒，全部组最大跨度 71.7 秒；301 组包含多句。本快照没有发现“无编号整段五分钟只算一次”的实例，但长句和同 tag 的合并仍然存在。

198 组有至少两个有效窗口。窗口两两余弦的组内中位数再取分布：最小 0.0533、P10 0.4353、中位 0.6185、P90 0.7378、最大 0.8481。23/198 组内部中位数低于 0.45，120/198 低于 0.65。无 tag 的 34 个多窗组内部中位数总体中位为 0.6076、最小 0.0533。

这些数字证实组内声学不一致，支持连续小窗判定；噪声、距离、短窗也会降低相似度，未逐段人工听辨，不能报告“23 组确定混了人”。

### 2. 自动样本污染：异人污染未证实，反馈偏置部分成立

| 样本 | 数量 | 对手动中心最低 / 中位 / 最高 | 两两余弦中位 | 低于中心 0.45 |
|---|---:|---:|---:|---:|
| 手动“我” | 39 | 0.2781 / 0.6141 / 0.8304 | 0.3310 | 5 |
| 自动“我” | 40 | 0.6526 / 0.7636 / 0.8255 | 0.7279 | 0 |

自动样本不是明显离群点，而是非常集中的一批；数量占“我”样本的 40/79，旧等权中心容易被这种声学条件主导。自动样本有效时长最短 3.02 秒、中位 10.03 秒、最长 35.26 秒，40/40 都不是本次要求的最多 3 秒连续窗。

有多个可重算窗口的自动样本 17 个，组内余弦中位总体中位 0.6111、最小 0.4958；手动样本对应 18 组为 0.5906、0.0533。不能据此证明自动样本比手动样本更“脏”。手动离群 5 条只标记，保留其多种声学条件，不自动删除。

新实现停止用自动样本形成识别模板；旧超长或低一致性自动样本可清理，人工样本不受自动清理影响。自动补样本仍要求整组有效窗一致，仅存一个连续窗，且不反过来强化下一轮判断。

### 3. 早期朗读音源不一致：证据不足

朗读 `enroll` 样本为 0，无法比较两种录音音源。按任务卡所述切换日期的本地日界，把 39 个手动句样本分成前 18 / 后 21 条，对共同手动中心的中位分数为 0.7125 / 0.5399；前后各自最低为 0.3065 / 0.2781。

后批并没有提高，但这些是从原话选出的样本，创建时间也不等于录音硬件/音源标签。因此既不能证实音源改动无效，也不能把差异归因于 VOICE_RECOGNITION 与 MIC。

### 4. 单中心打分与阈值：成立

分布来自同一批 39 正例、8 人工其他人负例，留出同一录音段。表内为最低 / 中位 / 最高；余弦不是概率。

| 方法 | 正例分布 | 负例分布 | 阈值 0.65 召回 | 误认 |
|---|---|---|---:|---:|
| 原全部样本中心 | 0.1652 / 0.5532 / 0.8879 | 0.1214 / 0.2195 / 0.2971 | 17/39，43.59% | 0/8 |
| 手动中心 | 0.2388 / 0.5870 / 0.8166 | 0.1668 / 0.2506 / 0.3023 | 13/39，33.33% | 0/8 |
| 手动中心过滤离群后 | 0.2140 / 0.6118 / 0.8364 | 0.1474 / 0.2349 / 0.2778 | 15/39，38.46% | 0/8 |
| 手动样本 Top-3 均值 | 0.3759 / 0.6006 / 0.8411 | 0.2690 / 0.3708 / 0.4545 | 18/39，46.15% | 0/8 |
| 手动样本最大值 | 0.4590 / 0.6760 / 0.8740 | 0.2928 / 0.3894 / 0.6235 | 21/39，53.85% | 0/8 |

降低阈值到 0.50：Top-3 认出 31/39（79.49%），误认 0/8；最大值认出 33/39，却误认 3/8（37.50%）。Top-3 降到 0.45 会误认 1/8，所以选 0.50，保留对当前负例最高 0.4545 的余量。

0.40～0.85、步长 0.05 的扫描中，过滤离群后的 Top-3 在 0.40 得到这批整组数据的最高零误认召回 38/39。没有直接采用：它依赖排除部分用户确认的不同声学条件，且负例只有 8 条。只看本批最高分数不足以选择长期默认。

**最终生产规则**：每个连续窗计算手动样本 Top-3 平均余弦，阈值 0.50；多人候选须比第二名高至少 0.08；按与句子的时间重叠投票，至少覆盖句长 75% 才命名。短窗、无向量、缺失部分仍计入句长分母。人工身份保持锁定，评估时只做影子判定以度量算法。

| 相同的保留录音源句 | 正例认出 / 总数 | 召回率 | 负例误认 / 总数 |
|---|---:|---:|---:|
| 原中心、0.65 | 11/31 | 35.48% | 0/8，0% |
| 新 Top-3、0.50、75% 窗口投票 | 21/31 | 67.74% | 0/8，0% |
| 新规则窗口阈值 0.45 | 23/31 | 74.19% | 0/8 |
| 新规则窗口阈值 0.55 | 13/31 | 41.94% | 0/8 |

不继续降到 0.45，因为整组对照已出现误认，窗口负例也仅 16 个、最高分 0.4191。正例 64 个有效窗分数最低 / 中位 / 最高为 0.1949 / 0.6546 / 0.7851。

按录音段确定性分组做事后稳定性检查：开发子集 19 正 / 5 负，旧 7/19、新 15/19；留出子集 12 正 / 3 负，旧 4/12、新 6/12，两者均无误认。身份模板采用逐段交叉验证，且阈值讨论已看过全批数字，这不是盲测独立测试集。0/8 误认不证明总体误认率为零。

### 5. 太短、太吵、外放：短音频成立，其余部分成立或未证实

- 原整组中心：1.5～3 秒正例认出 1/14（7.14%）；3～6 秒 5/12（41.67%）；至少 6 秒 11/13（84.62%）。短音频是明确瓶颈。
- 新 Top-3 单窗口：1.5～2 秒正例过阈值 3/7，2～3 秒 33/42，完整 3 秒 14/15。这是窗级弱标签统计，不等于句级召回，不能宣称 2 秒即可可靠识别。
- 569 个可解码组中，136 个有效语音不足 1.5 秒，285 个不足 3 秒。继续沿用模型 1.5 秒最低有效语音；自动补样本至少 2 秒；不足窗口不强猜。
- 883 个有效窗的原始 RMS：P10 0.0058、中位 0.0116、P90 0.0480。RMS 不能推算 SNR，现有数据无噪声真值，本次不新增未经验证的“噪声阈值”。RMS 裁剪也不是人声分类器，仍可能保留非语音。
- `playbackMillis > 0` 共 14 段，对应 8 个转写组；其中 4 组有有效缓存、0 组有人工身份标签。以播放标记作**负例代理**，旧方法与 Top-3 都命中 1/4；Top-3 最低 / 中位 / 最高 0.2492 / 0.3244 / 0.5586。可能存在同时真人讲话，不能把 1/4 报为真实误认率。已禁止播放标记录音进入自动样本库，但保留识别人声能力。
- 仓库已有电脑 `say` 合成夹具 1 个，有效约 2.001 秒；Top-3 分数 0.1680，未命中。只作为补充负例，不与真人负例混合扩大样本数。

### 6. 其他原因与实现核查

- 特征提取并非主要失真来源：Python 与仓库 Kaldi 特征夹具最大绝对误差 0.000367 以下；433 组重算整组向量与手机缓存余弦最低 0.9928、中位 0.9997、最高接近 1。Opus 解码器差异下高度一致。
- 手动点击原实现会连同同组其他句子一起确认。它能扩大误标影响，且整组混合向量直接进入样本。新代码保留既有“确认整组”接口语义，但新样本只取所点句子的连续窗；多个有效窗不一致则只确认身份，不新增污染向量。
- 32 句带不确定说话人标记，新规则继续不自动命名。
- 原自动补样本只在没有其他人物时执行。当前已有其他人物；40 条自动样本不能代表当前仍在持续自学习。
- 不使用同一段录音的样本对自身打分。保留窗口缓存版本隔离，不能把旧整组向量当成新窗口结果。重算遇到录音已删除时保留原结果。

## 最终范围与剩余问题

已实施窗口判定、Top-3 阈值、自动样本隔离与清理、手动离群标记、人工补样本窗口化、独立重算入口与缓存/并发保护。不改 UI、MainActivity、约定签名和数据库结构。

仍需更多其他人、播放混入、距离变化、噪声条件下的人工句级标注；重叠说话无法靠 3 秒窗自动分离。本次没有重新训练模型、没有把旧人工样本全部重抽成窗口，因此保留其原始多条件参考。现有标注数据只能支持上述保守改进，不能证明全天场景已解决。
