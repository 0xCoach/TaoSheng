# 091：蓝牙录音结束后原声回放误走听筒

## 真机证据

- 用户反馈 DJI Mic Mini 录音回放非常轻。在 preview.6 采集用户实际回放期间的系统快照，多次记录到涛声 MediaPlayer 为 `USAGE_MEDIA / CONTENT_TYPE_SPEECH`，实际 `deviceIds:[2]`；AudioPolicy 确认端口 2 是 Earpiece、端口 3 才是 Speaker。
- 回放期间媒体路由 `earpiece(1)`，Requested mode=MODE_NORMAL、Actual mode=MODE_IN_COMMUNICATION；涛声的旧通信模式请求还在模式栈中。开始切换时短暂出现 BT_SCO 和静音。
- 因此“回放很小”至少包含一个已复现的输出路由问题，不能全部归因于硬件强降噪。此证据不表示原始录音幅度已经足够。

## 修复

- 蓝牙录音释放时明确提交 MODE_NORMAL，撤销本进程的通信模式请求；不再恢复之前读到的全局模式，也不以当前全局模式为条件跳过释放。
- Android AudioService 的 MODE_NORMAL 移除调用进程的请求，由系统保留其他应用的有效请求；参考 Android 16 AudioService 源码：https://android.googlesource.com/platform/frameworks/base/+/refs/heads/android16-release/services/core/java/com/android/server/audio/AudioService.java 。
- 播放/恢复播放先等待录音服务完成取消及 finally 清理，再申请播放焦点并启动播放器；给系统异步模式切换最多 1 秒等待，整个等待最多 4 秒，失败提示重试并归还收音。
- 使用请求序号忽略暂停、停止或切换后的过期准备结果，避免异步等待结束后又自行播放。
- 不强制修改系统音量，不改原始音频或硬件降噪，不强制覆盖用户的耳机输出选择。

## 验证

- `BluetoothRelease091Test` 两项通过：开蓝牙输入失败后即使进入前全局模式已经是通信模式，也释放本次请求；没有录音权限时不改已有电话模式。
- `assembleRelease -PpreviewNumber=7` 通过，0.2.15-preview.7（46），签名与原手机安装一致。
- `LinePlayerStart091Test` 两项通过：等待文件定位期间停止后不再启动播放；等待音频模式切换期间暂停后不再自行播放、按时归还收音。
- 手机 `adb install -r` 返回 Success，版本确认 preview.7（46）。APK SHA-256：`fc2d71d92cb1001e21718a8c4f7ef5da7cb512d600dd43606305ac25adfbb130`。
- 用户复测反馈“变大了”。同轮系统快照确认多次回放均为 `deviceIds:[3]`、媒体路由 `speaker(2)`，Requested/Actual mode 均为 MODE_NORMAL；采集时仍能切入 BT_SCO / MODE_IN_COMMUNICATION。
- 这是手机实际播放路由与用户听感共同验证，不只是编译通过；未改变音频文件增益，仍不承诺恢复硬件降噪已经滤掉的细节。
- 私有诊断只保存在本机 `/tmp/taosheng-mic089/`，不提交包含其他应用活动的系统日志。
