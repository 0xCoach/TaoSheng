## 实现

### 批量读与时间戳

- `:shared` 新增 `CaptureReadPolicy`：有人订阅音量为 20 ms，无人为 200 ms；实现类新增时长函数，默认 20 ms。按原生采样率、声道数算每次读取长度，最大缓冲只分配一次。内部 AudioRecord 缓冲由至少 0.2 秒扩大到至少 1 秒。
- 手机、普通外接及蓝牙通话共用 `RoutedRecording`。插件设备音源不改。采样率、音源类型、编码、转换器、灵敏度、切段参数均不变。
- `:shared` 新增 `PcmBatchClock`：首次有效批次读完时注入墙钟，减去整批原生样本时长得到首样本时间，随后按累计 16 kHz 输出样本定位每帧。包含转换器未输出的不足 480 样本尾巴，不把回调次数当时长；路由不匹配或让麦时与转换器一起清零。后续不再用到达墙钟反复校正，避免同一段音频因批次或墙钟抖动漂移。
- 内部时间封装跟帧一起穿过 `flowOn(IO)`，到消费线程才更新现有 `AudioTimeline.frameEpochMillis`；避免生产端先覆盖共享时间属性。手机/外接实现现有可选时间接口，不改 `AudioSource.kt`、`AudioTimeline` 或 `*Contract.kt` 的签名。
- `CaptureService` 已有的时间接口分支可读取上述帧时间。`SegmentFiles.sink(epoch)` 用 `epoch + startSample / 16000` 创建文件时间，`SpeechSegmenter` 的起止、前滚、尾静音均按样本计。因此要修正的是音源第一帧的 epoch，而不是修改切段器。原先仅减当前 480 样本会把 200 ms 批次开头推迟约 170 ms，现在消除这项系统偏移。

### VAD 复用

- 原 `accept` 的 512 分帧、RMS、增益、门限、历史及递归状态处理搬到 `:shared/StreamingVad`。推理通过同步函数注入；保留原运算顺序、线程数、门限及清零语义。
- 复用 `input[576]`、`history[64]`、`state[256]`、`pending/pcm[512]`。完整帧回调的 PCM 只借用至回调返回。`finish()` 在原缓冲内补零，仍给回调一个独立、实际长度的尾帧，不延长录音。
- `SileroVad` 只负责 Android 模型适配：三个输入张量及输入 Map 每实例创建一次；input/state 使用 native-order 直接 FloatBuffer，sr 使用直接 LongBuffer。每次推理覆盖缓冲，结束时释放输入张量和 session，初始化失败清理已建张量。
- 输出仍由 `session.run()` 的 Result 创建并在每帧读取后关闭；没有引入预绑定输出，避免输出与下一轮递归输入共享生命周期。这部分仍有 ORT 的输出及 buffer-view 分配，不宣称零分配。
- 引用审计：`SpeechSegmenter` 活跃时 `copyOfRange` 再交 sink，前滚按 Short 值入队；`SegmentFiles.sink.write` 同步转字节写流；`ImportWork` 同步交给切段器；`EnvSoundGapExtractor` 只记录长度/人声标记，批处理每个文件 `reset()`；`LocalSpeakerDiarizer` 只留样本区间。环境声重做复用同一提取器，未发现保留 VAD 原数组引用的路径。新增测试同时验证保存后的 PCM 不受缓冲覆盖影响。

## 静态唤醒估算

- 卡片概述为旧约 50 次/秒，实际旧代码 `maxOf(960, rate*channels/50)`：16 kHz 单声道每读 960=60 ms，约 16.7 次/秒；48 kHz 单声道及更高字节率约 50 次/秒；8 kHz 单声道约 8.3 次/秒。
- 新的无人订阅路径目标为约 5 次阻塞读返回/秒；有人订阅为约 50 次/秒。上述是不发生短读、没有调度阻塞时的静态估计，未测实际功耗。
- 转换器仍输出每秒约 33.3 个 480 样本帧。无人订阅时这些帧集中在约 5 批送往 capture-state，不能把“5 批”声称为精确 5 次线程唤醒：调度器可能在一批内多次切换。
- VAD 仍每秒约 31.25 个 512 样本窗口；每个完整窗口少一个 PCM 拷贝、一个 input 数组、一个 history 切片。达到门限的窗口还省掉三个输入张量及 Map 的创建，推理次数不变。

## 真机注意与遗留

1. 熄屏录一段有停顿的对话，确认片段完整、不丢字头字尾，起始时间准确；亮屏打开首页声波应流畅，首次最多等待约 200 ms。
2. 蓝牙耳机通话输入，打开其他录音应用/语音输入法及系统通话，确认及时让麦、通话模式释放并在对方结束后恢复。
3. 暂停、恢复、丢弃当前片段确认响应；丢弃后的片段不保存。
4. 真模型逐位对照仍需负责人在同一目标设备、同一 PCM、同一模型/线程配置上跑改前与改后：核对每帧概率、状态及切段 PCM。电脑测试已证明组装和状态流转一致，不能代替 Android 原生 ONNX 的实测。
5. 在外放启动/停止边界、尤其占比接近一半时核对“外放跳过”；不是 PCM 丢失，但采样判定时点会有批量误差。
6. 真机电量/线程唤醒次数尚未测量；iOS 编译通过也不代表 iOS 收音或模型已可用。
7. 订阅计数接线待确认，未连接前实现类默认仍使用 20 ms，不能宣称无人订阅省电已生效。
