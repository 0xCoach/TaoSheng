# 外设驱动插口设计（第 2 步“核心重整”的蓝图）

> 2026-11-11 Claude 起草。配套：`docs/taoecho/TaoEcho-0.1-规范草案.md`。
> 状态：草案。模块怎么拆（第 3 节）要等卡 137（iOS 复用调研）的结论再定稿，其余部分可以先按此推进。

## 0. 一句话

**核心只认一种设备模型（TaoEcho 模型）。** 2 级 TaoEcho 设备、3 级说明卡、4 级插件都实现同一个“驱动”接口，把各自的设备翻译成这个模型；蓝牙、录音、存储、权限、后台、界面全部由核心统一管理，驱动碰不到。

## 1. 要解决的问题（来自 PR #30 和这几轮讨论）

| 问题 | 现状 | 改造后 |
|---|---|---|
| 品牌判断漏进核心 | `ManagedDevices` 里写 `card.id == "d3200"`；`AndroidDevices` 里塞了录音豆专属补传逻辑 | 核心里没有任何品牌名，自动检查守住 |
| 插口不够用 | 只有“说明卡”和“文件插口”，缺私有连接 / 状态 / 控制 / 设置 | 一个驱动接口覆盖全部，按能力声明 |
| 插件各自动手 | 录音豆自己扫描蓝牙、自己存设置、自己开经典蓝牙、自带设置页 | 扫描、连接、命令排队、存储、界面都归核心 |
| 设备按蓝牙地址认 | 配对记录、补传进度都按地址存 | 按设备身份（`deviceId`）认；iOS 拿不到地址 |
| 只能显示一个电量 | `DeviceState.battery: Int?` | 多个电池部件 + 充电状态 + 更新时间 |
| 没设备就测不了 | 只有部分单元测试 | 每个驱动附录包，改动后自动回放 |

## 2. 总体分层

```
┌──────────────────── 共用层（纯 Kotlin，不 import android.*，以后给 iOS 复用）────────────────────┐
│  设备模型  model/      身份、能力、状态、控制、设置项描述                                         │
│  驱动接口  driver/     DeviceDriver、DriverSession、DriverConnection                               │
│  驱动们    taoecho/    2 级：TaoEcho 通用驱动                                                     │
│            card/       3 级：说明卡驱动（现有 CardParser / FrameCodec 搬过来）                      │
│            plugins/<品牌>/ 4 级：录音豆、声云……每个一个文件夹，互相看不见                           │
│  调度      registry/   认设备、查冲突、一台设备绑一个驱动                                           │
│            sync/       补传、断点续传、校验、去重、确认后才删（现有 DeviceSync 规则搬过来）             │
│  工具箱接口 toolbox/   Opus 解码、加密（ECDH/AES/HKDF/验签）、CRC、Ogg 封装、时钟、键值存储、日志     │
│  录包回放  replay/     录包格式、假蓝牙通道、回放测试工具                                           │
└──────────────────────────────────────────────────────────────────────────────────────────────┘
                     ▲ 只通过接口                         ▲ 只通过接口
┌──────────── 安卓平台层 ─────────────┐        ┌──────────── iOS 平台层（以后）────────────┐
│ 蓝牙：扫描、连接、GATT 命令排队、重连 │        │ CoreBluetooth 实现同一套接口               │
│ 工具箱实现：MediaCodec、javax.crypto │        │ AVFoundation / CryptoKit 实现              │
│ 前台服务、保活、权限、通知、Room 存储 │        │ 后台模式、状态恢复                          │
│ 界面（Compose，按模型自动生成）       │        │ 界面（SwiftUI 或共用界面，看卡 137）        │
└────────────────────────────────────┘        └──────────────────────────────────────────┘
```

## 3. 模块怎么拆（等卡 137 定稿）

倾向方案：

- 新建 Gradle 模块 `:devices`：纯 Kotlin，先只编译给安卓 / 电脑单测用；以后加 iOS 目标（Kotlin 多平台）时只改这个模块的构建配置，不改代码。
- 每个 4 级插件放在 `:devices` 里自己的文件夹 `plugins/<品牌>/`。插件数量多了再拆成独立模块（`:devices-plugin-<品牌>`），用模块依赖强制“插件之间互相看不见、只能看见驱动接口和工具箱”。
- `:app` 依赖 `:devices`，提供安卓平台层实现。

如果卡 137 推荐“Swift 完全重写 iOS”，共用层仍然值得做（协议规则、补传规则可以照着翻译），只是不做 Kotlin 多平台配置。

## 4. 驱动接口（所有级别都实现它）

下面是接口清单与职责，最终签名在第 2 步编码时由 Claude 写进约定文件 `DeviceDriverContract.kt`。

### 4.1 DeviceDriver：驱动本身

| 成员 | 职责 |
|---|---|
| `id` | 驱动编号（如 `taoecho`、`card:omi`、`d3200`） |
| `match(ad)` | 看一条蓝牙广播，回答“是不是我的设备”和把握程度（确定 / 可能 / 不是）。只能看广播内容，不能自己扫描 |
| `open(session)` | 核心连上设备后调用，返回 `DriverConnection` |
| `meta` | 静态信息：显示名、别名（如“安克 / 飞书录音豆”）、图片、配对步骤、维护人、状态（稳定 / 试用）、平台支持（安卓 / iOS） |

### 4.2 DriverSession：核心交给驱动的东西（驱动只能用这些）

| 成员 | 说明 |
|---|---|
| `link` | 蓝牙收发把手：读、写、订阅通知、当前包大小。由核心排队执行，驱动不能扫描、不能另开连接 |
| `toolbox` | 公共工具箱：Opus 解码、加密、CRC、Ogg 封装、时间 |
| `store` | 本驱动、本设备专用的一小块键值存储（核心负责备份和清理） |
| `schedule(every, task)` | 定时任务，核心限制最短间隔（如 30 秒）和同时运行数 |
| `log(...)` | 诊断日志，进诊断导出 |
| `platformExtras` | 平台专有能力，**默认为空**。目前只考虑一项：安卓经典蓝牙串口（录音豆灯控用）。用它的功能必须在 `meta` 里标“仅安卓” |

### 4.3 DriverConnection：驱动交给核心的东西（就是 TaoEcho 模型）

| 成员 | 对应 TaoEcho | 说明 |
|---|---|---|
| `identity` | HELLO | `deviceId`（稳定身份）、厂商、型号、各部件固件版本。设备报不出序列号的（3/4 级老设备），驱动给出替代身份并标明“平台相关”（安卓上可用地址） |
| `capabilities` | 功能清单 | 有哪些能力；核心只为有的能力生成界面 |
| `live` | 实时声音 | 开始 / 停止；输出带时间信息的 16 kHz 单声道 PCM 帧（驱动负责解码到 PCM，用工具箱） |
| `files` | 离线文件 | 列出 / 读取（可续传）/ 确认保存 / 删除。现有 `FileSourcePlugin` 包一层即可 |
| `status` | 电量、存储、录音状态 | 一个可观察的状态：多个电池部件（电量、充电、更新时间）、存储、设备录音状态；读不到就是“未知” |
| `controls` | 录音控制、灯光、对时、识别我 | 每个控制返回**设备确认后的实际状态** |
| `settings` | 设置项 | 设置项描述（开关 / 数值 / 多选一 / 只读）+ 修改 |
| `policy` | — | 驱动声明的偏好：先补传再实时收音、新录音优先补传、补传时禁止控制（来自 PR #30） |
| `bind / unbind` | BIND / AUTH | 能做物理确认的设备走确认流程；老设备可声明“无绑定” |
| `close()` | — | 断开 |

## 5. 核心负责的事

| 事 | 说明 |
|---|---|
| 扫描 | 全 App 只有核心扫描，扫到的广播分发给各驱动的 `match`。遵守安卓“30 秒最多 5 次扫描”的限制 |
| 认设备与冲突 | 多个驱动都说“确定”时报冲突（审核阶段自动检查就该发现）；“可能”时让用户看图选；选定后记住“这台设备用这个驱动” |
| 绑定 | 只绑一部手机；按键确认 / 闪灯确认的界面由核心画 |
| 连接租约 | 每台设备同一时间只有一个连接持有者（收音、补传、临时管理共用），来自 PR #30 的做法，推广到所有驱动 |
| 命令排队与重连 | 蓝牙命令一条一条排队；断开按规则重连 |
| 选音源 | 用哪个设备收音由核心按优先级决定；驱动只供声音 |
| 补传 | 断点续传、校验、去重（同一段录音只留音质好的一份）、**确认保存后才通知驱动删除** |
| 状态显示 | 按模型自动生成设备卡片；未知显示“未知”，旧值标更新时间 |
| 故障隔离 | 驱动抛异常、卡住超时都在边界接住；同一驱动短时间内连续出错 N 次自动停用，并提示用户 |
| 远程开关 | 远程参数表可停用某个驱动或某个固件版本 |
| 诊断 | 统一导出：连接记录、收包统计、驱动日志 |

## 6. 防乱的自动检查（写成脚本，放进提交前检查）

1. 共用层代码里出现 `import android.` → 报错。
2. 品牌名（从设备清单里读出全部品牌和型号）出现在 `plugins/` 和设备数据文件以外 → 报错。
3. `plugins/A/` 引用了 `plugins/B/` → 报错。
4. 插件引入工具箱以外的第三方库 → 报错（例外需审核登记）。
5. 两个驱动的“确定匹配”规则重叠 → 报错。
6. 每个驱动必须有：`meta` 填全、至少一个录包、真机报告、维护人 → 缺一项报错。

## 7. 录包回放

- **录**：开发者模式里打开“记录蓝牙通信”，核心在 `link` 外面包一层，记下每次读 / 写 / 通知（时间、通道、方向、字节）。导出成一个文本文件（每行一条，字节用十六进制）。
- **放**：共用层提供“假蓝牙通道”，按录包回放设备那一侧的数据，驱动照常运行，测试检查它产出的模型（声音帧数、文件列表、电量等）和发出的命令是否与录包一致。
- **规矩**：每个驱动至少两段录包（实时收音、补传）。录包内容不做限制（负责人 11-11 定）；提交模板提醒“录包会公开”。

## 8. 现有代码怎么迁

| 现有 | 去向 |
|---|---|
| `DeviceContract.kt` 里的说明卡、文件插口 | 保留，作为 3 级说明卡驱动的内部实现；对外改由驱动接口暴露 |
| `core/CardParser`、`FrameCodec`、`Crc`、`StrictJson`、`FrameValidation` | 搬进共用层（已经基本是纯 Kotlin） |
| `core/AndroidOpusDecoder` | 留在安卓平台层，作为工具箱“Opus 解码”的安卓实现 |
| `ManagedDevices`、`DeviceAudioBus` | 拆：调度规则进共用层；`DeviceRadio` 变成平台层的蓝牙接口 |
| `AndroidDeviceLink`、`AndroidDevices` | 平台层的蓝牙实现；`createDevices` 里的品牌注册改为读驱动清单 |
| `DeviceSync` | 规则进共用层；数据库仍在平台层（Room），通过接口访问 |
| `plugins/sonicloud/` | 改成 4 级声云驱动（由 sheacoding 按样板做，合并 #14/#15） |
| PR #30 `plugins/d3200/` | 改成第一个 4 级样板驱动：去掉自己扫描、自己存设置、自带设置页；解密 / Opus 改走工具箱；经典蓝牙灯控走 `platformExtras` 并标“仅安卓” |
| 配对记录、补传进度按地址存 | 加数据库迁移：新增 `deviceId`，老记录保留地址作为“安卓替代身份”，不丢数据 |

## 9. 界面（Claude 做）

- 添加设备：自动搜索 + 按型号找（图片、别名、配对步骤）；同款多台用信号强弱 + “识别我”；匹配不确定时看图选。
- 设备卡片：只显示有的能力；多电池部件；未知 / 更新时间；控制按钮等设备确认；“试用”标与说明；被远程停用时显示原因。
- 设置项：按描述自动生成（开关、滑杆、胶囊点选、只读行）。
- 开发者模式：记录蓝牙通信、导出录包、TaoEcho 自检。
