# 任务卡 023：待办手动排序 + 记忆按天查看与 Markdown 导出（后端）

## 背景与已定方案（负责人已拍板）

- **待办不加“逾期”概念**。“进行中”改为可**长按拖动手动排序**；新接受的条目默认放最前面。“约定”按时间先后排。
- **记忆页加“按天”视图**：选某一天，看当天的回顾、时间线、当天的待办（新提到 / 当天到期 / 当天完成）、灵感等，原话可折叠。原有分类视图保留。
- **导出 Markdown**：单天、一周或任选范围，可选是否附原话，走系统分享。另有开关（默认关）：每晚备份时顺带把日记上传到坚果云 `回响日记/yyyy-MM-dd.md`。
- 界面全部由 Claude 做，**本卡只做后端**，不要改 `ui/` 下的文件。

## 约定（Claude 已写，签名不要改）

- `digest/MemoryContract.kt`：`MemoryItem` 新增 `doneAt`、`statusChangedAt`、`sortOrder`；新增 `DayItems`；`MemoryRepository` 新增 `inProgress()`、`appointments()`、`reorder(ids)`、`dayItems(date)`、`activeDays(month)`（接口里有默认实现，只是占位，请在真实仓库里覆盖实现），`setItemStatus` 注释里写了新规则。
- `diary/DiaryContract.kt`：`DiaryRepository`（`markdown`、`exportFile`、`cloudSync`、`setCloudSync`）。
- `AppGraph`：已加 `diary` 与 `isDiaryReady`，请在 `ResoundApp` 里赋值。

## 要做的

1. **数据库 9 → 10**：`memory_items` 加 `doneAt INTEGER`、`statusChangedAt INTEGER`、`sortOrder INTEGER`（都可空）。迁移时：已是 Done 的条目 `doneAt` 先填 `createdAt`（没有更准的时间，交付说明里写明）。加 `Index("dueAt")`。写 Migration 9→10，并跑一次 1→10 整链迁移测试。导出 `schemas/10.json`。

2. **状态与排序**
   - `setItemStatus`：同时写 `statusChangedAt = 现在`；转为 Done 时写 `doneAt = 现在`，离开 Done 时清空 `doneAt`；转为 Accepted 时 `sortOrder = 当前“进行中”的最小值 − 1`（没有则 0），即放到最前。从 Done 撤回到 Accepted 也放最前。
   - `inProgress()`：`status = Accepted` 且类别是待办或备忘；排序 `sortOrder IS NULL` 的排最后，先按 `sortOrder` 升序，再按 `createdAt` 降序。
   - `appointments()`：`status = Accepted` 且类别是约定；按 `dueAt` 升序，`dueAt` 为空的排最后（再按 `createdAt` 降序）。
   - `reorder(ids)`：在一个事务里把 `sortOrder` 依次写成 0、1、2…；不在列表里的不动。
   - 读出的 `MemoryItem` 要带上三个新字段。

3. **按天查询**（“一天”按手机本地时区的 0 点到次日 0 点）
   - `dayItems(date)`：
     - `mentioned`：当天提取（`createdAt` 在当天）的待办、约定、备忘，排除 Ignored，按提取时间先后；
     - `due`：`dueAt` 落在当天的待办、约定、备忘，排除 Ignored，按 `dueAt` 先后；
     - `done`：`doneAt` 在当天的，按 `doneAt` 先后；
     - `notes`：当天提取的灵感、关键信息、决定、知识，排除 Ignored，按提取时间先后。
     - 同一条可以同时出现在多组（比如当天提、当天做完），界面自己处理，不要去重。
   - `activeDays(month)`：该月里有事件（`memory_events.startAt`）或有条目（按 `createdAt`）的日期集合。两条 SQL 各取一次就行，别逐日查询。

4. **Markdown 生成** `DiaryRepository.markdown(from, to, includeLines)`，每天一节，格式固定如下（没内容的小节整节不写；整天都没内容就跳过这天）：

   ```
   # 10月23日 星期五

   ## 回顾
   一句话那行
   **要紧的**
   - …
   （其余栏目同上，按回顾里的顺序）

   ## 时间线
   ### 14:05–14:40 和客户聊会议室（会议）
   摘要文字
   - 要点 1
   - 要点 2
   人物：张三、李四 · 地点：公司

   ## 待办
   **当天提到**
   - [ ] 内容（截止 10月28日 14:00 · 对方：张三）
   **当天到期**
   - [ ] …
   **当天完成**
   - [x] …

   ## 灵感
   - …
   （关键信息、决定、知识同样各一节）

   ## 原话
   **14:05 我**：……
   **14:06 张三**：……
   ```

   - 回顾取 `ReviewRepository` 已生成的当天日回顾，没有就不写这节（**不要为了导出去调用大模型**）。
   - 时间线按开始时间先后，**跳过场景为“媒体”的事件**（外放的视频、音乐）。
   - 已完成的用 `- [x]`，其余用 `- [ ]`。
   - 原话只在 `includeLines = true` 时写；只取已转写的句子，按时间先后；说话人没有名字时写“某人”。
   - 多天时每天之间空一行，按日期先后；日期标题用 `M月d日 EEEE`（中文）。
   - `exportFile`：写到 `cache/diary/`，文件名 `回响日记_2026-10-23.md`（单天）或 `回响日记_2026-10-17至2026-10-23.md`（范围）。通过 FileProvider 返回 Uri；没有现成的 FileProvider 就加一个（只暴露 `cache/diary/`）。

5. **坚果云同步**（`cloudSync`，存 SharedPreferences `diary` 的 `cloudSync`，默认 false）
   - 打开时，每晚备份成功后，顺带把**最近 2 天**（今天和昨天，用来覆盖深夜才整理出来的内容）各生成一份**不带原话**的 Markdown，上传到 `回响日记/yyyy-MM-dd.md`（覆盖上传，目录不存在就建）。复用现有的 `WebDavClient`。
   - 日记上传失败**不能**让备份算失败：只记一条诊断，下次再传。
   - 把 `diary` 这个 SharedPreferences 文件加进备份的设置白名单（现在白名单里有 capture.xml、digest.xml）。
