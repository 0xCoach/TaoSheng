# TaoEcho 录包 v1

UTF-8、LF 分行，第一行必须为文件头；空行与后续 `#` 注释不参与通信。一个文件对应一次连接。

```text
#taoecho-capture v1 driver=card:example recordedAt=1794355200000 note=可选说明，可含空格
M 0 mtu=244
1 R service characteristic 0102
2 W service characteristic aabb
3 w service characteristic ccdd
4 N service characteristic 1122
5 D - - -
```

- 文件头 `driver` 是驱动编号，`recordedAt` 是录制开始时的 UTC 毫秒。`note` 可省略，不可换行。
- 普通记录为 `<相对毫秒> <方向> <服务编号> <特征编号> <十六进制字节>`。时间来自注入的单调时钟，相对录制开始计时，非负、不倒退；同一毫秒按行序执行。通道编号无空白、区分大小写，实际 BLE 应使用完整小写 UUID。
- `R` 保存读取返回值；`W` 带回应写、`w` 不带回应写，在调用底层前记录请求；`N` 保存通知原始字节；`D` 表示断开，其后三列都是 `-`。空字节也用 `-`；十六进制连续书写，不插空格、不交换端序。
- `M <相对毫秒> mtu=<值>` 的值是 **最大单次写入字节数**，不是 ATT MTU。省略模式时更新两种写入模式；可追加 `mode=W` 或 `mode=w` 表示只更新一种。包装器在 `maxWriteLength` 查询首次发生或结果变化时记录。无 M 的回放初值为 20；不据此推断手机 MTU。
- 异常扩展：`<相对毫秒> E <服务> <特征> <十六进制 UTF-8>`。解码文本为 `操作|错误码|说明`，操作是 R/W/w/N/M，错误码为 `ErrorCode` 名称、`Cancelled` 或 `Failure`。失败写入先有 W/w，再有 E；失败读取只有 E。M 的通道为 `- -`。说明可以含换行或 `|`，整段转十六进制后不会破坏行格式。录制端原对象重抛；回放端重建 DeviceException/取消异常，未知错误映射 ProtocolError。
- `# capture-stopped size-limit` 表示达到文件上限；`queue-full` 表示落盘跟不上，`cancelled` 表示写入任务取消。这些录包保留部分证据，`assertExhausted()` 会拒绝把它们当成完整测试通过。

包长、字节序、采样率、声道、序号及设备时间由驱动协议定义；录包只保留字节，不按通知次数猜音频时长。`AudioChunk` 输出遵循既有 16 kHz 单声道约定。

## 录制和安卓入口

`RecordingGattLink(inner, clock, sink)` 不加等待、不替换蓝牙异常；sink 必须快速且不阻塞，文件头和落盘由平台负责。通知记录的是交给收集器的数据；驱动同通道宜使用一个 GATT 收集器，再共享给内部消费者，避免把多次应用层观察当成多个物理包。下游消费者异常不记作蓝牙 E。`GattLink` 没有断开流，平台用 `recordDisconnected()` 补录 D（自动去重），没有修改约定签名。

`AndroidDevicePlatform.captureEnabled` 对应 `device-drivers` 中布尔键 `captureEnabled`，默认 false，修改后作用于新连接。驱动编号取中枢已保存的选择；没有选择时不创建匿名录包。初连记录两种写入长度，后续记录查询观察到的变化；没有新增 MTU 轮询。

路径：App 私有 `files/device-captures/<驱动>-<UTC毫秒>.txt`；同名时递增文件名时间避免覆盖，文件头仍保留真实开始时间。每个文件最多 20 MiB（20 × 1024 × 1024 字节，包括停止说明），达到上限关闭写入。256 条有界队列串行写盘；满时停止该文件并留下说明，不阻塞蓝牙。正常断开/关闭排空队列，连接 close 等待文件关闭。文件不可写时仍继续原蓝牙流程。

卡 144 可调用 `listCaptures(): List<DeviceCaptureFile>`（文件名、字节数、修改时间、是否录制中）与 `deleteCapture(name): Boolean`。删除只接受列表中的同格式文件名，活动文件返回 false。展示、分享和导出由卡 144 实现。

## 回放用法

在测试调度器的单一执行上下文使用 `ReplayGattLink(capture, masks)`。R/W/w 是严格有序的交互屏障；每次读写后立即推送紧随的 N、更新 M，直到下一次交互。D/EOF 结束通知。未订阅的通知暂存到第一次订阅，活跃的多个订阅者各收一份；读写不等待消费者。当前实现不按真实时间 sleep，录包时间可由 `elapsedMillis` 读取。

```kotlin
val mask = WriteMask(service, characteristic, positions = setOf(4, 5, 6, 7))
val link = ReplayGattLink(capture, listOf(mask))
// 按录包交互；行号、期望与实际值会出现在写入不匹配的 AssertionError 中。
link.assertExhausted()

val harness = ReplayHarness(toolbox, clock) // 显式注入测试解码器/加密、测试时钟
val live = harness.run(driver, capture, ReplayAction.Live(frames = 6))
val files = harness.run(driver, fileCapture, ReplayAction.Files(fromOffset = 0))
```

屏蔽位置从 0 开始，仅忽略该通道的对应字节，不忽略长度、方向或其他字节。助手执行 open、收集状态/关闭错误、实时 start/stop 或文件 list/read，最终关闭连接、定时任务和解码器。返回帧、总采样数、丢失采样数、出现缺口的帧数、文件清单/数据块、状态快照与错误。协议约定未提供精确 BLE 丢包数，因此不把采样缺口伪装成 BLE 包数。文件回放不 confirm/delete；部分读取失败仍保留已收数据。默认超时 5 秒，在 runTest 中使用虚拟时间；外部取消仍抛出，不转成成功结果。断言错误直接失败。

样板：`devices/src/jvmTest/resources/devices/replay/synthetic-live.txt`，14 行手工合成录包，配合原有 `synthetic.json`、CardParser、FrameCodec 和测试 Opus 解码器。它证明回放链路，不证明真实 Opus 解码或真机 BLE。
