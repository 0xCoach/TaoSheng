# 卡 233：设置与密钥读取进共用层——多组键值插口、密钥插口、服务商与转写配置共用

## 背景

卡 231 已把 `PlatformServices` 和建库配置移入共用层，卡 232 让 Swift 能直接调用共用层。下一步要让"服务商、模型、Key、请求头、转写配置"的读写规则在共用层，平台只提供存储：安卓继续用 SharedPreferences + Keystore，以后别的平台用自己的安全存储。本卡是之后迁移整理、问问、云端转写执行器的前提。**安卓行为必须完全不变：老用户升级后所有设置、Key、自定义请求头都还在、还能用。**

先读：`AGENTS.md`、`docs/任务卡/231-共用核心起点.md`、`docs/任务卡/231-交付说明.md`、`docs/任务卡/232-iOS框架产出.md`、`shared/.../platform/PlatformPorts.kt`、`shared/.../platform/PlatformServices.kt`、`app/.../platform/AndroidPlatform.kt`、`app/.../digest/SecretStore.kt`、`AndroidLlmProviders.kt`、`AndroidDigestSettings.kt`、`ServiceHeaders.kt`、`app/.../transcribe/AndroidTranscribeSettings.kt`、`AndroidHotwordSettings.kt`，以及共用层已有的 `LlmProvidersContract.kt`、`LlmPreset.kt`、`HeaderEntry.kt`、`DigestPreferenceStore.kt`。

## 要做的

1. **多组键值插口**：安卓现在按组（`transcribe`、`digest`、`llm-providers` 等）分文件存偏好。在共用层提供按组打开的键值存储（如 `KeyValueStores.open(group)`），按需要补齐 `getInt/putInt`、字符串集合，以及"同组多键一次提交"的原子写入（对应现在 `edit()...commit()` 成组提交的地方）。安卓实现直接映射到同名 SharedPreferences 文件。`PlatformServices` 增加这个字段；原有单一 `keyValueStore` 保留不删。
2. **密钥插口**：在共用层定义 `SecretVault`（按组读、写、删、是否存在；不得记录日志、不得出现在异常信息里）。安卓实现包装现有 `SecretStore`，组名、别名、密文字段名、加密方式完全不变，老密文照样能解开。
3. **服务商与模型配置移入共用层**：把 `AndroidLlmProviders` 里与平台无关的部分（已存服务商列表、当前选择、预设模板、Key 与自定义请求头的读写和"免 Key 来源"的判定、设置变化通知）移到 commonMain，只依赖第 1、2 条的插口和 `LlmClient` 等已在共用层的接口。`ServiceHeaders` 的秘密头同理。安卓侧留一个薄壳或直接改用共用实现，调用方改动尽量少。
4. **转写配置移入共用层**：`AndroidTranscribeSettings`、`AndroidHotwordSettings` 中的服务商、模型、端点、地址模式、间隔、热词、语言、Key 的读写规则移到共用层；安卓特有部分（本地模型进程、系统能力检测等）留在 `:app`。
5. 不能一次搬干净的（例如依赖 `Context`、`PackageManager`、`org.json` 的片段），先用插口隔开或留在安卓，写进交付说明，不要硬搬。

## 不要做

- 不改偏好文件名、键名、值格式、密文格式、默认值；不改 UI 包、`MainActivity.kt`、`*Contract.kt`、`AudioSource.kt` 签名。
- 不迁移整理、问问、推送、转写执行器本身（后续卡）。
- 不新增或删除服务商预设，不改任何服务商的请求行为。
- 不升级依赖、不引入 Hilt 或新存储库（DataStore 等）。

## 验收

- **升级对照测试（重点）**：用"旧版本写入的偏好 + 旧密文"夹具（Robolectric 或现有测试方式），升级后经新共用实现读出：服务商列表、当前选择、Key、自定义请求头（含秘密头）、转写服务商/模型/热词/语言全部一致；改一项后再读，其他项不变；成组写入中途失败不留半套。
- 共用层 jvmTest：用内存版键值和密钥插口，覆盖服务商增删改选、免 Key 判定、设置变化只通知一次、转写配置默认值。
- 必跑：`python3 tools/check_shared.py`、`./gradlew :shared:check`、`zsh tools/check_ios.sh`、`zsh tools/build_ios_framework.sh debug`、`./gradlew :app:assembleDebug` 和本卡相关的安卓单测（含已有的设置、密钥、服务商相关测试）。JDK 21（`/opt/homebrew/opt/openjdk@21`），`ANDROID_HOME=/opt/homebrew/share/android-commandlinetools`。
- 交付：在本分支提交（中文提交信息，不推送），写 `docs/任务卡/233-交付说明.md`：搬了哪些、留下哪些及原因、键名与密文不变的证据、真机注意事项、后续迁移整理执行器时的阻碍。
