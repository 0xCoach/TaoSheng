“录音”= 手机里保存的原始录音段（`files/segments/<日期>/*.ogg`），**OGG 原样，不转码**。只处理原声还在的段（受原声保留天数影响）。

## 一、录音批量导出（`RecordingPacker`）

- 选日期范围 → 打成一个 zip，保存到 `下载/Resound/录音包/`（MediaStore，同卡 068 的保存方式，不要存储权限）。
- 文件名：`涛声录音 2026-10-28 至 2026-10-29.zip`（单天写一天）；重名加“（2）”。
- zip 里按天分文件夹：`2026-10-29/14-05-33 3分12秒.ogg`；同一秒冲突加序号。zip 用**仅存储不压缩**（OGG 本身已压缩），流式写出，不在内存里攒整个包。
- `withText`：每段一个同名 `.txt`（该段原话，带说话人）；根目录一份 `原话.txt` 总表（每行：日期 时间、时长、文件名、原话首句或全文）。没转写的段写“（未转写）”。
- `skipMedia`：跳过事件场景为“媒体”的段，以及卡 070 判为已跳过（`SkippedEnv`）/ 疑似影视的段。
- 后台任务，仿卡 069（WorkManager + 前台通知“正在打包录音 35%”+ 取消）；完成通知点开 App。取消或失败删半成品。
- `estimate` 返回天数、段数、总字节、总时长（直接按文件大小加总，快）。
- `availableDays`：原声还在的日子，新的在前。
- `shareUri`：给分享用的 content:// 地址。

## 二、录音推送：推送通道订阅里加一项（负责人要求：放在原有推送通道里）

约定在 `push/PushContract.kt`：`PushSubscription.audio / audioWithText / audioWifiOnly`、`PushCapabilities.audio`、`AudioPush`、`AudioPushStatus`、`PushChannels.audioStatus(id)`。

- **只有“坚果云同步文件夹”（`PushKind.MarkdownFolder`）支持**：`capabilities(MarkdownFolder).audio = true`，其余 false。用该通道已有的账号（含 `useLinkedNutstore` 连接的数据备份账号）和文件夹。
- 云端路径：`<通道文件夹>/录音/<日期>/<HH-mm-ss> <时长>.ogg`，原话 `.txt` 同名（`audioWithText`）。不碰该通道已有的 Markdown 文件和 `my-notes/`；“全部重新生成”（`rebuild`）**不删**录音目录。
- **推哪些**：`Speech` 等转写完成再推（媒体场景、卡 070 判为已跳过 / 疑似影视、转写为空的不推）；`All` 落盘即可推。txt 在转写完成后推，之后重新转写（卡 071）则覆盖。订阅里 `excludeMedia` 同样生效。`rangeDays` / `backfillDays` 沿用：首次开启按 `backfillDays` 补传原声还在的段。
- 条件：`audioWifiOnly`（默认开）用 WorkManager 网络约束；批量上传，失败指数退避重试；和现有文字推送互不阻塞（录音失败不影响文字推送）。
- **只传不删**：本机原声过期删除时云端不删；记已传过，云端被删也不重传。
- `audioStatus`：已传、待传、本月已传字节、按最近 7 天估算的每月上传量、最后时间、最后错误（给人看的原因：“坚果云账号或应用密码不对”“坚果云本月上传流量用完了”等，按实际返回码映射）。推送日志里记一条“上传录音 N 段”。
- 问题记录里推送诊断一节加：哪些通道开了推录音、已传/待传、本月字节、最近错误（不含账号、密码、文件内容）。
- 已传记录等状态用本卡自己的小存储（见开头），不改 `CaptureDatabase`；订阅字段随现有通道配置一起存（沿用现有的订阅 JSON 存法，旧数据缺字段按默认值）。
