# 卡 128 · 更新前备份提前到下载完成后（点“安装”立刻弹系统确认）

- 工作目录 `~/Developer/TaoSheng-128`，分支 `codex/128-backup-before-ready`（从 `plan/0221` 拉出）。**不改 `ui/`**，界面文字由 Claude 改。
- 版本：进 0.2.21 正式版。

## 背景

现在应用内更新：下载好 → 用户点“安装” → `UpdateEngine.install()` 先跑 `platform.backup`（显示“正在备份”，几秒到一两分钟）→ 再交给系统 → 系统弹确认框。负责人觉得每次都要等备份、点两次很别扭。

## 目标

下载并校验完成后，**在后台自动做更新前备份**；用户点“安装”时，如果这份备份还新鲜，就**直接**交给系统，系统确认框立刻弹出。

## 要做

1. 下载/组装完成并 `verifyReady` 通过、状态进入 `Ready` 之后（在下载所在的后台任务里），接着跑一次 `platform.backup`：
   - 成功：记下 `preBackupFor = 安装包 sha256` 和 `preBackupAt = 时间`（存 `AndroidUpdateStore`）。
   - 失败：只记诊断，不改变 `Ready`，不报错给用户（点安装时会再备份一次）。
   - 备份进行中用户点了安装：等这次备份结束再用它的结果，不要并发跑两次备份（用现有 `gate` 或单独锁）。
2. `install()`：若 `preBackupFor == 当前 sha256` 且 `now - preBackupAt < 6 小时`，**跳过备份**直接 `platform.install`；否则照旧先备份（保持现有失败处理“更新前备份没成功，没有安装”）。
3. 新的安装包（版本或 sha 变了）、或用户取消后隔了很久，都按上面规则自然失效，不需要额外清理。
4. 诊断里记一行：安装时是否复用了预先备份、备份耗时。
5. `UpdateState` 约定不改。如需让界面知道“已经备份好”，在交付说明里写清楚，由 Claude 决定是否加约定。

## 必测（4～8 个用例）

- 下载完成后自动备份一次，记下 sha 和时间。
- 点安装时备份新鲜 → 不再备份、直接安装。
- 备份过期或 sha 不同 → 先备份再安装。
- 预先备份失败 → 仍为 Ready，点安装时照旧备份。
- 备份进行中点安装 → 不并发备份两次。
