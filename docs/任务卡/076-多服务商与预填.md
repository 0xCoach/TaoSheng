## 背景
现在整理模型只有“DeepSeek / 自定义”两档，自定义只能存一份。负责人要：常见服务商列出来点一下自动预填（地址、模型、余额查询），用户只填密钥；可保存多个，随时切换。

## 第一部分：调研（先做，产出数据文件）
为下列服务商查**官方文档**（记链接与查询日期），产出 `app/src/main/assets/llm-providers.json`（字段对应 `ProviderTemplate`）和 `docs/任务卡/076-服务商调研.md`：
DeepSeek、硅基流动 SiliconFlow、月之暗面 Kimi、智谱 GLM（BigModel）、阿里云百炼（通义千问，DashScope 兼容模式）、火山方舟（豆包）、MiniMax、百度千帆、腾讯混元、阶跃星辰、零一万物、OpenRouter、OpenAI。查不到/已停服的写明不收录。
每家要：
- OpenAI 兼容接口根地址（chat/completions 所在）；是否需要额外请求头。
- 推荐模型 2～4 个（第一个为默认：适合本 App 的“整理/问问”，便宜、中文好、长上下文、支持流式；写清理由和单价）。模型 ID 以官方文档为准。
- `/models` 是否可用。
- **余额查询**：是否有“用同一个 API Key（Bearer）就能查”的接口；有则给 URL 与余额字段路径（点分，如 `data.totalBalance`），单位是否为元；需要 AK/SK 签名或控制台登录的写 `balance: null` 并说明原因。
- 申请密钥的网页地址；一句话 note（如需实名）。
**有条件的话实测**：本机 `~/.config` 或负责人已给的密钥里若有该服务商的，可用来实测余额和 /models（只读调用，不打印密钥）；没有就只按文档，报告里标“未实测”。

## 第二部分：后台实现
1. `AndroidLlmProviders : LlmProviders`：模板从 assets 读；保存的服务商存 SharedPreferences（JSON 列表），密钥存现有 secrets（`key-<id>`）。
2. **迁移（关键，不能丢密钥）**：首次启动把现有 `deepseek`（若有密钥）和 `custom`（若填了地址/模型）转成 SavedProvider，**沿用原 id**（`deepseek`、`custom`），原 `preset` 选中项成为 activeId。原 `custom` 的余额查询（`llm-balance` prefs 的 customUrl/customPath）并入该服务商。没有任何已存的：建一个 `deepseek` 模板项（无密钥）作为当前。
3. `AndroidDigestSettings` 与之打通：`presets` = 已保存列表映射成 `LlmPreset`，`presetId` = activeId，`readKey`/`skillCredentials(id)`/`test`/`check` 按 id 取；现有调用方（整理、问问、回顾、技能、重做 `RedoFactory`/`AndroidRedoService`、`LocalSkillRepository`）不改语义。技能指定的服务商被删时回到跟随整理模型。
4. 余额 `LlmBalanceChecker` 改为读当前服务商的 balanceUrl/balancePath（DeepSeek 模板自带），切换服务商后缓存与“已提醒”状态按服务商分开。
5. 装配到 `AppGraph`：`lateinit var llmProviders: LlmProviders` + `isLlmProvidersReady`。

## 测试（适度，5～12 个）
迁移（deepseek+custom 都在 / 只有 custom / 都没有）、密钥不丢、切换后 presetId 与 readKey 正确、删当前被拒、技能引用被删回落、余额按服务商分开、assets 模板能解析。
