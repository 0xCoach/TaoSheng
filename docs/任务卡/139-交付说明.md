## 构建选择与编译门禁

采用 `com.android.library` + `androidTarget()`，另开 `jvm()`。在本仓库固定的 Kotlin 2.2.20 / AGP 8.11.1 下，这条既有 Android 库路径能直接对接 App 的 debug/release 变体，不必同时切换 Android KMP 新插件的 DSL。官方兼容表覆盖这个组合：[Kotlin Multiplatform 兼容说明](https://kotlinlang.org/docs/multiplatform/multiplatform-compatibility-guide.html)。

保留 compileSdk 36、minSdk 29、JDK 21 工具链及 JVM 17 字节码；Compose BOM 和 App 原依赖声明不变。commonMain 显式依赖只有 coroutines-core 1.9.0（对外接口含 Flow，因此用 api）和 serialization-json 1.9.0，另有 Kotlin 插件自动添加的标准库。serialization 编译插件与 Kotlin 同为 2.2.20；JSON 1.9.0 基于 Kotlin 2.2：[官方发布说明](https://github.com/Kotlin/kotlinx.serialization/releases/tag/v1.9.0)。

**仅有 Android/JVM 两个目标时，KGP 2.2.20 默认禁用共用 metadata 编译。** 本卡在目标注册完成后显式启用 `compileCommonMainKotlinMetadata`，并将它挂到 JVM、Android debug/release 编译和 `check`。这样常规 App 构建也必须经过无 JDK 的共用编译器。

实际验证：临时向 commonMain 放入 `java.io.File` 和 `android.content.Context`，执行 `:devices:compileKotlinJvm`，在 metadata 阶段出现对应 `Unresolved reference` 并失败。探针在 finally 中删除，正常源码随后通过编译。以后升级 KGP 时应保留这个门禁验证；不能把 metadata 的 `SKIPPED` 当作通过。

## JSON 严格规则及原字节验签

- 保留原 `StrictJson` 前置扫描，包括标准语法、尾部内容、嵌套深度、重复字段检查；字段名先解码转义，再判断重复，所以 `id` 与 `\u0069d` 仍冲突。仅把字符串解码改为 kotlinx.serialization。
- 扫描通过后才构造 `JsonElement` 树；保留各层字段白名单、引用关系、枚举、UUID、命令、版本、数值范围、空值和数组检查。
- 明确区分 JSON 字符串、布尔和数字；整数只接受未加引号的整数形式，再按 Long 和原字段范围校验。`"247"`、`247.0`、`2.47e2`、布尔值和超出 Long 的值都不能混成整数。已有中文错误含义保持不变。
- 原 256 KiB 限制仍按原实现的字符串长度判断，本卡未改这一语义。
- 远程验签代码完全未动：`Signature.update(table.json)` 仍直接使用收到的原始字节，验签通过后才解析表；没有先解析再序列化验签。App 的远程卡测试继续验证篡改、缓存、防降级及 Python 生成的 P-256 DER 向量。
