# 卡 224 交付说明：自定义转写"分说话人"模式也带热词（#48）

## 起因
#48 里"分说话人"模式按 OpenAI `gpt-4o-transcribe-diarize` 的格式请求（`diarized_json`）。这个接口不收 `prompt`，所以之前直接不发热词，这个模式下热词完全用不上。11-21 有自建服务的用户提了两个方案，当时漏回了，这次按他推荐的方案 B 做。

## 做了什么
- 分说话人模式且有热词时，multipart 多发一个 `definition` 字段，内容是 `{"phraseList":{"phrases":[...]}}`（Azure 快速转写的短语列表结构）。不带 `locales`，避免把语种写死。
- 热词去掉首尾空白、去空、按原顺序去重，最多 500 个（同千问）。没有热词、或"附带热词"开关没开（完整地址模式）时不发。
- `prompt` 逻辑不变：自动模式照旧发 `prompt`，分说话人模式仍不发 `prompt`。
- **兼容兜底**：带 `definition` 的请求返回 4xx（401/403/404/405/429 除外）时，去掉它用同一段音频再发一次。去掉后成功，就在本进程内记住这个"地址+模型"以后不带，避免每段都传两遍；去掉后仍失败，照旧提示"这个模型不支持分说话人"，且不记住。记忆不写盘，重启后会重新试一次。
- 设置页"分说话人"说明补一句：热词另放在 definition 字段，服务不认会自动不带。

## 怎么验证的
- 新增 `DiarizeHotwords224Test`（7 个用例）：字段内容与去重、无热词不发、自动模式仍走 prompt、500 上限、被拒后去掉重发并按地址记住、模型本身不支持时仍报原提示、401/429 不重发。
- `Qwen212Test`、`CustomAsrFormats196Test` 等原有用例全过。

## 没验证的
- 没有连真实服务。OpenAI 官方接口对多余字段是忽略还是报 400 没实测，两种情况代码都兜住了。需要 #48 那位自建服务的用户联调。
