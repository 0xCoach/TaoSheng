# D3200 灯控通道音频接收修复（本地交付）

基线：上游 main 6bcf05c333767aea775d6aee7c6d39d65602dc51（0.3.0）。本地分支 fix/d3200-spp-audio，不合并旧 PR #30，也不恢复已替换的设备框架。

## 问题与改动

官方驱动开启灯控后通过 1A0F 和经典串口建立 SPP，但只有灯控回执等待器读取 SerialChannel.incoming；实时和补传只读取 BLE 通知。旧 PR 的 transport 会把 BLE 和 SPP 的普通协议帧交给同一个音频接收队列。新版遗漏了串口音频路径。

本次让连接持有 BLE 和 SPP 各一个持续读取器、各自一个分帧器；普通协议帧进入共享广播流，QC 灯控帧单独进入回执流。命令等待、实时接收、补传接收和灯控心跳分别订阅，避免 Android receiveAsFlow 的多个消费者互相抢包。关闭灯控释放串口读取器；关闭连接或初始化失败释放全部读取任务。保持原固件限制与命令，不修改驱动约定、界面、数据库或版本号。
