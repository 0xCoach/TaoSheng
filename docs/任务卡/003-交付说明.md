# 任务卡 003 交付说明

日期：2026-10-23。分支：`codex/003-transcribe`。本次仅实现转写底层；未改界面、MainActivity、AppGraph 或任何约定文件的签名。

## 做了什么

- Room 升级至 v2，提供显式 `MIGRATION_1_2`，保留 v1 全部表及数据，将旧“待转写”转换为 Pending。片段新增尝试次数、下次重试时间、错误、完成时间、logid、累计送出时长；新增句子表、按自然日的用量账本及尝试记录表。导出 v2 schema，未使用 destructive fallback。
- `AsrProvider` 隔离服务商；`DoubaoConfig` 集中管理地址、资源 ID、超时和可选发送间隔。默认采用卡 002 验证的 `bigmodel_nostream` + `volc.seedasr.sauc.duration`，按要求设置鉴权头、随机连接 ID 和分人/完整结果参数。
- OGG/Opus 不转码，保留原始字节，按完整 OGG 页发送；M4A 通过 MediaExtractor/MediaCodec 解为 PCM16，再混单声道、线性重采样至 16k。发送端有队列背压，默认快速上传，每请求总超时 90 秒。
- 只采纳服务端最终包；中间文字不入库。断连、超时或取消保留音频，结果原子地先删后写，避免重复句子。缺少句内起点时用上句终点（首句为 0），其余时间限制在片段内。绝对时间为片段开始时间加句内偏移。只存请求内临时 speakerTag，speakerName 始终 null。
- WorkManager 默认每 30 分钟、仅不计流量网络；支持 45/60 分钟。设置变化更新周期任务及已排队的立即任务约束。`runNow()` 创建唯一加急任务，额度不足时退化为普通任务；补齐 Android 10/11 加急前台通知。队列、立即任务和密钥测试共用一把锁，按开始时间逐段上传，不合并、不并发。
- 网络、超时和暂时服务错误按 1/2/4/8 分钟退避，WorkManager 同时执行自己的退避与网络约束，实际重试可能更晚。每段最多尝试 5 次；不可重试错误留在 Failed，`retryFailed()` 将 Failed 清零重放。鉴权/未授权立即停止本轮，只消耗当前段一次尝试，`lastError` 为“密钥无效或未开通”。无密钥不上传，提示“还没填写转写密钥”。进程中断的 Running 在下次任务中恢复为 Failed 并按次数上限继续处理。
- 用量在首个音频包进入发送队列之前按整段时长预记到当天及片段累计量，失败不退回；崩溃或只发出部分音频也保守计整段。这是 App 侧送出时长估计，不是服务端账单。今天/累计秒数在累计毫秒后取整；3 秒密钥测试也入账。
- 每轮顺带清理 Done/Empty 且完成满 24 小时的录音，数据库及句子保留。Pending/Running/Failed 不删除；删除失败下轮重试。文件可用性按真实文件检查，并随库变化或每分钟刷新。
- 使用 Android Keystore AES-GCM；本地偏好只保存 IV 和密文，未使用 EncryptedSharedPreferences。异常只保留固定中文及错误枚举，禁止保存底层异常、请求头或服务端错误原文；logid 和密钥测试返回文本均额外过滤完整密钥及组成部分。
- `test()` 使用内置 3 秒 OGG/Opus：从卡 002 合成独白截取第一句（实测字级终点 2.2 秒，取前 2.3 秒），补静音至 3 秒；容器时长 3.0065 秒，保守按 3007ms 计入。测试与正常队列共用识别实现。临时转码/测试文件在 finally 删除，进程崩溃遗留的这类缓存在下次启动清理。
- 在 `ResoundApp.onCreate` 手工装配 `AppGraph.transcripts/transcribeSettings`。`exportDiagnostics()` 增加队列概况和最近 20 次尝试的结果、错误类型、耗时、保守送出时长及安全 logid；不含识别原文或密钥。

## 界面接入与小米 14 Pro 实测

由负责人/Claude 接入界面，本卡不增加界面代码：

1. 用 `AppGraph.transcribeSettings` 提供密钥保存/清除、是否已填写、30/45/60 分钟、仅不计流量网络及测试入口。密钥输入不回显已有值。点击测试会真实发送约 3 秒并计入用量。
2. 用 `AppGraph.transcripts.day(date)` 展示当天（按片段开始日归属，倒序）的状态、原话和文件可用性；`queue` 展示数量、用量、上次/计划时间、错误；按钮接 `runNow/retryFailed`。
3. 在有卡 001 数据的安装上覆盖升级（不要卸载），核对旧录音、统计、守护记录仍在，旧片段变 Pending。全新安装也验证。
4. 填正确密钥并测试；真实录音完成入库后立即运行，核对 OGG、绝对时间、原话、Done/Empty、用量及 logid。正在录的未入库段不应被上传。用真人近场、远场、口袋噪声及 1 秒/5 分钟边界另外验收。
5. 验证设备产生的 M4A 回退文件能够解码识别，重点检查采样率、声道、时长、开头尾部及内存占用。此路径尚未经过实体手机编解码器实测。
6. 连续点立即运行并等待周期触发，应只有一段在 Running。切飞行模式/中断网络，确认不采纳中间文字、文件保留、退避、恢复后只写一份句子。上传时杀进程再重开，检查 Running 恢复、次数上限和累计用量不归零。
7. 用无效/未授权密钥验证首段失败后本轮停止、后续片段次数不增加；换有效密钥后手动重试失败段。清除密钥后应提示未填写且不上传。
8. 开启“仅 WiFi”时，蜂窝及计流量 WiFi 不应发送；切换设置后已排队任务同步约束。这里实际语义为“不计流量网络”，不是单纯判断 WiFi 类型。锁屏/省电/重启后检查周期任务实际延迟及排队状态，不要求准点。
9. Done/Empty 完成满 24 小时后，下一轮任务才删除录音；文字/记录仍在、audioAvailable=false。Failed/Pending/Running 即使超过一天仍有文件。用独立测试数据验证边界，避免调整日常手机系统时间影响其他业务。
10. 导出诊断，核对队列与最近 20 次结果/错误类型/耗时，不应出现原话或密钥；重启 App 后密钥仍可用且界面只显示是否已填写，不回显内容。Keystore/系统安全区须由真机验证。

## 遗留与边界

- 尚未做本卡真实联网或真机验收；小米后台调度、Android Keystore、AAC 解码、全天积压、极短/5 分钟片段均待实测。周期/重试时间是最早计划，不保证系统准点运行。单次密钥测试等待当前队列锁释放。
- 24 小时是最短保留期；没有满足约束的任务运行时，清理会延后。文件删除失败不修改成功状态，下轮继续尝试。
- 快速发送沿用卡 002 方案；已集中提供 paceMillis 调整入口，但长片快速发送和服务长期限流仍待实测。不可重试的协议/音频错误直接保留 Failed，修复后人工重试。
- speakerTag 只是请求内临时编号，不表示真实身份，不能跨片段认人；卡 002 已观察到分人错误。本卡没有合并、认人、整理、导入或费用人民币换算。
- 用量账本按首包前的整段预记，可能高于实际出机/服务计费时长；不声称等于火山账单或剩余额度。
