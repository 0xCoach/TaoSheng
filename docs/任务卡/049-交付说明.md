# 卡 049 交付说明

## 实现

- 保留无障碍读取原文；面板退去后恢复可读节点时也直接读原文。读不到输入框或文字时，通过 `AccessibilityService.takeScreenshot` 和 ML Kit 内置中文模型在手机上识字。
- **（Claude 审核时改为负责人最终定的三张方案）**停止录音后 0.5 / 1 / 3 秒各截一张，每张失败不重试，三张各自独立识字（去掉了“上一张没识完就拒绝下一张”的限制）。输入框文字以 1 秒为准、没截成用 0.5 秒；3 秒那张出现与输入框相近、且之前上下文里没有的靠右气泡，就以气泡为准（真正发出去的那句）。0.5 秒前离开不截不记；中途离开，已识出的照用，后面的不再截。切应用、暂停、锁屏、关闭开关、新语音窗口都会使尚未完成的识字结果失效。
- 截图、硬件缓冲和软件位图仅在内存存活；系统回调关闭硬件缓冲，识字完成（含失败）回收位图并关闭识别器。没有图片文件写入或图片上传代码；诊断日志仅记录步骤、错误码、块数、字数。
- 按系统输入法窗口上沿过滤键盘，拿不到时排除屏幕下方 40%；按系统栏及刘海边距过滤状态栏、导航栏。两条路径共享界面文案和时间戳过滤规则。
- 按位置合并输入法上方最近的一段文字，提取上方最近 20 行／1500 字上下文及顶部标题。应用区域全黑、尺寸变化或没有贴近输入法的原话则跳过。
- 两条路径均不补记回复，新记录 `after`、回复等待时间均为 null；读取、更新旧设置时强制 `replies=false`。补齐 `screenOcr` 的保存和读取，默认 true。
- 去重在数据库事务中执行：同应用上一条原话在 30 分钟内规范化后完全相同就不再存；同应用同标题累计检查 30 分钟内已存的上下文和自己的原话，连续三段只保留新增行。标题均为空时按同应用处理。上下文全重复存 null。
- 规范化只统一 Unicode NFKC 形式和连续空白，保留标点、大小写、运算符；不做语义合并。录音转写的既有相似度重复检查保留。
- 未修改界面、MainActivity、约定签名或数据库版本；没有操作手机。

## 真机验证（负责人执行）

1. 安装后把回响无障碍服务关闭再开启，使新增截屏能力生效；确保回响正在收音、屏幕已解锁，打开语音输入记录和截屏识字开关。可断网验证首次中文识字不依赖模型下载。
2. 微信给“文件传输助手”或联系人语音输入一句／多行，停止后在原页面停留约 2 秒再发送。检查只留一条自己的原话，标题与之前上下文合理，没有之后回复。Claude 查看 `VoiceInputDbg`：一次“请求 1 张”、识字块数和字数，日志不得出现文本内容。
3. UU 远程终端语音输入一次，检查取输入法上方最下面一段命令／文字，历史输出仅作上下文，不把键盘候选存入。
4. 微信同一聊天连续输入三段，每次增加一条对方上下文；后两条只保存新增上下文，自己的前两句不再出现在上下文。重说完全相同的上一句不再存；换聊天时新上下文不应被旧聊天过滤。
5. 小米备忘录输入一次，确认仍走原文路径，没有“截屏识字：请求”日志。关闭截屏识字后再试微信，应无截图记录。
6. 停止语音后 1 秒内切应用；另外试锁屏、暂停和安全页面。应不留下截图识字记录；截屏失败不连续重试。

## 遗留与边界

- 微信／UU 实际 OCR 效果与澎湃 OS 回调尚未实机验收。坐标分组及标题是启发式判断，浮动键盘、特殊布局、很长的输入、多窗口可能漏记或误分组。
- 单张只能读当时屏幕可见文字；若已立即发送、输入框已清空，不回读气泡，也不补截。输入法窗口坐标缺失时的下方 40% 是兜底假设。
- Android 29 保留读节点路径；截图路径只在 API 30+ 使用。
- 开发期间负责人把方案改为三张截图（0.5 / 1 / 3 秒），Codex 交付的是单张版本；Claude 审核时已按三张实现并重写相关用例（048 共 12 个、049 共 10 个，全部通过）。
