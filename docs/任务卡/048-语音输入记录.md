# 卡 048 · 记下语音输入的文字和当时的上下文（后端）

负责人定（10-24）：用输入法语音输入时系统把麦克风交给输入法，回响录不到。改为用**无障碍服务**记下语音输入出来的**文字**，存成一句“我”说的话；同时记下**当时屏幕上的上下文**（之前的内容 + 发出后 2 分钟内的回复）。上下文**要进备份、坚果云同步文件夹和推送**（推送可单独关）。

**约定**（签名不要改）：
- `capture/VoiceInputContract.kt`（新）：`VoiceInputSettings`、`InputApp`、`VoiceInputCapture`；`AppGraph.voiceInput` / `isVoiceInputReady` 已加。
- `transcribe/TranscribeContract.kt`：`TranscriptLine.voiceInput: VoiceInputMeta?`、`VoiceInputMeta(app, packageName, title, before, after)`。
- `push/PushContract.kt`：`PushSubscription.lineContext`（默认 true）。

界面（录音与后台页“语音输入”开关与不记应用、原话里的“⌨ 语音输入”标签与可展开上下文、推送里“带上语音输入的上下文”）Claude 已在 main 做好。
**分支 / 工作树**：`codex/048-voice-input`，`~/Developer/resound-codex-048`。

## 一、无障碍服务

1. 新建 `VoiceInputService : AccessibilityService`，清单与配置 xml（描述用中文，说明只在语音输入时读输入框和当前对话、密码框不读）。监听文字变化、焦点、窗口内容 / 状态变化；`canRetrieveWindowContent = true`。设置关着时服务什么都不做。
2. `serviceEnabled`：读 `Settings.Secure.ENABLED_ACCESSIBILITY_SERVICES` 并用 ContentObserver 跟着变。
3. **回响自己暂停 / 停止录音时不记**；回响自己的界面不记；`excludedPackages` 不记；`isPassword` 的框永远不读。

## 二、判断“这是语音输入”

1. 用 `AudioManager.AudioRecordingCallback` / `activeRecordingConfigurations` 判断“有别的应用在录音”（不靠回响自己是否在录，外接麦时也成立）。从开始占用到释放后 **3 秒**为一个“语音窗口”。
2. 窗口开始时记下当前获得焦点的可编辑框的文字；窗口内及结束后跟踪它。**新多出来的文字**（与开始时对比，取插入部分）就是语音输入结果。说完就点发送、框被清空的情况：用清空前最后一次看到的文字。没多出来或被删掉就不记。
3. 同一句不重复记；连续几次语音输入各记各的。
4. 如果同一时间录音转写里已有意思相同的句子（±30 秒、文字高度相似），不再重复存。

## 三、上下文

1. **之前**：窗口开始时读当前窗口可见文字（排除输入框本身、按钮、状态栏等明显的界面文字，尽量只留对话内容），保留最近约 20 行 / 1500 字。
2. **界面标题**：尽量读出聊天对象 / 页面标题（如“老王”“ChatGPT”），读不到为 null。应用名用系统里的应用名。
3. **之后**：发出后 2 分钟内，同一应用同一界面新出现的内容（不含你自己那句），在 2 分钟到点或离开该界面时定稿，**只补记一次**。`replies` 关着不记；`context` 关着两者都不记。
4. 读不到（自绘界面等）就只记你那句，不报错。

## 四、存储与使用

1. 存成一条原话：`speakerName = "我"`、确定身份（不参与声纹判定，也不当声纹样本），挂在一个“语音输入”来源的无音频片段上（`sourceId = "voice-input"`，状态为已转写，`audioAvailable = false`），时间为窗口开始时刻。上下文与来源字段落库（库 16 → 17，字段设计你定；迁移测试用 `CaptureDatabase.VERSION`）。原话页、按天、搜索、整理、问问都能正常看到。
2. **整理**：把这句连同上下文一起送进整理，上下文标明是“资料”。提示词规则：用上下文理解这句话；**只从“我”说的话里提待办、约定**，别人的消息只用来补全对象、时间、内容（例如对方问“报告明天能交吗”，我说“好的，明天下午给你”→ 待办“明天下午把报告交给老王”）。验证只用**自己编的对话**（6～8 条，含容易误判的：别人提要求我没答应、AI 回答里的建议、终端输出），用 DeepSeek 跑（密钥从 `~/.config/resound/deepseek.key` 读，不打印），结果写进交付说明。
3. **问问**：取原话的工具结果里带上来源和上下文（可截断）。
4. **备份**：随数据库走；`VoiceInputSettings` 随设置备份（卡 037 规则）。
5. **推送**：原话里带上来源标签；`lineContext = true` 时带上下文。坚果云同步文件夹的 transcripts 文件里，这句后面加“⌨ 语音输入 · 微信 · 老王”和引用块形式的上下文；Webhook 的 line 数据带 `voice_input` 对象。
6. `todayCount`、`seenApps`（记过的应用，最近的在前）。

## 五、隐私与日志

- 日志、值班记录、诊断导出里**绝不写入输入的文字或上下文内容**，只写条数和应用名。
- 不联网发送除整理 / 推送本来就会发的内容之外的任何东西。

## 六、必测（8～12 个）

1. 语音窗口判定：别的应用录音开始 / 结束 + 3 秒；回响暂停时不记。
2. 取插入文字：中间插入、末尾追加、发送后清空、删掉不记、密码框不读、排除的应用不记。
3. 与录音转写重复的不存。
4. 上下文：之前截断与去掉输入框；之后只补记一次、2 分钟定稿；开关关掉不记。
5. 落库与迁移；原话映射出 `voiceInput`；不进声纹。
6. 整理输入里带上下文；推送 / 文件夹输出带标签与上下文、`lineContext=false` 时不带。
