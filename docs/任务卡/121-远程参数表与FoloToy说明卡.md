## 要做

### 1. 参数表格式与签名
- 一个 JSON 文件 `device-cards.json`：`{"version": 整数, "issuedAt": "...", "cards": [说明卡…]}`，外加同名签名文件 `device-cards.json.sig`。
- 签名用 **Ed25519**：App 里内置公钥；私钥只在负责人电脑上（`~/.config/taosheng/cards-signing.key`，不进仓库，权限 600）。
- 写一个签名脚本 `scripts/sign_device_cards.py`：读私钥、签名、输出 `.sig`；私钥不存在时生成一对并打印公钥（**生成后提醒负责人备份私钥**）。交付说明里写清负责人要做的步骤。
- App 验签失败、版本号比本地旧、JSON 解析失败：一律不用，保留旧的，记问题记录。

### 2. 加载与生效（实现 `DeviceCards`）
- 来源三层：包里自带（`assets/devices/*.json`，卡 118 放了 Omi、声云两张）→ 本地缓存的远程表 → 新取到的远程表。同 id 取 `version` 大的。
- 解析复用卡 118 的 `CardParser`（还没合并时先依赖它的接口，交付说明写明；或者先写最小解析，合并时由 Claude 收拢）。
- **启用规则**（负责人已定）：`verified` 默认启用；`trial` 默认不启用，用户在设备页手动打开；用户打开过的卡，更新版本后保持打开。
- 取表时机：App 启动后、每天最多一次；只在联网时；失败安静地等下次。地址：GitHub 仓库里的文件，取不到用魔搭镜像（与更新检查同一个镜像位置的思路，写清楚路径）。

### 3. FoloToy 说明卡
- 负责人手上有一张 FoloToy 开发卡，**支持蓝牙**。查它的开源固件和资料（GitHub 上 FoloToy 相关仓库），找出用蓝牙实时传声音的方式：服务和通道编号、开始/停止命令、声音格式、包外壳。
- 写成说明卡放 `assets/devices/folotoy.json`，`status: verified`（负责人会真机验证，不行再改）。
- **查不到确切协议就不要编**：写清楚查到了什么、缺什么，卡先标 `trial`，交付说明里列出需要负责人在手机上帮忙确认的事（比如用蓝牙调试 App 看服务编号）。
