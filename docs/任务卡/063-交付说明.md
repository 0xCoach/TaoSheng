- `transcribe/local/LocalAsrService.kt`：初始阶段改为 audio，路径检查/文件检查/解码完成才进入 speakers，识别模型初始化与推理属于 asr。Exception 和 LinkageError 回包增加异常类名。

- `transcribe/local/LocalAsrConnection.kt`：audio → `AsrError.Audio`，文件不存在的 detail 为“录音文件已不存在”；speakers → Speakers；asr → LocalEngine。缺失文件的 detail 由现有 TranscribeRunner 写入该段 error。
- `transcribe/local/LocalAsrProvider.kt`：音频错误直接返回，不再误触发 NPU 不可用判定或 CPU 回退。原有 asr 引擎失败自动再用 CPU 识别一次的逻辑保留，没有新增回退机制。
- 新增 `app/src/test/java/app/resound/transcribe/local/LocalAsrFailure063Test.kt`：4 个测试。

## 诊断

AsrAttempt 没有专门的异常类名列，未借用 logId，也未增加数据库字段。主进程收到失败回包后，在 PipelineTimes 增加一行：

`时间戳 本机转写 phase=audio errorType=Audio exceptionClass=java.lang.IllegalArgumentException`

IPC 只增加 exceptionClass 和 missingAudio；不传异常 message、cause、文件路径、识别文本。诊断阶段和类名经过白名单校验。现有运行诊断与问题记录导出已经包含 PipelineTimes，测试验证最终问题记录文件可见类名且不含敏感 message/路径。沿用最近 30 行容量。

## 重试和清理

- Audio 原本不在 ROUND_STOPPERS，现保持不变；单段坏文件不会终止整轮。
- 实际现有策略是 `Audio.retryable=false`：失败一次后 nextRetryAt=null，不再自动重试；并非每段重试 5 次。用户仍可通过已有手动重试入口再次尝试。本卡不更改此策略，避免坏文件反复消耗资源。
- 062 优先：日常原声清理和手动清除均保护所有 Failed 段（包括等待重试和已停止自动重试的），不额外删除已终止重试段。导入音频原有 3 天上限规则保持不变。
