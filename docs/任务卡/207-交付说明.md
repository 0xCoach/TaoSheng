## 已完成的后台行为

1. 共用人数规则按认出的姓名去重，“可能是我（未确认）”归入“我”。未知声音达到5句或计入句数的20%时只额外加1人。与会议事件重叠的计入原话可抵足人数门槛，仅在 minSpeakers ≥ 2 时使用。语音输入仍按配置整句排除。
2. 有门槛的卡在复核前补结束时间，优先使用有效引用原话的最晚 endAt，没有可用引用时取覆盖卡片起点的事件结束时间。多个事件覆盖时取时间范围最小的事件。补出的时间保存到卡片。普通运行、试跑、重做都使用共用规则。
3. 会议运行返回 Nothing 时，为本次输入中的会议事件分别保存说明，存入现有 skill_runs，使用独立的 meeting:event:事件编号记录，令牌数为0。记录不参与 meeting 技能的增量游标和自动次数。沿用现有运行日志清理策略。
4. 新增按事件手动生成入口，读取事件闭区间内的原话，只把这个事件交给模型，跳过调用前和逐卡人数/时长/句数门槛。输出起点限制在事件范围，允许选入的末句完整结束，沿用手动合并、日上限和模型调用/用量记录。该入口采用 event_manual 运行类型，避免推进全天自动整理游标或阻塞自动运行间隔。
5. 首次启动安排联网 WorkManager 唯一任务。最近2天解释为首次启动日及前一天，按历史时区确定归属日，日期固定后持久化。共用业务层逐天处理没有卡片覆盖的会议事件，同一天合为一次运行。补跑保留技能开关、正常门槛、软删除保护、每日卡片上限，跳过最短运行间隔。已有卡片及删除卡片覆盖的事件跳过。SharedPreferences 保存逐天完成凭据及最终完成标记，避免日志清理后再次补跑。取消时保留已完成日期，未完成日期恢复执行，已落库卡片可防止再次生成。

业务规则和补跑顺序位于 shared。Android 只提供数据库、启动与系统调度适配。数据库表结构和现有 Contract 签名未变。

## 给界面的窄入口

以下方法已在 SkillStoreRepository 和 LocalSkillRepository 提供，可由 Android 通过 LocalSkillRepository 调用。AppGraph.skills 目前声明为 SkillRepository，后续由 Claude 决定在约定中补入这些方法，或在界面适配层调用具体仓储。

- suspend fun meetingNothingReason(eventId: Long): String?。返回此会议事件最近一次 Nothing 的完整说明。事件不存在、场景已改变、尚无记录或记录已清理时返回 null。旧版的全天运行日志没有事件对应关系，不追认历史原因。
- suspend fun generateMeetingEvent(eventId: Long): SkillRunResult。用于“仍要生成”，返回卡片、Nothing 或 Failed。调用时重新检查事件仍存在且 scene 为会议。界面可显示返回结果并继续观察原有卡片流。建议运行期间禁用重复点击。

升级补跑内部使用 suspend fun backfillMeetings207(date: kotlinx.datetime.LocalDate)，由 Worker 调用。
