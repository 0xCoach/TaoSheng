# 卡 049 · 语音输入：读不到界面时截屏识字（后端）

**真机结论（10-24，诊断日志）**：卡 048 的“读界面”在负责人最常用的两个场景都失败——
- **微信**：无障碍只露出 1 个节点（根节点，无子节点），输入框和聊天内容都拿不到（微信屏蔽第三方无障碍）。
- **UU 远程终端**（`com.netease.uuremote`）：32 个节点、0 个可编辑框，文字是自绘的。
- 判断“正在语音输入”是成功的（讯飞 `com.iflytek.inputmethod.miui` 录音会话每次都被察觉）。

负责人提议并确认：**截屏 + 本地识字**。**两个方案都保留**：能用无障碍读到的照旧用原文（小米备忘录 10-24 实测已成功），读不到时自动改用截屏识字。

**约定**：`VoiceInputSettings.screenOcr`（默认 true）已加，界面开关已做。其余签名不变。
**分支 / 工作树**：`codex/049-voice-ocr`，`~/Developer/resound-codex-049`。main 上已有卡 048 及调试改动（`VoiceInputService` 的 `findEditable` 兜底、`connected` 运行状态、`VoiceInputDbg` 诊断日志——只写步骤和数字，保留这种写法）。

## 一、截屏

1. 无障碍配置加 `android:canTakeScreenshot="true"`，用 `AccessibilityService.takeScreenshot`（API 30+，小米 14 Pro 为 Android 15）。不走 MediaProjection，不弹录屏确认。
2. 截图只在内存里识别，**不落盘、不上传、不进日志**；识别完立即回收位图。禁止截屏的页面（返回错误或全黑）直接跳过不记。
3. 只在“语音窗口”期间截，系统对截屏有频率限制（约每秒一次），按限制排队，别连续失败重试。
4. 描述文字（`voice_input_description`）补一句“读不到界面时会截屏在手机上识别文字，图片不保存”。

## 二、识字

1. 用离线中文识字（建议 Google ML Kit 中文文字识别**内置模型版**，不依赖 Play 服务下载；版本与 AGP 8.11.1 / compileSdk 36 兼容，写进交付说明）。返回每块文字及位置。
2. 去掉状态栏（顶部）、导航栏和**输入法面板区域**（语音窗口开始时输入法面板盖住下半屏，用输入法窗口的位置排除；拿不到就排除屏幕下方约 40%）。

## 三、哪句是“我说的”

走截屏这条路时（读界面拿不到输入框或文字）：
1. **A 图**：语音窗口开始时截一张 → “之前的上下文”（最近约 20 行）。
2. **找我发出的那句**：别的应用停止录音后，每约 1.5 秒截一张，最多 20 秒（或离开该应用即停），和 A 比较：
   - 聊天类（微信等）：**新出现、靠右侧**（文字块中心在屏幕宽度 55% 以右）的气泡文字即我发出的话；可能分成几块，按位置合并成一句。
   - 其他（终端等）：新出现的文字块里，取最靠下、且在 A 中不存在的那一段；终端会把我输入的命令回显出来，同样适用。
   - 20 秒内没发现就不记（可能没发送或删掉了）。
3. **之后的回复**：确认我那句后 2 分钟再截一张（期间离开该应用则在离开前最后一次可见时截），比上一张新增、且不是我那句的文字 = “之后的回复”；只补记一次。
4. **标题**：聊天类取 A 图顶部区域的标题文字（如“文件传输助手”“老王”），拿不到为 null。
5. 识字结果去重、去掉时间戳样式（`23:41`）、“发送”“按住说话”等界面文字（复用 `CHROME` 列表）。
6. 记录与卡 048 相同：存成“我”的一句，`voiceInput` 带应用名、标题、前后上下文；与录音转写的重复检查照旧。

## 四、必测（6～10 个，用构造的识字结果，不用真图）

1. 聊天类：A/B 对比取右侧新增气泡；多块合并；左侧新增（对方消息）不当成我说的。
2. 终端类：取最靠下的新增段。
3. 20 秒没发现不记；离开应用即停。
4. 状态栏、输入法区域、时间戳、界面文字被过滤。
5. 回复补记一次，排除我那句。
6. 读界面成功时不截屏（走原路）；`screenOcr=false` 时不截屏。
7. 截屏失败 / 黑屏跳过。
