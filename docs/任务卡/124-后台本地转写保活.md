- 工作目录 `~/Developer/TaoSheng-124`，分支 `codex/124-local-asr-background`（从 `plan/0220` 拉出）。**不改 `ui/`、`MainActivity.kt`、约定文件签名、版本号**。
- 版本：**0.2.20**。不能影响小米等正常手机的录音、转写和耗电。

## 问题

GitHub #21（请先 `gh issue view 21` 读全文，作者已定位到代码）：鸿蒙兼容层上，切到后台后录音继续，但本地模型转写暂停或断断续续，回前台才恢复。对照：录音有前台服务 + 唤醒锁；实时转写 Worker（`MODE_REALTIME`）不前台化、`EARLY_WORK` 不加急；本地推理 `:local_asr` 独立进程是纯绑定服务，没有前台优先级、没有唤醒锁。

## 要做（按根因修，不要只针对鸿蒙打补丁）

1. **让本地推理进程继承录音服务的优先级**：主进程绑定 `LocalAsrService` 时加 `Context.BIND_IMPORTANT`（查官方文档确认在 API 29–35 的效果；如果还有更合适的标志如 `BIND_INCLUDE_CAPABILITIES`，评估后选用，交付说明写理由）。
2. **推理期间持有唤醒锁**：`:local_asr` 进程里每次推理开始拿 `PARTIAL_WAKE_LOCK`，结束或超时（单次最长按现有最长片段时长 + 余量）释放；用 `try/finally` 保证释放。
3. **实时转写任务**：`EARLY_WORK` 改为加急（与其他任务一致，配额用完退回普通任务）。实时模式要不要 `setForeground`：先查清安卓 12+ “后台启动前台服务”的限制在“应用已有麦克风前台服务在跑”时是否允许；允许且不会抛异常才加，不确定就不加，交付说明写依据链接。
4. **诊断**：转写进程被解绑/重建、推理超时、后台期间实时转写被推迟，各记一条诊断（阶段、是否前台、进程是否重建），不记录内容。
5. 不改转写结果、不改调度频率、不增加常驻耗电：只在有片段要转写时才占用。

## 必测（3～6 个即可）

- 绑定标志包含 `BIND_IMPORTANT`。
- 唤醒锁在成功、失败、超时三种情况下都释放（可抽一个小类测）。
- `EARLY_WORK` 请求是加急的。
