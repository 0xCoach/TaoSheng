## 授权与问题边界

用户明确要求直接制作专题界面改版，并要求新业务代码可供 iOS 复用。本次据此修改 `ui/`，并在 `TopicRepository` 增加只读的 `observeProgress`；这是本轮用户授权覆盖仓库原有分工限制的范围。没有升级依赖或数据库版本。

用户提供的预览版 6 问题记录中，专题请求为 HTTP 200，未发现输出截断凭据。原先的 JSON 外观统计不能证明实际解析失败原因。本次补齐解析阶段与专题阶段诊断，修复已确认的可恢复性缺口，不把某个模型或某个字段武断认定为该日志的唯一根因。

## 用户可以看到的变化

- 首页沿用顶部专题按钮，打开后可切换开始专题和专题记录。开始面板简化为类型、名称、结束方式；默认手动结束，仍遵守原有最长 4 小时规则。
- 记录采用应用现有图标、字号和分组样式，按日期排列；可搜索、筛选需要处理的记录、加载更多。列表中的继续整理有提交防重入。
- 详情展示当前阶段、已完成分段与恢复入口；没有最终事件的专题也能从当天时间线看到状态。
- 已完成纪要直接展开阅读，复用其他报告的复制全部、选择部分内容。时间轴默认折叠，调整操作放入右上角的独立面板。
- 重新生成期间，旧事件、旧纪要继续保留。新结果提交成功才在事务中替换，保留用户修改过的条目以及收藏状态；失败时可查看上次纪要。
- 深浅色均采用主题颜色，状态和进度少量用暖色；修正暗色主按钮文字对比，加强选中态边界。

## 长会议处理

- 共用层按照约 2400 字符分块（为行标记预留开销），长单条原话也按句末/字符边界拆分，保留原始编号。此为原话块大小，不是整个请求的 token 保证；提示词和上下文仍占容量。
- 每个通过业务格式校验的模型响应原子保存到本地断点文件。中断、进程重启后重用成功响应；失败段最多一次格式修复或短暂故障重试，再按原话边界缩小输入。认证、额度等永久错误立即停止。
- 每轮最多 96 次顶层模型调用，达到上限保留进度，用户可继续；底层既有备用线路切换的内部请求不计入这个数字。
- 局部纪要每次两份逐级合成，叶子结果中的要点、结论、行动和引用在共用层保留与精确去重，防止最后一次压缩删掉分段结果。不做无依据的语义矛盾裁决。
- 对拒收的内容不再静默跳过后标记整场完成。未通过格式校验的纯文本仅可展开查看为待确认草稿，不会自动创建待办。
- 断点文件位于 Android 的 `noBackupFilesDir`，不存整份请求正文。原话、说话人、类型、名称、范围或重点变化后来源指纹失效；删除或取消后缓存清理。数据库来源校验放在文件锁外，避免与事务清理互锁。
- 专题请求遵循现有深度思考开关；诊断增加专题编号、阶段、块序号及解析结果，不输出原话或密钥。

## 真机验收与限制

当前没有连接 Android 设备，没有发送真实模型收费请求。会议与故障响应测试使用模拟模型回复，不能替代真实模型质量验收。录音和转写引擎未改动。

需要手机确认：覆盖安装后旧专题与原话可见；在记录里继续整理历史失败专题；真实 1–2 小时会议中断网络/退出后续做；长纪要阅读、弹层操作、原话定位与系统大字体；原话修改或删除后不显示旧缓存。

这套流程降低对大上下文和稳定结构化输出的依赖，但不能保证所有模型成功。服务商不支持现有 OpenAI 兼容请求参数、能力不足、认证/额度/审核错误仍需解决配置或服务问题。当前接口仍沿用现有 JSON 请求方式；没有新增所有供应商的协议适配，也没有声称模型摘要事实已全部人工核验。
