# 卡 068 · 录音导出（合成一个 M4A + 原话文字 + 字幕）与批量删除（后端，关键）

App 名叫“涛声”。在 `preview-0.2.13` 分支上开发。约定（负责人已写，签名不要改）：`transcribe/AudioExportContract.kt`（`ExportRequest`、`ExportEstimate`、`ExportProgress`、`AudioExporter`、`SegmentDeleter`）；`AppGraph.audioExporter`、`AppGraph.segmentDeleter` 槽位已加，由 `ResoundApp` 装配。
界面（原话页多选、导出面板、事件详情/首页多选的导出入口、自动标题、批量播放）由 Claude 做，**本卡不改 `ui/` 和 `MainActivity.kt`**。

## 一、已定方案（负责人已确认）

1. **合成音频**：选中的段按时间顺序，解码（OGG/Opus 或 M4A/AAC，见 `audio/SegmentEncoder`、`AsrAudioReader`）→ 16 kHz 单声道 PCM → 段与段之间插 0.5 秒静音 → 用 `MediaCodec` AAC + `MediaMuxer` 写成一个 **M4A**（码率 48–64 kbps 即可）。流式处理，不要把整段 PCM 一次放进内存（导出可能有 1–2 小时）。
2. **哪些段进音频**：有原声文件的段；**语音输入段**（`voiceInputJson` 非空、无音频）和**原声已过期**的段只进文字；`skipMedia=true` 时，与“媒体”场景事件重叠的段音频和文字都跳过。
3. **原话文字 .txt**（`includeText`）：开头写标题、日期、总时长、涉及的事件标题和人名（来自事件 `people`）；每句一行：`[00:12] 14:05:32 说话人1：……`（前者为在合成录音里的位置，没进音频的句子写 `[—]`）；语音输入的句子标“⌨ 语音输入 · 应用名（无录音）”；说话人显示规则与原话页一致（名字 / 说话人 N / 待确认）。
4. **字幕 .srt**（`includeSrt`）：只含进了音频的句子，时间轴对齐合成录音。
5. **文件**：放 `cacheDir/exports/`，音频与文字、字幕同名（`title` 再兜底去掉 `/\:*?"<>|` 并截到 60 字）；通过现有 FileProvider 可分享（如需在 provider paths 里加 `exports/`）。`cleanup()` 删 1 天前的导出文件，App 启动和每次导出前调用。
6. **`estimate()`**：快速返回各类段数、合成时长（含空白）、预计大小（按码率估）。
7. **`export()`**：返回 Flow，进度 0..1；收集方取消时立即停止并删除半成品；失败给出可读原因（如“有 2 段录音读不出来，已跳过”时仍算成功，在 Done 前用 Working 结束；全都读不出来才 Failed）。坏文件跳过，不让整次失败。
8. **批量删除 `deleteSegments(ids)`**：删录音文件、段记录、其原话（`transcript_lines`）及原话的搜索索引/向量；**整理出的事件和待办不动**。复用现有隐私删除里删段的逻辑（`PrivacyDao` 等），在同一事务里完成；返回删掉的段数。

## 二、必测（适度，6～8 个）

- 两段录音（一段 OGG、一段 M4A）合成后的时长 ≈ 两段之和 + 0.5 秒，文件能用 `MediaExtractor` 读出 AAC 轨。
- 语音输入段、过期段只出现在 txt，且标记正确；音频里没有它们。
- skipMedia 跳过媒体段。
- txt 的 `[mm:ss]` 位置与 srt 时间轴一致（抽一句校验）。
- 取消导出后没有残留文件；cleanup 删除过期文件。
- deleteSegments 删掉段和原话，事件还在。

测试规矩见 `AGENTS.md`：只跑本卡测试，跑通一次就停。编译需 `JAVA_HOME=/opt/homebrew/opt/openjdk@21`（MediaCodec 相关可用 Robolectric 或仪器测试受限时，交付说明写清真机待验项）。
