# 卡 123 交付说明

## 做了什么

- 已用 `gh issue view 20 --json title,body,comments` 阅读 issue 全文（无评论）。仅在当前 `codex/123-backup-downloads` 分支、当前工作目录修改。
- 实现 `useDownloadsFolder()`：显示“下载/涛声备份”，访问状态 `Ok`，`sessionOnly=false`；支持切回系统文件夹，自动备份调度随选择切换。选择写入现有备份设置并随备份恢复，兼容没有新字段的旧文件夹备份。
- 新增 `DownloadsBackupFiles : VolumeStore`，复用现有 `HistoryVolumes` / `DayVolumes` 的备份、保留份数、恢复全部、恢复某一份逻辑。支持写入、列出、读取、复制、删除、旧 ZIP 访问。
- 文件写入 `Download/涛声备份/<安装标识>/…`，使用 MediaStore.Downloads，未增加存储权限。安装标识放在 `noBackupFilesDir`，不随备份恢复，防止换装后与遗留同名文件碰撞。查询限制本应用所有权和所选目录，清理再限制备份命名；不会接管其他应用、其他目录或旧安装的文件。换装后无本安装文件时列表为空，概况为 null，不报错。
- 临时名配合 `IS_PENDING` 写入，读回 SHA-256 校验后发布正式名；可变分卷保留 `.previous`，发布失败清理临时文件并恢复旧文件。
- 目录树诊断包含持久授权、解析目录、建探针、写、读回、改名、删除、列目录的步骤。树 URI 直接调用同一套 SAF 提供方 API，避免 DocumentFile 内部吞掉原始异常；记录异常类型和最多 200 字的脱敏说明，移除 URI、路径、账号、密钥和长串。
- 文件夹树失败的 `lastError` 改为：这个文件夹在本机用不了，可以改存到“下载/涛声备份”。授权/不支持的状态分类仍保留。
- 未修改 `ui/`、`MainActivity.kt`、约定文件签名、版本号、Manifest 和依赖；没有复制备份业务逻辑。

## 真机需要注意什么

### 负责人：小米 14 Pro

1. 备份页选择“改存下载”，应显示“下载/涛声备份”，不弹存储权限、没有仅本次可用提示。
2. 立即备份；在系统文件管理器检查“下载/涛声备份/<安装标识>/”里的 `history`、`objects` 文件。完成后不应留下本次临时 `.part`。
3. 开启自动备份，重启应用后确认位置和开关保留；设置保留 3 份，连续产生 4 个恢复点，列表保留 3 份。
4. 在可恢复的测试数据上分别验证“恢复某一份”“恢复全部”；恢复会覆盖当前数据并重启，先导出一份保存当前资料。
5. 再选普通系统文件夹，确认回到原位置和授权行为。

### 给 issue 提出者的测试步骤

请在鸿蒙 7／卓易通 anco 中更新测试版后，进入备份页：先尝试原来的“选择文件夹”，失败时应显示“可以改存到下载/涛声备份”；点击“改存下载”后立即备份，检查成功时间和历史恢复点，再退出并重新打开应用，确认位置仍保留。在保存当前资料的前提下，选择一份历史恢复点测试恢复。若任一步失败，请导出“关于 → 问题反馈 → 导出问题记录”，附上失败步骤、界面提示和“本机备份诊断”部分；新诊断应能看到 persist、resolve-directory、create-probe、probe-write、probe-readback、rename、delete、list-directory 等具体步骤。换装或换手机后旧文件列表为空属于预期，可用原有“导出一份／从文件恢复”迁移。
