# 任务卡 008：声纹自动补样本 + 用户纠正优先

## 背景（10-23 真机）

负责人手动标了 5 段“这是我”（约 40 秒）。本人语音分数约 0.40–0.89，合成音/视频 ≤0.25。阈值已调为 SURE 0.65 / MAYBE 0.45（`VoiceprintContract.kt`，Claude 维护，**不要改**）。
问题：①样本少，分数波动大；②第一次 markMe 后触发全量比对，后面几次 markMe 排队约 70 秒才生效，用户以为没反应。

## 要做的（只改 `voiceprint/` 和 `data/VoiceprintDao.kt`，不改 ui、Contract、数据库版本）

1. **自动补样本**：比对时，若某组分数 ≥ 0.80 且有效人声 ≥ 3 秒、且该组不在排除表，就作为 source="auto" 的样本加入（同组不重复）。自动样本总数上限 40 条，超出时删最早的自动样本；用户手动（line/enroll）样本永不自动删。加入后不必立刻全量重算，下一轮自然生效。
2. **纠正优先**：`markMe` / `markNotMe` 不能被后台全量比对挡住超过约 2 秒。做法自定（例如后台比对改成逐段持锁、每段之间让出锁；或纠正走单独的快速路径），但要保证数据一致：同一组不会被同时写。
3. **markMe 后的重算**：只重算受影响的分数（用新的平均向量对已处理的组重新打分），不必重新解码音频——为此可以把每组的特征向量缓存在样本外的新表里？**不允许改数据库版本**；如果需要缓存向量又必须加表，停下来在交付说明里提出方案，由 Claude 决定。
4. 重新打分后按 `VoiceprintThresholds.SURE` 写/清 `speakerName = "我"`（只动声纹写的“我”）。
5. 单元测试：自动补样本的门槛/去重/上限淘汰、手动样本不被淘汰、markMe 在长时间后台比对进行中 2 秒内完成（可用假引擎模拟耗时）。只跑本卡相关测试；`./gradlew assembleDebug` 通过（`JAVA_HOME=/opt/homebrew/opt/openjdk@21`）。
