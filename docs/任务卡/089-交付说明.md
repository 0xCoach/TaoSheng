# 089：DJI Mic Mini 蓝牙与小声收音

## 实机排查（2026-11-02）

- 手机原版本 0.2.15-preview.4（43）。系统蓝牙已连接 DJI，但涛声的 BLUETOOTH_CONNECT 权限未授予，输入偏好还指向断开的 USB 接收器。
- 经用户授权授予附近设备权限、选中 DJI 并恢复录音后，系统确认 SCO 输入，AudioRecord 为 VOICE_COMMUNICATION / 16 kHz / 单声道 / silenced=false。中途断连后再次连接也能建立输入。
- 用户按口令测试：21:39 的正常音量句子生成 5 秒片段，本地转写为“这是大家麦克风正常音量测试”（大疆被误识别）。小声句子没有形成新片段。因此连接问题已排除，但旧版小声收录没有通过。
- 此前没有逐帧能量日志，不能断言小声全部被 App 丢弃；系统降噪或麦克风端处理也可能影响送入 App 的声音。

## 调整

- 仅外接输入使用较敏感的人声检测参数：RMS 门槛 0.002 → 0.0005，概率阈值 0.5 → 0.4，累计人声保留门槛 1 秒 → 400 毫秒。
- VAD 模型输入按帧最多放大 8 倍；保存的原始音频保持不变。手机麦克风、离线转写等默认调用继续用原参数。
- 崩溃恢复标记保存本段的保留门槛，兼容旧版一秒标记，避免较短外接麦片段在恢复时丢失。
- 外接输入每 10 秒输出一次 MicSensitivity 能量峰值和判定人声时长，便于分辨“没有输入信号”和“有信号但未判为人声”；不输出声音内容或设备标识。
- 测试版本 0.2.15-preview.5（44），不发布远端。

## 验证

- MicSensitivity089Test 3 项、SpeechSegmenterTest 6 项通过：外接短人声保留、原始样本不变、手机规则不变、静音和短脉冲丢弃、检测增益上限。
- 使用仓库 Silero ONNX 和已有合成语音样本实跑：衰减至 1% 音量时，旧策略识别人声 0 秒，新策略 0.928 秒；本组噪声、静音样本未被判成人声。
- 复现脚本：`uv run --with onnxruntime --with numpy python tools/mic-probe/compare_vad089.py`。
- `assembleRelease -PpreviewNumber=5` 通过；签名证书与原安装包一致，`adb install -r` 返回 Success，手机包信息确认 0.2.15-preview.5（44），录音与蓝牙权限仍已授予。
- 启动后进程存在，自安装时刻起未见 AndroidRuntime 崩溃；手机随后在其他应用前台，尚未确认新版录音输入恢复。实际小声复测等待用户准备，离线衰减样本不能替代真人轻声或耳语。

## 注意与遗留

- 灵敏度提高可能增加环境人声误触发及推理耗电，需要日常佩戴观察。当前只验证有限合成噪声，不能声称不会误录。
- 蓝牙通话输入当时启用了系统降噪/回声消除。本次保留系统处理；若新日志显示轻声输入接近零，再单独比较系统处理和 DJI 设置。
- 顶部采集卡曾显示“手机麦克风”，与输入设置及系统真实 SCO 路由不一致；此次未改 UI，需界面负责人检查标签来源。
- 原始设备诊断仅留本机临时目录 `/tmp/taosheng-mic089/`，不提交含设备标识的系统日志。
