## 真机注意事项与遗留边界

1. 小米 14 Pro 上分别执行整理和问问后，从“关于 → 问题反馈 → 导出问题记录”确认新段；检查内容、用量、备用状态与当前配置一致。换成能稳定产生截断/格式失败的测试服务时，确认摘要能区分 `length`、非 JSON、合法空数组与全过滤。
2. 重启后最近 20 条摘要、放弃记录和切换历史仍在；冷却逻辑原本仅在内存，重启后当前进程冷却显示“暂无”，没有为了诊断改变切换行为。
3. 升级之前的响应和放弃批次无法补记。旧 `lastError` 只在与已知固定文案精确匹配时推断类型，自由文本不导出。无法关联原请求的历史缓存单独标“整理（缓存解析）”，模型/HTTP/耗时未知就显示“暂无”，不冒充当前模型发出的新请求。
4. 响应 `chars/json` 在有正文时针对模型正文；无正文的非流式错误针对已读到的响应包。问问自然语言 `json=false` 正常；仅这一标志不会改变结果或触发重试。没有 HTTP 响应、finish_reason 或不适用的解析数量显示“暂无”。回顾/技能等已覆盖请求摘要，但未新增其业务解析器的数量埋点。
5. 备用列表列出“已保存的其他配置”，不表示所有配置都有凭证或本轮一定会尝试。真实尝试顺序和失败结果看响应摘要；本次未更改备用候选规则。
6. 本卡只补诊断证据，未将议题中的偶发格式问题认定为某个具体根因。真实手机和鸿蒙兼容层表现仍需负责人复测；不涉及 UI 配合或约定签名变更。
