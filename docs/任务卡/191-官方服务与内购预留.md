# 卡 191：为“官方转写/整理服务 + 内购”预留接口（只预留，不上线）

状态：**待派**。等卡 189、190 合进 main 后再从最新 main 开分支（本卡要改的提供方、错误类型、用量、整理结果类型都在那两张卡的范围里）。执行：Codex（Astra）；约定签名由 Claude 定（见下）。

## 背景

负责人要为商业化做准备：以后除了“自己填密钥”，还要提供**涛声官方的转写服务和整理服务**，通过应用内购买开通。

现在的结构：

- 整理/问问等大模型调用：`LlmPreset(id, name, baseUrl, model)` + 用户密钥；`canUseWithoutKey(preset)`、备用模型切换 `LlmFailover`。
- 转写：`TranscribeSource { Doubao, Local, Custom }`，云端两种靠用户密钥。
- 错误：`LlmError.Auth/Quota` 和 `AsrError.Auth` 的提示都是“检查你的密钥/余额”。
- 用量：本机按用途记大模型 token（`UsagePurpose`）和云端转写时长（`AsrUsageRow`），价格是用户自填的。
- 关于页隐私文案写着“不用注册账号，**没有我们的服务器**”。

## 目标：今天什么都不变，以后接官方服务只需“填实现、开开关”

### 1. 账号与权益约定（放 `:shared`，签名由 Claude 定稿，Codex 不自行改）

```kotlin
// shared/.../service/ServiceContract.kt（草案，开工前 Claude 确认）
enum class OfficialFeature { Transcribe, Digest }          // 以后可加 Ask、Review 等

sealed interface Entitlement {
    data object Off : Entitlement                            // 功能没开放（当前唯一实现）
    data object SignedOut : Entitlement                      // 需要登录
    data class Active(val features: Set<OfficialFeature>, val expiresAt: Long?,
                      val remaining: Map<OfficialFeature, Long>) : Entitlement  // 剩余额度：转写=秒，整理=点数
    data class Exhausted(val feature: OfficialFeature) : Entitlement
    data class Expired(val at: Long) : Entitlement
}

interface ServiceAccount {
    val entitlement: StateFlow<Entitlement>
    /** 给官方服务请求用的短期凭据；拿不到返回 null（未登录/过期/功能关） */
    suspend fun accessToken(feature: OfficialFeature): String?
    suspend fun refresh()
}

/** 购买渠道：谷歌、微信/支付宝、华为、苹果各自一个实现；本卡只放接口和“不可用”实现 */
interface PurchaseChannel {
    val id: String
    val available: Boolean
    suspend fun products(): List<ServiceProduct>
    suspend fun purchase(productId: String): PurchaseResult
    suspend fun restore(): PurchaseResult
}
data class ServiceProduct(val id: String, val title: String, val priceText: String, val features: Set<OfficialFeature>)
sealed interface PurchaseResult { data object Done : PurchaseResult; data object Cancelled : PurchaseResult; data class Failed(val message: String) : PurchaseResult }
```

本卡只提供 `Entitlement.Off` 的空实现和“不可用”购买渠道，经 `AppGraph` 装配。**不接任何支付 SDK，不加依赖。**

### 2. 提供方留位

- 转写：`TranscribeSource` 加 `Official("涛声官方")`，界面暂不显示（由开关 `service.official_enabled` 控制，默认关，代码里集中一处判断）。对应提供方实现：凭据来自 `ServiceAccount.accessToken(Transcribe)`，地址从配置读取（本卡用占位，不发真实请求）；没开放时直接报“未开通”，不会落到网络请求。
- 整理：预置一个 `LlmPreset(id = "official", …)`，同样由开关隐藏；`canUseWithoutKey("official")` 在权益有效时为真，鉴权头用 `accessToken(Digest)`。走现有新网络层，不新建客户端。
- `LlmFailover`：允许“官方服务为主、自己的密钥做备用”或反过来，复用现有备用机制，不新写切换逻辑。
- 现有用户：开关关着时，界面、设置、请求、备份内容与改前**完全相同**。

### 3. 错误分开说

新增错误种类（`LlmError`、`AsrError` 各自加，或用卡 189 的整理结果类型携带原因）：

- 需要登录、额度用完、订阅过期、服务暂停。
- 这些错误**不能**提示“检查密钥”，界面以后会引导“去开通/续费”。自动整理遇到它们按卡 188 的规则当“需用户处理”（按完整间隔再试，不每分钟重试）。

### 4. 用量按来源记

- 大模型用量、云端转写时长加一个“来源”维度：`自己的密钥` / `官方服务`（数据库加列需要升库版本，按 `CaptureDatabase.MIGRATIONS` 规范加一条，默认值=自己的密钥，旧数据不动）。
- 用量页以后能分开显示“官方服务用了多少、还剩多少”；官方服务的余额以服务端为准，本机只做显示。

### 5. 隐私与开关

- 开关关闭时，不会有任何数据发往官方服务。
- 交付说明里列出：开放官方服务时需要同步改的隐私文案位置（关于页“没有我们的服务器”等）、首次使用前的告知与同意入口位置。**本卡不改文案**，由 Claude 和负责人在开放前定。

## 测试

- 开关关闭：转写/整理选择、请求、`canUseWithoutKey`、备用切换与改前一致（对照测试）。
- 开关打开但权益为 Off / SignedOut / Exhausted：官方提供方不发网络请求，报对应错误；自动整理按“需用户处理”处理。
- 权益 Active：鉴权头来自 `accessToken`，用量记为“官方服务”。
- 数据库迁移：旧库升级后旧用量全部归“自己的密钥”。
- 新增约 8～12 个；必跑与提供方、备用切换、用量、迁移相关的已有测试，按改动列清单。
