# 微信气泡说话人与折行

## 证据

真机记录 2299 中，绿色长消息第一行未标注，第二行被标成“测试”。用户切到微信后已截图核对：第一条收到的灰色气泡、两条绿色长消息、灰色长消息、最后一条绿色消息顺序清晰。原算法逐行比较文字左右距离，无法处理长消息居中、短折行偏左。

## 修改

- 微信 OCR 读取文字矩形内绿色背景的采样比例，绿色证据优先标“我”，不依赖文字长短。
- 在文字左右留白处沿同色背景探测气泡上下边界；绿色气泡为我，已确认独立的中性颜色气泡为对方。屏幕背景中的时间等不当作气泡。
- 相同气泡边界的文字合为连续一段，跨 OCR 文字块也合并；不同气泡不合并。仅无气泡证据时才退回邻近文字块及位置判断。
- 已发送消息兜底也使用气泡边界，避免拼入另一条消息。
- 原有同聊天上下文去重规则与原话去重未改，标题比例不变。旧记录不自动改写，截图不入库、不上传；生产中的图像仍仅在内存处理。

## 验证

VoiceInputSpeakerTest 5 项、VoiceInputChatOrderTest 2 项、VoiceInput049Test 21 项、VoiceInputEmptyBoxContextTest 3 项通过；assembleDebug 与 git diff --check 通过。

实际截图像素探测确认：两条绿色气泡背景约 RGB(62,181,117)，上下边界分别 y=445..622、655..832；灰色长气泡约 RGB(44,44,44)，边界 y=865..1042。测试以这些形状/颜色构造场景，并覆盖浅色主题灰白气泡、跨文字块折行、相邻不同气泡、居中时间不带气泡标识。

真机截图证明错误归属和像素特征，合成测试证明新算法；安装后仍需新的微信语音采集验证完整链路。图片、文件卡片、自定义背景/主题及不规则气泡可能无法获得可靠边界，此时保留回退行为，不声称已覆盖所有微信消息类型。
