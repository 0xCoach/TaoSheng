- 每通道 `files/push-state/<id>.json` 保存 SHA-256、拥有的文件及已发布模板。模板缓存用于摘要即时更新时保留尚未触发的记录；不含凭据。内容未变不会因“更新时间”变化而重传。每成功一个文件就落盘，可恢复分批进度。
- 上传逐级 MKCOL，PUT 临时 `.part-<随机>`，目标存在时 DELETE 后 MOVE；每轮最多 20 个上传文件，剩余 30 秒后续传。429/503 立即结束本轮，由 WorkManager 指数退避，不在同一轮连续重试。中断的临时文件下一轮清理。
- 删除事件、“这段别记”、取消标星、删除卡片均通过数据库变化进入下一轮更新；只删除指纹表内且符合生成路径白名单的文件。`rebuild` 先分批删除已拥有的文件，再按 backfillDays 重建；未知文件和用户笔记不碰。
- Webhook 增量发送 `records_delta` upsert/delete，保留原 HMAC 和地址校验；全量发送 `daily_memory`。Notion 按日期指纹更新、归档重建，某天删空时归档旧页。Telegram/邮件沿用 Markdown 附件发送。
- 每通道唯一 WorkManager 任务：网络约束、失败指数退避、最短间隔合并、多时刻/星期调度、全量校对及分批续传。Manual 不自动推整理结果，摘要与提醒独立触发。数据库启动监听覆盖进程重启期间的变更。
- 补齐此前只有主题定义、没有生产者的提醒调度：待办/约定到期、标星满三天且相关条目没有后续完成/状态进展，按通道去重。资料通道写入当日记录；消息通道发送提醒。
- `status(id)` 持久保存上次成功时间、结果、错误，运行状态通过 Flow 更新；推送日志记录更新/删除文件数或变化条数。

## 真机/接收端验收步骤（交负责人执行）

1. 先连接备份坚果云，新增同步文件夹通道并选“用已连接坚果云”；保存后确认界面账号、密码不重复填写。尝试另建同账号同文件夹，应给出占用通道名。断开备份账号后推送，应显示重新连接提示。
2. 用少量测试事件分别开启类别/按天布局，检查中文说明卡、英文路径、技能卡字段、MeOnly 和媒体过滤。向 `my-notes/` 及根目录放用户文件，后续同步和 rebuild 均应保留。
3. 首次补齐超过 20 个文件，查看状态进入续传；无修改再推应显示更新 0 个文件。修改条目状态、取消标星、删除事件/卡片或使用“这段别记”，下一轮远端应相应更新/删除。
4. 检查 OnChange 的 5 分钟以上间隔、多个时刻/星期、Manual 以及全量校对；独立生成回顾/技能通知时核对摘要。Manual 模式的摘要更新不能提前发布新整理结果。
5. 新建短时到期待办与标星测试数据，检查提醒仅发一次；已有相关条目进展的重点不应收到三天提醒。进程重启、断网恢复后观察续传及错误状态。
6. Webhook 接收端检查 upsert/delete 和签名；Notion 检查只重建变化的日期及删空归档；Telegram/邮件检查 Markdown 附件。
7. 使用“全部重新生成”，检查按 backfillDays 分批重建且用户文件仍在。

## 行为说明与遗留

- 本次后端完成；界面由 Claude 接入现有约定。未做手机、真实坚果云和真实第三方账号验收，不将模拟服务结果视为真机通过。
- WorkManager 的时刻受系统省电/网络约束影响，不保证精确到分钟；需在目标小米手机验证后台限制。
- `backfillDays=0` 从今天开始；30 表示含今天的 30 天。首次边界会持久保留，增量不会每天把首次历史范围往后推。修改补齐天数后用 rebuild 应用；rangeDays 是持续生效的滚动上限。Manual 抑制整理结果的自动触发及 fullCheck，摘要和提醒保持独立。
- 账号或目的文件夹更换时重新建立该目的地的本地拥有权，不跨账号清理旧目录；删除通道只停止任务并清理本地状态，不自动删远端资料。要删除已同步内容，应在原通道/目录仍有效时处理。
- MOVE 的目标 DELETE 与 MOVE 之间存在 WebDAV 服务端固有的短暂空窗；失败会保留本地未确认状态并重试，不能承诺服务端事务原子性。
- 提醒的“进展”按该重点关联条目的完成/状态变化判断；不额外调用模型推断语义关联。回顾、技能摘要沿用已有生成/通知入口的开关行为。
