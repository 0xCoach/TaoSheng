# 卡 231 交付说明

## 改动

- `PlatformServices` 移入 `:shared`，由安卓注入原有平台实现及 `AndroidEntitlements`。权限入口声明更多推送通道、Markdown 每日笔记、高级导出、每日回顾和每周回顾，安卓对所有枚举值返回可用。现有功能入口沿用原判断。
- `configureCapture()` 使用 `CaptureDatabase.MIGRATIONS`，依次注册全文搜索、导入记录、事情、待落库整理的回调。安卓主库仍使用 `AndroidSQLiteDriver` 加查询统计，备份恢复和日分卷仍通过原 `open` 入口打开指定路径。库版本和表结构沿用原定义。
- iOS 真机和模拟器目标共用 `openCaptureDatabase(path)`，各自在 `taosheng.ios=true` 时使用 `sqlite-bundled:2.6.2`。入口使用 `Dispatchers.IO`、共用建库配置，并记录传入的 `filePath`。
- `CoreRuntime` 持有平台插口与数据库。安卓传入 `ResoundApp.database` 原本使用的惰性实例，按原顺序发布 `AppGraph.platform`、建立标记设置、首次取数据库创建标记仓库，再按原条件结束 `:local_asr` 的启动装配。

## 后续执行器迁入的阻碍

| 执行器 | 当前依赖与接入点 |
| --- | --- |
| 转写 | `TranscribeRunner` 处理 `File` 和共享 PCM 文件，提供方路径还接安卓解码与本地识别子进程。需要平台无关的音频句柄、解码与识别接口，保留队列恢复、重试和用量记录。 |
| 整理 | `DigestRunner` 持有 `AndroidDigestSettings`、`digest-state` 偏好、系统单调时钟和诊断入口。迁移时需保留提供方的可用性判断、需用户处理的结果以及 `inflight` 和 `digest_pending` 的防重发流程。 |
| 问问 | `AndroidAskRepository` 从 `AppGraph` 读取地点、场景、屏幕时间和模板，使用 `org.json`、Java 日期及安卓偏好。共用编排需要显式注入这些数据来源、时间和持久化入口。 |
| 推送与调度 | `AndroidPushChannels` 依赖安卓密钥存储、文档树、文件目录及系统调度。迁移需为传输、状态存储、通知和调度提供平台实现，保留重试、游标与去重语义。 |
