# 卡 066 · 本地转写用上热词：同音纠正（后端）

App 名叫“涛声”。在 `preview-0.2.13` 分支上开发（在卡 065 之后）。**本卡不改 `ui/` 和 `MainActivity.kt`。**

## 一、问题（已查明）

热词只用于豆包云端（`DoubaoProtocol` 的 corpus.hotwords）、自定义云端（作为 prompt）和整理（`DigestPrompt.withHotwords` 让模型纠正同音字）。**本地转写（sherpa-onnx SenseVoice）完全没用热词**，该模型也不支持热词。所以用本地转写时，原话里“城改”仍是“承改”，用户觉得热词不生效。

## 二、已定方案（负责人已确认）

本地转写出文字后、保存前，用热词表做**同音纠正**：
1. 引入轻量中文转拼音库（建议 TinyPinyin，Apache-2.0，离线；如选别的说明理由与许可，并在 `docs/third-party/` 记录）。
2. 只用热词表里的词（`AndroidHotwordSettings.merged()`，含用户手动加的和声纹人物名）；**只用 ≥2 个汉字的词**；非汉字（英文、数字）不参与。
3. 在每句话里找与热词**长度相同、不带声调的拼音完全相同、但字不同**的片段，替换为热词。多音字：一个字的任一读音能对上就算匹配。
4. **防止改错**：
   - 原片段本身是常用词时不替换（随包带一份常用词表，几千到一两万个高频词即可，注意许可；或用拼音库自带词典，二选一并说明）。
   - 原片段跨越标点不替换。
   - 同一位置有多个热词可匹配时，选最长的；还相同则不替换。
5. **可追溯**：被替换过的句子记下原识别文本（如 `transcript_lines` 新增可空列 `originalText`，数据库 21 → 22 或与 065 合并的版本号顺延；按 `CaptureDatabase.MIGRATIONS` 规矩），并在 `PipelineTimes` 记一行“同音纠正 N 处”（不记内容）。
6. 只作用于**本地转写**（`LocalAsrProvider` 输出的句子）；云端转写不加这一步。导入录音走本地转写时同样生效。
7. 性能：每段额外耗时应在毫秒级；热词拼音结果缓存，热词变化时刷新。

## 三、必测（适度，6～8 个）

- “承改” + 热词“城改” → 替换；“城改”本身不动。
- 热词“李明”、原话“黎明到了” → 因“黎明”是常用词不替换。
- 单字热词不参与；英文热词不参与。
- 多音字能匹配（如“长”）。
- 跨标点不替换；替换后 `originalText` 记下原文。
- 云端转写结果不经过纠正。

测试规矩见 `AGENTS.md`：只跑本卡测试，跑通一次就停。编译需 `JAVA_HOME=/opt/homebrew/opt/openjdk@21`。
