App 名叫“涛声”。在 **`env-sound` 分支**上开发（从 0.2.13 正式版的 main 拉出）。**本卡不改 `ui/` 和 `MainActivity.kt`**，界面由 Claude 按约定另做。

研究依据：`docs/任务卡/061-评测报告.md`（阈值与规则都来自这里；评测数据在 `~/Datasets/taosheng-audio/results/`，只读，不入库）。

## 一、总原则（负责人已确认）

1. **人声优先，录音逻辑一律不改**：没人说话照旧不录。只对**已经录下的片段**，在**转写之前**判断一次，一次推理同时得出四样东西：是否可跳过、是否疑似影视、环境标签、对话中的特别声音。
2. **总开关默认关**。打开总开关时才下载模型；没下载好之前一切照旧（不判断、不影响转写）。
3. **宁可漏判，不可误伤真人对话**：任何不确定都按“照常转写”处理；声纹认出“我”的片段一律不跳过、不判影视。
4. **旧录音不补算**，只处理开关打开之后新录的片段。

## 二、模型与推理

- 模型：sherpa-onnx `sherpa-onnx-zipformer-small-audio-tagging-2024-04-15`（int8，约 27 MB，AudioSet 527 类）。
  - 来源：k2-fsa/sherpa-onnx GitHub Releases 的 `audio-tagging-models`。开发时从这里取；**正式下载走魔搭镜像** `OpenRecode/TaoSheng-models`（Claude 负责上传，路径定为 `audio-tagging/zipformer-small-2024-04-15/`，文件名保持原样），GitHub 作为备用源。下载复用 `LocalModels` 现有的断点续传、备用源切换和 SHA-256 校验；评测时模型 SHA-256 记录在 `zipformer-provenance.json`（`69304b8a…`，是目录哈希，单文件哈希请在交付说明里列出）。
  - 许可：Apache-2.0，在 `docs/third-party/` 补一份记录。
- 运行：用 sherpa-onnx 的 `AudioTagging` 接口。先确认现有 `app/src/main/jniLibs/arm64-v8a/libsherpa-onnx-jni.so`（v1.13.8，见 `docs/third-party/local-asr.md`）是否已带 AudioTagging 的 JNI；带了就补 Kotlin 接口文件（照 `com/k2fsa/sherpa/onnx/` 的做法），没带要说明换库方案后再动手，**不要改本地转写的运行库和进程结构**。
- 窗口：**≤30 秒的片段整段推理一次**；更长的片段**取开头、中间、结尾各 10 秒**（重合去重），每类取最大值。
- 2 线程；放在后台低优先级，跟现有转写队列串行，不和本地转写抢 CPU。每段耗时记进 `PipelineTimes`（只记耗时和结论，不记内容）。

## 三、判断规则（阈值写成一个配置对象，便于以后调）

记号：S = 语音类最大分（Speech、男/女/儿童语音、Conversation、Narration、Whispering、Speech synthesizer）；H = 人声保护类最大分（婴儿哭、哭泣、笑、咳嗽、呼吸、尖叫、喊叫）。

1. **可跳过（纯音乐 / 环境音）**：`S < 0.2 且 H < 0.05 且 max(Music, 各环境标签与特别声音的类分) ≥ 0.2`。
   - 跳过档位 `SkipMode`：**关**（不判）/ **只标记**（默认；照常转写，原话页标“可跳过”）/ **开**（不转写，判为 `Skipped`）。由用户手动选，**不自动切换**。
2. **疑似影视外放**：`S ≥ 0.05 且 Music ≥ 0.9 且 声纹没有认出“我”`。真实电视剧片段 Music 0.93–0.95，日常对话 ≤0.01（见报告第 6 节）。
   - 影视档位 `MediaMode`：**照常记录**（默认，只记一笔不影响任何东西）/ **标记为媒体**（整理时这段归为“媒体”场景，复用现有 `MEDIA_SCENE = "媒体"`）/ **不转写**（同 `Skipped`，可找回）。
   - 无配乐外放（新闻、口播）识别不了，照常记录，不要加报告第 5 节的频谱规则。
   - 疑似影视的片段**不记特别声音**（电视里的狗叫、婴儿哭不算）。
3. **环境标签（9 类，`EnvTag`）**：按报告第 4 节“环境标签归并与阈值”表，类映射见 `results/label-map.csv`：音乐 0.8、键盘 0.02、雨 0.2、宠物 0.1、流水 0.05、家电 0.005、脚步 0.02、闹钟 0.01、交通 0.3（给用户看的写法是“附近有车流”）。室内 / 户外 / 车上 / 厨房 / 嘈杂人声 / 发动机**不做**。
4. **对话中的特别声音（`SpecialSound`）**：婴儿哭 0.05、敲门 0.3、狗叫 0.1、警笛 0.3。**只记录、不提醒、不推送通知**。烟雾报警、门铃、玻璃碎不做。
5. 开关 `tags` / `specialSounds` 关掉时不再记录对应数据（已记录的保留）。

## 四、存储与对外接口（实现 `EnvSoundRepository`）

- 数据库 22 → 23：新表存每段的判断（段 id、时间范围、结论、原因、标签、特别声音、关键分数、是否找回、是否点过“判断错了”）。按 `CaptureDatabase.MIGRATIONS` 规矩只加一条迁移；迁移测试用 `CaptureDatabase.VERSION`。删除录音段、清除原声时同步清理或保留判断记录（保留判断、去掉可试听标记）。
- 设置 `EnvSoundSettings` 持久化；模型状态 `EnvModelState` 按下载进度更新。
- `flagged(date)`：当天 可跳过 / 已跳过 / 疑似影视 的段。
- `eventSounds(date)`：按事件的时间范围合并其录音段的标签和特别声音；`media` = 其中有疑似影视段。
- `eventsWith(tag, sound)`：带某标签 / 特别声音的事件 id，新的在前。
- `hourly(date)`：每小时说话分钟数、出现最多的标签、出现过的特别声音；没录音的小时不返回。
- `stats(days)`：过去 N 天标记了多少段、找回多少、点了多少次“判断错了”、约省了多少分钟转写（按跳过段的时长算）。
- `restore(segmentId)`：把已跳过 / 不转写的段送回转写队列（保留期内；过期返回失败，失败文案写“这段录音已过保留期”）。
- `reportWrong(segmentId)`：本机记下这段的分数（不上传），可跳过 / 已跳过的同时按“照常”处理并送去转写。
- `audio(segmentId)`：录音文件还在就返回。
- **已跳过的原声保留 1 天**（不受用户设的原声保留天数影响，取二者较长），过期后只剩判断记录。

## 五、和现有流程的衔接

- 转写前插入判断：`Skipped` 和“不转写”的影视段不送转写、不进整理；其余照常。判断失败（模型没下载、读文件出错）一律照常转写，记一行诊断。
- “标记为媒体”的段：整理时把这段的场景标为“媒体”（现有灰色显示和统计口径自动生效）。
- `showInSummaries` 打开时：每日 / 每周回顾和推送内容里，每件事可附一行环境（如“环境：雨、键盘声”），特别声音写成“期间有敲门声”；关掉则不写，数据照存。整理用的提示词**不加**环境信息（避免模型编造）。
- 问题记录（`ProblemReports.export`）加一节：开关与档位、模型状态、最近 7 天各结论的段数、平均耗时；不写内容和分数明细。

## 六、必测（适度，8～12 个）

- 规则：纯音乐 → 可跳过；S 高的真人对话 → Keep；H 触发（笑、咳嗽）→ Keep；背景音乐 + 声纹认出“我” → 不判影视。
- 档位：只标记仍转写；开 → 不转写且可找回；影视“不转写”同理；`reportWrong` 后送去转写。
- 窗口：40 秒片段只推理 3 个 10 秒窗。
- 总开关关 / 模型未下载 → 完全不影响转写。
- 迁移 22 → 23。
- 事件合并标签、按小时汇总的正确性。
