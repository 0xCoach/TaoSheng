# 008 交付说明

## 做了什么

- 分支：`codex/008-voiceprint-auto`，本地提交，不推送。
- 自动补样本：分数 ≥ 0.80、静音裁剪后的有效人声 ≥ 3000ms、未排除的组加入 `source="auto"`；同组不重复。插入、淘汰、分数和处理时间在同一事务提交。
- 自动样本最多 40 条，按 `createdAt` 从旧到新淘汰，同时间按 id 淘汰较早记录。`line/enroll` 不参与淘汰；用户确认自动样本后转成 `line`，保留原 id。
- 每轮固定平均向量，自动加入的样本下一轮参与计算，不立即触发全量重算。
- 后台轮次串行，解码和模型计算移到提交锁之外。人工操作串行，使用独立引擎；纠正提交后递增版本号，旧后台轮次不能覆盖纠正或重新添加已排除的组。
- `markMe` 立即保存样本、撤回排除并更新本组；`markNotMe` 立即删除本组样本、写排除并清本组结果。其他组标记待重算，沿用现有调度器后台更新，点击操作不再等待全量比对。
- 分组向量存入数据库文件旁的私有目录 `capture.db.voiceprint-features/`，不新增表、不改数据库版本。文件原子写入，键包含模型版本、录音身份和句子范围；短人声结果也缓存。缓存先于处理时间落盘，重启、音频过期后仍可复用。
- 重打分按 `VoiceprintThresholds.SURE` 写入或清除“我”，其他姓名保留。清空声纹同时清缓存；录音清理避开正在读取的段。
- 生产代码仅修改 `voiceprint/` 与 `data/VoiceprintDao.kt`；未改界面、`MainActivity`、Contract、数据库 schema 或依赖版本。

## 遗留与边界

- 旧版只有相似度、没有非样本分组的向量。首次升级后的重算需从仍存在的旧音频提取一次；此后复用缓存。缓存缺失或损坏也按此路径恢复；音频和缓存都不存在时无法恢复向量，清空该组声纹结果并放行整理，保留原有过期提示。
- 新的手动分组没有缓存时，仍需完成该组自身的解码和推理；2 秒目标针对等待后台全量比对，不承诺任意长度录音的首次提取都在 2 秒内。
- 历史分数异步重算，受现有 WorkManager 网络约束及重试时间影响；本组纠正先落库。后台因版本变化中断会返回重试。
- `withStableResults` 仍保留原有整理取数及网络请求期间的锁语义，因此整理请求本身仍可能延迟纠正；本卡解除的是后台声纹全量比对的阻塞。若要同时消除整理请求的等待，需要另卡协调整理结果快照和提交协议。
- 缓存是 App 私有的派生声纹数据，不计入样本数；reset 会清空。当前随历史分组增长，未增加定期淘汰策略，以保留音频过期后的重打分能力。
- 无需 UI 或 Contract 配合，无需新增数据库表。
