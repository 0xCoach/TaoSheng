# 卡 126 · 锁屏时实时转写攒批执行（省电）

- 工作目录 `~/Developer/TaoSheng-126`，分支 `codex/126-batch-when-screen-off`（从 `plan/0221` 拉出）。**不改 `ui/` 和 `MainActivity.kt`**。
- 版本：进 0.2.21。难度中，涉及转写调度，务必稳。

## 背景

0.2.20 卡 124 为修 #21（鸿蒙兼容层后台本地转写暂停）做了三件事：本地推理服务 `BIND_IMPORTANT`、推理期间持 `PARTIAL_WAKE_LOCK`、实时转写 `EARLY_WORK` 改加急（expedited）。
负责人用本地模型 + 实时转写，升级后耗电和“唤醒时间”明显增加。原因判断：每录完一段就加急唤醒一次，锁屏期间被一段一段频繁拉起来做重计算；以前系统会把这些合并推迟。

## 目标

锁屏且未充电时，不再每段都加急唤醒，改为**攒一批再转**；亮屏或充电时保持现在的“马上转”。同时不能让 #21 复发：锁屏时转写不能停摆，只是攒批。

## 要做

1. **判断“该攒批”**：屏幕关闭（`PowerManager.isInteractive == false`）且未充电（`BatteryManager` 充电状态）。判断写成一个纯函数，便于测试。
2. **攒批时的调度**（`TranscribeScheduler` 里排 `EARLY_WORK` 的地方）：
   - 不加急；用 `setInitialDelay(BATCH_DELAY)`，`BATCH_DELAY` 默认 10 分钟，放进 `CaptureTuning` 之类的常量处。
   - 唯一任务策略用 `KEEP`：已有一个在等的批次就不重复排、不重置计时，让这 10 分钟内的新段一起转。
   - 正在跑时追加一轮的现有逻辑（`APPEND_OR_REPLACE`）保留，但追加的那一轮同样按攒批规则（不加急、带延迟）。
3. **亮屏或插上充电时立刻补上**：监听 `ACTION_SCREEN_ON` 和 `ACTION_POWER_CONNECTED`（录音前台服务已有接收器的话复用），收到时若有在等的批次，改排一个立即执行（加急）的任务替换掉它。
4. **唤醒锁保持卡 124 的做法**（只在真正推理时持有、有超时兜底），不要扩大持有范围。核对一遍：排队、模型空闲驻留、等待批次期间都不持锁。
5. **兜底不变**：原有的周期转写任务、到点整理、间隔整理都不受影响；实时转写关闭时本卡逻辑不生效。
6. **诊断**（用于负责人验证效果）：在现有 `PipelineTimes` / 诊断里，按天累计并随问题记录导出三项：本地推理持锁总时长、实时转写被唤醒执行的次数、其中加急 / 攒批各多少次。不记录音频、文字、路径。

## 必测（5～10 个用例）

- 锁屏未充电 → 不加急、带 10 分钟延迟、KEEP 不重复排。
- 亮屏或充电 → 保持加急立即执行（与现状一致）。
- 有等待中的批次时收到亮屏/接电 → 替换成立即执行。
- 诊断计数累加正确。
- 卡 124 原有测试 `LocalAsrBackground124Test` 照过（只跑它和本卡新测试）。

## 真机由负责人测

本地模型 + 实时转写，锁屏 1 小时对比 0.2.20 的耗电与唤醒次数（`adb shell dumpsys batterystats` 里 `resound:local-asr` 唤醒锁），亮屏后几分钟内转写跟上。
