## 给自定义接口接收方

### 请求与响应

UTF-8 JSON，`POST` 到配置 URL，`Content-Type: application/json; charset=utf-8`。任意 HTTP 2xx 视为接收成功；无需返回固定 JSON。重定向不会跟随，接收方宜尽快入队后返回。

地址默认 HTTPS；仅以下地址允许 HTTP：`10.0.0.0/8`、`192.168.0.0/16`、`172.16.0.0/12`、`100.64.0.0/10`、以 `.local` 或 `.ts.net` 结尾的主机。公网 HTTP 拒绝。不能在 URL 中放账号密码或 fragment。附加请求头禁止 Host、Content-Length、Content-Type、Authorization、Connection、Transfer-Encoding、代理认证及 `X-Resound-*` 等保留头，重名也拒绝。

为支持任意局域网 / Tailscale IP，Manifest 开启 `usesCleartextTraffic`；具体可用 HTTP 目标由上述 Webhook 校验在保存和发送两处限制。Android 的此项开关是应用级，不能表达任意私网 IP 段，后续新增网络客户端仍应自行要求 HTTPS。

### 普通消息

```json
{
  "type": "new_event",
  "version": 1,
  "app": "回响",
  "title": "消息标题",
  "body": "消息正文",
  "topic": "NewEvent",
  "deepLink": "resound://...",
  "at": 1792800000000
}
```

| type | topic | 业务字段 |
| --- | --- | --- |
| `daily_review` | `DailyReview` | 公共字段；有完整回顾时另有 `review: {date, brief, sections:[{title, lines:[]}]}`。 |
| `todo_reminder` | `TodoReminder` | `title`、`body` 是提醒标题和内容；`deepLink` 可为空。 |
| `new_event` | `NewEvent` | `title`、`body` 是事件通知标题和内容；`deepLink` 可为空。 |
| `skill_card` | `SkillCard` | `title`、`body` 是技能卡通知标题和内容；`deepLink` 可为空。 |
| `test` | null | 无历史回顾时的连接测试。若测试按钮选中最近回顾或每日记忆，仍使用对应业务 type。 |

`at` 为毫秒时间戳；`body` 按通道格式取纯文本或 Markdown。Webhook 的 JSON 外层始终存在，与格式选择无关。当前事件、提醒、技能卡通知沿用现有通知入口提供的标题和正文，没有另加不存在于入口参数中的实体数据。

### 每日记忆

```json
{
  "type": "daily_memory",
  "version": 1,
  "app": "回响",
  "date": "2026-10-24",
  "generatedAt": 1792800000000,
  "markdown": "# 当天记忆\n...",
  "data": {
    "review": {"brief": "简述", "sections": [{"title": "一句话", "lines": ["内容"]}]},
    "events": [{"id": 1, "start": 1792800000000, "end": 1792800060000, "title": "事件", "summary": "摘要", "scene": "会议", "people": ["小王"], "important": true}],
    "items": [{"id": 2, "category": "待办", "kind": "我要做", "content": "发送报价", "due": null, "who": "小王", "status": "Accepted"}],
    "cards": [{"skill": "会议纪要", "title": "方案会", "summary": "摘要", "at": 1792800000000, "values": {}}],
    "lines": [{"id": 3, "at": 1792800000000, "speaker": "我", "text": "原话"}]
  }
}
```

- 未勾选带原话时，整个 `data.lines` 字段缺省，Markdown 也没有独立“原话”一节。技能卡自身保存的引用仍属于卡片内容。
- 没有回顾时 `review` 为 null；列表没有内容时为 `[]`。`due` 优先给毫秒时间戳，其次原始时间文字，没有则为 null；其它可空字段显式 null。
- 卡片 `values` 以字段 key 为键；值包含 `text`、`items[]`、`checked[]`、`number`、`unit`、`rating`、`quotes[]`。引用含 `lineId`、`speaker`、`at`、`text`。
- 所有时间数字为 Unix 毫秒；`date` 是本地回顾归属日。记忆接收方建议按 `app + type + date` 覆盖更新同一天；其它消息可按 `type + at + title` 做去重。

### 可选签名

填写签名密钥后，每次发送加：

- `X-Resound-Timestamp`：当前 Unix 秒，十进制字符串。
- `X-Resound-Signature`：`sha256=` + 小写十六进制 HMAC-SHA256；签名输入是 `timestamp + "." + 原始 HTTP body`，密钥使用 UTF-8。

Python 校验示例（必须使用请求原始字节，不要重新序列化 JSON）：

```python
import hashlib, hmac, time

def verify(secret, timestamp, signature, raw_body):
    try:
        fresh = abs(time.time() - int(timestamp)) <= 300
    except (ValueError, TypeError):
        return False
    digest = hmac.new(secret.encode(), timestamp.encode() + b"." + raw_body, hashlib.sha256).hexdigest()
    return fresh and hmac.compare_digest(signature, "sha256=" + digest)
```

发送失败沿用原重试机制，最多额外 3 次；重试重新生成时间戳与签名。接收成功但回包丢失时仍可能重发，接收方应幂等处理。

## 负责人真机注意事项与遗留边界

- 本次未操作手机；配置界面、系统网络策略、厂商后台定时、真实服务权限与送达需要负责人后续实测。SMTP 生产实现会校验证书和主机名，但本次没有真实 TLS 互通证据。
- 没有已知未完成的任务卡功能。普通 Notion 消息按卡限制最多 90 块；每日文档完整分批。响应超过 64 KiB 会安全失败；已有推送记录文件达到该上限时，WebDAV 追加会拒绝读取，需负责人归档后再继续。每日文档覆盖不受 GET 上限影响。
- Notion 同日更新按卡要求“先归档再新建”；如果创建时网络失败，旧页暂在归档中，后续重试再建。HTTP / SMTP 均是至少一次投递，邮件和 Telegram 超时重试可能重复送达。
- WebDAV 没有 ETag 的服务器无法保证外部客户端同时写入时无冲突；本 App 内部已串行化读改写。不要让另一个写入者同时修改“推送记录”。
- 编译沿用既有弃用 API、原生库无法剥离符号等警告；没有升级依赖或改 UI。
